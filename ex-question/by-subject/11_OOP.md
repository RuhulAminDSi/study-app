## Function overloading ambiguity (C++)

### Q9(b) <sub>Q0054</sub>

*38th BCS Written · 2018 · Written*

Why are the overloaded functions int f(int a, int b=5); and int f(int &a); inherently ambiguous?

- **Printed answer:** Calling a function with a reference parameter looks the same as calling one with a value parameter. The solver adds that 'int b' should not be in the question.
- **Correction:** The explanation is incomplete and the solver's remark is wrong. Because of the default argument, the call f(x) with an int lvalue matches both f(int, int=5) and f(int&) equally well, so the compiler cannot choose. The default b=5 is what causes the ambiguity, so it belongs in the question.
- **Source:** [BCS/20_software-risks-overloaded-functions.md](../BCS/20_software-risks-overloaded-functions.md) · [image](../BCS/20_software-risks-overloaded-functions.jpg); [BCS/18_database-security-osi-binary-logic.md](../BCS/18_database-security-osi-binary-logic.md) · [image](../BCS/18_database-security-osi-binary-logic.jpg)
