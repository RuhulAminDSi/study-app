## ১. কনস্ট্রাক্টর: নিয়ম ও প্রকার

**কনস্ট্রাক্টর (Constructor)** একটি বিশেষ মেম্বার ফাংশন, যা অবজেক্ট তৈরির সময় **স্বয়ংক্রিয়ভাবে** চলে এবং অবজেক্টকে একটি বৈধ প্রাথমিক অবস্থায় আনে। এর নাম **ক্লাসের নামের সমান** এবং **কোনো রিটার্ন টাইপ নেই — `void`-ও নয়**। এটি ওভারলোড করা যায়, `private` হতে পারে (সিঙ্গেলটন), কিন্তু C++-এ `virtual` বা `static` হতে পারে না, Java-তে `final`, `static` বা `abstract` হতে পারে না। এটি **ইনহেরিট হয় না**।

প্রতিটি অবজেক্টের জীবন: ① মেমোরি বরাদ্দ → ② কনস্ট্রাক্টর ইনিশিয়ালাইজ করে → ③ অবজেক্ট ব্যবহার → ④ ডিস্ট্রাক্টর পরিষ্কার করে → ⑤ মেমোরি মুক্ত।

```cpp
class Student {          // C++
    string name;  int age;
public:
    Student() {          // default
        name = "Unknown"; age = 0;
    }
    Student(string n, int a) {  // param.
        name = n; age = a;
    }
    Student(const Student& s) { // copy
        name = s.name; age = s.age;
    }
};
Student s1;              // default
Student s2("Alice", 20); // parameterized
Student s3 = s2;         // copy
```

| প্রকার | সিগনেচার | কখন চলে |
|---|---|---|
| **ডিফল্ট** | `A()` | `A a;` |
| **প্যারামিটারাইজড** | `A(int x)` | `A a(5);` |
| **কপি** | `A(const A&)` | `A b = a;` |
| **ইমপ্লিসিট** | কম্পাইলারের | একটিও **না লিখলে** |
| **ওভারলোডেড** | ভিন্ন প্যারামিটার | কম্পাইল টাইমে বাছাই |

| নিয়ম | C++ | Java |
|---|---|---|
| ফ্রি ডিফল্ট ctor | কেবল **কোনো** ctor ঘোষণা না থাকলে | কেবল একটিও না লিখলে; `super()` ডাকে |
| কপি কনস্ট্রাক্টর | ইমপ্লিসিট, মেম্বার-ভিত্তিক (শ্যালো) | **নেই**: নিজে লেখো বা `clone()` |
| রিটার্ন টাইপ দিলে | কম্পাইল এরর | `void A(){}` = সাধারণ **মেথড** |
| `new` ছাড়া অবজেক্ট | `A a;` অবজেক্ট বানায় (স্ট্যাক) | `A a;` কেবল null রেফারেন্স |

- 💡 **কৌশল:** কনস্ট্রাক্টর হলো জন্মসনদ: তাতে শিশুর নাম থাকে, জন্মের সময় একবারই দেওয়া হয়, আর কিছু ফেরত দেয় না।
- ⚠️ **ফাঁদ:** কেবল `A(int)` লিখলে `A a;` / `new A()` আর কম্পাইল হয় না। C++-এ `A a();` একটি **ফাংশন** ঘোষণা, অবজেক্ট নয়।

✍ **সমাধানকৃত উদাহরণ — কোনটি চলে?** `A a; A b(3); A c = b; A d = 7;` → ডিফল্ট, প্যারামিটারাইজড, **কপি**, প্যারামিটারাইজড (ইমপ্লিসিট রূপান্তর; `explicit` দিলে বন্ধ)।

## ২. কপি কনস্ট্রাক্টর; শ্যালো বনাম ডিপ কপি

**কপি কনস্ট্রাক্টর (Copy constructor)** একই ক্লাসের বিদ্যমান অবজেক্টের কপি হিসেবে একটি **নতুন** অবজেক্ট তৈরি করে। C++ রূপ: `ClassName(const ClassName& other)`। এটি চলে যখন একটি অবজেক্টকে আরেকটি থেকে **ইনিশিয়ালাইজ** করা হয় (`A b = a;`, `A b(a);`), যখন অবজেক্ট **পাস বাই ভ্যালু** হয়, এবং যখন **রিটার্ন বাই ভ্যালু** হয় (প্রায়ই বাদ পড়ে)। কম্পাইলারের সংস্করণ মেম্বার ধরে ধরে কপি করে — **শ্যালো কপি (Shallow copy)**।

ছবি: শ্যালো — `a.p` ও `b.p` দুটোই একই বাফার "Dhaka" দেখায় (এক বাফার, দুই মালিক); ডিপ — প্রত্যেকে নিজস্ব বাফার দেখায়।

```cpp
class Str {
    char* p;
public:
    Str(const char* s) {
        p = new char[strlen(s) + 1];
        strcpy(p, s);
    }
    Str(const Str& o) {     // deep copy
        p = new char[strlen(o.p) + 1];
        strcpy(p, o.p);
    }
    ~Str() { delete[] p; }
};
Str a("Dhaka");
Str b = a;   // copy ctor: own buffer
```

| বিষয় | শ্যালো কপি | ডিপ কপি (Deep copy) |
|---|---|---|
| কী কপি হয় | পয়েন্টার (ঠিকানা) | পয়েন্টার যে ডেটা দেখায় সেটি |
| কে বানায় | কম্পাইলারের কপি ctor / `Object.clone()` | নিজের কপি ctor / ওভাররাইড করা `clone()` |
| কপির পরে | *b*-তে বদল *a*-তেও দেখা যায় | অবজেক্ট দুটি স্বাধীন |
| বিপদ | **ডাবল delete**, ড্যাংলিং পয়েন্টার | ধীর, বেশি মেমোরি |
| ঠিক আছে যখন | পয়েন্টার/হ্যান্ডল মেম্বার নেই | ক্লাস হিপ মেমোরি, ফাইল, সকেটের মালিক |

- **কেন `const A&`?** রেফারেন্সে: বাই-ভ্যালু প্যারামিটার হলে কপি বানাতে আরেকটি কপি লাগত → অসীম পুনরাবৃত্তি, তাই C++ `A(A a)` নাকচ করে। `const`: `const` অবজেক্ট ও টেম্পোরারি কপি করা যায়, আর উৎস না বদলানোর প্রতিশ্রুতি। **রুল অব থ্রি (Rule of three):** যে ক্লাসের নিজস্ব ডিস্ট্রাক্টর লাগে, তার নিজস্ব কপি কনস্ট্রাক্টর ও কপি অ্যাসাইনমেন্টও লাগে।
- **Java-তে ডিফল্ট কপি কনস্ট্রাক্টর নেই।** নিজে লেখো: `Student(Student s) { name = s.name; age = s.age; }`, অথবা `clone()` ওভাররাইড করো। `Object.clone()` **শ্যালো**, `protected`, আর ক্লাস `implements Cloneable` না করলে `CloneNotSupportedException` ছোড়ে।
- 💡 **কৌশল:** শ্যালো ঠিকানা কপি করে; ডিপ পুরো বাড়ি। এক চাবির দুই মালিক আসবাব নিয়ে ঝগড়া করে।
- ⚠️ **ফাঁদ:** *b* আগে থেকেই থাকলে `b = a;` ডাকে **অ্যাসাইনমেন্ট অপারেটর**, কপি কনস্ট্রাক্টর নয়। `A b = a;` ইনিশিয়ালাইজেশন → কপি কনস্ট্রাক্টর।

✍ **সমাধানকৃত উদাহরণ — কপি গোনো।** `void f(A x){}`; `A a; A b = a; A c(a); f(a); b = c;` → কপি কনস্ট্রাক্টর: **৩ বার**; শেষ লাইনটি অ্যাসাইনমেন্ট।

## ৩. ইনিশিয়ালাইজার লিস্ট ও কনস্ট্রাক্টর চেইনিং

C++-এর **মেম্বার ইনিশিয়ালাইজার লিস্ট (Member initializer list)** (`A(int v) : x(v), Base(v) {}`) বডি চলার **আগেই** বেস ও মেম্বার ইনিশিয়ালাইজ করে। `const` মেম্বার, রেফারেন্স মেম্বার, ডিফল্ট কনস্ট্রাক্টরহীন ক্লাসের মেম্বার এবং আর্গুমেন্ট-চাওয়া বেস ক্লাসের জন্য এটি **বাধ্যতামূলক**। **কনস্ট্রাক্টর চেইনিং (Constructor chaining)** মানে এক কনস্ট্রাক্টর থেকে আরেকটি ডাকা: Java `this(…)` (একই ক্লাস) ও `super(…)` (প্যারেন্ট), C++ `: Base(…)` এবং C++11 থেকে ডেলিগেটিং `A() : A(0) {}`।

```cpp
class Point {               // C++
    const int x;  int& r;
public:
    Point(int a, int& b)
        : x(a), r(b) {}  // must
};
class P3 : public Point {
    int z;
public:
    P3(int a, int& b, int c)
        : Point(a, b), z(c) {}
    P3(int& b) : P3(0, b, 0) {}
};          // C++11 delegating ctor
```

```java
class A {                   // Java
    A() { System.out.print("A"); }
    A(int x) {
        this();          // 1st line
        System.out.print(x);
    }
}
class B extends A {
    B() {
        super(5);        // 1st line
        System.out.print("B");
    }
}
new B();   // prints A5B
```

কল চেইন: `new B()` → `B()` → `super(5)` → `A(int)` → `this()` → `A()` ছাপে A; ফেরার পথে `A(int)` ছাপে 5, তারপর `B()` ছাপে B → **A5B**। কল আগে চেইন বেয়ে ওপরে যায়; বডি ছাপে ফেরার পথে।

| কাজ | C++ | Java |
|---|---|---|
| প্যারেন্ট ctor ডাকা | লিস্টে `: Base(args)` | `super(args)`, **প্রথম লাইন** |
| নিজের অন্য ctor | `: A(args)` (C++11) | `this(args)`, প্রথম লাইন |
| কোনোটিই না লিখলে | বেসের ডিফল্ট ctor চলে | কম্পাইলার বসায় `super();` |
| দুটো একসঙ্গে? | ডেলিগেটিং হলে আর কিছু নয় | **না**, একটিই |
| ইনিশিয়ালাইজেশনের ক্রম | আগে বেস, তারপর মেম্বার **ঘোষণার ক্রমে**, লিস্টের ক্রমে নয় | (একই ধারণা) |

- 💡 **কৌশল:** সন্তানের আগে বাবা-মা গড়া হয়: `super` আগে, বডি শেষে। কল ওঠে ওপরে, প্রিন্ট নামে নিচে।
- ⚠️ **ফাঁদ:** প্যারেন্টে কেবল `A(int)`; `class B extends A { B(){} }` → **কম্পাইল এরর**: লুকানো `super()` কোনো `A()` পায় না। সমাধান: `super(0);`।

✍ **সমাধানকৃত উদাহরণ — লিস্টের ক্রম।** `int a, b;` তারপর `T() : b(1), a(b) {}` → *a* **আগে** সেট হয়, অনির্ধারিত *b* থেকে: **গার্বেজ**।

## ৪. ডিস্ট্রাক্টর ও অবজেক্টের আয়ু

**ডিস্ট্রাক্টর (Destructor)** (`~ClassName()`) অবজেক্টের আয়ু শেষ হলে স্বয়ংক্রিয়ভাবে চলে এবং তার দখলে থাকা জিনিস — হিপ মেমোরি, ফাইল, সকেট, লক — ছেড়ে দেয়। নিয়ম: টিল্ডা + ক্লাসের নাম; **প্যারামিটার নেই, রিটার্ন টাইপ নেই**; তাই **ওভারলোড করা যায় না** — প্রতি ক্লাসে ঠিক একটি; ইনহেরিট হয় না; `virtual` হতে পারে (কনস্ট্রাক্টর কখনো নয়)। অবজেক্ট ধ্বংস হয় গঠনের **উল্টো ক্রমে** (লোকাল অবজেক্ট স্ট্যাকে: গঠন ১ ২ ৩, ধ্বংস ৩ ২ ১)।

| অবজেক্টের ধরন | ডিস্ট্রাক্টর কখন চলে |
|---|---|
| লোকাল (অটোমেটিক) | স্কোপের শেষ `}`-এ, উল্টো ক্রমে |
| গ্লোবাল / `static` | প্রোগ্রাম শেষে (`main` ফেরার পর) |
| হিপ (`new`) | কেবল `delete`-এ — ভুললে **মেমোরি লিক** |
| টেম্পোরারি | পূর্ণ এক্সপ্রেশনের শেষে |
| মেম্বার অবজেক্ট | মালিকের ডিস্ট্রাক্টর বডির পরে |
| অ্যারের উপাদান | সবচেয়ে বড় ইনডেক্স আগে |

| বিষয় | কনস্ট্রাক্টর | ডিস্ট্রাক্টর |
|---|---|---|
| নাম | `A()` | `~A()` |
| প্যারামিটার / ওভারলোডিং | যেকোনো / হ্যাঁ | **নেই / না** |
| প্রতি ক্লাসে কয়টি | অনেক | **একটি** |
| `virtual` হতে পারে | না | হ্যাঁ — পলিমরফিক বেসে দরকার |
| ইনহেরিট্যান্সে ক্রম | বেস → ডিরাইভড | ডিরাইভড → বেস |

- **ভার্চুয়াল ডিস্ট্রাক্টর (C++):** `Base* p = new Derived; delete p;` — `~Base()` `virtual` না হলে কেবল `~Base` চলে (আনডিফাইন্ড বিহেভিয়ার; Derived অংশ লিক হয়)। বেস হিসেবে ব্যবহৃত যেকোনো ক্লাসে `virtual ~Base()` দাও। ভার্চুয়াল ডিসপ্যাচ কীভাবে কাজ করে: পরের লেসন।
- **Java: ডিস্ট্রাক্টর নেই।** **গার্বেজ কালেক্টর (Garbage collector)** অনাগম্য অবজেক্ট মুক্ত করে, কখন — আগে বলা যায় না; `System.gc()` কেবল অনুরোধ। `finalize()` সর্বোচ্চ একবার চলত, না-ও চলতে পারত, আর এটি **ডেপ্রিকেটেড** (Java 9; Java 18 থেকে অপসারণের জন্য)। ফাইল বন্ধ করো `try`-with-resources দিয়ে (`AutoCloseable`)।
- 💡 **কৌশল:** প্লেটের স্তূপ: সবশেষে রাখা প্লেটটিই আগে তোলা হয়। টিল্ডা `~` = বিদায়ের ঢেউ।
- ⚠️ **ফাঁদ:** গার্বেজ কালেকশন ডিস্ট্রাক্টর **নয়**: এটি কেবল মেমোরি ফেরত নেয়, নির্দিষ্ট সময়ে নয়। `finalize()` চলবেই — এমন নিশ্চয়তা নেই।

✍ **সমাধানকৃত উদাহরণ — ট্রেস।** `{ A a(1); A b(2); A* p = new A(3); }` → গঠন ১ ২ ৩; `}`-এ: **~2 ~1**; অবজেক্ট ৩ কখনো ধ্বংস হয় না (লিক)।

## ৫. অবজেক্টের অ্যারে

**অবজেক্টের অ্যারে (Array of objects)** এমন অ্যারে যার প্রতিটি উপাদান একটি ক্লাসের অবজেক্ট। **C++**-এ `Student s[3];` **তিনটি অবজেক্ট** বানায় এবং ডিফল্ট কনস্ট্রাক্টর তিনবার ডাকে, তাই ক্লাসে অ্যাক্সেসযোগ্য ডিফল্ট কনস্ট্রাক্টর লাগে (নয়তো প্রতিটি উপাদান ইনিশিয়ালাইজ করতে হয়)। **Java**-তে `new Student[3]` একটি অ্যারে বানায় যাতে **তিনটি null রেফারেন্স** — কোনো Student অবজেক্ট নেই, কনস্ট্রাক্টর কল নেই — যতক্ষণ না প্রতিটিকে `new` করা হয়।

```cpp
// C++
Student s[3];              // 3 x Student()
Student t[2] = { Student("A", 20),
                 Student("B", 22) };
Student* p = new Student[n];
p[0].display();
delete[] p;    // [] required
```

```java
// Java
Student[] s = new Student[3]; // nulls
s[0].display();     // NullPointerException
for (int i = 0; i < s.length; i++)
    s[i] = new Student();
s[0].name = "Alice";
s[0].display();     // now fine
```

| বিষয় | C++ `A arr[3];` | Java `A[] arr = new A[3];` |
|---|---|---|
| যা তৈরি হয় | ৩টি অবজেক্ট | ১টি অ্যারে অবজেক্ট + ৩টি রেফারেন্স |
| কনস্ট্রাক্টর কল | ৩ (ডিফল্ট ctor) | **০** |
| শুরুর উপাদান | গঠিত অবজেক্ট | `null` (সংখ্যা 0, boolean false) |
| ক্লাসে ডিফল্ট ctor নেই | সব ইনিশিয়ালাইজ না করলে কম্পাইল এরর | সমস্যা নেই |
| মুক্ত হয় | স্কোপ শেষে, বা `new A[n]`-এর জন্য `delete[]` | গার্বেজ কালেক্টর |
| দৈর্ঘ্য | সংরক্ষিত নয় (স্থির অ্যারেতে `sizeof` কৌশল) | `arr.length` (ফিল্ড, বন্ধনী নেই) |

- 💡 **কৌশল:** C++ সারি সারি বাড়ি বানায়; Java ছাপে সারি সারি খালি ঠিকানার চিরকুট। `new` না করলে বাড়ি নেই।
- ⚠️ **ফাঁদ:** `new A[n]` মুক্ত করতে হয় `delete[]` দিয়ে; শুধু `delete` আনডিফাইন্ড বিহেভিয়ার। C++ `A* q[3];` পয়েন্টারের অ্যারে: অবজেক্ট **নেই**।

✍ **সমাধানকৃত উদাহরণ — আউটপুট।** `A(){cout<<"A";} ~A(){cout<<"~";}` এবং `{ A arr[3]; }` → **AAA~~~**। একই প্রিন্টসহ Java `new A[3]`: কিছুই না।

## ৬. অবজেক্ট পয়েন্টার, `this`, new/delete, রেফারেন্স

**অবজেক্ট পয়েন্টার (Object pointer)** একটি অবজেক্টের ঠিকানা রাখে: `Student* p = &s;`। মেম্বারে পৌঁছাতে অ্যারো: `p->display()` ≡ `(*p).display()`। `new` হিপে অবজেক্ট বানিয়ে তার ঠিকানা দেয়; `delete` সেটি ধ্বংস করে। প্রতিটি নন-স্ট্যাটিক মেম্বার ফাংশন একটি লুকানো পয়েন্টার **`this`** পায়, যা কলকারী অবজেক্টকে দেখায়। Java-তে স্পষ্ট পয়েন্টার নেই: প্রতিটি অবজেক্ট ভ্যারিয়েবল একটি **রেফারেন্স (Reference)**।

```cpp
class Counter {
    int n = 0;
public:
    Counter& inc() {
        ++this->n;       // this->n == n
        return *this;    // allows chaining
    }
    int get() const { return n; }
};
Counter* c = new Counter;
c->inc().inc().inc();
cout << c->get();  // 3
delete c;  c = nullptr;
```

| বিষয় | `new` / `delete` (C++) | `malloc` / `free` (C) |
|---|---|---|
| এটি কী | অপারেটর (ওভারলোড করা যায়) | লাইব্রেরি ফাংশন |
| কনস্ট্রাক্টর / ডিস্ট্রাক্টর | **ডাকে** | ডাকে না |
| আকার ও টাইপ | নিজে হিসাব; ফেরত `A*` | বাইট হাতে দিতে হয়; ফেরত `void*` |
| ব্যর্থ হলে | `std::bad_alloc` ছোড়ে | `NULL` ফেরত দেয় |
| অ্যারে | `new A[n]` … `delete[]` | `malloc(n*sizeof(A))` … `free` |

| বিষয় | C++ পয়েন্টার `A* p` | C++ রেফারেন্স `A& r = a` | Java রেফারেন্স |
|---|---|---|---|
| null হতে পারে | হ্যাঁ | না; ইনিশিয়ালাইজ বাধ্যতামূলক | হ্যাঁ (`null`) |
| পরে অন্যটিকে দেখানো | হ্যাঁ | না (একটি অ্যালিয়াস) | হ্যাঁ |
| গাণিতিক / অ্যাক্সেস | `p++`; `->` ও `*` | নেই; `.` | নেই; `.` |
| অবজেক্ট মুক্ত করা | হাতে `delete` | মালিকের আয়ু | গার্বেজ কালেক্টর |

- 💡 **কৌশল:** ঠিকানার জন্য অ্যারো, সরাসরি জিনিসের জন্য ডট। `this` = "যে অবজেক্ট কলের জবাব দিল"।
- ⚠️ **ফাঁদ:** `static` বা `friend` ফাংশনে `this` নেই। `this`-এ অ্যাসাইন করা যায় না। `new`-এর সঙ্গে `free` (বা `malloc`-এর সঙ্গে `delete`) মেশানো আনডিফাইন্ড।

✍ **সমাধানকৃত উদাহরণ — Java অ্যালিয়াস।** `Student s = new Student(); s.age = 20; Student r = s; r.age = 21;` → `s.age` হয় **21**: এক অবজেক্ট, দুই রেফারেন্স।

## ৭. ইনহেরিট্যান্স: is-a ও পাঁচটি প্রকার

**ইনহেরিট্যান্স (Inheritance)** একটি নতুন **ডিরাইভড** (চাইল্ড, সাব) ক্লাসকে বিদ্যমান **বেস** (প্যারেন্ট, সুপার) ক্লাসের মেম্বার পেতে দেয়, তারপর সে নিজের মেম্বার যোগ বা পুনঃসংজ্ঞায়িত করে। এটি **is-a** সম্পর্ক বোঝায় (Car is-a Vehicle), কোড পুনর্ব্যবহার দেয় এবং রান-টাইম পলিমরফিজমের ভিত্তি। সিনট্যাক্স: C++ `class Car : public Vehicle {…};` · Java `class Car extends Vehicle {…}`।

| প্রকার | আকৃতি | C++ উদাহরণ | C++ / Java ক্লাস |
|---|---|---|---|
| **সিঙ্গেল (Single)** | A → B | `class B : public A` | ✓ / ✓ `extends` |
| **মাল্টিলেভেল (Multilevel)** | চেইন A → B → C | `B : A`, `C : B` | ✓ / ✓ |
| **হায়ারার্কিক্যাল (Hierarchical)** | A → B, A → C | `B : A`, `C : A` | ✓ / ✓ |
| **মাল্টিপল (Multiple)** | A, B → C | `C : public A, public B` | ✓ / ✗ (ইন্টারফেসে ✓) |
| **হাইব্রিড (Hybrid)** | মিশ্রণ, যেমন ডায়মন্ড | A; B, C : A; D : B, C | ✓ / কেবল ইন্টারফেসে |

- **যা ইনহেরিট হয় না:** কনস্ট্রাক্টর ও ডিস্ট্রাক্টর (C++11-এ `using Base::Base;` দিয়ে নেওয়া যায়) · কপি অ্যাসাইনমেন্ট অপারেটর (ডিরাইভডেরটি লুকিয়ে দেয়) · friend ফাংশন — বন্ধুত্ব উত্তরাধিকারে যায় না · private মেম্বার: C++-এ ডিরাইভড অবজেক্টের ভেতরে থাকে কিন্তু নাম ধরে ব্যবহার করা যায় না; Java বলে এগুলো ইনহেরিট হয় না। `final` ক্লাস (যেমন `String`) এক্সটেন্ড করা যায় না।

| বিষয় | is-a | has-a |
|---|---|---|
| কৌশল | ইনহেরিট্যান্স | কম্পোজিশন |
| উদাহরণ | Car is-a Vehicle | Car has-a Engine |
| কাপলিং | টাইট | লুজ |
| কোড | `extends` | একটি ফিল্ড |

- 💡 **কৌশল:** পাঁচ প্রকার: "**Some Mice Make Huge Holes**" = Single, Multilevel, Multiple, Hierarchical, Hybrid।
- ⚠️ **ফাঁদ:** মাল্টিলেভেল ≠ মাল্টিপল। মাল্টিলেভেল = একক ধাপের চেইন (Java-তে চলে); মাল্টিপল = একসঙ্গে দুই প্যারেন্ট (Java ক্লাসে চলে না)।

✍ **সমাধানকৃত উদাহরণ — শ্রেণিবিন্যাস।** `C : A, B` → মাল্টিপল। `B : A; C : B` → **মাল্টিলেভেল**। `B : A; C : A` → হায়ারার্কিক্যাল।

## ৮. ইনহেরিট্যান্সের অ্যাক্সেস মোড ও গঠনের ক্রম

C++-এ **ইনহেরিট্যান্স মোড (Inheritance mode)** — `public`, `protected` বা `private` — একটি **ছাদ**: ইনহেরিট হওয়া মেম্বার কম দৃশ্যমান হতে পারে, বেশি কখনো নয়। বেসের `private` মেম্বার ডিরাইভড ক্লাসে **কখনো অ্যাক্সেসযোগ্য নয়**, মোড যা-ই হোক। ডিফল্ট মোড: `class` → private, `struct` → public। Java-তে মোড একটিই: `extends` প্রতিটি অ্যাক্সেস লেভেল যেমন আছে তেমন রাখে।

| বেসে ↓ | `public` ইনহেরিট্যান্স | `protected` ইনহেরিট্যান্স | `private` ইনহেরিট্যান্স |
|---|---|---|---|
| `public` | **public** | protected | private |
| `protected` | protected | protected | private |
| `private` | **অ্যাক্সেস নেই** | **অ্যাক্সেস নেই** | **অ্যাক্সেস নেই** |

```cpp
class X { public:
    X()  { cout << "X"; }
    ~X() { cout << "~X"; } };
class Y { public:
    Y()  { cout << "Y"; }
    ~Y() { cout << "~Y"; } };
class Z : public X {
    Y y;                    // member
public:
    Z()  { cout << "Z"; }
    ~Z() { cout << "~Z"; } };
int main() { Z z; } // XYZ~Z~Y~X
```

গঠন: ① বেস `X()` ② মেম্বার `Y()` ③ বডি `Z()`। ধ্বংস: ① `~Z()` বডি ② মেম্বার `~Y()` ③ বেস `~X()` — ধ্বংস = গঠনকে উল্টো দিক থেকে পড়া।

১. আগে **ভার্চুয়াল বেস ক্লাস** (প্রতিটি একবার), তারপর **সরাসরি বেস** বেস-লিস্টের ক্রমে — `class C : public B, public A` আগে B, পরে A গড়ে, ইনিশিয়ালাইজার লিস্টে যা-ই লেখা থাক।
২. তারপর **মেম্বার অবজেক্ট** ঘোষণার ক্রমে, শেষে **কনস্ট্রাক্টর বডি**। ধ্বংস হুবহু উল্টো।
৩. **Java:** static ব্লক ক্লাস লোডের সময় একবার (প্যারেন্ট আগে); প্রতি `new`-এ: `super()` চেইন `Object` পর্যন্ত, তারপর ফিল্ড ইনিশিয়ালাইজার ও বডি, প্যারেন্ট আগে।

```cpp
class A { int a;            // private
  protected: int b;  public: int c; };
class B : private A {
  void f() { a = 1;   // ✗ base-private
             b = 2;   // ✓ now private in B
             c = 3; } };  // ✓ private in B
class C : public B {
  void g() { c = 4; } };  // ✗ private in B
B obj;  obj.c = 5;    // ✗ in main
```

✍ **সমাধানকৃত উদাহরণ — টেবিল পড়ো।** `B : private A` A-র *b* ও *c*-কে **B-তে private** করে দেয়: B-র মেথড এগুলো ব্যবহার করতে পারে; B-র চাইল্ড *C* ও `main` পারে না; A-র *a* B-র ভেতরেও অনাগম্য। `B : public A` হলে `obj.c` ও `c = 4` কম্পাইল হয়; *a* **তবুও তালাবদ্ধ**।

- 💡 **কৌশল:** মোড হলো ছাদ। public রেখে দেয়, protected public-কে protected-এ নামায়, private সবকিছুকে private-এ নামায়; বেসের private তালাবদ্ধই থাকে।
- ⚠️ **ফাঁদ:** `class B : protected A`, *A*-তে public `f()`: `main`-এ `B b; b.f();` → **কম্পাইল এরর**; B-র নিজের মেথডে `f()` চলে।

✍ **সমাধানকৃত উদাহরণ — আউটপুট।** `A(){cout<<"A";} ~A(){cout<<"a";}`, *B*-তে একইভাবে "B"/"b", `class B : public A`, `B obj;` → **ABba**।

## ৯. ডায়মন্ড সমস্যা ও ভার্চুয়াল বেস ক্লাস

**ডায়মন্ড সমস্যা (Diamond problem):** *B* ও *C* দুটোই *A*-কে ইনহেরিট করে, আর *D* ইনহেরিট করে *B* ও *C*-কে। সাধারণ *D* অবজেক্টে তখন *A*-র **দুটি কপি** থাকে, তাই `d.x` **অস্পষ্ট (ambiguous)** (কম্পাইল এরর)। C++ সমাধান করে **ভার্চুয়াল বেস ক্লাস (Virtual base class)** দিয়ে: `class B : virtual public A` ও `class C : virtual public A` ভাগ করে **একটি A**। Java অবস্থার (state) ক্ষেত্রে এটি এড়ায় কেবল একটি প্যারেন্ট ক্লাস দিয়ে।

```cpp
class A { public: int x;
    A() { cout << "A"; } };
class B : virtual public A {
public: B() { cout << "B"; } };
class C : virtual public A {
public: C() { cout << "C"; } };
class D : public B, public C {
public: D() { cout << "D"; } };

D d;          // prints ABCD
d.x = 5;      // OK: one shared A
// without virtual: ABACD, and
// d.x is ambiguous (use d.B::x)
```

| বিষয় | সাধারণ মাল্টিপল ইনহেরিট্যান্স | `virtual` বেসসহ |
|---|---|---|
| D-র ভেতরে A-র কপি | দুটি (একটি B দিয়ে, একটি C দিয়ে) | **একটি**, শেয়ার্ড |
| `d.x` | অস্পষ্ট → `d.B::x` বা `d.C::x` | ঠিক আছে |
| A কে গড়ে | B ও C, প্রত্যেকে নিজের A | সবচেয়ে ডিরাইভড ক্লাস D, **সবার আগে** |
| কনস্ট্রাক্টর আউটপুট | A B A C D | A B C D |

```java
interface Fly  { default void go()
                    { System.out.print("fly"); } }
interface Swim { default void go()
                    { System.out.print("swim"); } }
class Duck implements Fly, Swim {
    public void go() {        // must override
        Fly.super.go();       // pick one
    }
}
```

- **Java: ইন্টারফেস দিয়ে।** একটি `extends`, অনেক `implements`: `class Car extends Vehicle implements Horn, Gps`। Java 8 থেকে ইন্টারফেসে `default` মেথড থাকতে পারে, তাই মেথড-স্তরের ডায়মন্ড সম্ভব: একই সিগনেচারের দুটি default → ক্লাস ওভাররাইড না করা পর্যন্ত **কম্পাইল এরর**; চাইলে `Fly.super.go()` ডাকা যায়। ক্লাসের মেথড ইন্টারফেসের default-কে হারায়।
- 💡 **কৌশল:** ভার্চুয়াল বেস = এক শেয়ার্ড দাদি। দুই প্যারেন্ট, কিন্তু পারিবারিক দাওয়াতে দাদি একজনই, দুজন নন।
- ⚠️ **ফাঁদ:** `virtual` বসে **মাঝের** ক্লাসে (B ও C), D-তে নয়। ভার্চুয়াল বেস ক্লাস আর ভার্চুয়াল ফাংশন এক নয়; দ্বিতীয়টি পরের লেসনে।

✍ **সমাধানকৃত উদাহরণ — আকারের দৃষ্টিতে।** 4-বাইট `int x` হলে সাধারণ ডায়মন্ড *D*-তে x-এর **২টি** কপি; ভার্চুয়াল সংস্করণে ১টি (সঙ্গে লুকানো বেস পয়েন্টার)।

## লিখিত প্রশ্ন (১০ নম্বর)

কপি কনস্ট্রাক্টর কী? এটি কখন ডাকা হয়? হিপ মেমোরির মালিক একটি C++ ক্লাস দিয়ে শ্যালো ও ডিপ কপি ব্যাখ্যা করো, এবং মাল্টিলেভেল ইনহেরিট্যান্সে কনস্ট্রাক্টর ও ডিস্ট্রাক্টর কলের ক্রম লেখো।

**নমুনা উত্তর:**

১. **সংজ্ঞা (২)** — `A(const A& o)` কনস্ট্রাক্টর, যা বিদ্যমান অবজেক্ট থেকে নতুন অবজেক্ট গড়ে; রেফারেন্সে (বাই-ভ্যালু হলে অসীম পুনরাবৃত্তি), `const` যাতে const অবজেক্ট ও টেম্পোরারি নেওয়া যায়।
২. **কখন ডাকা হয় (২)** — `A b = a;` / `A b(a);`, পাস বাই ভ্যালু, রিটার্ন বাই ভ্যালু; `b = a;`-এ নয় (অ্যাসাইনমেন্ট অপারেটর)।
৩. **শ্যালো বনাম ডিপ (৪)** — ডিফল্ট কপি পয়েন্টার কপি করে → শেয়ার্ড বাফার, ডাবল delete; ডিপ কপি নতুন বাফার নিয়ে ডেটা কপি করে (`new char[]`, `strcpy`, `delete[]`সহ *Str* ক্লাস); রুল অব থ্রি।
৪. **ক্রম (২)** — A → B → C হলে: কনস্ট্রাক্টর A, B, C; ডিস্ট্রাক্টর ~C, ~B, ~A।

**পরীক্ষার আগে ✓** কনস্ট্রাক্টর ও ডিস্ট্রাক্টরের নিয়ম বলতে পারি · ডিপ-কপি কনস্ট্রাক্টর লিখতে পারি · গঠন/ধ্বংসের ক্রম ট্রেস করতে পারি · অ্যাক্সেস-মোড টেবিল পূরণ করতে পারি · পাঁচ প্রকার ইনহেরিট্যান্স আঁকতে পারি · `virtual` দিয়ে ডায়মন্ড ঠিক করতে পারি।
