## ১. ট্রান্সপোর্ট লেয়ার (Transport Layer)

**ট্যাগ: MCQ + লিখিত।** OSI-এর লেয়ার ৪ **প্রসেস-টু-প্রসেস (এন্ড-টু-এন্ড)** ডেলিভারি দেয়; নেটওয়ার্ক লেয়ার (IP) দেয় কেবল হোস্ট-টু-হোস্ট ডেলিভারি। সেবাগুলো: **পোর্ট** দিয়ে মাল্টিপ্লেক্সিং/ডিমাল্টিপ্লেক্সিং, সেগমেন্টেশন ও রিঅ্যাসেম্বলি, আর (TCP-তে) নির্ভরযোগ্যতা, ক্রম বজায় রাখা, ফ্লো কন্ট্রোল ও কনজেশন কন্ট্রোল। এটি চলে কেবল **এন্ড হোস্টে**, রাউটারে কখনো নয়।

- **পোর্ট** = ১৬-বিট সংখ্যা → **0–65,535**
  - **ওয়েল-নোন (Well-known)** 0–1023 (সার্ভার)
  - রেজিস্টার্ড 1024–49,151
  - ডায়নামিক / এফিমেরাল 49,152–65,535 (ক্লায়েন্ট)
- **সকেট (Socket)** = IP অ্যাড্রেস + পোর্ট। একটি TCP কানেকশন চেনা যায় **৪-টাপল** দিয়ে (src IP, src port, dst IP, dst port)।
- **PDU:** TCP-তে **সেগমেন্ট** · UDP-তে **ডেটাগ্রাম**। IP প্রোটোকল নম্বর **TCP = 6, UDP = 17**।

|---|---|---|
| FTP ডেটা · কন্ট্রোল | 20 · 21 | TCP |
| SSH · Telnet | 22 · 23 | TCP |
| SMTP | 25 | TCP |
| DNS | 53 | UDP/TCP |
| DHCP · TFTP | 67/68 · 69 | UDP |
| HTTP · HTTPS | 80 · 443 | TCP |
| POP3 · IMAP | 110 · 143 | TCP |
| SNMP · ট্র্যাপ | 161 · 162 | UDP |

## ২. TCP সেগমেন্ট হেডার

**ট্যাগ: হাই-ইল্ড।** নির্দিষ্ট অংশ **20 B**; নিচের সবই এর ভিতরে, আর **অপশন + প্যাডিং** আরও 40 বাইট পর্যন্ত যোগ করতে পারে।

| বিট | ফিল্ড | আকার | মন্তব্য |
|---|---|---|---|
| 0–15 | সোর্স পোর্ট | 16 | প্রেরকের পোর্ট |
| 16–31 | ডেস্টিনেশন পোর্ট | 16 | গ্রাহকের পোর্ট |
| 32–63 | সিকোয়েন্স নম্বর | 32 | গোনে **বাইট**; ISN দৈবভাবে বাছা হয় |
| 64–95 | অ্যাকনলেজমেন্ট নম্বর | 32 | **পরবর্তী প্রত্যাশিত বাইট**, কিউমুলেটিভ |
| 96–99 | HLEN | 4 | গোনে **৩২-বিট ওয়ার্ড**: 5 → 20 B, 15 → **60 B** |
| 100–102 | সংরক্ষিত | 3 | — |
| 103–111 | **ফ্ল্যাগ** | 9 | URG · ACK · PSH · RST · SYN · FIN (+ ECN বিট CWR, ECE) |
| 112–127 | উইন্ডো সাইজ | 16 | রিসিভারের খালি বাফার, স্কেলিং ছাড়া ≤ 65,535 B |
| 128–143 | চেকসাম | 16 | বাধ্যতামূলক, সিউডো-হেডারসহ হিসাব হয় |
| 144–159 | আর্জেন্ট পয়েন্টার | 16 | — |
| 160+ | অপশন + প্যাডিং | 0–40 বাইট | 20 B নির্দিষ্ট অংশের বাইরে |

- 💡 **কৌশল: ফ্ল্যাগ।** "**U**nskilled **A**ttackers **P**ester **R**eal **S**ecurity **F**olks" = URG ACK PSH RST SYN FIN, হেডারের ক্রম অনুযায়ী।
- ⚠️ **ফাঁদ।** HLEN = 8 মানে 8 × 4 = **32 বাইট** হেডার, 8 বাইট নয়।

## ৩. TCP কানেকশন ম্যানেজমেন্ট

**ট্যাগ: হাই-ইল্ড।** **থ্রি-ওয়ে খোলা (নীল) · ফোর-ওয়ে বন্ধ (লাল):**

| ধাপ | ক্লায়েন্ট → সার্ভার | সার্ভার → ক্লায়েন্ট |
|---|---|---|
| খোলা ① | SYN, seq = x | |
| খোলা ② | | SYN+ACK, seq = y, ack = x+1 |
| খোলা ③ | ACK, seq = x+1, ack = y+1 | |
| ডেটা | দুই দিকেই ডেটা | |
| বন্ধ ① | FIN, seq = u | |
| বন্ধ ② | | ACK, ack = u+1 — *হাফ-ক্লোজ: সার্ভার তখনও পাঠাতে পারে* |
| বন্ধ ③ | | FIN, seq = w |
| বন্ধ ④ | ACK, ack = w+1 | |

| পক্ষ | স্টেট, ক্রমে |
|---|---|
| ক্লায়েন্ট | CLOSED · SYN_SENT · ESTABLISHED · FIN_WAIT_1 · FIN_WAIT_2 · **TIME_WAIT (2 MSL)** |
| সার্ভার | LISTEN · SYN_RCVD · ESTABLISHED · CLOSE_WAIT · LAST_ACK · CLOSED |

- **থ্রি-ওয়ে হ্যান্ডশেক** — দুই পক্ষই নিজের **ইনিশিয়াল সিকোয়েন্স নম্বর (ISN)** বেছে নেয় ও নিশ্চিত করে। SYN ও FIN প্রত্যেকে **একটি সিকোয়েন্স নম্বর খরচ করে**; শুধু ACK কোনো নম্বর খরচ করে না।
- **ফোর-ওয়ে ক্লোজ** — TCP **ফুল ডুপ্লেক্স**, তাই প্রতিটি দিক আলাদাভাবে বন্ধ হয় (প্রতি দিকে FIN + ACK)। সার্ভারের ACK ও FIN একসাথে গেলে ৩টি সেগমেন্টেই হয়।
- **স্টেট** — TCP-র **১১টি স্টেট**। যে পক্ষ আগে বন্ধ করে (**অ্যাকটিভ ক্লোজার**) সে **TIME_WAIT-এ 2 MSL** অপেক্ষা করে, যাতে শেষ ACK হারালে আবার পাঠানো যায় এবং পুরোনো ডুপ্লিকেট সেগমেন্ট মুছে যায়।

| স্টেট | অর্থ | স্টেট | অর্থ |
|---|---|---|---|
| LISTEN | সার্ভার SYN-এর অপেক্ষায় (প্যাসিভ ওপেন) | CLOSE_WAIT | অপর পক্ষের FIN এসেছে; অ্যাপ এখনো বন্ধ করেনি |
| SYN_SENT | ক্লায়েন্ট SYN পাঠিয়েছে (অ্যাকটিভ ওপেন) | LAST_ACK | নিজের FIN পাঠিয়ে তার ACK-এর অপেক্ষা |
| SYN_RCVD | হাফ-ওপেন: SYN+ACK পাঠানো হয়েছে | CLOSING | দুই পক্ষ একসাথে FIN পাঠিয়েছে |

**দুটি নয়, তিনটি সেগমেন্ট কেন?** প্রত্যেক পক্ষের নিজের ISN-এর **অ্যাকনলেজমেন্ট** পাওয়া দরকার; দুই ধাপে হলে পুরোনো, দেরিতে আসা একটি SYN ভুয়া কানেকশন খুলে ফেলতে পারত।

✍ **সমাধানকৃত উদাহরণ।** ক্লায়েন্ট ISN = 1000, সার্ভার ISN = 5000। ① SYN seq = 1000 ② SYN+ACK seq = 5000, ack = **1001** ③ ACK seq = 1001, ack = 5001। এবার ক্লায়েন্ট ৪০০ বাইট পাঠায়: seq = 1001 (বাইট 1001–1400); সার্ভারের উত্তর ack = **1401**।

- ⚠️ **ফাঁদ।** **RST** কানেকশন সঙ্গে সঙ্গে ভেঙে দেয় (৪-ধাপের বিনিময় ছাড়াই)। **SYN ফ্লাড**: আক্রমণকারী শেষ ACK পাঠায় না, ফলে সার্ভারের হাফ-ওপেন (SYN_RCVD) কিউ ভরে যায়; প্রতিকার = **SYN কুকি**।
- 💡 **কৌশল।** খোলা = "**কড়া নাড়া, পাল্টা সাড়া, ভেতরে ঢোকা**"। বন্ধ = **দুবার বিদায়, দুবার মাথা নাড়া**। যে আগে বিদায় বলে, সে-ই দরজায় দাঁড়িয়ে থাকে (TIME_WAIT)।

## ৪. ফ্লো কন্ট্রোল (Flow Control): স্লাইডিং উইন্ডো

**ট্যাগ: MCQ + লিখিত।** রিসিভার প্রতিটি সেগমেন্টে **rwnd** (খালি বাফার) জানিয়ে দেয়; প্রেরক অ্যাকনলেজমেন্ট-না-পাওয়া বাইট উইন্ডোর মধ্যে রাখে। কার্যকর উইন্ডো = **min(rwnd, cwnd)**: ফ্লো কন্ট্রোল রক্ষা করে **রিসিভারকে**, কনজেশন কন্ট্রোল রক্ষা করে **নেটওয়ার্ককে**।

| প্রেরকের চোখে বাইট স্ট্রিমের অংশ | অবস্থা |
|---|---|
| সবচেয়ে বাম | পাঠানো ও ACK পাওয়া |
| এরপরেরটি | পাঠানো, ACK আসেনি |
| সেন্ড উইন্ডো = min(rwnd, cwnd)-এর ভিতরে | **এখন পাঠানো যাবে** |
| উইন্ডোর ডানে | এখনো পাঠানো যাবে না |

ACK এলে উইন্ডো ডানে সরে যায়।

✍ **সমাধানকৃত উদাহরণ।** সর্বোচ্চ থ্রুপুট ≈ উইন্ডো / RTT। উইন্ডো 65,535 B, RTT 100 ms → 65,535 × 8 / 0.1 ≈ **5.24 Mbps**, লিংকের গতি যত বেশিই হোক। এজন্যই লং ফ্যাট নেটওয়ার্কে **উইন্ডো-স্কেল** অপশন (শিফট সর্বোচ্চ 14, উইন্ডো 2<sup>30</sup> B ≈ 1 GB পর্যন্ত) লাগে।

**ট্রান্সমিশন পলিসি (দক্ষতা):**

| সমস্যা / কৌশল | কী করে |
|---|---|
| **সিলি উইন্ডো সিনড্রোম** | ক্ষুদ্র সেগমেন্টে ব্যান্ডউইথ নষ্ট (1 B ডেটায় 40 B হেডার) |
| Nagle অ্যালগরিদম (প্রেরক) | ACK না আসা বা MSS পূর্ণ না হওয়া পর্যন্ত ছোট ডেটা জমায় |
| Clark-এর সমাধান (রিসিভার) | min(MSS, অর্ধেক বাফার) খালি না হওয়া পর্যন্ত উইন্ডো 0 জানায় |
| ডিলেড ACK | ACK একত্র বা পিগিব্যাক করতে অপেক্ষা (≤ 500 ms, সাধারণত 200) |
| জিরো উইন্ডো | প্রেরক থামে; পারসিস্ট টাইমার দিয়ে প্রোব পাঠায় |

## ৫. TCP টাইমার ম্যানেজমেন্ট

- **রিট্রান্সমিশন (RTO)**: সময়মতো ACK না এলে আবার পাঠায়।
- **পারসিস্ট**: উইন্ডো প্রোব দিয়ে জিরো-উইন্ডো **ডেডলক (Deadlock)** ভাঙে।
- **কিপঅ্যালাইভ**: নিষ্ক্রিয় অপর পক্ষকে যাচাই (ডিফল্ট ২ ঘণ্টা)।
- **TIME_WAIT**: অ্যাকটিভ ক্লোজের পর 2 × MSL।

**RTO: Jacobson / Karn**

```
SRTT   = ⅞ SRTT + ⅛ R
RTTVAR = ¾ RTTVAR + ¼ |SRTT − R|
RTO    = SRTT + 4 × RTTVAR
```

**Karn**: রিট্রান্সমিট করা সেগমেন্ট থেকে RTT নমুনা নয়; প্রতি টাইমআউটে RTO **দ্বিগুণ**।

✍ **সমাধানকৃত উদাহরণ।** SRTT = 100 ms, RTTVAR = 20 ms, নতুন নমুনা R = 120 ms। RTTVAR = 15 + ¼(20) = 20 ms; SRTT = 87.5 + 15 = 102.5 ms; RTO = 102.5 + 80 = **182.5 ms** (এরপর RFC 6298 অনুযায়ী সর্বনিম্ন 1 s ধরা হয়)।

## ৬. TCP কনজেশন কন্ট্রোল (Congestion Control)

**ট্যাগ: হাই-ইল্ড।** প্রেরক রাখে একটি **কনজেশন উইন্ডো (cwnd)**, যা MSS এককে গোনা হয়, আর একটি থ্রেশহোল্ড **ssthresh**। প্যাকেট হারানোকে জটের লক্ষণ ধরা হয়। মূল নিয়ম: **AIMD** — যোগাত্মক বৃদ্ধি (additive increase), গুণাত্মক হ্রাস (multiplicative decrease)।

| পর্যায় / ঘটনা | নিয়ম | বৃদ্ধি |
|---|---|---|
| **স্লো স্টার্ট** (cwnd < ssthresh) | প্রতি ACK-এ +1 MSS | **প্রতি RTT-তে ×2** |
| **কনজেশন অ্যাভয়েডেন্স** (≥ ssthresh) | প্রতি RTT-তে +1 MSS | রৈখিক |
| **টাইমআউট** (Tahoe, Reno) | ssthresh = cwnd/2; cwnd = **1 MSS** | আবার স্লো স্টার্ট |
| **৩টি ডুপ্লিকেট ACK**: ফাস্ট রিট্রান্সমিট | হারানো সেগমেন্ট তখনই পাঠায়, RTO-র অপেক্ষা নয় | — |
| … তারপর **ফাস্ট রিকভারি** (Reno) | ssthresh = cwnd/2; cwnd = ssthresh | রৈখিক |
| … Tahoe-তে বরং | ssthresh = cwnd/2; cwnd = 1 | স্লো স্টার্ট |

**সমাধানকৃত ট্রেস: শুরুতে ssthresh = 16** — cwnd (MSS) বনাম ট্রান্সমিশন রাউন্ড, Reno:

| রাউন্ড | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| cwnd | 1 | 2 | 4 | 8 | 16 | 17 | 18 | 19 | **20** |

| রাউন্ড | 10 | 11 | 12 | 13 | 14 | 15 | 16 | 17 | 18 |
|---|---|---|---|---|---|---|---|---|---|
| cwnd | 1 | 2 | 4 | 8 | 10 | 11 | **12** | 6 | 7 |

ট্রেস পড়া: **ssthresh 16** → স্লো স্টার্টে 16, তারপর কনজেশন অ্যাভয়েডেন্সে 20 → **টাইমআউট** → **ssthresh 10** → স্লো স্টার্ট ssthresh-এ গিয়ে থামে (8 → 10, 16 নয়) → কনজেশন অ্যাভয়েডেন্সে 12 → **৩ ডুপ্লিকেট ACK** → **ssthresh 6** → রৈখিক বৃদ্ধি 6, 7।

20-এ টাইমআউট → ssthresh = **10**, cwnd = 1। স্লো স্টার্ট ssthresh-এ গিয়ে থামে (8 → 10, 16 নয়)। 12-তে তিনটি ডুপ্লিকেট ACK → ssthresh = cwnd = **6** (Reno স্লো স্টার্টে ফেরে না)।

- 💡 **কৌশল।** "**টাইমআউট = আবার 1 থেকে শুরু; ডুপ্লিকেট ACK = অর্ধেক**"। ৩টি ডুপ্লিকেট ACK বোঝায় পরের সেগমেন্টগুলো তখনও পৌঁছাচ্ছে।
- ⚠️ **ফাঁদ।** "স্লো" স্টার্ট আসলে **সূচকীয় (exponential)**। একে ধীর বলা হয় কারণ cwnd শুরু হয় 1 MSS থেকে (আধুনিক স্ট্যাকে 10 পর্যন্ত)। Tahoe ১৯৮৮, Reno ১৯৯০; Linux-এ ডিফল্ট CUBIC।

## ৭. UDP: ইউজার ডেটাগ্রাম প্রোটোকল

**ট্যাগ: MCQ-তে প্রিয়।** UDP (RFC 768, ১৯৮০) একটি **কানেকশনবিহীন (connectionless), অনির্ভরযোগ্য** ট্রান্সপোর্ট: হ্যান্ডশেক নেই, ACK নেই, রিট্রান্সমিশন নেই, ক্রমের নিশ্চয়তা নেই, ফ্লো বা কনজেশন কন্ট্রোল নেই। এটি IP-র সাথে কেবল পোর্ট ও চেকসাম যোগ করে এবং **বার্তার সীমানা (message boundary) বজায় রাখে**।

| বিট | ফিল্ড | আকার |
|---|---|---|
| 0–15 | সোর্স পোর্ট | 16 |
| 16–31 | ডেস্টিনেশন পোর্ট | 16 |
| 32–47 | দৈর্ঘ্য (Length) | 16 |
| 48–63 | চেকসাম | 16 |
| 64+ | ডেটা | — |

৪টি ফিল্ড × 16 বিট = **8 বাইট**।

- হেডার স্থির **8 বাইট** (TCP: 20–60)।
- **Length** = হেডার + ডেটা, সর্বনিম্ন 8।
- চেকসাম **IPv4-এ ঐচ্ছিক** (0 = ব্যবহৃত নয়), **IPv6-এ বাধ্যতামূলক**।
- IPv4-এ সর্বোচ্চ পেলোড: 65,535 − 20 − 8 = **65,507 B**।
- **ব্রডকাস্ট ও মাল্টিকাস্ট** কেবল UDP-তে সম্ভব।

**ব্যবহার:** **DNS** কোয়েরি, DHCP, TFTP, SNMP, RIP (520), NTP (123), VoIP/RTP, লাইভ স্ট্রিমিং, অনলাইন গেম, এবং **QUIC** (UDP 443-এর ওপর HTTP/3)।

## ৮. TCP বনাম UDP

**ট্যাগ: লিখিত প্রশ্নে প্রিয়।**

| বৈশিষ্ট্য | TCP | UDP |
|---|---|---|
| কানেকশন | কানেকশন-ওরিয়েন্টেড (হ্যান্ডশেক) | কানেকশনবিহীন |
| নির্ভরযোগ্যতা | ACK + রিট্রান্সমিশন, ক্রমানুসারে | বেস্ট এফোর্ট; হারাতে বা ক্রম বদলাতে পারে |
| ডেটা একক | বাইট স্ট্রিম (সেগমেন্ট) | বার্তা (ডেটাগ্রাম) |
| হেডার | 20–60 বাইট | 8 বাইট |
| ফ্লো / কনজেশন কন্ট্রোল | আছে / আছে | নেই / নেই |
| ডেলিভারি | কেবল ইউনিকাস্ট | ইউনিকাস্ট, ব্রডকাস্ট, মাল্টিকাস্ট |
| উদাহরণ | HTTP, HTTPS, FTP, SMTP, SSH | DNS, DHCP, SNMP, VoIP |

**অন্যান্য ট্রান্সপোর্ট প্রোটোকল।** **SCTP** নির্ভরযোগ্য ও **বার্তাভিত্তিক**, সাথে **মাল্টি-স্ট্রিমিং** ও **মাল্টি-হোমিং**; ৪-ধাপের হ্যান্ডশেক (INIT, INIT-ACK, COOKIE-ECHO, COOKIE-ACK); টেলিকম সিগন্যালিংয়ে (SIGTRAN) ব্যবহৃত। **DCCP** অনির্ভরযোগ্য ডেটাগ্রাম দেয় **তবে** কনজেশন কন্ট্রোলসহ; মিডিয়া স্ট্রিমিংয়ের জন্য। **RTP** চলে UDP-র ওপর, রিয়েল-টাইম অডিও/ভিডিওর জন্য টাইমস্ট্যাম্প ও সিকোয়েন্স নম্বর যোগ করে।

- ⚠️ **ফাঁদ।** "UDP অনির্ভরযোগ্য" মানে এটি **ডেলিভারির নিশ্চয়তা দেয় না**, ডেটা নষ্ট করে এমন নয়: চেকসাম তখনও ত্রুটি ধরে। জোন ট্রান্সফার ও বড় উত্তরের জন্য DNS **TCP** 53 ব্যবহার করে।

## ৯. ATM অ্যাডাপটেশন লেয়ার (AAL)

**ট্যাগ: MCQ।** একটি ATM সেল **53 বাইট** (5 হেডার + 48 পেলোড)। ATM লেয়ারের ওপরের AAL ওপরের স্তরের ডেটাকে সেলে রূপান্তর করে দুটি সাবলেয়ারের মাধ্যমে: **CS** (কনভারজেন্স) ও **SAR** (সেগমেন্টেশন ও রিঅ্যাসেম্বলি)।

| AAL | ক্লাস | ট্রাফিক | সেলপ্রতি পেলোড | সাধারণ ব্যবহার |
|---|---|---|---|---|
| AAL1 | A | CBR, টাইমিংসহ | 47 B | সার্কিট ইমুলেশন, ভয়েস |
| AAL2 | B | VBR, টাইমিংসহ | মিনি-প্যাকেট | কম্প্রেসড ভয়েস/ভিডিও |
| AAL3/4 | C, D | ডেটা (কানেকশনসহ/বিহীন) | 44 B | SMDS, পুরোনো ডেটা |
| **AAL5** | C, D | ডেটা, সরল (SEAL) | **48 B** | **IP over ATM**, LANE |

**AAL5: একটি ফ্রেম → অনেক সেল**

| অংশ | আকার |
|---|---|
| ইউজার ডেটা | 1500 B |
| প্যাড | 28 B |
| ট্রেইলার | 8 B |
| প্রতিটি সেল | 5 + 48 |
| সেল সংখ্যা | × 32 |

✍ **সমাধানকৃত উদাহরণ।** AAL5-এ 1500 বাইটের IP প্যাকেট: 1500 + 8 = 1508 → ⌈1508/48⌉ = **৩২টি সেল** (প্যাড 28 B)। লাইনে যায় 32 × 53 = 1696 B, দক্ষতা 1500/1696 ≈ **88.4%**। ট্রেইলার: UU, CPI, দৈর্ঘ্য, **CRC-32**; শেষ সেল চেনায় PTI বিট।

💡 **কৌশল।** "**1 = স্থির (Constant), 2 = পরিবর্তনশীল (Variable), 3/4 = পুরোনো ডেটা, 5 = ডেটার প্রধান বাহন**"। ক্লাস A → D চলে AAL নম্বরের ক্রমে।

## ১০. ক্রিপ্টোগ্রাফির মূল কথা

**ট্যাগ: MCQ + লিখিত।** **প্লেইনটেক্সট** → (একটি **কী** দিয়ে এনক্রিপশন) → **সাইফারটেক্সট** (গোপন সংকেত) → (ডিক্রিপশন) → প্লেইনটেক্সট। **ক্রিপ্টোলজি** = ক্রিপ্টোগ্রাফি (গোপন সংকেত তৈরি) + ক্রিপ্টঅ্যানালাইসিস (তা ভাঙা)। লক্ষ্য: গোপনীয়তা (confidentiality), তথ্যরক্ষা / অখণ্ডতা (integrity), অথেনটিকেশন, নন-রিপুডিয়েশন। **Kerckhoffs-এর নীতি**: নিরাপত্তা নির্ভর করবে কেবল কী-এর ওপর।

| | সিমেট্রিক (সিক্রেট কী) | অ্যাসিমেট্রিক (পাবলিক কী) |
|---|---|---|
| কী | একটি শেয়ার করা কী | পাবলিক + প্রাইভেট জোড়া |
| গতি | দ্রুত (বড় ডেটা) | 100–1000 গুণ ধীর |
| n জন ব্যবহারকারীর কী | **n(n − 1)/2** | 2n |
| উদাহরণ | DES, 3DES, IDEA, AES, RC4, Blowfish | RSA, Diffie–Hellman, ECC, ElGamal |

## ১১. ক্লাসিক্যাল সাইফার

- ✍ **প্রতিস্থাপন (Substitution)।** প্রতিটি অক্ষর বদলে অন্য অক্ষর। **সিজার** (৩ ঘর সরানো): ATTACK → **DWWDFN**। মনোঅ্যালফাবেটিক: 26! টি কী, তবু **অক্ষরের ফ্রিকোয়েন্সি** দেখে ভাঙা যায়। পলিঅ্যালফাবেটিক: Vigenère, Playfair। ওয়ান-টাইম প্যাড: নিখুঁত গোপনীয়তা।
- ✍ **ট্রান্সপজিশন (Transposition)।** অক্ষর একই থাকে, কেবল অবস্থান বদলায়। **রেল ফেন্স** (২ সারি): ATTACKATDAWN → সারি ১ ATCADW + সারি ২ TAKTAN = **ATCADWTAKTAN**। অক্ষরের ফ্রিকোয়েন্সি অপরিবর্তিত থাকে।

Shannon: শক্তিশালী সাইফারে লাগে **কনফিউশন (confusion)** (প্রতিস্থাপন, S-বক্স) ও **ডিফিউশন (diffusion)** (পারমুটেশন, P-বক্স)। ব্লক সাইফার (DES, AES) নির্দিষ্ট আকারের ব্লক এনক্রিপ্ট করে; স্ট্রিম সাইফার (RC4, ChaCha20) বিট বা বাইট ধরে ধরে।

## ১২. DES ও ত্রিপথাক্ষেদ (Triple DES)

**ট্যাগ: হাই-ইল্ড।**

- IBM (Lucifer থেকে), FIPS 46, **১৯৭৭**।
- ব্লক **64 বিট**; কী 64 বিট, কার্যকর **56** (8টি প্যারিটি বিট)।
- **১৬টি ফাইস্টেল (Feistel) রাউন্ড**, 48-বিট রাউন্ড কী; IP … IP⁻¹।
- f: 32 → 48 সম্প্রসারণ, কী-এর সাথে XOR, **৮টি S-বক্স (6 → 4 বিট)**, P-বক্স।
- S-বক্সই একমাত্র **অরৈখিক (non-linear)** অংশ।
- ব্রুট-ফোর্সে ভাঙা: EFF "Deep Crack", ১৯৯৮ (56 ঘণ্টা)।

**একটি ফাইস্টেল রাউন্ড**

```
L_i, R_i
  f <- f(R_i) XOR K_i
L_(i+1) = R_i
R_(i+1) = L_i XOR f(R_i)
```

**ত্রিপথাক্ষেদ (3DES, EDE):** C = E<sub>K3</sub>(D<sub>K2</sub>(E<sub>K1</sub>(P)))। ৩টি কী: 168-বিট কী, শক্তি ≈ 112 বিট; ২টি কী (K1 = K3): 112-বিট কী। K1 = K2 = K3 হলে → সাধারণ DES। **ডাবল DES** মাত্র ≈ 57 বিট (**মিট-ইন-দ্য-মিডল (meet-in-the-middle)** আক্রমণ)।

## ১৩. IDEA ও AES

IDEA: Lai ও Massey (ETH Zürich)। AES: Rijndael (Daemen ও Rijmen), FIPS 197; প্রতি রাউন্ড = SubBytes, ShiftRows, MixColumns, AddRoundKey।

| সাইফার | ব্লক | কী | রাউন্ড | গঠন / মন্তব্য |
|---|---|---|---|---|
| DES | 64 | 56 | 16 | Feistel |
| **IDEA** 1991 | 64 | **128** | 8 + ½ | XOR, + mod 2<sup>16</sup>, × mod 2<sup>16</sup>+1; PGP |
| **AES** 2001 | 128 | 128/192/256 | **10/12/14** | SPN (Rijndael) |

- 💡 **কৌশল।** DES "**64-56-16**" (ব্লক, কী, রাউন্ড)। IDEA "**64-128-8**"। AES-এর রাউন্ড "**10-12-14**" = কী/32 + 6।
- ⚠️ **ফাঁদ।** IDEA **Feistel নয়**: ৬টি সাবকী × ৮ রাউন্ড + ৪ (অর্ধ-রাউন্ড) = **৫২টি** সাবকী। AES-ও Feistel নয়।

## ১৪. পাবলিক-কী ক্রিপ্টোগ্রাফি

**ট্যাগ: হাই-ইল্ড।** প্রত্যেক ব্যবহারকারীর থাকে একটি **পাবলিক কী** (প্রকাশ্য) ও একটি **প্রাইভেট কী** (গোপন)। গোপনীয়তার জন্য: প্রাপকের পাবলিক কী দিয়ে এনক্রিপ্ট, প্রাপকের প্রাইভেট কী দিয়ে ডিক্রিপ্ট। নিরাপত্তা নির্ভর করে একটি কঠিন গাণিতিক সমস্যার ওপর: **উৎপাদকে বিশ্লেষণ (factoring)** (RSA) বা **ডিসক্রিট লগারিদম** (Diffie–Hellman, ElGamal, ECC)। প্রথমে আসে Diffie–Hellman (**১৯৭৬**), পরে RSA (১৯৭৭)।

**RSA (Rivest, Shamir, Adleman, ১৯৭৭)**

1. দুটি মৌলিক সংখ্যা p, q বাছো; **n = p × q**
2. **φ(n) = (p − 1)(q − 1)**
3. e বাছো যেন 1 < e < φ(n), gcd(e, φ(n)) = 1
4. d = e⁻¹ mod φ(n), অর্থাৎ **e · d ≡ 1 (mod φ(n))**
5. পাবলিক কী (e, n) · প্রাইভেট কী (d, n)
6. এনক্রিপ্ট C = M<sup>e</sup> mod n · ডিক্রিপ্ট M = C<sup>d</sup> mod n

✍ **সমাধানকৃত উদাহরণ।**

```
p = 3, q = 11  →  n = 33, φ = 2 × 10 = 20
e = 7           (gcd(7, 20) = 1)
7d ≡ 1 (mod 20):  7 × 3 = 21 = 20 + 1  →  d = 3
M = 2 :  C = 2⁷ mod 33 = 128 − 99 = 29
যাচাই: 29³ mod 33;  29 ≡ −4, (−4)³ = −64 ≡ −64 + 66 = 2   ✓
```

বাস্তবে n হয় **2048 বিট** বা তার বেশি। RSA ধীর, তাই এটি দিয়ে সেশন কী বিনিময় বা সিগনেচার করা হয় (অথেনটিকেশন ও ডিজিটাল সিগনেচার লেসন দেখো), আর মূল ডেটা এনক্রিপ্ট করে AES: TLS ও PGP-র এই **হাইব্রিড** পদ্ধতি।

**Diffie–Hellman কী বিনিময় (Key Exchange)** — খোলা চ্যানেলে কী-এর ব্যাপারে একমত হওয়া। প্রকাশ্য: **p = 23, g = 5**।

| পক্ষ | গোপন | নেটওয়ার্কে পাঠায় | হিসাব করে |
|---|---|---|---|
| Alice | a = 4 | A = 5⁴ mod 23 = 4 | K = 10⁴ mod 23 = 18 |
| Bob | b = 3 | B = 5³ mod 23 = 10 | K = 4³ mod 23 = 18 |

দুজনেই পায় **K = g^(ab) mod p = 18**; a, b ও K কখনো নেটওয়ার্কে যায় না।

✍ **হিসাব যাচাই।** 5⁴ = 625 = 27 × 23 + 4 → A = 4। 5³ = 125 = 5 × 23 + 10 → B = 10। Alice: 10² = 100 ≡ 8, 8² = 64 ≡ **18**। Bob: 4³ = 64 ≡ **18** ✓

- ⚠️ **ফাঁদ।** সাধারণ Diffie–Hellman **কেবল কী ঠিক করে, এনক্রিপ্ট করে না**, আর এতে অথেনটিকেশন নেই, তাই **ম্যান-ইন-দ্য-মিডল** আক্রমণে ভাঙে। A ও B প্রকাশ্য মান, কী নয়।
- 💡 **কৌশল।** RSA গোপনীয়তায়: "**পাবলিক দিয়ে তালা, প্রাইভেট দিয়ে খোলা**"। **ECC**: 256-বিট ECC ≈ 3072-বিট RSA ≈ AES-128-এর সমান শক্তি, তাই কী অনেক ছোট।

## লিখিত প্রশ্ন (৮ নম্বর)

স্লো স্টার্ট ও কনজেশন অ্যাভয়েডেন্স ব্যাখ্যা করো। ssthresh = 8 MSS এবং রাউন্ড ১-এ cwnd = 1; cwnd = 12 হলে টাইমআউট ঘটে। রাউন্ড ১৩ পর্যন্ত cwnd ট্রেস করো।

**মডেল উত্তর:**

1. **স্লো স্টার্ট (২)** — প্রতি ACK-এ cwnd += 1 MSS, ফলে ssthresh-এ পৌঁছানো পর্যন্ত প্রতি RTT-তে দ্বিগুণ হয়।
2. **কনজেশন অ্যাভয়েডেন্স (২)** — প্রতি RTT-তে cwnd += 1 MSS (যোগাত্মক বৃদ্ধি); প্যাকেট হারালে গুণাত্মক হ্রাস।
3. **রাউন্ড ১–৮ (২)** — 1, 2, 4, **8**, 9, 10, 11, **12** → টাইমআউট।
4. **রাউন্ড ৯–১৩ (২)** — ssthresh = 12/2 = **6**, cwnd = 1। রাউন্ড ৯–১৩: 1, 2, 4, **6** (ssthresh-এ সীমিত), 7।
