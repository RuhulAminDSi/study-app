## ১. প্রোগ্রাম বনাম প্রসেস ও PCB

একটি **প্রোগ্রাম** হলো ডিস্কে রাখা নির্দেশনার নিষ্ক্রিয় ফাইল। একটি **প্রসেস** হলো সেই প্রোগ্রাম **মেমোরিতে তুলে চালু হওয়া** — তার কোড, ডেটা, প্রোগ্রাম কাউন্টার, সে যে রেজিস্টারগুলো ধরে আছে এবং খোলা ফাইলসহ। প্রোগ্রাম স্থির, প্রসেস গতিশীল — একটি প্রোগ্রাম একসঙ্গে অনেক প্রসেস হতে পারে।

| বিষয় | প্রোগ্রাম | প্রসেস |
|---|---|---|
| প্রকৃতি | নিষ্ক্রিয়, স্থির | সক্রিয়, গতিশীল |
| মেমোরি | ডিস্কই যথেষ্ট | মেইন মেমোরি লাগে |
| পরিচয় | একটি ফাইলের নাম | **PID**, অনেক ইনস্ট্যান্স |
| জীবন | যতদিন ফাইল আছে | new → running → terminated |

*(চিত্র: নীল বর্গ "ডিস্কে প্রোগ্রাম", সবুজ তির "লোড", হলুদ বর্গে কোড (টেক্সট), ডেটা · ভ্যারিয়েবল, স্ট্যাক · হিপ, PC · রেজিস্টার, খোলা ফাইল; "OS" লেখা নীল তির দ্বিতীয় বর্গের দিকে, যার লাল লেখা PCB — ভেতরে PID 4217, স্টেট, PC 121, R1…Rn।)*

| PCB-র ঘর | কী থাকে | OS-র কেন দরকার |
|---|---|---|
| **প্রসেস স্টেট** | New · Ready · Running · Waiting · Terminated | ঠিক করে **কোন সারিতে** আছে |
| **প্রোগ্রাম কাউন্টার** | পরবর্তী নির্দেশনার ঠিকানা | ঠিক যেখানে থেমেছিল সেখান থেকেই চালু করতে |
| **CPU রেজিস্টার** | অ্যাকুমুলেটর, base, limit, স্ট্যাক, R0…Rn | অসমাপ্ত হিসাব মনে রাখা |
| **CPU শিডিউলিং তথ্য** | অগ্রাধিকার, সারির পয়েন্টার | পরে কে চলবে ঠিক করা |
| **মেমোরি ম্যানেজমেন্ট তথ্য** | পেজ টেবিল বেস, সেগমেন্ট টেবিল পয়েন্টার | ঠিকানা অনুবাদ |
| **অ্যাকাউন্টিং তথ্য** | ইউজার ও কার্নেল সময়, I/O গণনা, শিশুর PID | হিসাব, কোটা, পরিষ্কার |

- 💡 **কৌশল:** PCB হলো প্রসেসের **পাসপোর্ট**: **PID** বলে সে কে, **স্টেট** বলে কোথায়, **PC ও রেজিস্টার** মনে রাখে ঠিক কোথায় থেমেছিল; বাকিগুলো বলে সার কী ধরে আছে।
- ⚠️ **ফাঁদ:** (i) PCB একটি **কার্নেল** কাঠামো, OS-ই বানায়; প্রসেস কখনো তার ভেতরে লেখে না। (ii) প্রসেস **তার PCB নয়** — শেষ হলে দুটোই মুক্তি পায়। (iii) PID চলমান প্রসেসের মধ্যে অনন্য, পরে **পুনরায় ব্যবহৃত** হতে পারে।

✍ **সমাধানকৃত উদাহরণ — একটি PCB ডাম্প পড়ো।** PID 4217, স্টেট **Waiting**, PC 121, base 240, limit 460, ইউজার সময় 128, কার্নেল সময় 12।
- **(ক)** এটি রেডি সারিতে **নয়** — এটি একটি I/O ঘটনার অপেক্ষায়।
- **(খ)** বৈধ ঠিকানা = **240 … 459**।
- **(গ)** ব্যবহৃত CPU = 128 + 12 = **140** ইউনিট।
- **(ঘ)** PID নিজে শিডিউলিংয়ের চাবিকাঠি নয়; **অগ্রাধিকার** হলো।

## ২. পাঁচ-অবস্থার মডেল ও সারিগুলো

একটি প্রসেস ঠিক **পাঁচটি** অবস্থার একটিতে থাকে: **new** (তৈরি হচ্ছে), **ready** (মেমোরিতে, CPU-এর অপেক্ষায়), **running** (CPU ধরে আছে), **waiting / blocked** (CPU ছাড়া অন্য কোনো ঘটনার অপেক্ষায়) এবং **terminated** (শেষ, রিসোর্স মুক্ত)।

*(চিত্র: এক সারিতে NEW → READY → RUNNING → WAITING; নিচের দিকে ফেরার তির WAITING → READY, লেখা I/O শেষ; উপর থেকে READY-তে আসা তির, লেখা ইন্টারাপ্ট বা স্লাইস শেষ; নিচে RUNNING → TERMINATED, লেখা শেষ বা বন্ধ হলো; আর নিচে ঘুরে NEW → TERMINATED, লেখা ভর্তি বাতিল।)*

| থেকে → পর্যন্ত | কী ঘটে | কে করে |
|---|---|---|
| New → Ready | ভর্তি | দীর্ঘমেয়াদি শিডিউলার |
| Ready → Running | CPU বরাদ্দ | স্বল্পমেয়াদি শিডিউলার |
| Running → Ready | ইন্টারাপ্ট, স্লাইস শেষ, বেশি অগ্রাধিকারার প্রসেস এল | স্বল্পমেয়াদি শিডিউলার |
| Running → Waiting | I/O অনুরোধ বা ঘটনার অপেক্ষা | প্রসেস নিজে |
| Waiting → Ready | I/O শেষ, ঘটনা ঘটেছে | ইন্টারাপ্ট হ্যান্ডলার |
| Running → Terminated | শেষ, ভুল, বা বন্ধ করা হয়েছে | প্রসেস নিজে |
| New → Terminated | ভর্তি বাতিল | দীর্ঘমেয়াদি শিডিউলার |

| সারি | কী রাখে / কে খালি করে |
|---|---|
| **জব সারি** | এখনো ভর্তি হয়নি; দীর্ঘমেয়াদি শিডিউলার |
| **রেডি সারি** | মেমোরিতে CPU-এর অপেক্ষায়; স্বল্পমেয়াদি শিডিউলার |
| **ডিভাইস সারি** | ওই I/O-এর অপেক্ষায়; ডিভাইস কন্ট্রোলার |

- 💡 **কৌশল:** "**রেডি** চায় **CPU**, **ওয়েটিং** চায় **অন্য কিছু**।" দুটোই একইভাবে ফেরে — ঘটনা শেষ, প্রসেস আবার **রেডি** সারিতে যায়, সরাসরি CPU-তে নয়।
- ⚠️ **ফাঁদ:** শুধু CPU-এর অপেক্ষা মানে **রেডি**, ওয়েটিং নয় — এটিই সবচেয়ে বেশি জিজ্ঞাসিত অবস্থা-প্রশ্ন। ডিভাইস সারিতে থাকা প্রসেস মেমোরিতে থেকেও ওয়েটিং। তিনটি শিডিউলার আছে: **দীর্ঘমেয়াদি** (জব সারি), **মধ্যবর্তী** (সোয়াপ করা ও ফেরানো) ও **স্বল্পমেয়াদি** (CPU)। কেবল CPU শিডিউলারই অবিরাম চলে।

✍ **সমাধানকৃত উদাহরণ — একটি প্রসেসের ট্রেস।** আপনি একটি কমান্ড টাইপ করলেন। **(ক)** দীর্ঘমেয়াদি শিডিউলার ভর্তি করলে new → ready। **(খ)** CPU শিডিউলার পাঠালে ready → running। **(গ)** প্রিন্টের অনুরোধ দেওয়ামাত্র running → waiting। **(ঘ)** প্রিন্টার শেষ হলে waiting → ready। **(ঙ)** এর আগে একটি ক্লক ইন্টারাপ্ট স্লাইস শেষ করেছিল: এটি running → ready, **not** running → waiting।

## ৩. প্রসেস তৈরি ও সমাপ্তি

**তৈরি**: OS একটি PID নেয়, PCB বরাদ্দ করে পূরণ করে, অ্যাড্রেস স্পেস বানায়, খোলা ফাইল জুড়ে দেয় এবং PCB-কে **রেডি সারিতে** রাখে। **সমাপ্তি**: স্টেট টার্মিনেটেড হয়, মেমোরি ও ফাইল মুক্ত হয়, এক্সিট স্ট্যাটাস প্যারেন্টের কাছে যায়।

*(চিত্র: একটি প্রসেস ট্রি — উপরে init, তারপর প্যারেন্ট → শিশু ১, শিশু ২, প্রত্যেকের নিজস্ব PID 301 / 302 / 303।)*

| তৈরির ধাপ | কী ঘটে |
|---|---|
| ১. PID নেওয়া | PID টেবিল থেকে; মুক্তির পর পুনরায় ব্যবহৃত হয় |
| ২. PCB বরাদ্দ | কন্ট্রোল ব্লকের জন্য মেমোরি সংরক্ষিত |
| ৩. সূচনা | স্টেট, **এন্ট্রি পয়েন্টে PC**, হিসাব = 0, সারির পয়েন্টার |
| ৪. অ্যাড্রেস স্পেস | প্যারেন্টের ছবি কপি; পেজ/সেগমেন্ট টেবিল তৈরি |
| ৫. খোলা ফাইল | ডেস্ক্রিপ্টর একই ইনোডের দিকে যায় |
| ৬. রিসোর্স | I/O, মেমোরি ও CPU কোটা |
| ৭. কনটেক্সট প্রস্তুত | স্ট্যাক ও রেজিস্টার প্রথম পাঠানোর জন্য |
| ৮. সারিতে ঢোকা | PCB → **রেডি সারি**, কখনো সরাসরি running নয় |

| প্রসেস শেষ হওয়ার উপায় | সাধারণ কারণ |
|---|---|
| **স্বাভাবিক শেষ** | main() ফেরত হয় বা `exit(0)`; মানটিই এক্সিট স্ট্যাটাস |
| **ভুলে শেষ** | ফ্যাটাল এরর — শূন্যে ভাগ, অবৈধ মেমোরি রেফারেন্স |
| **অন্য প্রসেস বন্ধ করে** | SIGKILL-এর মতো সিগন্যাল, যা ধরা যায় না |
| **OS বন্ধ করে** | মেমোরি সীমা অতিক্রম, প্রোটেকশন ফল্ট, শাটডাউন |

- ⚠️ **ফাঁদ:** প্যারেন্ট তার খবর না নেওয়া পর্যন্ত শেষ হয়ে যাওয়া শিশুকে **জম্বি** বলে: কাজ শেষ, কিন্তু এক্সিট স্ট্যাটাস ও কিছু টেবিল এন্ট্রি প্যারেন্ট অপেক্ষা করে। **প্যারেন্ট আগে মারা গেলে** শিশু হয় **অরফান**, init তাকে গ্রহণ করে।
- 💡 **কৌশল:** "**জন্ম রেডি, মৃত্যু শেষ।**" তৈরি শেষ হয় রেডি সারিতে; সমাপ্তিতে PID ও PCB মুক্তি পায়। init অরফান গ্রহণ করে বলে কোনো জম্বি অসংগৃহীত থাকে না।

✍ **সমাধানকৃত উদাহরণ — একটি শেল সেশন।** আপনি লিখলেন `ls > out.txt`। **(ক)** শেল দুইবার fork করে — একবার `ls`-এর জন্য, একবার রিডাইরেকশনের ডান পাশের জন্য। **(খ)** `exec`-এর আগে শিশু ফাইলটি খোলে; ইনোড **ভাগ** হয়, কপি নয়। **(গ)** `exec` ছবি বদলায় কিন্তু **PID রাখে**। **(ঘ)** `ls` শেষ হলে শেলের `wait()` তাকে সংগ্রহ করে, তাই জম্বি মিলিসেকেন্ডই থাকে।

## ৪. থ্রেড: এক অ্যাড্রেস স্পেসের ভাগ

একটি **থ্রেড** হলো প্রসেসের ভেতরে **কার্যকরণের একক**। একই প্রসেসের থ্রেডগুলো **অ্যাড্রেস স্পেস, কোড, ডেটা, খোলা ফাইল ও সিগন্যাল ভাগ করে**; প্রতিটির নিজস্ব **স্ট্যাক, রেজিস্টার, প্রোগ্রাম কাউন্টার ও থ্রেড-লোকাল স্টোরেজ** থাকে।

| বিষয় | প্রসেস | থ্রেড |
|---|---|---|
| অ্যাড্রেস স্পেস | নিজস্ব, সুরক্ষিত | **ভাইদের সাথে ভাগ** |
| নিজস্ব অবস্থা | সবকিছু | স্ট্যাক, রেজিস্টার, PC, TLS |
| তৈরির খরচ | ভারী: ছবি কপি হয় | সস্তা: একটি থ্রেড কন্ট্রোল ব্লক |
| যোগাযোগ | IPC লাগে | শেয়ার্ড ভ্যারিয়েবল পড়লেই হলো |
| ব্যর্থতার প্রভাব | সীমাবদ্ধ | খারাপ লেখা **সব** থ্রেড মারতে পারে |
| শিডিউলারে | সবসময় আলাদা সত্তা | নিচের মডেলের ওপর নির্ভর করে |

| স্তর | কোথায় থাকে | যা দেয় |
|---|---|---|
| **ইউজার-লেভেল** | প্রসেসের ভেতরের একটি লাইব্রেরি | সস্তা সুইচ, কিন্তু একটি ব্লকিং কল পুরো **প্রসেসকেই** থামায় |
| **কার্নেল-লেভেল** | OS প্রতিটি সত্তার জন্য আসল থ্রেড রাখে | একটি ব্লকিং কল **একটি** থ্রেড থামায়; অনেক কোরে সত্যিকারের সমান্তরালতা |

তিনটি **মাল্টিথ্রেডেড মডেল** (চিত্র: many-to-one, one-to-one, many-to-many — *m* ইউজার থ্রেড *n* কার্নেল থ্রেডে, *m* ≥ *n*):

| মডেল | ম্যাপিং | পরিণতি |
|---|---|---|
| **many-to-one** | অনেক ইউজার থ্রেড → ১ কার্নেল থ্রেড | সমান্তরালতা নেই; একটি ব্লকিং কল **সব** থ্রেড থামায় |
| **one-to-one** | ১ ইউজার থ্রেড → ১ কার্নেল থ্রেড | আসল সমান্তরালতা; প্রতিটি থ্রেডের জন্য PCB ও কার্নেল স্ট্যাক লাগে |
| **many-to-many** | *m* ইউজার থ্রেড → *n* কার্নেল থ্রেড | মাঝামাঝি: লাইব্রেরি ইউজার থ্রেড শিডিউল করে, কার্নেল *n* আসল থ্রেড |

- ⚠️ **ফাঁদ:** প্রথম দুই মডেলে **থ্রেড শিডিউলিং ≠ প্রসেস শিডিউলিং**: কার্নেল কার্নেল থ্রেড শিডিউল করে, লাইব্রেরি ইউজার থ্রেড।
- 💡 **কৌশল:** "**থ্রেড ভাগ করে, কপি করে না।**" `fork()` বলতে হলে সেটি **প্রসেস**; শুধু একটি গ্লোবালে মান বসালেই হলো সেটি **থ্রেড**।

## ৫. ইন্টার-প্রসেস কমিউনিকেশন

**IPC** একটি প্রসেসকে অন্যকে **তথ্য পাঠাতে** এবং তার সাথে **সমন্বয়** করতে দেয়। দুই পরিবার: **মেসেজ পাসিং** (কপি কার্নেল দিয়ে যায়) এবং **শেয়ার্ড মেমোরি** (সবচেয়ে দ্রুত — কোনো কপি নেই — তবে এতে **কোনো** সিঙ্ক্রোনাইজেশন নেই)।

| পদ্ধতি | ধরন | নোট |
|---|---|---|
| **শেয়ার্ড মেমোরি** | shared | সবচেয়ে দ্রুত; **লক নিজেই লিখতে হয়** |
| **অ্যানোনিমাস পাইপ** | message | বাইট স্ট্রিম, কেবল **সম্পর্কিত** প্রসেস |
| **নেমড পাইপ (FIFO)** | message | ফাইলসিস্টেমের নাম আছে, **অসম্পর্কিত** প্রসেসও খুলতে পারে |
| **মেসেজ কিউ** | message | কার্নেলে **বিভিন্ন** বার্তার তালিকা |
| **সকেট** | message | নামযুক্ত প্রান্ত, স্থানীয় **অথবা** TCP/IP |
| **সিগন্যাল** | message | একপাশে **সংকেত**; SIGKILL ধরা যায় না |
| **মেইলবক্স** | message | পরোক্ষ: নামযুক্ত ড্রপ বক্স |

| কখন বেছে নেবেন | খরচ |
|---|---|
| **শেয়ার্ড মেমোরি** বড় বাফারের জন্য — ভিডিও ফ্রেম | প্রতিটি লক আপনাকেই লিখতে হবে |
| **পাইপ / FIFO** বাইটের ধারা ছাঁকতে | বাফার সীমিত, বার্তার সীমানা নেই |
| **মেসেজ কিউ** ক্রম ঠিক রেখে টুকরো কাজের জন্য | কিউয়ের নির্দিষ্ট সর্বোচ্চ দৈর্ঘ্য |
| **সকেট** অন্য মেশিন বা সার্ভিসে পৌঁছাতে | সিরিয়ালাইজেশন, প্রতি কানেকশনে আলাদা অ্যাড্রেস স্পেস |
| **সিগন্যাল** "কিছু বদলেছে — আবার পড়ো" বলতে | কোনো তথ্য নেই; হ্যান্ডলার অস্বাভাবিক সময়ে চলে |

- ⚠️ **ফাঁদ:** **পাইপ কেবল সম্পর্কিত প্রসেসের জন্য** — একটি শেল পাইপলাইন, বা প্যারেন্ট ও তার শিশু। দুটি অসম্পর্কিত প্রোগ্রামের জন্য লাগবে **নেমড FIFO**, সকেট বা শেয়ার্ড মেমোরি। শেয়ার্ড মেমোরি কোনো **মিউচুয়াল এক্সক্লুশন** দেয় না: দুই লেখক দৌড়ে গেলে ডেটা হারায়।
- 💡 **কৌশল:** "**কপি** মানে মেসেজ পাসিং, **ম্যাপ** মানে শেয়ার্ড মেমোরি, **নামযুক্ত** মানে অসম্পর্কিত।" ডেটা যদি নড়েই না, তবে নিরাপদ করার কাজ মিউটেক্সের।

✍ **সমাধানকৃত উদাহরণ — পদ্ধতি বাছো।** **(ক)** `sort < file | head` — অ্যানোনিমাস **পাইপ**। **(খ)** একটি লগার ডেমন ও ৪০টি অসম্পর্কিত সার্ভিস — **নেমড FIFO** বা **সকেট**। **(গ)** দুই ডিকোডারে ৪ MB ফ্রেম লেখা একটি ভিডিও সার্ভার — **শেয়ার্ড মেমোরি** প্লাস মিউটেক্স। **(ঘ)** "কনফিগ ফাইল বদলেছে" — একটি **সিগন্যাল**, তারপর প্রসেস নিজে ফাইল আবার পড়ে: সিগন্যাল একটা ঠেলা, স্থানান্তর নয়।

## ৬. সেমাফোর, মিউটেক্স ও প্রোডিউসার–কনজিউমার

একটি **সেমাফোর** (ডিকস্ট্রা, ১৯৬৫) হলো ঋণাত্মক নয় এমন একটি পূর্ণসংখ্যা ও একটি অপেক্ষা-সারি, যা কেবল দুটি **অ্যাটমিক** ক্রিয়ায় বদলায়: **P (ওয়েট): S = 0 হলে ব্লক, তারপর S ← S − 1** এবং **V (সিগন্যাল): S ← S + 1, একজন অপেক্থাকে জাগান**। একটি **বাইনারি** সেমাফোর — মিউটেক্স — 0 বা 1-এই থাকে।

| কনস্ট্রাক্ট | মান | মালিক? | সেরা কাজে |
|---|---|---|---|
| **সেমাফোর** | পূর্ণসংখ্যা ≥ 0 | **না** — যে কেউ V করতে পারে | গণনার রিসোর্স, ক্রম |
| **মিউটেক্স** | 0 বা 1 | **হ্যাঁ** — ধারকই আনলক করে | ক্রিটিক্যাল সেকশন |
| **মনিটর** | সুত্ত্বক, ভেতরে একটি থ্রেড | স্বয়ংক্রিয় | ডেটা + প্রসিডিউর + কন্ডিশন ভ্যারিয়েবল |

**সমাধান — তিনটি সেমাফোর।** N স্লটের বাফারের জন্য: **mutex = 1** (বাফার কোডের ভেতরে একটি প্রসেস), **empty = N** (খালি স্লট), **full = 0** (ভর্তি স্লট)।

```
producer:                  consumer:
wait(empty);  wait(full);
wait(mutex);   wait(mutex);
  put item;       take item
signal(mutex);  signal(mutex);
signal(full);   signal(empty);
```

**দুইটি বাইরের wait-এর ক্রমই পুরো সমস্যা**: প্রোডিউসার মিউটেক্সের **আগে** খালি স্লট দাবি করে, কনজিউমার মিউটেক্সের আগে ভর্তি স্লট দাবি করে। উল্টো করলে দুজনেই মিউটেক্সের ওপর চিরকাল আটকে থাকতে পারে।

**সেমাফোর ট্রেস — ২ স্লটের বাফার** (তাই mutex = 1, empty = 2, full = 0):

| ধাপ | কাজ | mutex | empty | full | বাফার (in → out) |
|---|---|---|---|---|---|
| — | শুরু | 1 | 2 | 0 | খালি |
| 1 | P1 **x** দেয় | 1 | 1 | 1 | x |
| 2 | P2 **y** দেয় | 1 | 0 | 2 | x y |
| 3 | P3 **z** দিতে চায় | 1 | **0** | 2 | **P3 ব্লক** |
| 4 | C1 **x** নেয় | 1 | 1 | 1 | y |
| 5 | C2 **y** নেয় | 1 | 2 | 0 | খালি |
| 6 | P3 জাগে, **z** দেয় | 1 | 1 | 1 | z |

- 💡 **কৌশল:** "**empty ঘর গোনে, full জিনিস গোনে, mutex অনুমতি গোনে, আর empty + full সবসময় = N।**" উপরের প্রতিটি ধাপে empty + full = 2; না হলে ট্রেসটাই ভুল।
- ⚠️ **ফাঁদ:** **P কমায়, V বাড়ায়** — সেমাফোর P-তে ঢালে। ৭ থেকে শুরু, ১০টি P ও ৬টি V হলে শেষ মান **7 − 10 + 6 = 3**। তোমার না-ধরা মিউটেক্স আনলক করা অর্থহীন।

## ৭. শিডিউলিংয়ের মানদণ্ড ও প্রিমপশন

CPU শিডিউলিং ঠিক করে **কোন রেডি প্রসেস পরে চলবে** এবং **কতক্ষণ**। কোনো অ্যালগরিদম সব মাপেই জেতে না, তাই শিডিউলিংকে **পাঁচটি মানদণ্ডের** বিপরীতে বিচার করা হয়।

| মানদণ্ড | সংজ্ঞা ও সূত্র | চাওয়া |
|---|---|---|
| **CPU ব্যবহার** | ব্যবহৃত অংশ = **1 − ফাঁকা অংশ** | যত **বেশি** |
| **থ্রুপুট** | প্রতি একক সময়ে সম্পন্ন প্রসেস | যত **বেশি** |
| **টার্নআরাউন্ড টাইম** | **সমাপ্তি − অ্যারাইভাল**, পুরো জীবন | **যত কম** |
| **ওয়েটিং টাইম** | **টার্নআরাউন্ড − CPU বার্স্ট** | **যত কম** |
| **রেসপন্স টাইম** | **প্রথম চাল − অ্যারাইভাল** | কম — **ইন্টারঅ্যাক্টিভ** ব্যবহারকারী যা অনুভব করে |

| বিষয় | নন-প্রিমপটিভ | প্রিমপটিভ |
|---|---|---|
| চলমান প্রসেস | শেষ না হয়ে বা ব্লক না হওয়া পর্যন্ত CPU ধরে রাখে | **বাধা** দিয়ে সারিতে ফেরানো যায় |
| যা লাগে | বিশেষ কিছু নয় | টাইমার ইন্টারাপ্ট, OS-এর সহায়তা |
| ওভারহেড | কম — সামান্য সুইচ | প্রতিটি প্রিমপশনে একটি সুইচ |
| রেসপন্স টাইম | **খারাপ** হতে পারে: লম্বা কাজ সবাকে আটকায় | ভালো, q দিয়ে সীমাবদ্ধ |
| ফাঁদ | **ক্রিটিক্যাল সেকশনের ভেতরে** কখনো প্রিমপট নয় | করলে অবস্থা নষ্ট হয় |

| সিস্টেম | অর্থ |
|---|---|
| **মাল্টিপ্রোগ্রামিং** | মেমোরিতে কয়েকটি প্রোগ্রাম, CPU তাদের মধ্যে বদলায় |
| **মাল্টিপ্রসেসিং** | কয়েকটি **প্রসেসর**, আসল সমান্তরালতা |
| **টাইম-শেয়ারিং** | একটি CPU **টাইম স্লাইসে** ভাগ করা — চিরায়ত টাইম-শেয়ারিং OS হলো রাউন্ড রবিন |
| **মাল্টিটাস্কিং** | একটি CPU-তে কয়েকটি কাজ, টাইম-শেয়ারিংয়ের ভিত্তি |
| **রিয়েল-টাইম** | থ্রুপুটের চেয়ে ডেডলাইন বেশি গুরুত্বপূর্ণ |
| **ব্যাচ** | থ্রুপুট সর্বোচ্চ, রেসপন্স উপেক্ষিত |

- ⚠️ **ফাঁদ:** ওয়েটিং টাইম **টার্নআরাউন্ড টাইম নয়**, আর রেসপন্স টাইম **ওয়েটিং টাইম নয়**। বার্স্ট 10, অ্যারাইভাল 2, সমাপ্তি 20 হলে TAT = **18**, WT = **8**, আর রেসপন্স হিসাব হয় **প্রথম** পাঠানো থেকে।
- 💡 **কৌশল:** "**টা**র্নআরাউন্ড = অ্যা**রি**ভাল থেকে ফি**নি**শ। **ও**য়েটিং = টার্নআরাউন্ড − **বা**র্স্ট। **রে**সপন্স = অ্যারাইভাল থেকে প্রথম **রান**।"

✍ **সমাধানকৃত উদাহরণ — তিনটি সময়ই।** একটি কাজ t = 2-এ এসেছে, প্রথমবার পাঠানো হয়েছে t = 5-এ, I/O-র জন্য ব্লক হয়েছে t = 9-এ, আবার পাঠানো হয়েছে t = 12-এ এবং শেষ হয়েছে t = 24-এ; তার মোট CPU বার্স্ট 12।
- **(ক)** টার্নআরাউন্ড = 24 − 2 = **22**।
- **(খ)** ওয়েটিং = 22 − 12 = **10**; ফাঁকগুলোই তা যাচাই করে — সারিতে থাকা অবস্থায় (5−2) + (12−9) = 6, আর শেষ পাঠানোয় 4।
- **(গ)** রেসপন্স = 5 − 2 = **3**।
- **(ঘ)** নন-প্রিমপটিভ হলে রেসপন্স 0 হতো — কিন্তু পাশের প্রসেসগুলো দাম দিত।

## ৮. নন-প্রিমপটিভ: FCFS, SJF ও প্রায়োরিটি

একটি প্রসেস শেষ না হওয়া বা না ব্লক হওয়া পর্যন্ত CPU ধরে রাখে। **FCFS** অ্যারাইভালের ক্রমে সেবা দেয়, **SJF** সবসময় সবচেয়ে ছোট CPU বার্স্ট বাছাই করে, **প্রায়োরিটি শিডিউলিং** সবচেয়ে উচ্চ অগ্রাধিকারের প্রসেস বাছাই করে এবং সমান অগ্রাধিকারে FCFS-এর নিয়মে সমাধান করে।

| অ্যালগরিদম | নিয়ম | ভালো | খারাপ |
|---|---|---|---|
| **FCFS** | অ্যারাইভালের ক্রম | CPU সময়ে ন্যায্য, সহজ, স্টারভেশন নেই | **কনভয় প্রভাব**: একটি লম্বা কাজ প্রতিটি ছোট কাজ দেরি করায় |
| **SJF** | ছোট বার্স্ট আগে | **সর্বনিম্ন গড় ওয়েটিং টাইম**, প্রমাণযোগ্যভাবে সেরা | বার্স্ট আগে জানা লাগে; লম্বা কাজ **স্টার্ভ** হতে পারে |
| **SRTF** (প্রিমপটিভ) | সবচেয়ে কম *অবশিষ্ট* সময় | গড় ওয়েটিং টাইমেও সেরা | বারবার সুইচ; বার্স্টের অনুমান লাগে |
| **প্রায়োরিটি** | উচ্চ অগ্রাধিকার আগে | গুরুত্ব বোঝায়; জরুরি কাজে দ্রুত সাড়া | নিম্ন অগ্রাধিকারের প্রসেসে **স্টারভেশন** |
| **রাউন্ড রবিন** (প্রিমপটিভ) | পালা করে একটি করে **টাইম কোয়ান্টাম** | ন্যায্য CPU ভাগ, সীমিত রেসপন্স টাইম | কোয়ান্টাম ছোট হলে সুইচের ওভারহেড |

✍ **সমাধানকৃত উদাহরণ ১ — FCFS।** বার্স্ট **24, 3, 3**, সবাই t = 0-এ। P1 0–24, P2 24–27, P3 27–30। ওয়েটিং 0, 24, 27 → গড় 51/3 = **17 ms**। দুটি 3 ms কাজ 24 ms কাজের পিছনে বসে ছিল — এটাই কনভয়।

✍ **সমাধানকৃত উদাহরণ ২ — SJF** (গ্যান্ট চার্ট: P4 0–3, P1 3–9, P3 9–16, P2 16–24)। বার্স্ট P1 = 6, P2 = 8, P3 = 7, P4 = 3। ওয়েটিং 0, 3, 9, 16 → গড় 28/4 = **7 ms**। FCFS দিলে 0, 6, 14, 21 → **10.25 ms**।

- ⚠️ **ফাঁদ:** SJF **গড় ওয়েটিং টাইমে** সেরা — টার্নআরাউন্ড বা রেসপন্সে নয়, ওজনযুক্ত সংমিশ্রণেও নয়। এটি বার্স্ট **জানা** থাকতে চায়; বাস্তবে OS প্রসেসের ইতিহাস থেকে অনুমান করে, তাই SRTF আসলে "সবচেয়ে কম অবশিষ্ট সময় *পরবর্তীতে*।"
- 💡 **কৌশল:** SJF-এর জন্য "**ছোট আগে, লম্বা পরে**"; **কনভয়** FCFS-এর রোগ; **স্টারভেশন** প্রায়োরিটির, আর তার ওষুধ **এজিং** — অপেক্ষার সময় বাড়লে কার্যকর অগ্রাধিকারও বাড়ে।

**এজিং ঠিকভাবে।** প্রতিটি অপেক্ষার ব্যবধানের পর OS প্রসেসের কার্যকর অগ্রাধিকার বাড়াতে পারে, অথবা "অনেকক্ষণ অপেক্ষা করেছে" ধরে প্রমোশন ধরে নিতে পারে। **এজিং শুধু স্টারভেশন ঠিকায়**: ডেডলকে এর কোনো প্রভাব নেই, কারণ সেখানে কিছুই এগোয় না এবং কোনো অগ্রাধিকার পুনর্মূল্যায়ন হয় না। এজিংহীন শুধু প্রায়োরিটি সারি প্রায় প্রতিটি বাস্তব নকশাতেই প্রত্যাখ্যাত হয়।

## ৯. প্রিমপটিভ: SRTF ও রাউন্ড রবিন

**SRTF** নতুন এসে যখন কোনো কাজের অবশিষ্ট সময় চলমান প্রসেসের চেয়ে কম হয়, তখন প্রিমপট করে। **রাউন্ড রবিন** একটি বৃত্তাকার **রেডি সারি** রাখে এবং প্রতি **টাইম কোয়ান্টাম q** পর প্রিমপট করে; সময় বাকি থাকলে প্রসেসটি সারির **পেছনে** চলে যায়।

✍ **সমাধানকৃত উদাহরণ ১ — রাউন্ড রবিন, q = 4** (গ্যান্ট চার্ট: P1 0–4, P2 4–7, P3 7–10, এরপর P1 একাই 10–30)। P1 = 24, P2 = 3, P3 = 3, সবাই 0-এ এসেছে। ওয়েটিং = সমাপ্তি − বার্স্ট: P1 = 30 − 24 = 6, P2 = 7 − 3 = 4, P3 = 10 − 3 = 7 → গড় 17/3 = **5.67 ms**। এই সেটে SJF দিলে 0, 3, 6 → **3 ms**; FCFS 17 ms।

✍ **সমাধানকৃত উদাহরণ ২ — SRTF, ভিন্ন অ্যারাইভাল।** P1 (0, 8), P2 (1, 4), P3 (2, 9), P4 (3, 5)। t = 1-এ P2 (4) হারায় P1-এর অবশিষ্ট 7-কে → প্রিমপট; t = 5-এ P4 (5) হারায় P1 (7) ও P3 (9)-কে; t = 10-এ P1 (7) হারায় P3 (9)-কে। গ্যান্ট: **P1 0–1 | P2 1–5 | P4 5–10 | P1 10–17 | P3 17–26**। সমাপ্তি 17, 5, 26, 10 → টার্নআরাউন্ড 17, 4, 24, 7 → গড় **13 ms**; ওয়েটিং 9, 0, 15, 2 → গড় **6.5 ms**।

| টাইম কোয়ান্টাম q | আচরণ |
|---|---|
| **q → বড়** (q ≥ বার্স্ট) | বাস্তবে প্রিমপট নেই → **RR অপসারিত FCFS হয়ে যায়** |
| **q → ছোট** | অনেক কনটেক্সট সুইচ; বেশির ভাগ সময় সুইচেই যায়, থ্রুপুট কমে |
| **q গড় বার্স্টের ঠিক ওপরে** | সাধারণ পছন্দ — ইন্টারঅ্যাক্টিভের জন্য যথেষ্ট দ্রুত, বেশির ভাগ কাজ কয়েক পালাতেই শেষ করার মতো ধীর |
| সর্বোচ্চ রেসপন্স | n টি রেডি প্রসেসের জন্য **(n − 1) × q** দিয়ে সীমাবদ্ধ |

- 💡 **কৌশল:** "কোয়ান্টাম হলো **অপেক্ষার একটি প্রতিশ্রুতি**: ছোট q ন্যায্যতা ও দ্রুত প্রথম সাড়ার কথা দেয় এবং সুইচে দেয়; বড় q দক্ষতার কথা দেয় এবং রেসপন্স টাইমে দেয়।"
- ⚠️ **ফাঁদ:** (i) RR-এ ওয়েটিং টাইম হলো **সমাপ্তি − অ্যারাইভাল − বার্স্ট**, প্রতিটি কোয়ান্টাম গুনে "সারিতে কাটানো সময়" নয়। (ii) কোয়ান্টামের মধ্যেই শেষ হয়ে গেলে প্রসেস **আর কোনোদিন অপেক্ষা করে না**। (iii) RR **প্রিমপটিভ**; "স্লাইসে ভেঙে চালিয়ে যাওয়া" বলতে FCFS বোঝায়।
- 📌 **থ্রেড বনাম প্রসেস শিডিউলিং:** প্রতিটি প্রসেসে একটি করে থ্রেড থাকলে RR প্রতিটি **প্রসেসকে** পালা দেয় — একটি প্রসেসের পঞ্চাশটি থ্রেড থাকলে অন্যায় হয়। আধুনিক কার্নেল তাই **থ্রেড** শিডিউল করে।

## ১০. মাল্টিলেভেল সারি, ফিডব্যাক ও রিয়েল-টাইম

একটি **মাল্টিলেভেল সারি** স্থায়ী শ্রেণি রাখে — সিস্টেম প্রসেস ছোট কোয়ান্টামে রাউন্ড রবিনে, ইউজার প্রসেস FCFS বা SJF-তে। **মাল্টিলেভেল ফিডব্যাক সারি (MLFQ)** সরাচর করতে দেয়: পুরো কোয়ান্টাম খাটিয়ে যাওয়া প্রসেস নামানো হয়, যথেষ্টক্ষণ অপেক্ষা করলে ওঠানো হয়।

| বিষয় | মাল্টিলেভেল সারি | মাল্টিলেভেল ফিডব্যাক সারি |
|---|---|---|
| সরাচর | **নেই** — শ্রেণি স্থির | প্রসেস ওঠানো বা নামানো হয় |
| প্রতি সারির কোয়ান্টাম | শ্রেণির জন্য একটি | অগ্রাধিকার কমলে বাড়ে |
| শক্তি | সহজ ও সস্তা; প্রতি শ্রেণিতে আলাদা ভর্তি নীতি | **ইন্টারঅ্যাক্টিভ** ও **CPU-বাউন্ড** কাজ নিজে থেকেই আলাদা করে |
| দুর্বলতা | নিচের শ্রেণি **স্টার্ভ** হতে পারে | স্টারভেশন এড়াতে প্রমোশন নিয়ম লাগে |

| রিয়েল-টাইম নীতি | অগ্রাধিকারার নিয়ম |
|---|---|
| **রেট মনোটনিক** | **স্থির**: ছোট পিরিয়ড → বেশি অগ্রাধিকারা |
| **EDF** | **পরিবর্তনশীল**: সবার আগে ডেডলাইন আছে যার |

**হার্ড রিয়েল-টাইম এক লাইনে।** এক প্রসেসরে nটি পিরিয়ডিক কাজের জন্য প্রতিটির C ≤ T লাগে **এবং** মোট ব্যবহার ≤ **n(2^(1/n) − 1)**: ১ কাজ ১০০ %, ২ কাজ ৮৩ %, ৩ কাজ ৭৮ %।

- ⚠️ **ফাঁদ:** **EDF সেরা** — এটি কেবল তখনই ডেডলাইন বাদ দেয় যখন কোনো নির্ভেজ্ঞ সূচি-ই নেই। রেট মনোটনিক কেবল **স্থির** অগ্রাধিকারায় সেরা এবং ৭৬ %-এর বেশি ব্যবহারে EDF-এর কাছে হেরে যায়।
- 💡 **কৌশল:** "**স্থায়ী শ্রেণি সরে না; ফিডব্যাক সারি শিডিউলারকে শেখায়।**" আর "**রেট** স্থির, **ডেডলাইন** প্রতি মুহূর্তে আবার পড়া হয়।"
- ⚠️ **ফাঁদ:** দীর্ঘ শিডিউলার খালি না থাকলে কেবল **সর্বোচ্চ** সারিতেই সেবা দেয়, তাই নিচের শ্রেণি অনির্দিষ্টকাল অপেক্ষায় থাকে — এমন স্টারভেশন-ব্যর্থতা যা **এজিং** বা প্রমোশনই ঠিক করে।

✍ **সমাধানকৃত উদাহরণ — দুটি পিরিয়ডিক কাজ।** একটি কন্ট্রোল লুপ প্রতি 40 ms-এ 10 ms চায়; একটি লগার প্রতি 100 ms-এ 5 ms চায়।
- **(ক)** ব্যবহার = 10/40 + 5/100 = 0.25 + 0.05 = **0.30**।
- **(খ)** দুটি কাজ, তাই রেট মনোটনিক সীমা 2(2^(1/2) − 1) ≈ **0.828**; 0.30 < 0.828, তাই সেটটি **রেট মনোটনিকে চালানোর উপযোগী**।
- **(গ)** EDF একই ডেডলাইন মেলায় অনেক বেশি ভার নিতে পারে।
- **(ঘ)** লুপের পিরিয়ড 12 ms হলে ব্যবহার ≈ 0.883 > 0.828, তখন রেট মনোটনিক আর নিশ্চয়তা দিতে পারে না, EDF ব্যবহার করতে হবে।

## রাতের-পরীক্ষার তথ্য-পত্র

- প্রোগ্রাম = নিষ্ক্রিয় ফাইল, প্রসেস = চলমান
- প্রসেস = কোড, ডেটা, PC, রেজিস্টার
- **PID** চিহ্নিত করে; পরে পুনর্ব্যবহার
- PCB: স্টেট, PC, রেজিস্টার, শিডিউলিং, মেমোরি, হিসাব
- new → ready → running → waiting → terminated
- রেডি = CPU চায়, ওয়েটিং = ঘটনা চায়
- দীর্ঘমেয়াদি = জব সারি · মধ্যবর্তী = সোয়াপ
- স্বল্পমেয়াদি = CPU শিডিউলার
- থ্রেডরা অ্যাড্রেস স্পেস ভাগ করে, নিজস্ব স্ট্যাক থাকে
- ইউজার-লেভেল পুরো প্রসেস থামায়
- many-to-one · one-to-one · many-to-many
- কার্নেল-লেভেল একটি থ্রেড থামায়
- IPC: shm, pipe, FIFO, queue, socket, signal
- অ্যানোনিমাস পাইপ = সম্পর্কিত প্রসেস
- সেমাফোর P = −1 (ব্লক হতে পারে), V = +1
- মিউটেক্সের মালিক আছে, সেমাফোরের নেই
- empty + full = বাফারের আকার N
- প্রোডিউসার empty আগে, কনজিউমার full আগে
- TAT = সমাপ্তি − অ্যারাইভাল
- WT = TAT − বার্স্ট · রেসপন্স = প্রথম চাল − অ্যারাইভাল
- SJF = ন্যূনতম গড় ওয়েটিং টাইম
- FCFS = কনভয় · প্রায়োরিটি = স্টারভেশন
- RR: q বড় → FCFS, q ছোট → সুইচ বেশি
- RR-এ সবচেয়ে খারাপ রেসপন্স = (n − 1)q
- MLFQ CPU-বাউন্ডকে নামায়, অপেক্ষাকারীকে ওঠায়
- EDF সেরা · RM সীমা n(2^(1/n) − 1)

## লিখিত প্রশ্ন (১০ নম্বর)

প্রসেস কী, আর প্রসেস কন্ট্রোল ব্লকে কী থাকে? পাঁচ-অবস্থার ডায়াগ্রামটি সাতটি তিরসহ আঁকো এবং মেমোরিতে থেকে শুধু CPU-এর অপেক্ষায় থাকা প্রসেস কোন সারিতে পড়ে। বার্স্ট P1 = 24, P2 = 3, P3 = 3 ms সবাই t = 0-এ এসেছে: FCFS-এ এবং q = 4 ms রাউন্ড রবিনে গড় ওয়েটিং টাইম বের করো, আর গড় অপেক্ষার জন্য কোন অ্যালগরিদম সেরা তা নামাও।

**মডেল উত্তর:**

1. **প্রসেস ও PCB (৩)** — মেমোরিতে তুলে চলা একটি প্রোগ্রাম, সঙ্গে কোড, ডেটা, প্রোগ্রাম কাউন্টার, রেজিস্টার ও খোলা ফাইল। PCB = প্রসেস স্টেট, প্রোগ্রাম কাউন্টার, CPU রেজিস্টার, CPU শিডিউলিং তথ্য, মেমোরি ম্যানেজমেন্ট তথ্য, অ্যাকাউন্টিং তথ্য।
2. **ডায়াগ্রাম (৩)** — new → ready (ভর্তি); ready → running (পাঠানো); running → ready (ইন্টারাপ্ট বা স্লাইস শেষ); running → waiting (I/O বা ঘটনার অপেক্ষা); waiting → ready (সমাপ্তি); running → terminated; new → terminated (ভর্তি বাতিল)। শুধু CPU-এর অপেক্ষা মানে **রেডি সারি**, ডিভাইস সারি নয়।
3. **FCFS (২)** — P1 0–24, P2 24–27, P3 27–30। ওয়েটিং 0, 24, 27 → গড় 51/3 = **17 ms**।
4. **RR, q = 4 (২)** — P1 0–4, P2 4–7, P3 7–10, এরপর P1 একাই 10–30। ওয়েটিং = সমাপ্তি − বার্স্ট: 6, 4, 7 → গড় 17/3 = **5.67 ms**। গড় অপেক্ষায় সেরা: **SJF** (প্রিমপটিভ SRTF) — 0, 3, 6 → **3 ms**।

**আরও অনুশীলন (লিখিত):** ① সাতটি রূপান্তর ও প্রতিটির একটি বাস্তব উদাহরণ ② নতুন প্রসেস কেন রেডি সারিতে যায়, running-এ নয় ③ ২ স্লটের বাফারে প্রোডিউসার–কনজিউমারের সেমাফোর ট্রেস ④ একই অ্যারাইভাল সেটে RR ও SRTF-এর তুলনা ⑤ ব্যবহারের সীমাসহ রেট মনোটনিক বনাম EDF।

**পরীক্ষার আগে ✓** পাঁচটি অবস্থা ও সাতটি রূপান্তর নামাতে পারি · PCB-র ঘরগুলো মুখস্থ ছাড়া বলতে পারি · FCFS, SJF ও RR-এর গ্যান্ট চার্ট আঁকতে পারি · প্রোডিউসার–কনজিউমারে সেমাফোর ট্রেস করতে পারি।
