1Why a Memory Hierarchy?

MCQ + Written
Definition Memory built as levels, each smaller, faster and costlier per bit than the one below. Thanks to locality the system runs at nearly the speed of the fastest level at nearly the cost of the cheapest.

Going DOWN the pyramid:

  • capacity ↑
  • access time ↑ (slower)
  • cost per bit ↓
  • frequency of access by the CPU ↓

Properties: inclusion (level i ⊂ level i+1), coherence (copies agree), locality. 90/10 rule: ≈ 90% of time is spent in 10% of the code.

2Locality of Reference

high-yield
Temporal an item used now is used again soon (loop counter, sum, loop code). Exploited by keeping recent items (LRU).
Spatial nearby addresses are used soon (arrays, sequential code). Exploited by fetching a whole block (64 B) and prefetching.
sum = 0; for (i = 0; i < n; i++) sum += a[i]; /* a[i]: spatial */ /* sum, i: temporal */
Memory trick Temporal = same Thing, again in Time. Spatial = Surrounding Space. C is row-major: loop a[i][j] with j inside.

Exam trap "Static" does not mean non-volatile: SRAM and DRAM both lose data when power goes. DRAM's row and column addresses share pins (multiplexed with RAS / CAS), so a 1M × 1 DRAM needs only 10 address pins, not 20.

DRAM family: asynchronous DRAM → FPM → EDO → SDRAM (clocked) → DDR (data on both clock edges) → DDR2 / 3 / 4 / 5. Peak rate = transfers/s × bus width: DDR4-3200 on a 64-bit (8 B) channel = 3200 × 10⁶ × 8 B = 25.6 GB/s.

SRAM → cache, DRAM → main memory

CA · Memory HierarchyCapacity & interleaving

5Memory Organisation & Capacity Maths

calculation
Key formulas 2ⁿ words × m bits → n address lines, m data lines · chips = (words ÷ chip words) × (width ÷ chip width) · address bits = log₂(addressable units)
Width (word-size) expansion chips side by side share all address lines; each supplies some data bits (two 1K × 4 → 1K × 8).
Depth (word-count) expansion extra high-order address bits go to a decoder whose outputs drive the chips' chip select (CS).
Worked examples ✍
  1. A 4K × 8 chip: 4K = 2¹² → 12 address lines, 8 data lines; capacity 32 Kbit = 4 KB
  2. 16K × 8 memory from 1K × 4 chips: (16K / 1K) × (8 / 4) = 16 × 2 = 32 chips; 14 address lines: A9–A0 to every chip, A13–A10 into a 4-to-16 decoder
  3. 64 MB, byte-addressable: 2²⁶ bytes → 26 address bits. Same memory, 32-bit (4-byte) words, word-addressable: 2²⁴ words → 24 bits
  4. 32-bit byte address → 2³² B = 4 GB; 8086 (20 lines) → 1 MB
Exam trap Check byte- vs word-addressable before taking log₂.

6Memory Interleaving

  • k modules (banks) work in parallel
  • Low-order: low address bits pick the module (address mod k); consecutive words in different modules → a block is fetched in parallel
  • High-order: high bits pick the module; consecutive words in the same module → easy expansion, no speed-up
Worked example ✍ 4-word block; 1 cycle to send the address, 15 cycles per DRAM access, 1 cycle per word on the bus. One-word-wide memory: 1 + 4 × 15 + 4 × 1 = 65 cycles. 4-bank interleaved: 1 + 15 + 4 × 1 = 20 cycles (3.25× faster miss penalty).

CA · Memory HierarchyCache & access time

7Cache Memory: the Basics

high-yield
Definition A small, fast SRAM memory between the CPU and main memory that holds copies of recently used blocks (lines). Invisible to the programmer: managed entirely by hardware.
  • Block / line: the unit moved between cache and memory (typ. 64 B)
  • Hit: word found in cache · Miss: not found → fetch the block
  • Hit ratio h = hits / (hits + misses); miss ratio = 1 − h
  • Hit time (Tc) · miss penalty (time to bring the block)
  • Each line stores a tag (which block is here), a valid bit, and a dirty bit for write-back

8Average Access Time: Which Formula?

very high-yield
OrganisationA miss costsFormula
Hierarchical (look-through)Tc + TmT = h·Tc + (1 − h)(Tc + Tm)
Simultaneous (parallel)Tm onlyT = h·Tc + (1 − h)·Tm
AMAT (Hennessy–Patterson)miss penaltyAMAT = hit time + miss rate × miss penalty

Hierarchical: the cache is checked first, then memory. Simultaneous: both are started together. Hierarchical simplifies to Tc + (1 − h)·Tm, the AMAT form with penalty = Tm. Default when the question is silent: hierarchical, but check whether the options hold the simultaneous answer.

Worked examples ✍
  1. Tc = 10 ns, Tm = 100 ns, h = 0.9: hierarchical 0.9 × 10 + 0.1 × 110 = 20 ns; simultaneous 9 + 10 = 19 ns; speed-up = 100 / 20 = 5
  2. Classic: Tc = 100 ns, Tm = 1000 ns, h = 0.9 → hierarchical 200 ns (simultaneous 190 ns)
  3. AMAT: hit 1 ns, miss rate 5%, penalty 100 ns → 1 + 0.05 × 100 = 6 ns
  4. Find h: Tc = 5, Tm = 80, target 9 ns: 9 = 5 + (1 − h) × 80 → h = 0.95
  5. CPI (see CPU Organization): base 1, 1.3 accesses / instr., miss 2%, penalty 100 → 1 + 1.3 × 0.02 × 100 = 3.6
Memory trick "Through" the cache: a miss pays both, Tc + Tm. "Side by side": a miss pays Tm only.
Exam trap Given the miss ratio (0.1)? Don't use it as h. Check: Tc ≤ T ≤ Tc + Tm.

9Cache Mapping Techniques

very high-yield

Mapping decides where a memory block may be placed in the cache, and so how the address is split. Let block size = B bytes, lines = L, associativity = k, sets S = L / k.

Direct block j → line j mod L. One place only, one comparator. Simple, fast; suffers conflict misses (thrashing).
Fully associative block → any line; all tags compared in parallel (L comparators, CAM). No conflict misses; costly.
k-way set assoc. block j → set j mod S, any of its k lines; k comparators. The compromise used in real CPUs.

10Mapping: Worked Examples

written favourite
Example 1: split an address ✍ Direct-mapped 64 KB cache, 64 B blocks, 32-bit address 0x12345678 (tag 16 | line 10 | offset 6): offset = 0x78 AND 0x3F = 56 · line = (0x12345678 ÷ 64) mod 1024 = 345 · tag = upper 16 bits = 0x1234
Example 2: 2-way set associative ✍ 32 KB cache, 32 B blocks, 32-bit address. Offset = log₂ 32 = 5; lines = 32 KB / 32 B = 1024; sets = 1024 / 2 = 512 → set = 9; tag = 32 − 9 − 5 = 18.
Example 3: tag memory ✍ Example 1's cache: 1024 lines × (16 tag + 1 valid) = 17,408 bits = 2176 B on top of the 64 KB of data.

Example 4: block trace 0, 8, 0, 6, 8 in a 4-block cache

Write-allocate (fetch-on-write): on a write miss, load the block, then write it. No-write-allocate (write-around): write straight to memory.

Traffic ✍ A loop writes one variable 100 times: write-through 100 memory writes, write-back 1 (at eviction).
Write-back time ✍ Tc = 5 ns, Tm = 50 ns, h = 0.9, 30% of victims dirty: T = 5 + 0.1 × (50 + 0.3 × 50) = 11.5 ns

Multicore: several caches may hold copies; a coherence protocol (MESI, snooping) keeps them consistent.

14Multilevel Caches

  • L1: split I + D caches, per core; aim: short hit time
  • L2: unified, per core; aim: low miss rate
  • L3: shared by all cores (last level)
  • Local miss rate = misses / accesses to that level; global = misses / all CPU accesses
Two-level AMAT ✍ L1: 1 ns, miss 5%. L2: 10 ns, local miss 20%. RAM 100 ns.
AMAT = 1 + 0.05 × (10 + 0.2 × 100) = 1 + 0.05 × 30 = 2.5 ns
Without L2: 1 + 0.05 × 100 = 6 ns. Global L2 miss rate = 0.05 × 0.2 = 1%.

15Virtual Memory & TLB (Summary)

MCQ

VM uses main memory as a cache for the disk. The MMU translates virtual addresses page by page through the page table (in RAM, found via the PTBR).

A page fault costs millions of cycles → large pages (4 KB), fully associative placement, LRU-like replacement, always write-back.

TLB = small associative cache of recent page-table entries.

CacheVMFormula / example
blockpage / framepages = 2^(VA bits − offset bits)
misspage fault (OS)32-bit VA, 4 KB page → 2²⁰ PTEs × 4 B = 4 MB
tag storepage table, TLB64 MB RAM, 4 KB pages → 2¹⁴ frames
EAT with a TLB ✍ TLB 20 ns, memory 100 ns, TLB hit 0.8, one-level table: 0.8 × (20 + 100) + 0.2 × (20 + 100 + 100) = 140 ns (a TLB miss adds one memory access). Paging algorithms, thrashing → OS chapter.

16Secondary Storage: Disk & RAID

calculation
Disk formulas Access time = seek + rotational latency + transfer (+ controller overhead) · average latency = ½ × (60 / rpm) s · capacity = surfaces × tracks × sectors/track × bytes/sector
Worked example ✍ 6000 rpm, average seek 8 ms, 100 sectors × 512 B per track.
  1. Rotation = 60 / 6000 s = 10 ms → latency 5 ms; 1 sector = 10 / 100 = 0.1 ms
  2. Access = 8 + 5 + 0.1 = 13.1 ms; 4 KB (8 sectors) = 13.8 ms; rate = 51,200 B / 10 ms = 5.12 MB/s
  3. 16 surfaces × 1024 tracks × 128 sectors × 512 B = 2³⁰ B = 1 GB

RAID 2 = bit-level Hamming, 3 = byte-level, 4 = block-level, each with a dedicated parity disk (bottleneck). Parity = XOR. 5 × 2 TB: RAID 5 → 8 TB, RAID 6 → 6 TB.
