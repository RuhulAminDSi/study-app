1Polling vs Interrupt-Driven I/O

MCQ + Written
Interrupt A signal (hardware, instruction or CPU-generated) that makes the CPU suspend the program after the current instruction, run an Interrupt Service Routine (ISR), then resume where it stopped.

Polling (programmed I/O): the CPU keeps reading a status port in a loop until the device is ready → simple, but wastes CPU time and a fast event can be missed.

Interrupt-driven I/O: the device tells the CPU when it is ready; the CPU does useful work in between. Cost: a little extra hardware and the save/restore overhead (interrupt latency).

Memory trick Polling = checking your phone every minute · interrupt = it rings · DMA = a courier with the store-room key.

4Interrupt Vector Table (IVT)

Vector the 4-byte far address (IP, CS) of an ISR. IVT = 256 × 4 = 1 KB at 00000H–003FFH.
Formula vector address = 4 × N

5What the 8086 Does on an Interrupt

written favourite
  1. Finishes the current instruction, then samples NMI and INTR (INTR only if IF = 1)
  2. INTR only: two INTA cycles. 1st: 8259A resolves priority; 2nd: it puts type N on D0–D7 (NMI, software: N already known)
  3. Pushes FLAGS (SP − 2)
  4. Clears IF and TF: no INTR, no single-step in the ISR
  5. Pushes CS, then IP (SP − 4 more: 6 bytes in all)
  6. Loads IP from 4N, CS from 4N + 2 → ISR runs
  7. ISR saves registers, services the device, sends EOI, ends with IRET
  8. IRET pops IP, CS, FLAGS (old IF, TF return)

RET vs IRET

InstructionPopsBytes
RET (near)IP2
RETF (far)IP, CS4
IRETIP, CS, FLAGS6
; ISR skeleton (PC: 8259A at 20H) ISR: PUSH AX ... ; service device MOV AL, 20H ; non-specific EOI OUT 20H, AL POP AX IRET
Memory trick Push order "F-C-I" (Flags, CS, IP), pop order reversed "I-C-F". Interrupt = a far CALL that also saves the flags.

MPI · Interrupts & DMA8259A PIC

78259A Programmable Interrupt Controller

high-yield
Why a PIC? The 8086 has one maskable input (INTR). The 8259A takes 8 requests (IR0–IR7), masks and prioritises them, raises INTR and hands the CPU the winner's type number.
  • 28-pin DIP, single +5 V, works with 8085 and 8086/88
  • 8 levels; cascade 1 master + 8 slaves → 64 levels
  • Each IR can be masked separately (IMR)
  • Edge- or level-triggered inputs (LTIM bit)
  • Priority modes: fully nested, rotating, special mask, poll
  • Programmed with 4 ICWs (init) and 3 OCWs (run time)
RegisterHoldsSet / cleared by
IRR (request)IR lines now requestingset by IR input; cleared on 1st INTA
ISR (in-service)levels being servicedset on 1st INTA; cleared by EOI/AEOI
IMR (mask)masked levels (1 = masked)written by OCW1
Priority resolverhighest unmasked IRR bitmode set by OCW2

One request, step by step (8086 mode)

  1. IR3 goes high → IRR bit 3 set; if unmasked and higher than anything in service, 8259A raises INT
  2. CPU (IF = 1) answers with the 1st INTA → ISR bit 3 set, IRR bit 3 cleared
  3. 2nd INTA → 8259A puts the type byte on D0–D7: T7–T3 of ICW2 + 011
  4. ISR bit 3 stays set (blocks equal/lower levels) until the ISR sends EOI; in AEOI mode it clears itself at the end of the 2nd INTA
Exam trap The 8259A sends the type number (one byte), not the ISR address. With an 8085 it sends a CALL opcode + 2 address bytes (3 INTA pulses); with an 8086, 2 pulses.

10Cascading: up to 64 Levels

high-yield
  • Slave INT → a master IR input; master CAS0–2 outputs the slave ID; slaves read it as inputs
  • Hardware sets master/slave by SP/EN (1 = master) or by ICW4 in buffered mode
  • On the 2nd INTA the selected slave puts the type on the bus
  • Levels with s slaves = 8 + 7s: 1 slave → 15 (PC/AT), 8 slaves → 64
  • ISR on a slave level sends two EOIs: slave, then master
Worked example ✍ Master + slaves on IR2 and IR5 (edge, 8086): master ICW1 = 11H (cascade), ICW2 = 08H, ICW3 = 0010 0100 = 24H, ICW4 = 01H · slave A: 11H, 70H, ICW3 = 02H, 01H · slave B: ICW3 = 05H. Levels = 8 + 7 × 2 = 22.

11Direct Memory Access (DMA)

MCQ + Written
Definition DMA moves a block between an I/O device and memory (or memory to memory) without the CPU running an instruction per byte: a DMA controller (DMAC) borrows the bus, drives addresses and strobes itself, then returns the bus.
Why? Polling/interrupt I/O moves every byte through the CPU (IN, MOV, INC, LOOP ≈ tens of clocks). A DMAC needs one bus cycle per byte (4 clocks on the 8237).
Cost: an extra chip, and the CPU is held off the bus during transfers (it may still run from its queue).

The HOLD / HLDA handshake (8086 minimum mode)

  1. Device asks the DMAC with DREQ; DMAC raises HRQ, wired to the 8086 HOLD pin
  2. 8086 finishes the current bus cycle, floats its address/data/control lines and answers HLDA
  3. DMAC sends DACK, drives the address and MEMR + IOW (or IOR + MEMW)
  4. At terminal count (or EOP) HRQ drops → the 8086 drops HLDA and takes the bus back
DMA modeHow the bus is usedEffect
Burst (block)whole block in one bus grantCPU off the bus; fastest
Cycle stealing (single)one byte per grant, bus returnedCPU slowed slightly
Transparent (hidden)only cycles the CPU leaves idleno slowdown; slowest
Memory trick Burst = take the road for the whole convoy · stealing = slip in one car at a time · transparent = drive only when the road is empty.
Exam trap HOLD is honoured even when IF = 0 (it is not an interrupt). In maximum mode HOLD/HLDA are replaced by RQ/GT0 (higher priority) and RQ/GT1.

128237 Programmable DMA Controller

high-yield
  • 40 pins, 4 channels (DREQ/DACK 0–3)
  • 16-bit address + count → 64 KB per block
  • 8237A-5: 5 MHz, up to 1.6 MB/s
  • Fixed (ch0 highest) or rotating priority
  • A8–A15 sent on DB0–DB7, latched by ADSTB
  • AEN cuts off the CPU address latches
  • EOP: out at TC, or in to stop a transfer
  • PC/AT: 2 cascaded → 7 usable channels
