1The 8254 Programmable Interval Timer

MCQ + Written
Definition The Intel 8254 PIT is a 24-pin, +5 V counter/timer chip with three independent 16-bit down counters (Counter 0, 1, 2). Each counter has a CLK input, a GATE input and an OUT output, works in any of 6 modes (0–5) and counts in binary or BCD, decrementing on each falling CLK edge. It replaces software delay loops, so the CPU is free while time is measured in hardware.

24 pins at a glance

  • D7–D0: 8-bit data bus (8 pins)
  • CLK, GATE, OUT × 3 counters (9 pins)
  • RD′, WR′, CS′ (active low), A1, A0
  • VCC, GND → total 24
A1A0Selects
00Counter 0
01Counter 1
10Counter 2
11Control word reg.

8253 vs 8254 (the favourite comparison)

Inside each counter: CR (count register, written by the CPU) → CE (16-bit counting element) → OL (output latch, read by the CPU). The count moves CR → CE on the next CLK pulse after it is written.

Memory trick "3-16-6-24": 3 counters, 16 bits each, 6 modes, 24 pins. 8254 = 8253 + read-back + faster clock.
Exam trap The control word register is write-only; A1A0 = 11 never reads a count. Max count is loaded as 0000 = 65,536 (binary) or 10,000 (BCD).

3Reading a Counter While It Runs

  1. Simple read: stop the count first (GATE = 0 or block CLK), then read LSB, MSB
  2. Counter latch command: SC bits + RW = 00 freezes CE into OL; counting continues (latch counter 1 = 40H)
  3. Read-back (8254 only): latches count and/or status of several counters at once

Status byte: OUT · NULL COUNT · RW1 RW0 · M2 M1 M0 · BCD
Read-back examples ✍ latch count + status of counter 1 → 11 0 0 0 1 0 0 = C4H · latch status only of all three → 11 1 0 1 1 1 0 = EEH · latch counts of counters 0 and 2 → 11 0 1 1 0 1 0 = DAH
Memory trick "Who · How · What · Which number": counter, access, mode, binary/BCD = 2 + 2 + 3 + 1 bits.
Exam trap Mode 2 = X10, mode 3 = X11 (so 110 is mode 2). RW = 00 is not "no access": it is the latch command.

5Count Calculation & Programming

written favourite
Formulas

Modes 2, 3: N = f_clk ÷ f_out

Delay (modes 0, 1, 4, 5): N = t × f_clk

T_clk = 1 ÷ f_clk (2 MHz → 0.5 µs)

Lowest f_out = f_clk ÷ 65,536

Mode 3, odd N: high (N+1)/2, low (N−1)/2

N > 65,536 → cascade two counters

Example 1: the classic program ✍ Counter 0 at port 40H, control at 43H, CLK0 = 2 MHz, want 5 kHz square wave.
  1. N = 2 MHz ÷ 5 kHz = 400 = 0190H (for 1 kHz: 2000 = 07D0H)
  2. CW: 00 11 011 0 = 36H (counter 0, LSB/MSB, mode 3, binary)
  3. Write CW to 43H, then LSB 90H, then MSB 01H to 40H
MOV AL, 36H ; control word OUT 43H, AL MOV AL, 90H ; LSB of 0190H OUT 40H, AL MOV AL, 01H ; MSB of 0190H OUT 40H, AL
Example 2: delay ✍ 1 ms delay on counter 2, mode 0, CLK = 2 MHz: N = 1 ms × 2 MHz = 2000 (07D0H); CW = 10 11 000 0 = B0H. OUT2 goes high after 2000 + 1 clocks ≈ 1 ms → wire it to an interrupt input (8259A, lesson mp4).
Example 3: BCD ✍ CLK1 = 1 MHz, 1 kHz in BCD: N = 1000 → write 00H then 10H (BCD digits 1 0 0 0); CW = 01 11 011 1 = 77H.
Example 4: cascade ✍ 1 Hz from 2 MHz needs N = 2,000,000 > 65,536, so one counter cannot do it. Counter 0, mode 2, N = 2000 → 1 kHz; feed OUT0 into CLK1; counter 1, mode 3, N = 1000 → 1 Hz. Check: 2000 × 1000 = 2 × 10⁶ ✓
IT link: the IBM PC The PC's 8253/8254 sits at ports 40H–43H with CLK = 1.193182 MHz. Counter 0, mode 3, count 0 (65,536) → 18.2 Hz system tick on IRQ0 (every 54.9 ms); counter 1, mode 2, count 18 (CW 54H) → DRAM refresh every 15.1 µs; counter 2, mode 3 (CW B6H) → speaker tone (1 kHz needs N ≈ 1193).
Exam trap N is a frequency ratio; do not divide periods the wrong way round. Write the count to the counter's port, LSB first, never to the control port.

7The Asynchronous Character Frame

high-yield
  • Idle line = 1 (mark); start bit = 0 (1 bit, the 1→0 edge wakes the receiver)
  • Data: 5–8 bits, LSB first
  • Parity: even / odd / none (optional)
  • Stop bit(s) = 1: 1, 1.5 or 2 bits
Baud vs bit rate Baud = signal changes (symbols) per second; bit rate = baud × bits per symbol. With 2-level signalling (RS-232, UART) baud = bps.
Worked examples ✍ ① 9600 baud, 8N1 (1 + 8 + 1 = 10 bits) → 960 chars/s; bit time = 1 ÷ 9600 = 104.17 µs · ② 9600 baud, 8 data + parity + 2 stop = 12 bits → 800 chars/s · ③ modem at 2400 baud with 16 levels (4 bits/symbol) → 2400 × 4 = 9600 bps · ④ efficiency of 8N1 = 8 ÷ 10 = 80%

8Simplex, Half Duplex, Full Duplex

  • Simplex: one way only (broadcast radio/TV, keyboard → CPU)
  • Half duplex: both ways, one at a time (walkie-talkie)
  • Full duplex: both ways at the same time (telephone; RS-232 with TxD + RxD)
Memory trick The frame "starts low, stops high": start = 0, stop = 1, so every character begins with a guaranteed 1 → 0 edge.

108251A USART (Communication Interface)

MCQ + Written
Definition The Intel 8251A Universal Synchronous/Asynchronous Receiver/Transmitter (28 pins, +5 V) turns CPU bytes into serial bits (P → S, TxD) and serial input into bytes (S → P, RxD); full duplex.
  • Async: 5–8 data bits, clock ×1, ×16 or ×64, 1/1.5/2 stop bits, up to 19.2 kbps
  • Sync: one or two SYNC characters, internal or external sync detect, up to 64 kbps
  • Parity even/odd/none; detects parity, overrun, framing errors and break
UART vs USART
UART = async only (8250, 16550: 16-byte FIFO, PC COM ports)
USART = both modes (8251A)
C/D′RD′WR′Operation
001CPU reads data
010CPU writes data
101CPU reads status
110CPU writes mode / command
  • TxRDY: CPU may write the next byte
  • TxEMPTY: last bit has left TxD
  • RxRDY: a byte is waiting for the CPU
  • TxRDY/RxRDY can drive IRQs (8259A)

Interfacing serial I/O devices

Memory trick C/D′ = "Control when 1, Data when 0". Control + read = status; control + write = mode/command.
Exam trap The 8251 has no internal baud generator: TxC/RxC must come from outside, typically an 8254 in mode 3.

Initialise and poll (data 80H, control 81H)
