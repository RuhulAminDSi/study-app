Q1 Analyze the following code: what does it return?Combined Bank Officer(IT) 2023 · Rupali Bank ANE 2023 · also on the Petrobangla ANE suggestion sheet
SELECT d.department_name, AVG(e.salary) AS average_salary FROM employees e JOIN department d ON e.department_id = d.department_id WHERE e.salary > (SELECT AVG(salary) FROM employees) GROUP BY d.department_name HAVING COUNT(*) > 2 ORDER BY average_salary DESC;
  1. WHERE keeps employees paid above the company average (59556): Karim, Rahim, Nila, Babu, Hasan
  2. GROUP BY department: IT 3, HR 1, Accounts 1
  3. HAVING keeps groups with more than 2 such employees
  4. Shows their average, highest first

→ IT | 70000 (only IT has 3 above-average employees: 90000 + 60000 + 60000)

Exam trap As printed, the query is invalid: alias e is used but never declared (FROM employees needs e), and the suggestion-sheet copy has an empty COUNT(). Say so, fix it, then explain. The suggestion-sheet version compares with the own department's average (correlated subquery): on these rows it returns no row.
Memory trick "WHERE before, HAVING after": WHERE cannot use AVG/COUNT, HAVING can. An alias from SELECT works only in ORDER BY.

Same pattern, other schemas: courses with exactly 2 / more than 2 offerings → GROUP BY c.crscode HAVING COUNT(*) = 2 Petrobangla AM(CSE) 2024 · courses and student count where enrolment ≤ 30 → HAVING COUNT(*) <= 30 ICB Securities AP 2026

Q11 employee(id, name, salary), equipment(id, name, price), hire(employee_id, equipment_id): name of the employee who borrowed the most equipment.BAPEX AGM(ICT) 2023
SELECT e.name, COUNT(*) AS items FROM employee e JOIN hire h ON h.employee_id = e.id GROUP BY e.id, e.name HAVING COUNT(*) = (SELECT MAX(cnt) FROM (SELECT COUNT(*) AS cnt FROM hire GROUP BY employee_id) t);

Q12 Product(pname, price, category, maker), Purchase(buyer, seller, stock), Company(cname, country), Person(per-name, address, phone); maker = cname, buyer/seller = per-name. (a) Persons who bought a product made by an American company. (b) Sum of all products and of all sold products by country.NWPGCL AM(ICT) 2024
(a) SELECT DISTINCT pu.buyer FROM Purchase pu JOIN Product p ON p.pname = pu.stock JOIN Company c ON c.cname = p.maker WHERE c.country = 'USA'; (b) SELECT c.country, (SELECT SUM(p2.price) FROM Product p2 JOIN Company c2 ON c2.cname = p2.maker WHERE c2.country = c.country) AS all_products, SUM(p.price) AS sold_value FROM Purchase pu JOIN Product p ON p.pname = pu.stock JOIN Company c ON c.cname = p.maker GROUP BY c.country;

Q13 Actor(actor_id, name, age), Play(play_id, writer), Role(play_id, actor_id): (i) number of actors who acted in 3 or more plays by Shakespeare; (ii) actors in a Chekhov play but never in a Shakespeare play.Petrobangla ANE suggestion sheet (no dated paper)
(i) SELECT COUNT(*) FROM (SELECT r.actor_id FROM Role r JOIN Play p ON p.play_id = r.play_id WHERE p.writer = 'Shakespeare' GROUP BY r.actor_id HAVING COUNT(DISTINCT r.play_id) >= 3) t; (ii) SELECT name FROM Actor WHERE actor_id IN (… WHERE p.writer = 'Chekhov') AND actor_id NOT IN (… WHERE p.writer = 'Shakespeare');
Memory trick "in A but never B" = IN … AND NOT IN … (or EXCEPT). "at least n" = GROUP BY + HAVING COUNT ≥ n.

Q20 Employee(emp_id, emp_name, dept_id, salary), Department(dept_id, dept_name, increment_dept): create a trigger that increases an employee's salary by 10 % when it is above 30000.PGCB AE(CSE) 2021
CREATE TRIGGER raise_salary BEFORE INSERT ON Employee FOR EACH ROW BEGIN IF NEW.salary > 30000 THEN SET NEW.salary = NEW.salary * 1.10; END IF; END; -- MySQL syntax

Insert 25000 → stays 25000
Insert 40000 → stored 44000

A trigger runs automatically on INSERT / UPDATE / DELETE; a view is a stored SELECT (a virtual table, no own data unless materialized).

Q21 While converting an E-R diagram into tables, how is a many-to-many relationship set between entities A and B converted?BPSC SAE 2021

Answer: tables A(a_id, …), B(b_id, …) and a third table R(a_id, b_id, attributes of R); a_id → A, b_id → B, and (a_id, b_id) together is the primary key. One extra column in A or B cannot hold "many" values.

Q22 What is a weak entity? Find a weak entity and its identifying relationship for a school database: Student(student_id, student_name, admission_year), Teacher(…), Course(course_id, subject_name, credit).BCC AP 2021

A weak entity has no key of its own; it is identified only through an owner entity. Here none of the three is weak (each has its own id). Add one: Guardian(name, relation), owned by Student through the identifying relationship HAS_GUARDIAN; its PK = (student_id, name).

★Night before the exam

  1. Write order: SELECT FROM WHERE GROUP BY HAVING ORDER BY
  2. Run order: FROM → WHERE → GROUP → HAVING → SELECT → ORDER
  3. Aggregate in WHERE ✗ → use a subquery or HAVING
  4. "compare with average" → > (SELECT AVG…)
  5. "manager / same table" → self-join e, m
  6. "at least n" → HAVING COUNT ≥ n
  1. "in A, never B" → IN … AND NOT IN …
  2. Nth highest → DISTINCT … LIMIT 1 OFFSET N-1
  3. COUNT(*) counts NULL rows, COUNT(col) doesn't
  4. M:N → new table with composite PK
  5. Candidate key = minimal super key
  6. ACID: undo log, constraints, locks, redo log
