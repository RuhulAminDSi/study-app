1Aggregation: GROUP BY + HAVING

asked 9×
Q3 Employee(empno, empname, monthlysalary, deptno FK, mgrno FK), Department(deptno, deptname, deptlocation), Course(crscode, crsdesc, crscategory, crsduration), Offering(offbegindate, crscode FK, offeringlocation, empno FK). (a) Display departments that have an average monthly salary greater than 1000. (b) Retrieve course details for courses that contain exactly 2 course offerings. · Petrobangla Assistant Manager (CSE) · 31.05.2024; also BOGMC (Petrobangla) AM 2024, where (b) reads "more than two offerings"
-- (a) SELECT d.deptno, d.deptname, AVG(e.monthlysalary) AS avg_sal FROM Department d JOIN Employee e ON e.deptno = d.deptno GROUP BY d.deptno, d.deptname HAVING AVG(e.monthlysalary) > 1000;
-- (b) SELECT c.* FROM Course c WHERE c.crscode IN ( SELECT crscode FROM Offering GROUP BY crscode HAVING COUNT(*) = 2 );
Exam trap The condition is on an aggregate, so it goes in HAVING; WHERE AVG(…) > 1000 is an error because WHERE runs before grouping. "Course details" means the Course columns, not just crscode, COUNT(*). For "more than two": HAVING COUNT(*) > 2.
Q11 Write an SQL query to find the department name and average salary of employees by joining the Department and Employee tables. · Islamic Bank PLC SQA, Senior Officer (Network) · 14.03.2025
-- Department(dept_id PK, dept_name) -- Employee(emp_id PK, name, salary, dept_id FK) SELECT d.dept_name, AVG(e.salary) AS avg_salary FROM Department d JOIN Employee e ON e.dept_id = d.dept_id GROUP BY d.dept_id, d.dept_name;

Every non-aggregated SELECT column must be in GROUP BY. Grouping by dept_id too keeps two departments with the same name apart. LEFT JOIN would also list departments with no staff (AVG = NULL).

Q2 Given the Student and Course tables: (a) find student information; (b) find the courses and the number of students where enrollment is less than or equal to 30. · ICB Securities Trading Co. Ltd, Assistant Programmer · 27.06.2026
-- Course(course_id PK, course_name, credit) -- Student(student_id PK, name, email, course_id FK) SELECT * FROM Student; -- (a) SELECT c.course_id, c.course_name, -- (b) COUNT(s.student_id) AS students FROM Course c LEFT JOIN Student s ON s.course_id = c.course_id GROUP BY c.course_id, c.course_name HAVING COUNT(s.student_id) <= 30;
Exam trap The tables were not printed: state your schema. With LEFT JOIN count COUNT(s.student_id); an empty course gives one NULL row, which COUNT(*) would count as 1.

Q5 CREATE TABLE t(val INT); INSERT INTO t(val) VALUES (1),(2),(3),(NULL),(NULL),(4),(5); What will SELECT COUNT(*) FROM t; and SELECT COUNT(DISTINCT val) FROM t; return? · asked in a recruitment paper
ExpressionResultWhy
COUNT(*)7counts rows, NULL too
COUNT(DISTINCT val)51 … 5; NULL skipped
COUNT(val) · AVG(val)5 · 3AVG = 15 / 5
Exam trap 6 is a common wrong answer for COUNT(*). Every aggregate except COUNT(*) ignores NULL. (The paper spells "Distint": write DISTINCT.)
Q5 Write an SQL query to insert a tuple in the table Employee(ID, Name, Designation, Salary). · asked in a recruitment paper
INSERT INTO Employee (ID, Name, Designation, Salary) VALUES (101, 'Rahim Uddin', 'Officer', 22000);

Q4 Define SQL. Write an SQL query to find duplicates in the employee table. · asked in a recruitment paper

SQL (Structured Query Language): the standard declarative language of relational databases: DDL (CREATE, ALTER, DROP), DML (SELECT, INSERT, UPDATE, DELETE), DCL (GRANT, REVOKE), TCL (COMMIT, ROLLBACK). Assume Employee(emp_id PK, name, email, …); a duplicate = same name + email under different emp_ids.

-- which values repeat SELECT name, email, COUNT(*) AS copies FROM Employee GROUP BY name, email HAVING COUNT(*) > 1;
-- the full duplicate rows SELECT e.* FROM Employee e JOIN (SELECT name, email FROM Employee GROUP BY name, email HAVING COUNT(*) > 1) d ON d.name = e.name AND d.email = e.email;
Q3 Write a SQL query to get the second highest salary from the Employee table. · BCC Assistant Programmer Written Test · 2017
-- 1. standard, works everywhere SELECT MAX(salary) AS second_highest FROM Employee WHERE salary < (SELECT MAX(salary) FROM Employee); -- 2. MySQL / PostgreSQL SELECT DISTINCT salary FROM Employee ORDER BY salary DESC LIMIT 1 OFFSET 1; -- 3. window function (N-th highest: rnk = N) SELECT DISTINCT salary FROM (SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk FROM Employee) t WHERE rnk = 2;
Exam trap "ORDER BY salary DESC LIMIT 2, then take the smaller" fails on ties: 90k, 90k, 70k gives 90k. Use DISTINCT or DENSE_RANK. Method 1 returns NULL when no second salary exists, which is correct.
Memory trick "Second highest = the highest below the highest." Change the inner MAX to a nested one for the third.

3Nested Subqueries and Self-Join

Q10 EMPLOYEE(id, name, department, salary): write an SQL query to find employees who work in a department where the average salary is lower than the average salary of all departments. · BPDB Assistant Engineer (CSE) (BUET) · 24.02.2023
SELECT e.id, e.name, e.department, e.salary FROM Employee e WHERE e.department IN ( SELECT department FROM Employee GROUP BY department HAVING AVG(salary) < (SELECT AVG(salary) FROM Employee));
Exam trap Do not add AND e.salary < (SELECT AVG(salary) …): the question filters departments, so a well-paid person in a low-paid department still qualifies. If "average of all departments" means the average of department averages, use (SELECT AVG(a) FROM (SELECT AVG(salary) AS a FROM Employee GROUP BY department) t) and say so.
Q3(ii) Schema employee(id, name, salary), equipment(id, name, price), hire(employee_id, equipment_id). Write the SQL query to show the name of the employee who borrowed the maximum equipment. · BAPEX Assistant General Manager (ICT) (BUET) · 20.01.2023
SELECT e.name FROM employee e JOIN hire h ON h.employee_id = e.id GROUP BY e.id, e.name HAVING COUNT(*) >= ALL (SELECT COUNT(*) FROM hire GROUP BY employee_id);
Exam trap Group hire by employee_id; grouping by equipment_id finds the most-hired equipment, a different question. ≥ ALL keeps ties.

Shorter (MySQL 8 / PostgreSQL) but drops ties: … GROUP BY e.id, e.name ORDER BY COUNT(*) DESC LIMIT 1;

Q5 Given the database schema, write an SQL query to find the employees whose manager belongs to the same region as the employee. · DPDC Assistant Manager (ICT) · 27.06.2025
-- Employee(emp_id PK, name, region, -- manager_id FK → Employee(emp_id)) SELECT e.emp_id, e.name, e.region FROM Employee e JOIN Employee m ON e.manager_id = m.emp_id WHERE e.region = m.region;
Memory trick A self-join = "photocopy the table": give it two aliases (e, m) and join the FK of one copy to the PK of the other.

4Trigger: Raise Salary by 10%

asked 4× incl. viva
Q1 'Employee' (emp_id, emp_name, dept_id, salary) and 'Department' (dept_id, dept_name, increment_dept). Create a trigger to increment the salary of the employee by 10% whose salary is above 30000. · PGCB Assistant Engineer (CSE) (BUET) · 30.09.2021
-- MySQL DELIMITER // CREATE TRIGGER trg_raise_salary BEFORE INSERT ON Employee FOR EACH ROW BEGIN IF NEW.salary > 30000 THEN SET NEW.salary = NEW.salary * 1.10; END IF; END// DELIMITER ;

Fires once per new row and changes NEW (the incoming row) before it is stored. Oracle: … FOR EACH ROW WHEN (NEW.salary > 30000) BEGIN :NEW.salary := :NEW.salary * 1.10; END;

Exam trap "ALTER INSERT" is not a timing: only BEFORE / AFTER (INSTEAD OF on views). MySQL forbids a row trigger from UPDATE-ing its own table: set NEW. For staff already stored use UPDATE Employee SET salary = salary * 1.10 WHERE salary > 30000;

Viva (bank IT): a trigger is a stored program that runs automatically on INSERT, UPDATE or DELETE; used for audit trails, logs, business rules, integrity and alerts (e.g. copy every change of account into account_audit).

Q8 Πs.name, s.id(σd.name='ECE'(Student s ⋈s.dept_id = d.dept_id Department d)): write the equivalent SQL query. · BUET MSc in CSE · 03.10.2026

Q12 You are designing a database for a library. Explain the relationship between a "Book" table and a "borrower" table. Is it 1-to-1, 1-to-many or many-to-many? Justify your answer. · Bank Assistant Programmer Written (bank name not shown) · 10 marks

Many-to-many. Over time one borrower borrows many books and one book is borrowed by many borrowers. Neither table can hold the other's key as one FK, so add an associative table Loan(loan_id, book_id FK, borrower_id FK, issue_date, due_date, return_date); the dates belong to the relationship.

Exam trap At one moment a physical copy is with one borrower (1 : N). State your view; the full history is M : N.

8Weak Entity and Keys

13 viva + MCQ
Q7 What is a weak entity for data modelling using the ER model? Find any weak entity and its identifying relationship for the school database: Student(student_id, student_name, admission_year), Teacher(teacher_id, teacher_name, teacher_join_date), Course(course_id, subject_name, credit). · asked in a recruitment paper

A weak entity has no key of its own; it is identified by its owner's key + its partial key through an identifying relationship, with total participation. None of the three tables is weak (each has its own key). A weak one: Section of a Course (section 1, 2 … repeat in each course): Section(course_id FK, section_no, room), relationship offers, ON DELETE CASCADE.

KeyMeaning (Student example)
Superany unique attribute set: {id}, {id, name}, {nid}
Candidateminimal super key: {id}, {nid}, {email}
Primarychosen candidate: unique + NOT NULL, one per table
Alternatethe candidates not chosen: nid, email
Composite≥ 2 attributes: (manufacturer_id, product_id)
Foreignrefers to a PK elsewhere; may repeat or be NULL
Exam trap "A super key does not identify a row" and "a candidate key need not be unique" are both wrong: both are unique; the difference is minimality. A composite key does not make an entity weak. No NID? Use another candidate key (birth registration or passport no.); name + date of birth is not guaranteed unique.

PK vs FK (viva): the PK identifies rows of its own table; an FK in another table refers to it and enforces referential integrity (no loan for a missing borrower).

9Normalization

viva

Normalization = decomposing tables, guided by functional dependencies, to remove redundancy and insert / update / delete anomalies, losslessly. Why: no duplicate data, consistent updates, less storage, easier maintenance. Cost: more joins.

NFRule
1NFatomic values, no repeating groups
2NFno partial dependency on part of a key
3NFno transitive dependency
BCNFevery determinant is a super key
4NF · 5NFno multivalued · join dependency
Memory trick Every non-key attribute depends on "the key (1NF), the whole key (2NF), and nothing but the key (3NF)".

10Transactions: ACID, ROLLBACK, 2PL

viva + MCQ
MeansEnsured by
Atomicityall or nothingundo log
Consistencyvalid → validconstraints

Durabilitycommit is permanentredo log, WAL
START TRANSACTION; UPDATE account SET balance = balance - 5000 WHERE acc_no = 'A'; UPDATE account SET balance = balance + 5000 WHERE acc_no = 'B'; COMMIT; -- on any error: ROLLBACK;

ROLLBACK (BPSC viva) undoes every change of the current transaction (or back to a SAVEPOINT); COMMIT makes them permanent. 2PL: growing phase, then shrinking phase → conflict-serializable, deadlock still possible. Strict 2PL holds exclusive (write) locks till commit/abort → no cascading rollback; rigorous 2PL holds all locks.

11How Indexing Speeds Up Queries

Q4 How does indexing improve database query performance? · Bangladesh Satellite Company PLC, Assistant Engineer (CSE) · 23.08.2025

An index is a separate sorted structure (usually a B+ tree) from key values to row addresses. Without it, WHERE dept_id = 10 needs a full table scan, O(n). With it the DBMS walks root → leaf in a few reads, O(log n). Example: 1,000,000 rows, 100 per block: scan = 10,000 block reads; B+ tree (fan-out ≈ 200) = 3 index reads + 1 data block.

It also speeds ORDER BY, joins (index the FK), MIN/MAX and covering queries. Clustered = rows stored in key order (one per table); non-clustered = many. Hash: equality only. Bitmap: low-cardinality columns. Cost: storage and slower INSERT/UPDATE/DELETE, so index selective WHERE/JOIN columns: CREATE INDEX idx_emp_dept ON Employee(dept_id);

12Database Security

asked 5×
Q9(c) What is database security? Describe different approaches to ensure database security. · 38th BCS Written · 2018

Database security protects data, DBMS software, hardware and people against intentional or accidental threats to confidentiality, integrity and availability (CIA).

  • Authentication: strong passwords, MFA
  • Access control: DAC (GRANT/REVOKE), MAC, RBAC, least privilege
  • Views: expose only allowed rows / columns
  • Encryption: at rest (TDE), in transit (TLS)
  • Auditing, monitoring: audit trail, alerts
  • Backup + DR site: availability
  • Integrity: constraints; prepared statements vs SQL injection
  • Patching, segmentation, physical security, masking
GRANT SELECT, UPDATE ON account TO teller; REVOKE UPDATE ON account FROM teller;

Viva rapid-fire (BPSC · NTRCA · bank IT)

  • Data: raw facts; information: processed data. Database: organised collection of related data; DBMS: the software managing it.
  • Schema: logical structure (tables, columns, types, constraints); instance: data at a moment. Tuple: one row (Python: immutable sequence).
  • SQL = Structured Query Language. Clauses: SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY (+ JOIN, LIMIT). WHERE holds the row condition.
  • JOIN: INNER, LEFT, RIGHT, FULL OUTER, CROSS (+ self, natural).
  • View: virtual table, stores the query. Materialized view: stores the result; fast, needs refresh.
  • SQL injection: input becomes SQL text (' OR '1'='1); stop it with prepared statements, validation, least privilege.
  • DBA: install, secure, back up, tune, monitor. Assistant DBA: monitoring, backups, users; risks: data loss, wrong grants, accidental DROP, downtime.
  • Branch user: permitted business operations only; DBA: full admin rights. Oracle RAC: many servers, one database → HA, scale-out.
  • Bank DB crash: isolate → fail over to DR / standby → restore backup + apply archived logs → verify, reconcile.
  • PHP–MySQL: new PDO("mysql:host=…;dbname=bank", $u, $p) or mysqli_connect().
