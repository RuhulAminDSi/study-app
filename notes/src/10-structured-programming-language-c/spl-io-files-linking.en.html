1Standard Streams & Formatted Output (printf)

basics ★
Definition A stream is C's uniform view of any source or destination of bytes — keyboard, screen, file, pipe — reached through a FILE *. Every hosted C program starts with three streams already open, declared in <stdio.h>: stdin (keyboard), stdout (screen; line-buffered on a terminal, fully buffered into a file) and stderr (screen, unbuffered — shows at once).
Exam trap (i) stderr is not a log file: it goes to the screen too, but prog > out.txt redirects only stdout, so errors still show. (ii) Text left in the stdout buffer is lost if the program crashes — fflush(stdout) forces it out.

Anatomy: % [flags] [width] [.precision] [length] letter

- left-justify · + show the sign · 0 pad with zeros · # 0x for %x, 0 for %o

printf returns the number of characters printed (negative on error): printf("%d", printf("Hello")) prints Hello5.

Worked example ✍ predict the output (_ = a space) "%5d|", 42 → ___42| · "%-5d|", 42 → 42___| · "%05d", 42 → 00042 · "%+d", 42 → +42 · "%.2f", 3.14159 → 3.14 · "%8.3f|", 3.14159 → ___3.142| · "%#x %X %o", 255 ×3 → 0xff FF 377 · "%.3s", "Bangladesh" → Ban · "%2d", 12345 → 12345.
Exam trap (i) In printf, %f serves float and double — a float is promoted to double; the split matters only in scanf. (ii) printf("%d", 3.5) is undefined. (iii) strlen returns size_t: print it with %zu, not %d or %lu.
Memory trick "Flags, Width, Dot, Length, Letter" — always in that order. "Minus moves left, zero fills, plus shows."

2Formatted Input (scanf) & Character / Line I/O

trap-heavy ★
Definition scanf reads characters from stdin, converts them according to the format and stores each result through a pointer — so every non-array argument needs &. It returns the number of items assigned, or EOF if input fails before the first conversion. %d, %f and %s skip leading white space; %c does not.
TypeprintfscanfWhy they differ
float%f%fgets a float * — 4 bytes
double%f (also %lf since C99)%lfa double *: 8 bytes; %f fills only 4

short / long%hd / %ld%hd / %ldsize must match the pointer
char%c%c, or " %c"the space skips the leftover '\n'
string%s%s with no &an array name is an address; stops at a space
FunctionDoes
getchar() / putchar(c)one character in / out; getchar returns an int so EOF fits

Worked example ✍ what does scanf return? int a = 0, b = 0, r = scanf("%d %d", &a, &b); (a) input 10 20 → r = 2, a = 10, b = 20. (b) input 10 abc → r = 1, b stays 0 and "abc" stays in the buffer for the next read. (c) input abc → r = 0. (d) end of input (Ctrl+Z / Ctrl+D) → r = EOF. Safe loop: while (scanf("%d", &x) == 1) sum += x;
Three scanf tools worth knowing

%9s — width limit: at most 9 chars into char s[10]

%[^\n] — scanset: a whole line, spaces included

%*d — read and discard; not counted in the return

Exam trap (i) scanf("%d", x) without & passes a value as an address — undefined behaviour, usually a crash. (ii) char c = getchar(); can never equal EOF where char is unsigned — keep it int. (iii) fflush(stdin) is undefined in standard C. (iv) %s reads one word only.
Memory trick "printf takes values, scanf takes addresses." And "lf = long float = double": in scanf the l is the only thing standing between a float and a double.

3File Access: FILE *, fopen Modes, Text vs Binary

most tested ★
Definition A file is used through a pointer to a FILE structure (declared in <stdio.h>) that holds the buffer, the current position and the end-of-file and error flags. Every file job has three steps: open with fopen(name, mode), which returns NULL on failure; process; close with fclose(fp), which flushes the buffer and returns 0 (or EOF on failure).

Add b for binary: "rb", "wb", "ab", "r+b" (= "rb+"), "w+b", "a+b". C11 adds x ("wx"): fail instead of overwriting. Note printf(…) ≡ fprintf(stdout, …).

/* copy in.txt to out.txt */ FILE *in = fopen("in.txt", "r"); FILE *out = fopen("out.txt", "w"); if (in == NULL || out == NULL) { perror("fopen"); return 1; } int c; /* int, not char */ while ((c = fgetc(in)) != EOF) fputc(c, out); fclose(in); fclose(out);
Text vs binary In text mode the library may translate line ends — on Windows '\n' is written as "\r\n" and read back as '\n'. Binary mode moves bytes exactly. On Linux/UNIX the two modes are identical. fprintf(fp, "%d", 12345) writes 5 characters; fwrite(&n, sizeof n, 1, fp) writes sizeof(int) bytes (4 on most systems).
Exam trap (i) "w" destroys the old contents; use "a" to keep them. (ii) "r+" never creates a file. (iii) fopen signals failure with NULL, not EOF or −1. (iv) Forgetting fclose can lose buffered data. (v) In "a"/"a+" a write lands at the end even after fseek.
Memory trick "r reads, w wipes, a adds — and + gives the other half." "b means bytes." Only the two r-modes fail on a missing file; every w- and a-mode creates it.

4Random Access: fseek, ftell, rewind & the EOF Rules

arithmetic ★
Definition Every open stream has a file position indicator — the byte offset where the next read or write happens. Sequential I/O moves it forward by itself; random access moves it directly with fseek(fp, offset, whence), so record k of a binary file can be read without reading the k − 1 before it.
CallEffect · return
fseek(fp, off, whence)move to origin + off · 0 on success
ftell(fp)current offset as long · −1L on error
rewind(fp)back to 0 and clears the error flag · void
feof(fp)non-zero once a read has already hit the end
ferror(fp) / clearerr(fp)error flag set? / reset both flags
fflush(fp)write an output buffer out now
remove(n) / rename(o, n)delete / rename a file · 0 on success
Worked example ✍ a binary file of student records struct student { int roll; char name[16]; float cgpa; }; — 4 + 16 + 4 = 24 bytes (no padding needed here; padding rules are in the structures lesson). (a) File size: fseek(fp, 0, SEEK_END); long n = ftell(fp); → n = 240 ⇒ 240 ÷ 24 = 10 records. (b) Read the 5th record (k = 4): fseek(fp, 4 * sizeof(struct student), SEEK_SET) → byte 96, then fread(&s, sizeof s, 1, fp) returns 1. (c) Now ftell(fp) = 96 + 24 = 120. (d) Update it in place: open with "rb+", fseek(fp, -24L, SEEK_CUR), then fwrite(&s, sizeof s, 1, fp). (e) The last record: fseek(fp, -24L, SEEK_END) → byte 216.
/* WRONG: the last line prints twice */ while (!feof(fp)) { fgets(line, 80, fp); fputs(line, stdout); } /* RIGHT: test the read itself */ while (fgets(line, sizeof line, fp) != NULL) fputs(line, stdout);
EOF is a value, not a byte EOF is a macro in <stdio.h> for a negative int (usually −1) that input functions return when nothing is left. No EOF character is stored in the file; a file simply ends. That is why fgetc returns int: it must fit all 256 byte values and EOF.
Exam trap (i) feof() does not look ahead: it turns true only after a read has failed, so a while (!feof(fp)) loop runs once too often. (ii) Byte arithmetic with ftell needs binary mode. (iii) Between a write and a read, call fseek or fflush.
Memory trick "SET, CUR, END = 0, 1, 2 — start, here, end." And "read first, then ask": test the value fgetc/fgets/fread returned; ask feof() only to learn why it stopped.

5Variable-Length Argument Lists (stdarg.h)

written favourite ★
Definition A variadic function takes a variable number of arguments, declared with an ellipsis ... after at least one named parameter: int printf(const char *fmt, ...);. The macros of <stdarg.h> walk the unnamed arguments one by one; the function itself has no way to know how many arrived.
#include <stdarg.h> int sum(int count, ...) { va_list ap; int total = 0; va_start(ap, count); for (int i = 0; i < count; i++) total += va_arg(ap, int); va_end(ap); return total; } sum(4, 10, 20, 30, 40) → 100 sum(2, 5, 15) → 20
Macro / typeJob
va_list apthe cursor over the arguments
va_start(ap, last)start after the last named parameter
va_arg(ap, T)fetch the next one as type T
va_copy(d, s)duplicate the cursor (C99)
va_end(ap)clean up — one per va_start
Exam trap Unnamed arguments undergo the default promotions: char, short → int; float → double. So va_arg(ap, float) and va_arg(ap, char) are undefined — ask for double / int. Reading past the last argument is also undefined.
How the callee learns the count a count argument (sum above) · a sentinel at the end (NULL, −1) · a format string — printf counts the % signs. Get the count wrong and va_arg reads garbage.

6Command-Line Parameters (argc, argv)

most tested ★
Definition int main(int argc, char *argv[]) (or char **argv) receives the words typed after the command. argc = how many words, the program name included; argv[0] = the program name; argv[1] … argv[argc − 1] = the arguments, always as strings; and argv[argc] = NULL.
Worked example ✍ $ ./sum 10 20 30 argc = 4; argv[1] is the string "10", so the sum needs a conversion: for (i = 1; i < argc; i++) s += atoi(argv[i]); → 60. (b) $ ./prog "hello world" → argc = 2: the shell's quotes make one argument. (c) $ ./prog alone → argc = 1, argv[1] = NULL: test argc < 2 first. (d) atoi("12ab") silently gives 12 — strtol can report errors.
Exam trap (i) argc is never 0 in practice — the name counts. (ii) argv[1] + argv[2] adds pointers, not numbers. (iii) The names argc/argv are only convention; the types are what the standard fixes.
Memory trick "argc counts the name; argv ends in NULL." For stdarg: "start, arg, arg, …, end" — and "small things grow": char → int, float → double.

7Error Handling: Return Values, errno, perror, assert, exit

high-yield ★
Definition C has no exceptions. A library function reports failure through its return value and, for many, by storing a code in errno; the program must check, report on stderr, and end with a failure exit status. Nothing happens automatically if the check is skipped.
CallFailure looks like
fopen, malloc, calloc, fgetsNULL
scanf, fscanffewer items than asked, or EOF
fgetc, getchar, fclose, fputsEOF
printf, fprintfa negative value
fseek / ftellnon-zero / −1L
fread, fwritefewer than n items
sqrt(−1) · strtol overflowerrno = EDOM · ERANGE
#include <stdio.h> #include <stdlib.h> #include <errno.h> #include <string.h> FILE *fp = fopen("data.txt", "r"); if (fp == NULL) { perror("data.txt"); fprintf(stderr, "code %d: %s\n", errno, strerror(errno)); exit(EXIT_FAILURE); }
errno · perror · strerror errno (<errno.h>) is set to a positive code by a failing call and never reset to 0 by the library. ISO C defines only EDOM, ERANGE, EILSEQ; ENOENT etc. are POSIX. perror("data.txt") prints data.txt: No such file or directory to stderr; strerror(errno) (<string.h>) returns that text.
assert, exit, abort — how a program ends

assert(expr): if false, prints expression, file, line to stderr, then abort()

#define NDEBUG before <assert.h> ⇒ every assert disappears

exit(status): flushes and closes streams, runs atexit() handlers

return n; in main ≡ exit(n) · EXIT_SUCCESS 0 · EXIT_FAILURE ≠ 0

abort(): abnormal end, no atexit handlers. The shell reads the status as $? / %ERRORLEVEL%.

Worked example ✍ division by zero Integer a / b with b = 0 is undefined behaviour — no return code, no errno, usually a crash — so test first: if (b == 0) { fputs("divide by zero\n", stderr); return EXIT_FAILURE; }. (IEEE 754 floats give 1.0 / 0.0 = inf.)
Exam trap (i) errno is meaningful only right after a call that failed. (ii) assert is not input validation — it vanishes in a release build. (iii) Report errors on stderr, not stdout. (iv) 0 = success, non-zero = failure — not the reverse.
Memory trick "Check, tell, leave." Check the return value, tell stderr (perror), leave with EXIT_FAILURE. "Assert for bugs, if for users."

8Graphics in C (graphics.h, Turbo C)

MCQ ★
Definition graphics.h is Borland's BGI (Borland Graphics Interface) for Turbo C/C++ under DOS — not part of ISO C (gcc has no such header). The screen is a pixel grid with the origin (0, 0) at the top-left and y growing downward; in VGA high mode (640 × 480, 16 colours) getmaxx() = 639 and getmaxy() = 479.

Exam trap (i) getch() is in conio.h, not graphics.h — it just holds the picture until a key is pressed. (ii) rectangle takes two corners, not width and height. (iii) A larger y is lower.

MCQ ★

Memory trick "abs in stdlib, fabs in math." "Header declares, library defines" — only the linker brings the code.

10From Source to Executable: Compiling & Linking

written favourite ★
Definition Building a C program takes four stages, and the linker is the last: it combines object files and libraries into one executable by resolving symbols — matching every use of an external name with exactly one definition — and relocating addresses. The loader then places the executable in memory and starts it.
StageIn → outWhat it does · typical error
Preprocessor.c → .i#include, #define, #if; strips comments (preprocessor lesson) · missing header file
Compiler.i → .ssyntax and type checks, assembly code · missing semicolon, type mismatch
Assembler.s → .o / .objmachine code with unresolved external symbols
Linker ★.o + libs → exeresolves and relocates · undefined reference, multiple definition
AspectStatic linkingDynamic (shared) linking
Library file.a (Linux) · .lib (Windows).so (Linux) · .dll (Windows)
When boundat link time: only the needed object modules are copied inat load time by the dynamic linker (or run time: dlopen, LoadLibrary)
Size · memorylarger file; each program has its own copysmaller file; one copy shared in memory
Updating the libraryrelink every programreplace the .so/.dll once
Risknone at run time — self-containedmissing or wrong version ("DLL hell")
/* util.h */ extern int counter; int add(int a, int b); /* util.c */ int counter = 0; int add(int a, int b) { counter++; return a + b; } /* main.c */ #include "util.h" gcc -c main.c → main.o gcc -c util.c → util.o gcc main.o util.o -o prog gcc prog.c -o prog -lm (libm)
extern & linkage extern declares a name defined elsewhere; the definition must appear in exactly one file. static at file scope gives internal linkage: the name is invisible to the linker and to other files (storage classes lesson). -lm links libm, the maths library; put it after the source files.
Exam trap (i) <math.h> gives only prototypes; "undefined reference to sqrt" is a linker error cured by -lm. (ii) Static linking does not copy the whole library.
Memory trick "Please Compile And Link" — Preprocess, Compile, Assemble, Link; the flags -E -S -c stop after the first three. "Static = suitcase, dynamic = borrow on arrival."

Written question Write a C program that takes a file name on the command line, reads the integers in that file and prints their sum, handling every error properly. Explain argc/argv and each check you make. 10
  1. Arguments — int main(int argc, char *argv[]); argc counts the program name, so one file name means argc == 2, and argv[1] is the name. If argc != 2, print a usage line to stderr and return EXIT_FAILURE;. 2
  2. Open — FILE *fp = fopen(argv[1], "r"); and if (fp == NULL) { perror(argv[1]); return EXIT_FAILURE; } — perror adds the reason from errno, on stderr. 2
  3. Read — long sum = 0; int x; while (fscanf(fp, "%d", &x) == 1) sum += x; — the loop tests the return value (not feof), so it stops on end of file and on bad data; then if (ferror(fp)) report a read error. 3
  4. Finish — fclose(fp); printf("Sum = %ld\n", sum); return EXIT_SUCCESS; — status 0 tells the shell it worked. 1
  5. Explain — argv holds strings, argv[argc] is NULL; every library call is checked because C has no exceptions: NULL from fopen, the item count from fscanf, the flag from ferror. 2
