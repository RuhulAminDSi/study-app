1Uncertainty, the Rules of Probability & Bayes

foundation ★
Definition Probabilistic reasoning draws conclusions under uncertainty, using probability to say how far to believe each alternative. A random variable is a quantity not known until observed — discrete (Rain = yes/no) or continuous (a whole range). AI needs it because data are noisy and evidence partial.
ConceptDefinition
Random variableRain = yes or no
ProbabilityP(A) ∈ [0, 1]
JointP(A∧B), both together
ConditionalP(A|B)=P(A∧B)/P(B)
MarginalP(A) = ΣB P(A∧B)
IndependenceP(A∧B) = P(A)P(B)
The rules you must have on your fingertips Axioms (Kolmogorov 1933): 0 ≤ P(A) ≤ 1, P(Ω) = 1, P(A∪B) = P(A)+P(B) for disjoint A, B. Complement: P(A′) = 1 − P(A). Chain rule: P(A∧B) = P(A)P(B|A). Total probability: P(B) = Σᵢ P(B|hᵢ)P(hᵢ).
Bayes' theorem (1763) P(H|E) = P(E|H)·P(H)/P(E)
equivalently P(E|H)P(H) = P(H|E)P(E).
In odds form: posterior odds = prior odds × likelihood ratio. Bayes' essay appeared posthumously in 1763; Laplace (1813) gave it the first systematic use.
Exam trap The names are fixed: prior P(H) = before the evidence; likelihood P(E|H) = the evidence assuming H; evidence P(E) = the normaliser; posterior P(H|E) = after it.
Memory trick "Prior in, posterior out." Multiply the prior by the likelihood, then divide by the evidence; in odds form there is no division at all.
Worked example 1 ✍ the base-rate trap A disease hits 1 % of people; the test is 90 % sensitive and gives 10 % false positives. P(D|+) = (0.9 × 0.01)/[(0.9 × 0.01) + (0.1 × 0.99)] = 0.009/0.108 = 0.083. A very good test still leaves a small posterior when the prior is tiny — you must always divide by the evidence.
Worked example 2 ✍ the odds form Prior odds = 0.01/0.99 = 1/99; likelihood ratio = 0.9/0.1 = 9; posterior odds = 9/99 = 1/11, so P = (1/11)/(1 + 1/11) = 1/12 = 0.083 ✓ — the same answer with no division. Reach for odds whenever the fractions get ugly.

2Naive Bayes Classification

most tested ★
Definition A naive Bayes classifier picks the class C that maximises the posterior, using one conditional probability per feature. The normaliser P(x) is the same for every class, so it drops out: Ĉ = argmaxC P(C)·P(x₁|C)·P(x₂|C)···P(xₙ|C)
PieceMeaning
P(C)prior — class frequency
P(xᵢ|C)likelihood of xᵢ inside C
∏ᵢ P(xᵢ|C)the naive step
argmaxhighest-scoring class
Three flavours Multinomial (word counts): P(w|C) = count(w,C)/Σ count(·,C)
Bernoulli (word present / absent)
Gaussian (real features): P(xᵢ|C) = 𝒩(xᵢ; μ, σ²)
Exam trap "Naive" does not mean equal priors, uniform features or linear separability — only that P(x₁,…,xₙ|C) = ∏ᵢ P(xᵢ|C). Score in log space: thousands of small numbers underflow to zero.
Worked example ✍ scoring one mail 100 spam and 200 ham mails. Spam holds 2 000 words (offer 40, free 60, money 30); ham holds 1 200 words (offer 5, free 10, money 8). spam = (1/3)(40/2000)(60/2000)(30/2000) = 3.0 × 10⁻⁶ · ham = (2/3)(5/1200)(10/1200)(8/1200) = 1.54 × 10⁻⁷ · ratio 19.4, so P(spam) = 95.1 %.
Memory trick "Multiply the per-feature probabilities, then add the prior once." Log space is what stops 10 000 features from underflowing.
The zero-frequency problem A word never seen in class C gets P(w|C) = 0, and one zero kills the product. Fix it with add-one smoothing: (count+1)/(total+|V|) — 0 hits in 1 200 words with |V| = 5 000 gives 1/6200.
Laplace's rule of succession After 10 heads the next is predicted with (10+1)/(10+2) = 11/12 = 0.917 — never let a count of zero become a probability of zero.
Over-smoothing, and where NB is used Flattening the model destroys rare-word signal too. For imbalanced text use complement naive Bayes or Bernoulli. MNB is linear in the features, so it trains in one pass — which is why it survives in spam filters.
Everyday jobs Spam filtering · sentiment analysis · named-entity recognition · news categorisation · e-mail triage · review rating · medical coding from text. "Naive" only ever means conditional independence given the class — never equal priors, never uniform features.

3Bayesian Networks: DAG, CPT, Factorisation

high-yield ★
Definition A Bayesian network (belief network) is a directed acyclic graph whose nodes are random variables and whose arcs X → Y say "X is a direct cause of Y". Each node carries a CPT (conditional probability table) P(node | its parents), and a parentless node holds a marginal. The whole joint is written P(x₁,…,xₙ) = ∏ᵢ P(xᵢ | Pa(xᵢ)) — n small tables instead of one with 2ⁿ cells.
The graph saysRule
Root nodestores the marginal P(X)
Child nodestores P(child | parents)
Local Markovindep. of non-descendants given parents
d-separationblocked path ⇒ independent
Why a DAGa cycle has no topological order
CPT of WetGrass — one row per parent assignmentP(W = yes | Rain, Sprinkler on)P(W = yes | Rain, off)P(W = yes | no Rain, on)P(W = yes | no Rain, off)
probability0.900.800.400.10
Worked example ✍ marginalise, then condition With P(Rain) = 0.30, P(S=on|Rain) = 0.10 and P(S=on|¬Rain) = 0.50: P(W=yes) = Σr,s P(r)P(s|r)P(W|r,s) = 0.30[0.10(0.90)+0.90(0.80)] + 0.70[0.50(0.40)+0.50(0.10)] = 0.30(0.86) + 0.70(0.25) = 0.418. · P(Rain|yes) = 0.243/0.418 = 0.581 — wet grass nearly triples the prior. P(Sprinkler|yes) = 0.167/0.418 = 0.399.
Memory trick "A BN stores one row per parent assignment, never the whole table." The factorisation is the chain rule plus a Markov assumption at every node: multiply the factors, then Σ over whatever you have not fixed.
Exam trap (i) A BN is a DAG: a cycle makes a variable its own ancestor, so no topological order and no valid CPT exist. (ii) Arcs mean direct dependence, not proven causation. (iii) Two colliders A → C ← B are marginally independent but become dependent once C is observed.
Learning the parameters MLE: choose θ maximising P(data | θ) — for a Bernoulli, p̂ = 7/20 = 0.35. EM: alternate an E-step (expected hidden labels) with an M-step (re-fit θ); the likelihood never decreases. EM trains mixture models and HMMs.
Three ways to answer a query Enumeration — multiply the CPTs, then Σ over every hidden variable; fine up to about ten variables.
Variable elimination — the same sum, one variable at a time (next sheet).
Sampling — importance sampling or MCMC when the treewidth is hopeless.

AI · Probabilistic Reasoning & NLPInference & evidence

4Inference: Variable Elimination, noisy-OR, D-S

written ★
Definition Exact inference in a BN sums over every assignment of the hidden variables — fine for three variables, hopeless for three hundred. Variable elimination does the same sum one variable at a time: multiply the factors that contain a variable, then Σ it out. The cost is the size of the largest intermediate factor, roughly the treewidth + 1 variables, so the elimination order is the thing you actually choose.
Worked example ✍ eliminate Rain first f₁ = P(R), f₂ = P(S|R), f₃ = P(W|R,S). Multiply f₁ and f₂ (both contain R), then ΣR P(R)P(S|R) = P(S) = 0.30(0.10) + 0.70(0.50) = 0.38. The factor now mentions only S, so the next product is tiny. Eliminate Rain last instead and you keep a factor on (R, S, W) — same answer, far more work.
noisy-OR — the compact cause model For a symptom with several independent causes, any one of them is enough: P(Y|X₁…Xₙ) = 1 − ∏ᵢ (1 − P(Y|Xᵢ = 1, others 0)).
0.4 and 0.3 and 0.2 give 1 − 0.6·0.7·0.8 = 0.664, never the naive sum 0.9. It needs only n parameters instead of 2ⁿ.
Dempster–Shafer — evidence that admits ignorance Mass m(A) is belief assigned to a focal element, a set rather than a point. Under the closed-world assumption m(∅) = 0, and every probability is bracketed: Bel(A) = ΣB⊆A m(B) ≤ P(A) ≤ ΣB∩A≠∅ m(B) = Pl(A). Dempster's rule combines two sources and normalises by the conflict k = ΣB∩C=∅ m₁(B)m₂(C).
Exam trap Bayes assumes one true value whose probabilities sum to 1; D-S admits ignorance, so it can only bracket a probability. Bel ≤ Pl, never the reverse. Two sensors both giving 0.6 on {s} and 0.4 on {s, f} combine to Bel(s) = 0.84 and Pl(s) = 1.00.
Memory trick Three ways to combine evidence, three shapes: Σ = sum a variable out (elimination), ∏(1−p) = noisy-OR, m(∅) = 0 plus a bracket = Dempster–Shafer. In every case: multiply first, normalise afterwards.
IT link Variable elimination is literally a join order in a database: a chain of β-joins. Multiplying factors = joining relations; summing a variable = projecting a column away. "Smallest scope first" is exactly the rule a query planner uses.

5Markov Chains & Hidden Markov Models

classic ★
Definition A Markov chain is a discrete-time process in which the next state depends on the present state alone: P(Xt+1|Xt,…,X₀) = P(Xt+1|Xt). The probabilities sit in a transition matrix A whose rows all sum to 1; after k steps the distribution is πAk. An HMM adds an unobservable state — you see only noisy observations emitted by the states.
The HMM 5-tupleWhat it is
S = {s₁…sN}hidden states
O = {o₁…oM}observation symbols
A = [aij]transition matrix
B = [bj(o)]emission probs
πinitial distribution
WeatherSunCloudRain
Sun0.50.30.2
Cloud0.20.40.4
Rain0.40.40.2
Three classical problems Evaluation — how likely is this string? P(O) = Σ over all paths.
Decoding — which hidden path explains it? argmax.
Learning — fit A, B, π from data: Baum–Welch (EM).
Where HMMs earn their keep Speech recognition · POS tagging · spelling correction · gene finding (DNA is a four-letter observation alphabet) · handwriting · anomaly detection. The future depends only on the present state, the observation only on the current one.
Worked example ✍ a two-step weather chain Day 1: (0.5, 0.3, 0.2). Day 2 = πA = (0.39, 0.35, 0.26). Day 3 = (0.369, 0.361, 0.27). The rows always sum to 1 — the quickest check that your arithmetic is still alive.
Memory trick "Markov = memoryless. Hidden Markov = the states are hidden, the observations are visible." Rows of A sum to 1; the 5-tuple is S, O, A, B, π; a symmetric k-state chain has stationary distribution 1/k.
Exam trap A plain Markov chain is fully observed — there is nothing to decode. The MDP (states, actions, transition probabilities, rewards) and reinforcement learning belong to the expert-system and machine-learning notes.
Common misconception "Hidden" does not mean hidden from the algorithm — it means hidden from the observer. The algorithms on the next sheet recover the most likely path from exactly the same five quantities. PageRank is a Markov chain over web pages with damping d = 0.85.

6Forward, Backward & Viterbi Decoding

written favourite ★
Forward — sum every path αt(j) = P(o₁…ot, qt=sj) = bj(ot)·Σi aij αt−1(i)
α₁(j) = πjbj(o₁) · P(O) = Σj αT(j) · cost O(TN²).
Backward — what is still possible βt(j) = P(ot+1…oT | qt=sj) = Σi aji bi(ot+1) βt+1(i)
βT(j) = 1 · smoothing: P(qt=sj|O) = αt(j)βt(j)/P(O)
Viterbi — the single best path δt(j) = maxi [δt−1(i)·aij] · bj(ot), with ψ storing the argmax, then backtrack along ψ. The whole difference from forward: max, not Σ.
Exam trap Forward gives P(O), Viterbi gives the best path, and the best path is not the most probable state at every instant. Long sequences underflow: divide by ct = Σj αt(j) each step and multiply it back at the end.
Worked example 1 ✍ three states, observations (dry, dry, wet) π = (0.5, 0.3, 0.2); A as on the previous sheet; b(dry) = (0.9, 0.6, 0.1), b(wet) = (0.1, 0.4, 0.9). · α₁ = (0.45, 0.18, 0.02) · α₂ = (0.1998, 0.1926, 0.0107) · α₃ = (0.0122, 0.0798, 0.0738) · P(O) = 0.1658 · δ₃ = (0.0065, 0.0324, 0.0365) ⇒ best path S₁ → S₂ → S₃.
Worked example 2 ✍ marginals differ from the best path γ3 = α₃(j)β₃(j)/P(O) = (0.073, 0.481, 0.445): the most likely state at t = 3 is S₂, yet the most likely path ends in S₃. Marginal ≠ path.

Memory trick "Forward adds, Viterbi takes the max, backward looks back." Write forward once; then max replaces the Σ, ψ replaces the α, and you have Viterbi.
IT link These recursions are a dynamic-programming shortest path over a lattice — the same shape as shortest path in a weighted DAG, and the same shape as the beam search inside a speech recogniser.

AI · Probabilistic Reasoning & NLPNLP I: text to tokens

7NLP I: Pipeline, Morphology, Tokenisation

half the syllabus ★
Definition Natural language processing (NLP) is the branch of AI that lets a computer understand, interpret, generate and respond to human language, closing the gap between human communication and computer understanding. It is a pipeline: every stage consumes the tokens the previous stage produced, so a mistake at the bottom is never repairable at the top.
Levels of analysis Morphological — words are built from a root plus affixes.
Lexical — split into tokens, look each one up.
Syntactic — POS tags, chunks, parse trees.
Semantic — meaning of words and sentences.
Pragmatic / discourse — intent, sarcasm, cohesion.
Morphology ✍ A lexeme is one word-form family — go, goes, went, gone are four forms of one lexeme. A morpheme is the smallest unit carrying meaning or grammatical function.
Affixes The root carries the core meaning; affixes modify it — prefix (un-), suffix (-ing), infix (unbelievable), circumfix (German ge…t).
Stop words Frequent function words carrying little content — the, of, and, a, is in English, the equivalents in Bangla. Removing them shrinks the index, but they carry negation and emphasis — "not good" is not "good".
Memory trick "Morphology builds words, tokenisation cuts them, stop words go out, stems come back." Six levels in one order: M L S S P D = morphological, lexical, syntactic, semantic, pragmatic, discourse.
IT link The pipeline is a real ETL: tokenisation is the split, stop-word removal the filter, stemming the projection, and the chain ends in an inverted index — the structure behind every search engine.
Tokenisation ✍ Splitting raw text into tokens: word-level, sentence-level, and subword — BPE, WordPiece, Unigram LM — which cut rare words into seen pieces. "The Bank of Dhaka didn't approve my loan!" gives ten tokens.
Why it is hard ✍ Bangla has no clear word boundary and drops most case endings, so whitespace tokenisation fails. Sentence segmentation is the same problem one level up: the full stop after "Ltd." does not end a sentence.

8NLP II: Stemming, POS, Chunking, Parsing

high-yield ★
Stemming vs lemmatisation Stemming chops suffixes with heuristic rules (Porter, 1980): relational → relat, connected → connect — the output is not a real word. Lemmatisation uses a vocabulary plus the part of speech: better → good, teeth → tooth.

POS tagging & chunking POS tagging labels every token's part of speech. Penn Treebank: 45 tags (a 36-tag reduced set is also quoted); the Universal POS set has 17 tags. Chunking (shallow parsing) groups tags into flat phrases — NP, VP, PP.
Worked example 1 ✍ tag the sentence "The flies hit the wall" → The/DT flies/NNS hit/VBD the/DT wall/NN. But "The flies hit the wall" is a complete grammatical sentence too, and only context decides.
Parsing Constituency parsing uses a context-free grammar and produces nested phrases like the tree on the right. Dependency parsing links every word to its grammatical head; Universal Dependencies defines 16 universal relations — nsubj, obj, det, amod, ROOT, case, nmod.
Memory trick "Stemming is the scissors, lemmatisation is the dictionary." A POS tag says what kind of word it is, chunking adds one level of phrase, parsing adds all of them. Counts: 45 Penn tags · 17 Universal POS · 16 UD relations.
Exam trap POS tagging is not parsing — a tagger answers "what kind of word is this?", a parser "how do the words hang together?". Stemming is not lemmatisation. And "flies" alone carries three readings: plural noun, third-person verb, or acrobats.
Ambiguity — four types, all tested Lexical (bank: river / money) · Syntactic ("I saw the man with the telescope") · Semantic ("He kicked the bucket") · Pragmatic / scope ("He saw her with the dog").
Worked example 2 ✍ chunk the sentence "The boy hit the ball in the park" → [NP The boy] [VP hit the ball] [PP in the park]. Chunking stops there — it never says which noun phrase attaches to which verb.
IT link An inverted index stores, for every term, the sorted list of documents containing it; chunks and dependency arcs sit beside it. A ranker then scores each (document, term) pair — the same shape as a naive Bayes document score with TF-IDF weights.

AI · Probabilistic Reasoning & NLPNLP III: words as vectors

9NLP III: Embeddings & n-gram Language Models

modern ★
Definition A word embedding maps every word to a short dense vector so that words used in similar contexts end up near each other — Firth's distributional hypothesis, "you shall know a word by the company it keeps". One-hot vectors are the opposite: sparse, all distances equal, no semantics.
ModelIdea
Word2Vec (2013)CBOW from context; skip-gram from centre word
GloVe (2014)factorises global co-occurrence counts
FastText (2016)embeds subwords, so rare words get vectors
n-gram language model The chain rule P(w₁…wT) = ∏t P(wt|w₁…wt−1) is exact but needs the whole history. Markov's approximation keeps only n−1 words: P(wt|wt−2:t−1) is a bigram, P(wt|wt−3:t−1) a trigram. Longer n-gram = better model, far more sparsity.
Exam trap The zero-frequency problem is the whole reason smoothing exists. Add-one: P(wᵢ|wi−1) = (c+1)/(c·+|V|). Interpolation blends unigram and bigram. Kneser–Ney uses continuation counts. Perplexity = exp(per-token NLL): lower is better.
Worked example 1 ✍ a bigram N = 19 words, |V| = 6 (+1 for <unk>). P(I) = 5/19; P(am|I) = 2/5 = 0.4; P(a|am) = 2/2 = 1.0; P(student|a) = 3/4 = 0.75. So P("I am a student") = 0.2632 × 0.4 × 1 × 0.75 = 0.0789. That 1.0, built from two observations, is overfitting in miniature.
Worked example 2 ✍ add-one smoothing With |V| = 7: P(I) = 6/26 = 0.2308, P(am|I) = 3/12 = 0.25, P(a|am) = 3/9 = 0.333, P(student|a) = 4/11 = 0.3636, so the same sentence drops to 0.0070. Smoothing costs accuracy on frequent words and buys you no zeros.
Worked example 3 ✍ perplexity picks the model Two models predict three tokens with probabilities (0.4, 0.4, 0.2) or (0.2, 0.2, 0.6). Mean NLL is 1.147 against 1.243, so the perplexities are e^1.147 = 3.15 and e^1.243 = 3.47. The first model wins — lower perplexity is better.
Memory trick "Longer n-gram, better model, more zeros." Embeddings answer "which words are alike?" as points in space; language models answer "what comes next?" as a probability. king − man + woman ≈ queen is a property of the geometry, not a programmed rule.
Exam trap + timeline A word embedding is not a language model, and Word2Vec is not trained from labels. Four eras of NLP: rule-based → statistical (HMM, n-grams) → machine learning → deep learning (RNN, LSTM, then the Transformer of 2017, BERT 2018, GPT).
