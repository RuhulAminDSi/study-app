মূল পরিভাষা ★
সংজ্ঞা ফ্লো নেটওয়ার্ক (Flow Network) হলো একটি নির্দেশিত গ্রাফ G = (V, E), যার প্রতিটি এজ (u, v)-এর একটি ধারণক্ষমতা (Capacity) c(u, v) ≥ 0; সঙ্গে দুটি বিশেষ শীর্ষ: উৎস (Source) s, যেখান থেকে প্রবাহ শুরু, আর সিঙ্ক (Sink) t, যেখানে তা শোষিত হয়। প্রবাহ (Flow) f প্রতিটি এজে আসলে কতটা যাচ্ছে তা নির্ধারণ করে। পানির পাইপ, রাস্তার লেন, নেটওয়ার্ক লিংক, কনভেয়ার বেল্ট — সবই একই মডেল: প্রতি একক সময়ে s থেকে t-তে সর্বোচ্চ কত যেতে পারে?
নিয়মবিবৃতিঅর্থ
ক্যাপাসিটি শর্ত0 ≤ f(u,v) ≤ c(u,v)কোনো এজ তার ক্যাপাসিটির বেশি বহন করে না, ঋণাত্মকও নয়।
প্রবাহ সংরক্ষণ (Conservation)Σ f(·, v) = Σ f(v, ·), প্রতিটি v ≠ s, tযা শীর্ষে ঢোকে, তা-ই বেরোয় — শুধু s ও t ব্যতিক্রম।
প্রবাহের মান|f| = Σ f(s, v) − Σ f(v, s)সোর্স থেকে নিট বহির্গমন = সিঙ্কে নিট আগমন।
বটলনেকc_f(p) = পথ p-তে ন্যূনতম রেসিডুয়াল ক্যাপাসিটিএকটি অগমেন্টিং পাথ যতটা যোগ করতে পারে।
রেসিডুয়াল গ্রাফ (Residual Graph) G_f ✍ c ক্যাপাসিটির যে এজে f প্রবাহ, তার জন্য রেসিডুয়াল গ্রাফে থাকে একটি সামনের এজ, c_f(u,v) = c(u,v) − f(u,v) (বাকি জায়গা), এবং একটি পেছনের এজ, c_f(v,u) = f(u,v) (যে প্রবাহ বাতিল করা যায়)। G_f-এ যেকোনো s→t পথই অগমেন্টিং পাথ (Augmenting Path); c_f = 0 এজ বাদ।
পরীক্ষার ফাঁদ ✍ তিনটি ১. s ও t-তে সংরক্ষণ খাটে না — প্রবাহের মান সেখানেই মাপা হয়। ২. পেছনের এজ আসল পাইপ নয়; এ পথে পাঠানো মানে আগে পাঠানো প্রবাহ বাতিল করা। ৩. স্যাচুরেটেড এজ (f = c) সামনে থেকে মুছে যায়, কিন্তু পেছনে থেকে যায়।
মনে রাখার কৌশল "সামনে = বাকি জায়গা, পেছনে = অনুশোচনা।" যত একক পাঠাও, পরে তা নিয়ে মত বদলানোর অধিকারও কিনে নাও — এক লাইনে এটাই রেসিডুয়াল গ্রাফ।

পরীক্ষার ফাঁদ ✍ তিনটি ১. প্রতিটি FPTAS একটি PTAS, উল্টোটা নয়। ২. স্ট্রংলি NP-হার্ড সমস্যার FPTAS নেই (P = NP না হলে); ন্যাপস্যাক কেবল উইকলি NP-হার্ড। ৩. "সেট কভার গ্রিডির অনুপাত ২" ভুল — এটি ln n।
মনে রাখার কৌশল "কভার ২, ট্যুর ২ তারপর ১.৫, সেট ln n, ন্যাপস্যাক 1+ε।" আর "FPTAS = Fully পলিনোমিয়াল — n ও 1/ε দুটোতেই।"

৭প্যারালাল অ্যালগরিদম: স্পিডআপ, দক্ষতা, গ্র্যানুলারিটি, অ্যামডালের সূত্র

সূত্রের পাতা ★
সংজ্ঞা প্যারালাল (সমান্তরাল) অ্যালগরিদম (Parallel Algorithm) একটি সমস্যাকে উপ-সমস্যায় ভাগ করে একাধিক প্রসেসরে একসঙ্গে সমাধান করে, তারপর ফলাফল জোড়া দেয়। এর মান মাপা হয় সেরা ক্রমিক (Sequential) অ্যালগরিদমের সঙ্গে তুলনা করে, এক প্রসেসরে নিজের সঙ্গে নয়।
পরিমাপসূত্রঅর্থ
স্পিডআপ SS = T₁ / TₚT₁ = সেরা ক্রমিক সময়, Tₚ = p প্রসেসরে সময়। আদর্শ (লিনিয়ার): S = p।
দক্ষতা (Efficiency) EE = S / pপ্রসেসর-সময়ের যে অংশ কাজে লাগে; সাধারণত 0 < E ≤ 1।
খরচ (Cost)p × Tₚp·Tₚ = Θ(T₁) হলে কস্ট-অপটিমাল।
গ্র্যানুলারিটিগণনা / যোগাযোগফাইন-গ্রেইনড: অনেক ছোট কাজ, বেশি যোগাযোগ। কোর্স-গ্রেইনড: অল্প বড় কাজ।
ওয়ার্ক–স্প্যানTₚ ≥ T₁/p, Tₚ ≥ T∞T∞ (স্প্যান) = দীর্ঘতম নির্ভরতা-শৃঙ্খল; প্যারালেলিজম = T₁/T∞; ব্রেন্ট: Tₚ ≤ T₁/p + T∞।
ডেটা বনাম টাস্ক প্যারালেলিজম ডেটা: ভিন্ন ভিন্ন ডেটায় একই অপারেশন — ভেক্টর যোগ, ম্যাট্রিক্স গুণ, ইমেজ ফিল্টার (SIMD, GPU)। টাস্ক: একসঙ্গে ভিন্ন ভিন্ন অপারেশন — পাইপলাইনের ধাপ, ওয়েব সার্ভারের স্বাধীন অনুরোধ (MIMD)।
ফ্লিনের শ্রেণিবিভাগ SISD সাধারণ একক প্রসেসর · SIMD ভেক্টর ইউনিট, GPU · MISD বিরল (ফল্ট-টলারেন্ট পাইপলাইন) · MIMD মাল্টিকোর, ক্লাস্টার। PRAM মডেল: EREW, CREW, CRCW (এক্সক্লুসিভ/কনকারেন্ট রিড/রাইট)।
অ্যামডালের সূত্র (Amdahl's Law, নির্দিষ্ট সমস্যা-আকার) ✍ কাজের P অংশ N প্রসেসরে সমান্তরালে চলে আর 1 − P ক্রমিক থাকে: S(N) = 1 / ((1 − P) + P/N)। N → ∞ হলে S → 1 / (1 − P) — ক্রমিক অংশই স্পিডআপের সীমা টানে।
সমাধান-কৃত উদাহরণ P = 0.9, N = 10: S = 1 / (0.1 + 0.09) = 1/0.19 ≈ 5.26; E = 5.26/10 ≈ ৫৩%; যত প্রসেসরই হোক, সীমা 1/0.1 = 10। P = 0.8, N = 4: S = 1/(0.2 + 0.2) = 2.5; সীমা 5।
গুস্তাফসনের সূত্র (বাড়ানো আকার) N-এর সঙ্গে সমস্যা বড় হলে: S = (1 − P) + P·N (P = সমান্তরাল রানের সমান্তরাল অংশ)। P = 0.9, N = 10 → 0.1 + 9 = 9.1। অ্যামডাল হতাশাবাদী, গুস্তাফসন আশাবাদী।
পরীক্ষার ফাঁদ অ্যামডালের সূত্রে P = সমান্তরাল অংশ; ক্রমিক অংশের সঙ্গে গুলিয়ে ফেললে সব উত্তর উল্টে যায়। p-এর বেশি স্পিডআপ (সুপারলিনিয়ার) ক্যাশের প্রভাবে হতে পারে, তবে তা স্বাভাবিক নয়।
মনে রাখার কৌশল "সবচেয়ে ধীর অংশই গতি ঠিক করে।" দশ শতাংশ ক্রমিক ⇒ কখনো দশ গুণের বেশি দ্রুত নয়।

৮প্যারালাল সর্টিং, ম্যাট্রিক্স গুণ, BFS — ও সমস্যাগুলো

প্রচলিত অ্যালগরিদম ★
সমস্যাসমান্তরাল পদ্ধতিখরচ / সময়
রিডাকশন (n সংখ্যার যোগ)জোড়ায় জোড়ায় গাছ: n/2 যোগ, তারপর n/4, …O(log n) ধাপ, n/2 প্রসেসর
প্যারালাল মার্জ সর্টp প্রসেসরে ভাগ, স্থানীয়ভাবে সর্ট, log p স্তরের গাছে মার্জ।O((n/p) log(n/p)) স্থানীয় সর্ট + মার্জ
বাইটনিক সর্টসর্টিং নেটওয়ার্ক: বাইটনিক অনুক্রম বানাও, তারপর কম্পেয়ার–এক্সচেঞ্জে বাইটনিক মার্জ; n = 2-এর ঘাত।O(log² n) সময়, O(n log² n) তুলনা
ম্যাট্রিক্স গুণব্লক বিভাজন; √p × √p প্রসেসর গ্রিডে ক্যাননের অ্যালগরিদম।O(n³/p) গণনা, √p শিফট ধাপ
গ্রাফ সার্চলেভেল-সিনক্রোনাস BFS: পুরো ফ্রন্টিয়ার একসঙ্গে বাড়াও; প্যারালাল ডায়াক্সট্রাও (Δ-স্টেপিং)।রাউন্ড = BFS গাছের গভীরতা
সমাধান-কৃত উদাহরণ: প্যারালাল মার্জ সর্ট অ্যারে [38, 27, 43, 3, 9, 82, 10], ২টি প্রসেসরে। P0 পায় [38, 27, 43] → সর্ট করে [27, 38, 43]; P1 পায় [3, 9, 82, 10] → [3, 9, 10, 82] — দুটোই একই সময়ে। একটি মার্জ ধাপ → [3, 9, 10, 27, 38, 43, 82]। p প্রসেসরে মার্জ-গাছের log₂ p স্তর।
বাইটনিক হাফ-ক্লিনার ✍ বাইটনিক অনুক্রম আগে বাড়ে তারপর কমে (বা তার ঘূর্ণন)। i-তম উপাদানকে i + n/2-তমর সঙ্গে তুলনা করে উল্টো হলে অদলবদল: [2, 5, 8, 9 | 7, 6, 3, 1] → নিচু [2, 5, 3, 1], উঁচু [7, 6, 8, 9]। প্রতিটি নিচু ≤ প্রতিটি উঁচু, এবং প্রতিটি অর্ধেক আবার বাইটনিক — পুনরাবৃত্তি। n = 8-এ লাগে 3·4/2 = 6টি তুলনা-ধাপ।
ক্যাননের অ্যালগরিদম প্রসেসর P(i,j)-এর কাছে ব্লক A(i,j), B(i,j)। স্কিউ: A-এর i-তম সারি i ঘর বামে, B-এর j-তম কলাম j ঘর ওপরে সরাও। তারপর √p বার: স্থানীয় ব্লক গুণ-যোগ, A এক ঘর বামে ও B এক ঘর ওপরে। প্রতিটি প্রসেসর একবারে প্রতিটি ম্যাট্রিক্সের কেবল একটি ব্লক রাখে।
চ্যালেঞ্জকী ভুল হয় / প্রতিকার
যোগাযোগের ওভারহেডডেটা পাঠাতে সময় লাগে; সূক্ষ্ম গ্র্যানুলারিটিতে Tₚ, T₁-এর চেয়েও খারাপ হতে পারে।
লোড ব্যালান্সিংঅসম ভাগে প্রসেসর বসে থাকে — ডায়নামিক শিডিউলিং, ওয়ার্ক স্টিলিং।
সিনক্রোনাইজেশন, রেস, ডেডলকব্যারিয়ারে দ্রুত প্রসেসর অপেক্ষা করে; ক্রমহীন আপডেটে রেস কন্ডিশন (BFS-এর "visited" ফ্ল্যাগ → অ্যাটমিক compare-and-swap); বৃত্তাকার লক-অপেক্ষায় ডেডলক।
প্রয়োগ বৈজ্ঞানিক সিমুলেশন (আবহাওয়া, পদার্থবিদ্যা) · বিগ ডেটা: Hadoop MapReduce, Apache Spark · GPU-তে গ্রাফিক্স রেন্ডারিং · ডিস্ট্রিবিউটেড ML ট্রেনিং (ডেটা-প্যারালাল গ্র্যাডিয়েন্ট, all-reduce)।
পরীক্ষার ফাঁদ বাইটনিক সর্ট মার্জ সর্টের চেয়ে বেশি তুলনা করে (n log² n বনাম n log n) — তবু জেতে কারণ এর তুলনার ধরন নির্দিষ্ট, হার্ডওয়্যার ও GPU-র জন্য আদর্শ।
