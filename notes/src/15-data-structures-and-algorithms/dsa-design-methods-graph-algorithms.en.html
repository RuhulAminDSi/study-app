1Divide and Conquer: Split, Solve, Combine

recurrences ★
Definition Divide and conquer solves a problem by (1) Divide: splitting it into a smaller instances of the same problem, (2) Conquer: solving each one recursively (tiny instances directly), (3) Combine: merging the sub-answers. The sub-problems are independent (they do not overlap), which is what separates it from dynamic programming. Its cost is the recurrence T(n) = aT(n/b) + f(n): a sub-problems of size n/b, f(n) = divide + combine work.

Worked example ✍ Strassen Ordinary block multiplication of n×n matrices splits each into four n/2 blocks and needs 8 block products: T(n) = 8T(n/2) + n² = Θ(n³). Strassen rearranges the work into 7 products (and 18 additions): T(n) = 7T(n/2) + Θ(n²). Since log₂7 ≈ 2.807 > 2, the leaves dominate: Θ(nlog₂7) ≈ O(n2.81).
Solving it fast Compare f(n) with nlogba. Leaves heavier → Θ(nlogba); equal → Θ(nlogba · log n); root heavier → Θ(f(n)). Full master theorem with its regularity condition: recursion & sorting lesson.
Exam trap (i) Quick sort is D&C even though its combine step is empty — the work is in the partition. Merge sort is the opposite: trivial divide, real combine. (ii) Binary search keeps one half (a = 1), so it is sometimes called "decrease and conquer".
Memory trick "D-C-C: Divide, Conquer, Combine." Strassen: "seven, not eight" → log₂7 ≈ 2.81. Karatsuba: "three, not four" → log₂3 ≈ 1.585.
When D&C fits sub-problems are of the same kind, independent and roughly equal in size. If the same sub-problem keeps reappearing (naive Fibonacci), switch to DP.
Worked example ✍ binary search A = [3, 9, 14, 21, 27, 35, 42], key 27. mid = A[3] = 21 < 27 → right half [27, 35, 42]; mid = 35 > 27 → left half [27]; found. 3 comparisons = ⌊log₂7⌋ + 1, the worst case for n = 7. Needs a sorted array with random access.
MergeSort(A, l, r): if l < r: m = (l + r) / 2 MergeSort(A, l, m) // conquer MergeSort(A, m + 1, r) // conquer Merge(A, l, m, r) // combine, O(n)

2The Greedy Method: Best Choice Now, Never Undo It

fractional knapsack ★
Definition A greedy algorithm builds a solution one piece at a time, always taking the choice that looks best right now (the local optimum) and never reconsidering it. It gives the global optimum only when the problem has both the greedy-choice property (some optimal solution starts with the greedy choice) and optimal substructure (after that choice, the rest is an optimal solution of the smaller problem). Otherwise it gives a fast but possibly wrong answer.
Worked example ✍ fractional knapsack, W = 50 Items (value, weight): I₁ (60, 10), I₂ (100, 20), I₃ (120, 30). Ratios v/w = 6, 5, 4. Sort by ratio and fill: take all of I₁ (w 10, v 60), all of I₂ (w 30, v 160), then 20/30 of I₃ → 120 × 2/3 = 80. Total = 240, optimal. Cost: O(n log n) for the sort.
Exam trap: greedy fails here (i) 0/1 knapsack (items cannot be split): by ratio, greedy takes I₁ + I₂ = 160, but the optimum is I₂ + I₃ = 220. Use DP. (ii) Coin change with coins {1, 3, 4}, amount 6: greedy gives 4 + 1 + 1 (3 coins), optimum is 3 + 3 (2 coins). Greedy is optimal only for "canonical" systems like 1, 2, 5, 10.

3Dynamic Programming: Solve Each Sub-problem Once

two properties ★
Definition Dynamic programming (DP) breaks a problem into sub-problems that overlap, solves each one only once and stores the answer in a table. It needs two properties: overlapping sub-problems (the same sub-problem recurs many times) and optimal substructure (an optimal solution is built from optimal sub-solutions). Steps: define the sub-problem → write the recurrence → fix the base cases → fill the table in a safe order → trace back the answer.

Longest common subsequence (LCS)

Recurrence c[i][j] = 0 if i = 0 or j = 0; c[i−1][j−1] + 1 if xᵢ = yⱼ; else max(c[i−1][j], c[i][j−1]). Time and space O(mn). A subsequence keeps order but need not be contiguous (a substring must be).
Memory trick "Match → diagonal + 1; mismatch → max of up and left." Trace back from the bottom-right: diagonal moves on matches spell the LCS.

Exam trap (i) DP is not "recursion with a table" for every problem: without overlapping sub-problems (merge sort), a table saves nothing — that is plain D&C. (ii) LCS of lengths m, n costs O(mn), not O(m + n). (iii) Memoization and tabulation have the same asymptotic time; they differ in order and overhead.

4DP Classics: Knapsack and Matrix Chain

worked tables ★
0/1 knapsack recurrence K[i][w] = best value using items 1..i with capacity w.
K[i][w] = K[i−1][w] if wᵢ > w; else max(K[i−1][w], vᵢ + K[i−1][w − wᵢ]).
Time O(nW) — pseudo-polynomial (polynomial in the value W, exponential in its bit length).
Exam trap: the 1-D version With one array, K[w] = max(K[w], vᵢ + K[w − wᵢ]) is correct only if w runs downward from W to wᵢ. Running w upward reuses item i in the same pass, which solves the unbounded knapsack (unlimited copies) instead.

Matrix-chain multiplication (MCM)

Problem Matrix Aᵢ is pi−1 × pᵢ. Choose the parenthesisation of A₁A₂…Aₙ with the fewest scalar multiplications (a p×q times q×r product costs pqr). The order changes the cost, never the result. Recurrence: m[i][j] = min over i ≤ k < j of m[i][k] + m[k+1][j] + pi−1pkpj, m[i][i] = 0. Time O(n³), space O(n²). The number of parenthesisations is the Catalan number Cn−1, so brute force is exponential.
Worked example ✍ 3 matrices A₁ 10×30, A₂ 30×5, A₃ 5×60.
(A₁A₂)A₃ = 10·30·5 + 10·5·60 = 1500 + 3000 = 4500
A₁(A₂A₃) = 30·5·60 + 10·30·60 = 9000 + 18000 = 27000
Same product, 6× the work with the wrong order.

5Backtracking: DFS of the State Space

N-Queens ★
Definition Backtracking builds a solution one component at a time along a state-space tree, exploring it depth-first. At each node a bounding (feasibility) function checks the partial solution; if it can no longer lead to a valid answer, the whole subtree is pruned and the algorithm steps back to the previous choice. Uses: N-Queens, sum of subsets, graph m-colouring, Hamiltonian cycle, Sudoku. Worst case stays exponential.
Worked example ✍ 4-Queens One queen per row. Queens (r₁, c₁), (r₂, c₂) clash if c₁ = c₂ or |r₁ − r₂| = |c₁ − c₂| (diagonal). Try row 1 col 1 → row 2 col 3 → row 3 has no safe column → back to row 2 col 4 → row 3 col 2 → row 4 dead → back up to row 1 col 2 → (2, 4, 1, 3) ✓. 8-Queens: 92 solutions (12 distinct).
Sum of subsets S = {3, 5, 6, 7}, target 15: include/exclude each item, prune when the sum passes 15 or cannot reach it. Only solution {3, 5, 7}.

6Branch and Bound: Bounds Prune the Tree

LB ≥ best ★
Definition Branch and bound (B&B) also searches a state-space tree, but for optimisation. Each live node gets a bound on the best answer reachable through it; if the bound cannot beat the best complete solution so far, the node is killed. Order: FIFO (BFS-like), LIFO or LC (least-cost) search with a priority queue. Uses: TSP (reduced cost matrix), 0/1 knapsack (fractional bound), job assignment.
Exam trap: the prune rule For minimisation (TSP, assignment): LB(node) = least cost any completion can have; UB / best = cost of the best full solution found. Prune when LB ≥ best — a node with LB equal to best can only tie, so it is pruned too ("LB > UB" misses ties). For maximisation (0/1 knapsack): prune when the node's upper bound ≤ best value found.
Memory trick "Backtracking asks 'is it legal?', B&B asks 'can it still win?'" Backtracking = DFS + feasibility; B&B = any order (usually BFS / LC) + bound.

7Graph Traversal: BFS and DFS

O(V+E) ★
BFS Breadth-first search uses a queue: visit the source, then all vertices at distance 1, then 2, … It finds shortest paths in unweighted graphs (fewest edges), tests bipartiteness, and drives Edmonds-Karp and web crawlers.
DFS Depth-first search uses a stack (or recursion): go as deep as possible, then back up. It records discovery/finish times and powers cycle detection, topological sort, SCC, articulation points and maze solving.
BFSDFS
Structurequeue (FIFO)stack (LIFO) / recursion
Order from A (alphabetical)A B C D E FA B D F C E
TimeO(V + E) with adjacency list · O(V²) with adjacency matrix
On a tree it giveslevel-order traversalpre-, in-, post-order traversals
DFS edge classes (directed) Tree: to a new vertex · Back: to an ancestor still open · Forward: to a finished descendant · Cross: to a vertex in another finished branch. Undirected DFS has only tree and back edges. A back edge exists ⇔ the graph has a cycle.
Exam trap "DFS = pre/in/post-order, BFS = level order" is true for trees only; a general graph has no "in-order". BFS finds fewest-edge paths, not least-weight paths. A disconnected graph needs a fresh BFS/DFS from every unvisited vertex.

8Topological Sorting

DAG only ★
Definition A topological order of a directed graph lists the vertices so that for every edge u → v, u comes before v. One exists if and only if the graph is a DAG (directed acyclic graph), and it is usually not unique. Uses: task scheduling, course prerequisites, build systems (make), spreadsheet recalculation, package installers.
Kahn's algorithm (BFS) ✍ In-degrees A0 B1 C1 D2 E1 F2. Queue the 0s: A. Pop A → B, C drop to 0. Pop B → D = 1. Pop C → D = 0, E = 0. Pop D → F = 1. Pop E → F = 0. Pop F. Order A B C D E F. If fewer than V vertices come out, the graph has a cycle.
DFS method ✍ Run DFS; when a vertex finishes, push it on a list. Finish order F, D, B, E, C, A → reversed: A C E B D F. Different from Kahn's, and equally valid. Both run in O(V + E).
Memory trick "Kahn counts in-degrees, DFS reverses finish times." Prerequisite example: Math → Data Structures → Algorithms, Physics → Robotics gives Math, Physics, Data Structures, Algorithms, Robotics.

9Connected and Strongly Connected Components

Kosaraju ★
Undirected A connected component is a maximal connected subgraph. Start a BFS/DFS from every unvisited vertex: number of starts = number of components, O(V + E).
Directed A strongly connected component (SCC) is a maximal set where every vertex reaches every other. Kosaraju: (1) DFS on G, note finish order; (2) build the transpose Gᵀ (reverse all edges); (3) DFS on Gᵀ in decreasing finish time — each tree is one SCC. Tarjan: one DFS with a stack and low-link values; v is an SCC root when low[v] = disc[v]. Both O(V + E).
Exam trap Shrinking every SCC to one node gives the condensation, which is always a DAG. An articulation point (cut vertex) is a vertex whose removal disconnects the graph; a bridge is such an edge. With DFS low values: the root is a cut vertex iff it has ≥ 2 DFS children; another vertex u is one iff some child v has low[v] ≥ disc[u]; edge (u, v) is a bridge iff low[v] > disc[u].

10Minimum Spanning Tree: Prim and Kruskal

greedy ★
Definition A spanning tree of a connected undirected graph contains all V vertices and exactly V − 1 edges, no cycle. A minimum spanning tree (MST) has the least total weight. Cut property: the lightest edge crossing any cut belongs to some MST — the reason both greedy algorithms are correct. Distinct weights ⇒ the MST is unique.
Worked example ✍ same graph, two algorithms Edges AB 4, AC 1, BC 2, BD 5, CD 8, DE 3, CE 9.
Kruskal (sort, add if no cycle): AC 1 ✓, BC 2 ✓, DE 3 ✓, AB 4 ✗ (cycle A-B-C), BD 5 ✓ → 4 edges, stop.
Prim from A (grow one tree): AC 1 → CB 2 → BD 5 → DE 3.
Both: weight 1 + 2 + 3 + 5 = 11, 4 = V − 1 edges.

11Shortest Paths: Relax Until Stable

relaxation ★
Relaxation Keep d[s] = 0, others ∞, and relax edges: if d[u] + w(u, v) < d[v] then d[v] ← d[u] + w(u, v), parent[v] ← u. The algorithms differ only in which edges they relax and in what order.
Worked example ✍ Dijkstra from A
SettleABCD
start0∞∞∞
A (0)041∞

Dijkstra (greedy) Repeatedly settle the unsettled vertex with the smallest d and relax its out-edges; a settled distance is final. Needs non-negative weights. Time: O(V²) array · O((V+E) log V) binary heap · O(E + V log V) Fibonacci heap.
Exam trap: negative edge A→B 2, A→C 3, C→B −2. Dijkstra settles B at 2 and never revisits it, but A→C→B = 1. One negative edge is enough to break it; use Bellman-Ford.
Bellman-Ford (DP) Relax every edge V − 1 times (a shortest path has ≤ V − 1 edges). One more pass: if any edge still relaxes, a negative-weight cycle is reachable from the source. Handles negative edges. Time O(VE).
Floyd-Warshall (DP) All pairs: for k = 1..V, for i, for j: d[i][j] = min(d[i][j], d[i][k] + d[k][j]). Time O(V³), space O(V²). Negative edges are fine; a negative cycle shows as d[i][i] < 0, and then shortest paths are undefined.
