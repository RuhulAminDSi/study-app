1 Terminology, Binary Tree Types & Node Formulas ★ MCQ formulas

Tree A hierarchical, non-linear structure with one root and no cycles; n nodes have n − 1 edges (file system, HTML DOM). A binary tree: every node has at most 2 children, left and right (a lone left child ≠ a lone right child).

Proof (written favourite) In a full (proper) binary tree, leaves = internal nodes + 1. Let I = internal nodes, L = leaves. Count edges two ways: each non-root node has one parent edge, so edges = I + L − 1; each internal node has 2 children, so edges = 2I. Hence 2I = I + L − 1, i.e. L = I + 1. ∎
Exam trap Height convention. Here height counts edges (lone root = 0). Some books count nodes (lone root = 1), so “N levels” gives 2^N − 1. State your convention.
Memory trick Levels double: 1, 2, 4, 8 …, so h+1 full levels hold “next power of two, minus one”. Perfect ⊂ complete and perfect ⊂ full, but full ⇏ complete.

2 Traversals: Pre, In, Post & Level Order ★ Most tested

Traversal Visit every node once. The 3 depth-first orders differ only in when the root is visited; level order is breadth-first (queue). All O(n).
TraversalOrderTypical use
PreorderRoot L Rcopy / serialise a tree, prefix (Polish) form
InorderL Root RBST keys in ascending order, infix form
PostorderL R Rootdelete/free a tree, postfix evaluation, folder sizes
Level orderby levels (queue)BFS, print by levels, heap array order
Worked example Insert 8 3 10 1 6 14 4 7 13 into an empty BST and traverse it in every order, including the unusual Right → Left → Root.
Pre: 8 3 1 6 4 7 10 14 13
In: 1 3 4 6 7 8 10 13 14 (sorted ✓)
Post: 1 4 7 6 3 13 14 10 8
Level: 8 3 10 1 6 14 4 7 13
R → L → Root: 13 14 10 7 4 6 1 3 8 (= preorder reversed)
Expression tree for X = (a² − 5b) × (7a + b³): operators inside, operands at the leaves.
Prefix (pre): × − ^ a 2 × 5 b + × 7 a ^ b 3
Postfix (post): a 2 ^ 5 b × − 7 a × b 3 ^ + ×
Memory trick Pre / In / Post = where the Root goes. Walk round the outline; write a node at its left side (pre), bottom (in) or right (post).
Exam trap Child deleted before its parent → postorder. Inorder is sorted only for a BST.

DSA ▸ Tree WorkshopBST: Search & Insert

3 Binary Search Tree: Search & Insert ★ Bank & PSU written

BST property For every node: all keys in its left subtree are smaller, all keys in its right subtree are larger (no duplicates, unless you state a rule such as “equal goes right”). Consequence: inorder = sorted.
/* search: iterative */
node* search(node* t, int k) {
  while (t && t->key != k)
    t = (k < t->key) ? t->left
                     : t->right;
  return t;   /* NULL = absent */
}
/* insert: recursive */
node* insert(node* t, int k) {
  if (!t) return newNode(k);
  if (k < t->key)
    t->left = insert(t->left, k);
  else if (k > t->key)
    t->right = insert(t->right, k);
  return t;   /* duplicate ignored */
}
Worked example Insert 8 3 10 1 6 14 4 7 13 into an empty BST: each key walks down from the root, left if smaller, right if larger, until it meets an empty link.
Memory trick “Smaller left, larger right, stop at NULL.” The first key is always the root; sorted input turns a BST into a linked list.
Exam trap A BST is not automatically balanced: search is O(log n) only when balanced and O(n) in the worst case. Min = leftmost node, max = rightmost.

DSA ▸ Tree WorkshopBST: Delete

4 BST Delete: the Three Cases ★ Written favourite

  1. Leaf: just remove it. Delete 13 → 14 loses its left child.
  2. One child: link the child to the parent. Delete 10 → 14 moves up.
  3. Two children: copy in the inorder successor (smallest key of the right subtree), then delete that successor (it has ≤ 1 child). The predecessor (largest on the left) also works.
Worked example 1 Delete the root 8: successor = 10 (no left child), so 10 moves up and 14 takes its place → 10(3(1, 6(4, 7)), 14(13)). Using the predecessor, 7 becomes the root.
Worked example 2: a full written question (a) Insert 50, 30, 70, 20, 40, 60, 80. (b) Print the postorder. (c) Delete 50 and redraw.
(a) 50 root; 30, 70; then 20, 40 and 60, 80.
(b) Postorder: 20 40 30 60 80 70 50
(c) Successor = 60: copy it up, remove the leaf.
Memory trick Successor = “one right, then all the way left”; predecessor = “one left, then all the way right”. Then check the inorder is still sorted.
Exam trap In case 3 you copy the successor's key; “replace with the right child” is wrong when that child has a left subtree (deleting 3: 6 has left child 4).

5 Storing a Binary Tree in an Array ★ Written + BCS MCQ

Sequential representation Put the root at index 1 and number the positions in level order, left to right. A missing node leaves an empty slot; index arithmetic replaces pointers.
Root atLeft child of iRight child of iParent of i
1-indexed12i2i + 1⌊i / 2⌋
0-indexed (C, Java)02i + 12i + 2⌊(i − 1) / 2⌋
Worked example: a tree with gaps The BST of sheet 4: 14 = right of 10 → 2·3+1 = 7; 13 = left of 14 → 2·7 = 14. 9 keys use 14 slots; a right-skewed tree of n nodes needs 2ⁿ − 1.
Worked example: postorder → array Nodes a…i, postorder a b f c h d e g i. Assume a complete tree (one traversal alone is ambiguous): its positions in postorder are 8 9 4 5 2 6 7 3 1, so 8 = a, 9 = b, 4 = f, …
Array vs linked Array: parent in O(1), ideal for complete trees (heaps), wasteful if sparse. Linked: n + 1 NULL pointers, any shape.
Memory trick Double to go down-left, halve to go up (1-indexed).
Exam trap Read the indexing! “Zero-based, left child of i?” → 2i + 1, not 2i. Leaves of a complete tree (1-indexed) are ⌊n/2⌋+1 … n.

DSA ▸ Tree WorkshopRebuilding a Tree I: with Inorder

6 Rebuilding a Tree from Inorder + One More ★ BUET-pattern written

The rule Preorder names the root first; postorder names it last. Inorder splits the rest into left and right subtrees. Recurse. Inorder + pre or post = one unique tree.
Worked example 1: preorder + inorder Inorder: 4 2 1 7 5 8 3 6 · Preorder: 1 2 4 3 5 7 8 6
  1. Pre[0] = 1 = root. Inorder: left {4 2}, right {7 5 8 3 6}.
  2. Left: root 2; inorder “4 2” → 4 is its left.
  3. Right, pre 3 5 7 8 6: root 3; inorder “7 5 8 | 3 | 6”.
  4. {7 5 8}, pre 5 7 8: root 5, left 7, right 8; 6 is 3's right.
Read back pre ✓ and in ✓; postorder = 4 2 7 8 5 6 3 1.
Worked example 2: postorder + inorder Inorder: D B E A F C · Postorder: D E B F C A.
  1. Root = last = A; left {D B E}, right {F C}.
  2. Left post “D E B” → root B, D left, E right.
  3. Post “F C” → root C; inorder “F C” → F is its left.
Preorder of the result: A B D E C F.
Worked example 3: a classic with a misprint Preorder a b d e c f g with a 5-letter inorder “d e a f g”: an inorder must list all 7 keys. Reading it as d b e a f c g gives a(b(d, e), c(f, g)), postorder d e b f g c a. State the assumption.
Memory trick “Pre/Post point, In splits.” Pre/post say who is the root; inorder says who goes where.

DSA ▸ Tree WorkshopRebuilding a Tree II: Pre + Post

7 Preorder + Postorder, and BST Shortcuts ★ Bank & BUET

Method (full trees only) Root = pre[0] = post[last]. The next preorder key roots the left subtree; in postorder, everything up to it is the left subtree, the rest the right. Recurse.
Worked example 1 Pre: 1 2 4 8 9 5 3 6 7 · Post: 8 9 4 5 2 6 7 3 1
  1. Root 1, next key 2: post up to 2 → left {8 9 4 5 2}, right {6 7 3}.
  2. Root 2, next key 4: post up to 4 → {8 9 4}; 5 is 2's right.
  3. 4(8, 9); right part 3(6, 7).
Worked example 2 Pre: 1 2 4 5 3 6 8 9 7 · Post: 4 5 2 8 9 6 7 3 1
  1. Root 1, next key 2: post up to 2 = {4 5 2} → 2(4, 5).
  2. Right: pre 3 6 8 9 7 → root 3, next key 6 → 6(8, 9); 7 is 3's right.
Exam trap Pre + post is ambiguous once a node has one child: pre “A B”, post “B A” fits B as left or right child. Inorder + any one other is always unique; one traversal alone never is.
BST shortcut For a BST the inorder is the sorted keys, so preorder alone fixes it: pre 8 3 1 6 4 7 10 14 13 → sort → rebuild (or insert in that order) → the BST of sheet 4.
Drill Pre 1 5 8 7 4 9 3 · In 8 5 7 1 9 4 3 → 1(5(8, 7), 4(9, 3)): a plain binary tree, not a BST.

8 Heap & B-tree: the Exam Essentials ★ Priority queue · DB index

Heap A complete binary tree in an array: max-heap parent ≥ children (root = max), min-heap parent ≤ children. Siblings are unordered.
  1. Insert 45 at index 6; parent ⌊6/2⌋ = 3 holds 40 < 45 → swap; parent 50 ≥ 45 → stop (sift-up, O(log n)).
  2. Delete max: remove 50, move the last key 40 to the root; child 45 > 40 → swap (sift-down, O(log n)).
  3. Build-heap: sift-down from node ⌊n/2⌋ back to 1: total O(n), not O(n log n). Find-max is O(1); heapsort O(n log n).
B-tree of order m A self-balancing multi-way search tree: ≤ m children and ≤ m − 1 keys per node; non-root internal nodes ≥ ⌈m/2⌉ children; all leaves on the same level. Height = O(logm n).
Why databases use B-trees Node = disk block with hundreds of keys: millions of rows in 3–4 levels = 3–4 reads. B+ tree: records only in the linked leaves, so range queries are a leaf scan (MySQL InnoDB, PostgreSQL).
Exam trap A heap is not a BST: searching a heap is O(n). “Order m” = max m children (Knuth); CLRS uses minimum degree t. Say which.
Memory trick Heap = priority, BST = search, B-tree = disk. Insert sifts up, delete sifts down.

DSA ▸ Tree WorkshopDecision Tree Lower Bound · Night-Before

9 Decision Tree: Why Sorting Needs Ω(n log n) ★ BCS MCQ

Decision tree model Any comparison sort on n keys is a binary tree: internal node = one comparison (a ≤ b?), leaf = one final ordering, one run = one root-to-leaf path. So worst-case comparisons = height.
  1. n distinct keys have n! orderings, each needs its own leaf → leaves ≥ n!.
  2. A binary tree of height h has at most 2^h leaves → 2^h ≥ n! → h ≥ log₂(n!).
  3. n! ≥ (n/2)^(n/2) ⇒ log₂(n!) ≥ (n/2)·log₂(n/2) = Ω(n log n). Merge sort and heapsort are optimal.
Exam trap Counting/radix sort are not comparison sorts: O(n + k) is possible. In ML a “decision tree” is a classifier.
Numbers ⌈log₂ n!⌉: n = 3 → 3, n = 4 → 5, n = 5 → 7. Search in a sorted array: Ω(log n).
Night-before sheet
  • n nodes → n − 1 edges, n + 1 NULL links
  • max nodes height h = 2^(h+1) − 1; N levels = 2^N − 1
  • full tree: L = I + 1; any tree: n₀ = n₂ + 1
  • complete tree height = ⌊log₂ n⌋
  • Pre = Root L R · In = L Root R · Post = L R Root
  • BST inorder = sorted; postorder deletes a tree
  • level order uses a queue; DFS uses a stack
  • R-L-Root = preorder reversed
  • BST ops O(h): balanced O(log n), skewed O(n)
  • delete, 2 children → inorder successor
  • 1-indexed: 2i, 2i+1, ⌊i/2⌋; 0-indexed: 2i+1, 2i+2
  • inorder + pre/post → unique tree
  • heap: insert/delete O(log n), build O(n)
  • B-tree: all leaves same level, node = disk block
  • sorting lower bound: h ≥ log₂ n! = Ω(n log n)
  • 4 keys need ≥ 5 comparisons
Memory trick “n! leaves, 2^h room”: a tree with 2^h slots must fit n! answers, so h ≥ log₂ n!.

Written (10 marks): A binary tree has inorder D B H E A I F J C G and preorder A B D E H C F I J G. Draw the tree and write its postorder.
Model answer:
Root = first of preorder = A; inorder splits left {D B H E}, right {I F J C G}. [2]
Left: pre B D E H → root B; inorder “D | B | H E” → D is B's left; {H E} with pre E H → E, with H as its left child. [2]
Right: pre C F I J G → root C; inorder “I F J | C | G” → G is C's right; {I F J} with pre F I J → F(I, J). [2]
Tree: A(B(D, E(H, –)), C(F(I, J), G)). [2] Postorder: D H E B I J F G C A; reading back the preorder and inorder from the drawing confirms it ✓. [2]
