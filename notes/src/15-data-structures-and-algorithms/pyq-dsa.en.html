Q In a Quicksort algorithm taking the first element as the pivot, analyse the time complexity when all the elements supplied are already sorted. Petrobangla AM (CSE), 31.05.2024 · BOGMC (Petrobangla) AM 2024
  1. Partitioning n keys compares the pivot with the other n − 1: cn work.
  2. Sorted input: the pivot is the smallest key, so the split is 0 | n − 1, the worst possible.
  3. T(n) = T(n − 1) + cn = c[n + (n − 1) + … + 2] + T(1)
  4. Comparisons = (n − 1) + … + 1 = n(n − 1)/2 = Θ(n²); recursion depth n.

A balanced split gives T(n) = 2T(n/2) + cn = Θ(n log n) (best and average). Cure: a random pivot or median-of-three. Reverse-sorted input is also Θ(n²) here; for insertion sort, sorted input is the best case.

MCQs asked 49th BCS 2025, ICT (281) paper 2

2Merge Sort, Bubble Sort, Binary Search

45th BCS · bank
Q Write the Mergesort algorithm to sort n elements using the divide and conquer strategy. 5 marks 45th BCS Written (CSE-971), 31.01.2024
MergeSort(A, lo, hi) if lo < hi mid = (lo + hi) / 2 // divide MergeSort(A, lo, mid) // conquer MergeSort(A, mid+1, hi) Merge(A, lo, mid, hi) // combine Merge: copy halves to L and R; repeatedly move the smaller front key back to A (L first on ties); then copy the rest

T(n) = 2T(n/2) + cn: log₂n levels, each merging n keys → Θ(n log n) in every case; O(n) extra space; L first on ties keeps it stable.

Qs (a) What is bubble sort? Why does it fail if the array is unsorted? (b) Explain its logic; why is it inefficient for large datasets compared to merge sort? 10 + 10 Bank Assistant Programmer written (bank name cut off)

Logic: compare adjacent pairs left to right, swap if out of order; after pass k the k largest keys sit at the end; stop when a pass makes no swap. 5 1 4 2 8 → 1 4 2 5 8 → 1 2 4 5 8 → no swap, stop.

Exam trap Bubble sort does not fail on unsorted data: sorting it is its job (slowly). Binary search is what fails on unsorted data. Say so, then answer.

Inefficient: up to n − 1 passes × n − 1 comparisons = Θ(n²) vs Θ(n log n). n = 10⁶: 10¹² vs 2 × 10⁷ steps. Merits: O(1) space, stable, O(n) if nearly sorted.

3Heaps, Heapsort & Hashing

BPSC · BUET-set
Q Write down the properties of a max heap. Also write down the heapsort algorithm. BPSC (Ministry of Home Affairs) Senior Computer Operator, 13.09.2022
  1. Shape: a complete binary tree (levels full, last filled left to right), height ⌊log₂n⌋.
  2. Order: key(parent) ≥ key(child) everywhere → maximum at the root.
  3. Siblings are not ordered: a heap is not a BST.
  4. Array form: children of i at 2i + 1, 2i + 2, parent ⌊(i − 1)/2⌋ (0-based).
  5. Max O(1); insert, delete-max O(log n); build O(n).
HeapSort(A, n) for i = n/2 − 1 downto 0 Heapify(A, n, i) // build for end = n − 1 downto 1 swap A[0], A[end] // max → end Heapify(A, end, 0) Heapify(A, n, i) // sift down big = larger of i, 2i+1, 2i+2 (< n) if big ≠ i: swap A[i], A[big] Heapify(A, n, big)

Heapsort: Θ(n log n) in every case, in place, not stable; a max heap sorts ascending.

Q You store a set of objects and want O(1) expected search time. Which data structure suits? asked in a recruitment paper

A hash table: h(key) gives the slot directly; expected O(1) with a good hash function and load factor α = n/m kept bounded (resize as it grows); worst case O(n) if all keys collide. BST or sorted array: O(log n).

  • MCQ (49th BCS 2025): a suffix tree is useful for? → fast string search: a pattern of length m in O(m)

Q Given the preorder and inorder traversals of a binary tree, reconstruct the tree; show the construction clearly. Bangladesh Satellite Company PLC AE (CSE), 21.08.2026 (sequences not reproduced; method on an example)

Preorder A B D E G C F, inorder D B G E A C F:

  1. First of preorder = root A; inorder splits {D B G E} | A | {C F}.
  2. B roots the left part: D | B | G E; then E roots {G E} with G on its left.
  3. C roots the right part, F its right child. Check postorder: D G E B F C A ✓

Trap: inorder + pre- (or post-) order fixes a unique tree; pre + post does not.

5Stacks & Queues

38th BCS · bank · BAPEX
Q Push(200), Push(500), Push(100), S = Pop(). What is the value of S? BAPEX AGM (ICT), 20.01.2023 (BUET)

A stack is LIFO: Pop removes the latest push. S = 100; left: 500 (top) over 200.

Q You have two stacks. Explain the logic required to implement a queue (FIFO) using only two stacks. 10 marks bank AP written
enqueue(x): S1.push(x) dequeue(): if S2.empty(): while not S1.empty(): S2.push(S1.pop()) // reverse if S2.empty(): error "empty" return S2.pop()

Pouring S1 into S2 reverses the order, so the oldest element reaches the top of S2. Each element is pushed and popped at most twice → amortised O(1) per operation (one dequeue may cost O(n)). Pour only when S2 is empty, or the order breaks.

6Arrays & Linked Lists

38th, 45th BCS · BPDB
Q The list 3, 5, 7, 11, 13, 17 is stored in sequence. Which of FIFO, queue, heap, linked list and stack has the least data movement when 11 is removed? Justify. 38th BCS Written, 2018

Linked list: point 7's next at 13 and free the node, 0 elements move. A FIFO/queue must dequeue 3, 5, 7 to reach 11 and re-enqueue them; a stack must pop 17 and 13 and push them back; an array heap moves its last key into the hole and re-heapifies.

Q Write int equilibrium(int arr[], int n) returning an index where the sum of the lower-index elements equals the sum of the higher-index ones, or −1. {−7, 1, 5, 2, −4, 3, 0} → 3; {1, 2, 3} → −1. BPDB AE (CSE), 24.02.2023 (BUET)
int equilibrium(int a[], int n) { long total = 0, left = 0; for (int i = 0; i < n; i++) total += a[i]; for (int i = 0; i < n; i++) { total -= a[i]; /* = right sum */ if (left == total) return i; left += a[i]; } return -1; }

Trace (total 0): i = 0: right 7, left 0 · i = 1: 6 vs −7 · i = 2: 1 vs −6 · i = 3: right −1 = left −1 → 3. {1, 2, 3}: (5, 0), (3, 1), (0, 3) → −1.

Recomputing both sums for each i is correct but O(n²); one running sum gives O(n) time, O(1) space.

Q What is a parameterized algorithm, and how does it improve code reusability and efficiency? BUET MSc in CSE, 03.10.2026

In code: one routine with its varying parts passed as parameters (type, comparator, size), e.g. qsort(base, n, size, cmp), templates, generics: one tested routine for many types (reuse), tuned by the caller (efficiency). In complexity theory: time f(k) · nO(1), fast when the parameter k is small (vertex cover O(2kn)).

  1. d[s] = 0, all other d[v] = ∞; min-priority queue of vertices.
  2. Take the unvisited u with the smallest d[u]; d[u] is final.
  3. Relax each edge (u, v, w): if d[u] + w < d[v], d[v] = d[u] + w, parent[v] = u.
  4. Repeat until empty; follow parent[ ] back for the path.

Q A pathfinding robot needs the shortest path. Which algorithm would you select? Explain why and describe its steps. asked in a recruitment paper

A*: Dijkstra with the queue ordered by f(n) = g(n) + h(n) (g = cost so far, h = straight-line or Manhattan distance to the goal). If h never overestimates (admissible) the path is still shortest, but far fewer cells are expanded. Steps: open = {start}; take least f; stop at the goal; else update neighbours' g and parent, add them. h = 0 gives Dijkstra.

Q How do you find single-source shortest paths in a graph with negative weights? Justify it, and show how you detect a negative-weight cycle. Petrobangla AM (IT), 16.09.2022 (BUET)
d[v] = ∞ for all v; d[s] = 0 // Bellman–Ford repeat |V| − 1 times: for each edge (u, v, w): if d[u] + w < d[v]: d[v] = d[u] + w for each edge (u, v, w): // extra pass if d[u] + w < d[v]: report "negative cycle"

Why V − 1 passes: a shortest path repeats no vertex, so it has ≤ V − 1 edges; after pass k every shortest path of ≤ k edges is right. Detection: if the extra pass still lowers a d[v], a negative cycle is reachable and shortest paths are undefined (as in the figure). Cost O(V · E).

VViva Rapid-Fire

bank IT · NTRCA 2023

Array? Same-type elements in contiguous memory; O(1) access by index.

Linked list? Nodes of (data, next pointer) anywhere in memory; size changes at run time.

Array vs list, which is better? Neither always: array for indexing and cache, list for frequent middle inserts/deletes.

Their problems? Array: fixed size, O(n) shifting. List: O(n) access, pointer overhead.

Stack? Queue? Stack = LIFO (push/pop at top); queue = FIFO (enqueue rear, dequeue front).

Stack vs queue? One open end vs two: undo, recursion, DFS vs scheduling, buffers, BFS.

Tree? Why use it? Non-linear, root and parent-child links, no cycles; hierarchies (folders, DB indexes), O(log n) search when balanced.

Binary vs sequential search? Halves the range: O(log n) vs O(n); needs sorted data.

D&C on a linked list? Yes, merge sort (split by slow/fast pointers); not binary search (no O(1) middle).

Quicksort? Pick a pivot, partition smaller | larger, recurse on both; avg n log n.
