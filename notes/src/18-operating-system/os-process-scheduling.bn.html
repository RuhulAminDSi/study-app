১প্রোগ্রাম বনাম প্রসেস ও PCB

সংজ্ঞা ★
সংজ্ঞা একটি প্রোগ্রাম হলো ডিস্কে রাখা নির্দেশনার নিষ্ক্রিয় ফাইল। একটি প্রসেস হলো সেই প্রোগ্রাম মেমোরিতে তুলে চালু হওয়া — তার কোড, ডেটা, প্রোগ্রাম কাউন্টার, সে যে রেজিস্টারগুলো ধরে আছে এবং খোলা ফাইলসহ। প্রোগ্রাম স্থির, প্রসেস গতিশীল — একটি প্রোগ্রাম একসঙ্গে অনেক প্রসেস হতে পারে।
বিষয়প্রোগ্রামপ্রসেস
প্রকৃতিনিষ্ক্রিয়, স্থিরসক্রিয়, গতিশীল
মেমোরিডিস্কই যথেষ্টমেইন মেমোরি লাগে
পরিচয়একটি ফাইলের নামPID, অনেক ইনস্ট্যান্স
জীবনযতদিন ফাইল আছেnew → running → terminated
PCB-র ঘরকী থাকেOS-র কেন দরকার
প্রসেস স্টেটNew · Ready · Running · Waiting · Terminatedঠিক করে কোন সারিতে আছে
প্রোগ্রাম কাউন্টারপরবর্তী নির্দেশনার ঠিকানাঠিক যেখানে থেমেছিল সেখান থেকেই চালু করতে
CPU রেজিস্টারঅ্যাকুমুলেটর, base, limit, স্ট্যাক, R0…Rnঅসমাপ্ত হিসাব মনে রাখা
CPU শিডিউলিং তথ্যঅগ্রাধিকার, সারির পয়েন্টারপরে কে চলবে ঠিক করা
মেমোরি ম্যানেজমেন্ট তথ্যপেজ টেবিল বেস, সেগমেন্ট টেবিল পয়েন্টারঠিকানা অনুবাদ
অ্যাকাউন্টিং তথ্যইউজার ও কার্নেল সময়, I/O গণনা, শিশুর PIDহিসাব, কোটা, পরিষ্কার
মনে রাখার কৌশল PCB হলো প্রসেসের পাসপোর্ট: PID বলে সে কে, স্টেট বলে কোথায়, PC ও রেজিস্টার মনে রাখে ঠিক কোথায় থেমেছিল; বাকিগুলো বলে সার কী ধরে আছে।
পরীক্ষার ফাঁদ (i) PCB একটি কার্নেল কাঠামো, OS-ই বানায়; প্রসেস কখনো তার ভেতরে লেখে না। (ii) প্রসেস তার PCB নয় — শেষ হলে দুটোই মুক্তি পায়। (iii) PID চলমান প্রসেসের মধ্যে অনন্য, পরে পুনরায় ব্যবহৃত হতে পারে।
সমাধানকৃত উদাহরণ ✍ একটি PCB ডাম্প পড়ো PID 4217, স্টেট Waiting, PC 121, base 240, limit 460, ইউজার সময় 128, কার্নেল সময় 12. (ক) এটি রেডি সারিতে নয় — এটি একটি I/O ঘটনার অপেক্ষায়। (খ) বৈধ ঠিকানা = 240 … 459। (গ) ব্যবহৃত CPU = 128 + 12 = 140 ইউনিট। (ঘ) PID নিজে শিডিউলিংয়ের চাবিকাঠি নয়; অগ্রাধিকার হলো।

২পাঁচ-অবস্থার মডেল ও সারিগুলো

সবচেয়ে বেশি আসে ★
সংজ্ঞা একটি প্রসেস ঠিক পাঁচটি অবস্থার একটিতে থাকে: new (তৈরি হচ্ছে), ready (মেমোরিতে, CPU-এর অপেক্ষায়), running (CPU ধরে আছে), waiting / blocked (CPU ছাড়া অন্য কোনো ঘটনার অপেক্ষায়) এবং terminated (শেষ, রিসোর্স মুক্ত)।
থেকে → পর্যন্তকী ঘটেকে করে
New → Readyভর্তিদীর্ঘমেয়াদি শিডিউলার
Ready → RunningCPU বরাদ্দস্বল্পমেয়াদি শিডিউলার
Running → Readyইন্টারাপ্ট, স্লাইস শেষ, বেশি অগ্রাধিকারার প্রসেস এলস্বল্পমেয়াদি শিডিউলার
Running → WaitingI/O অনুরোধ বা ঘটনার অপেক্ষাপ্রসেস নিজে
Waiting → ReadyI/O শেষ, ঘটনা ঘটেছেইন্টারাপ্ট হ্যান্ডলার
Running → Terminatedশেষ, ভুল, বা বন্ধ করা হয়েছেপ্রসেস নিজে
New → Terminatedভর্তি বাতিলদীর্ঘমেয়াদি শিডিউলার
সারিকী রাখে / কে খালি করে
জব সারিএখনো ভর্তি হয়নি; দীর্ঘমেয়াদি শিডিউলার
রেডি সারিমেমোরিতে CPU-এর অপেক্ষায়; স্বল্পমেয়াদি শিডিউলার
ডিভাইস সারিওই I/O-এর অপেক্ষায়; ডিভাইস কন্ট্রোলার
পরীক্ষার ফাঁদ তিনটি শিডিউলার আছে — দীর্ঘমেয়াদি (জব সারি), মধ্যবর্তী (প্রসেস বাইরে-ভেতরে সোয়াপ) ও স্বল্পমেয়াদি (CPU)। শুধু CPU শিডিউলারটিই অবিরাম চলে।
মনে রাখার কৌশল "রেডি চায় CPU, ওয়েটিং চায় অন্য কিছু।" দুটোই একইভাবে ফেরে — ঘটনা শেষ, প্রসেস আবার রেডি সারিতে যায়, সরাসরি CPU-তে নয়।
পরীক্ষার ফাঁদ শুধু CPU-এর অপেক্ষা মানে রেডি, ওয়েটিং নয় — এটিই সবচেয়ে বেশি জিজ্ঞাসিত অবস্থা-প্রশ্ন। ডিভাইস সারিতে থাকা প্রসেস মেমোরিতে থেকেও ওয়েটিং।
সমাধানকৃত উদাহরণ ✍ একটি প্রসেসের পথ ধরো আপনি একটি কমান্ড লিখলেন। (ক) দীর্ঘমেয়াদি শিডিউলার ভর্তি করলে new → ready। (খ) CPU শিডিউলার পাঠালে ready → running। (গ) প্রিন্টের অনুরোধ দিলেই running → waiting। (ঘ) প্রিন্টার শেষ করলে waiting → ready। (ঙ) আগে ঘড়ির ইন্টারাপ্টে স্লাইস শেষ হয়েছিল: এটি running → ready, running → waiting নয়।

লিখিত প্রশ্ন ★
সংজ্ঞা তৈরি: OS একটি PID নেয়, PCB বরাদ্দ করে পূরণ করে, অ্যাড্রেস স্পেস বানায়, খোলা ফাইল জুড়ে দেয় এবং PCB-কে রেডি সারিতে রাখে। সমাপ্তি: স্টেট টার্মিনেটেড হয়, মেমোরি ও ফাইল মুক্ত হয়, এক্সিট স্ট্যাটাস প্যারেন্টের কাছে যায়।
তৈরির ধাপযা ঘটে
১. PID নাওPID টেবিল থেকে; মুক্তির পর পুনর্ব্যবহার
২. PCB বরাদ্দকন্ট্রোল ব্লকের জন্য মেমোরি সংরক্ষিত
৩. প্রাথমিকায়নস্টেট, PC এন্ট্রি পয়েন্টে, অ্যাকাউন্ট = 0, সারির পয়েন্টার
৪. অ্যাড্রেস স্পেসপ্যারেন্টের ছবি কপি; পেজ/সেগমেন্ট টেবিল তৈরি
৫. খোলা ফাইলডেস্ক্রিপ্টর একই ইনোডের দিকে যায়
৬. রিসোর্সI/O, মেমোরি ও CPU কোটা
৭. কনটেক্সট প্রস্তুতপ্রথম পাঠানোর জন্য স্ট্যাক ও রেজিস্টার
৮. সারিতে ঢোকাPCB → রেডি সারি, কখনো সরাসরি running নয়
প্রসেস শেষ হওয়ার উপায়সাধারণ কারণ

ভুলে শেষফ্যাটাল এরর — শূন্যে ভাগ, অবৈধ মেমোরি রেফারেন্স
অন্য প্রসেস বন্ধ করেSIGKILL-এর মতো সিগন্যাল, যা ধরা যায় না
OS বন্ধ করেমেমোরি সীমা অতিক্রম, প্রোটেকশন ফল্ট, শাটডাউন
পরীক্ষার ফাঁদ প্যারেন্ট তার খবর না নেওয়া পর্যন্ত শেষ হয়ে যাওয়া শিশুকে জম্বি বলে: কাজ শেষ, কিন্তু এক্সিট স্ট্যাটাস ও কিছু টেবিল এন্ট্রি প্যারেন্ট অপেক্ষা করে। প্যারেন্ট আগে মারা গেলে শিশু হয় অরফান, init তাকে গ্রহণ করে।
মনে রাখার কৌশল "জন্ম রেডি, মৃত্যু শেষ।" তৈরি শেষ হয় রেডি সারিতে; সমাপ্তিতে PID ও PCB মুক্তি পায়। init অরফান গ্রহণ করে বলে কোনো জম্বি অসংগৃহীত থাকে না।
সমাধানকৃত উদাহরণ ✍ একটি শেল সেশন আপনি লিখলেন ls > out.txt। (ক) শেল দুইবার fork করে — একবার ls-এর জন্য, একবার রিডাইরেকশনের ডান পাশের জন্য। (খ) exec-এর আগে শিশু ফাইলটি খোলে; ইনোড ভাগ হয়, কপি নয়। (গ) exec ছবি বদলায় কিন্তু PID রাখে। (ঘ) ls শেষ হলে শেলের wait() তাকে সংগ্রহ করে, তাই জম্বি মিলিসেকেন্ডই থাকে।

সমাধানকৃত উদাহরণ ✍ তিনটি সময়ই হিসাব করো একটি কাজ t = 2-এ আসে, প্রথমবার t = 5-এ পাঠানো হয়, t = 9-এ I/O-র জন্য ব্লক হয়, t = 12-এ আবার পাঠানো হয় এবং t = 24-এ শেষ হয়; মোট CPU বার্স্ট 12। (ক) টার্নঅ্যারাউন্ড = 24 − 2 = 22। (খ) ওয়েটিং = 22 − 12 = 10; ফাঁক দিয়ে যাচাই — (5−2) + (12−9) = 6 সারিতে থেকে, আর শেষ পাঠানোর ভেতরে 4। (গ) রেসপন্স = 5 − 2 = 3। (ঘ) নন-প্রিমপটিভ হলে রেসপন্স 0 হতো — কিন্তু পাশের প্রসেসরা দিত।

OS · প্রক্রিয়া ও সিডিউলিংFCFS, SJF, প্রায়োরিটি

৮নন-প্রিমপটিভ: FCFS, SJF ও প্রায়োরিটি

সবচেয়ে বেশি আসে ★
সংজ্ঞা প্রসেস CPU রাখে যতক্ষণ না শেষ হয় বা ব্লক হয়। FCFS অ্যারাইভালের ক্রমে সেবা করে, SJF সবচেয়ে ছোট CPU বার্স্ট বাছে, প্রায়োরিটি শিডিউলিং সবচেয়ে উচ্চ অগ্রাধিকারার প্রসেস বাছে এবং টাই রাখে FCFS।
অ্যালগরিদমনিয়মভালোখারাপ
FCFSঅ্যারাইভালের ক্রমCPU সময়ে ন্যায্য, সহজ, স্টারভেশন নেইকনভয় ইফেক্ট: একটি লম্বা কাজ প্রতিটি ছোট কাজ দেরি করায়
SJFছোট বার্স্ট আগেন্যূনতম গড় অপেক্ষা, প্রমাণযোগ্যভাবে সেরাবার্স্ট আগেই জানা লাগে; লম্বা কাজ স্টার্ভ হতে পারে
SRTF (প্রিমপটিভ)ছোট বাকি সময় আগেগড় অপেক্ষাতেও সেরাবেশি সুইচ; বার্স্টের অনুমান লাগে
প্রায়োরিটিবেশি অগ্রাধিকারা আগেগুরুত্ব বোঝায়; জরুরি কাজে দ্রুত সাড়াকম অগ্রাধিকারার প্রসেস স্টার্ভ হয়
রাউন্ড রবিন (প্রিমপটিভ)পালা করে একটি টাইম কোয়ান্টামন্যায্য CPU ভাগ, সীমিত রেসপন্সকোয়ান্টাম ছোট হলে সুইচের খরচ
সমাধানকৃত উদাহরণ ১ ✍ FCFS বার্স্ট 24, 3, 3, সবাই t = 0-এ। P1 0–24, P2 24–27, P3 27–30। ওয়েটিং 0, 24, 27 → গড় 51/3 = 17 ms। দুটো 3 ms কাজ 24 ms কাজের পেছনে বসে ছিল — এটাই কনভয়।
সমাধানকৃত উদাহরণ ২ ✍ SJF বার্স্ট P1 = 6, P2 = 8, P3 = 7, P4 = 3। ক্রম P4 0–3, P1 3–9, P3 9–16, P2 16–24। ওয়েটিং 0, 3, 9, 16 → গড় 28/4 = 7 ms। একই সেটে FCFS দিলে 0, 6, 14, 21 → 10.25 ms।
পরীক্ষার ফাঁদ SJF গড় অপেক্ষার জন্য সেরা — টার্নঅ্যারাউন্ড বা রেসপন্সের জন্য নয়, ওজনযুক্ত সমন্বয়ের জন্যও নয়। বার্স্ট আগে থেকে জানা লাগে; বাস্তবে OS ইতিহাস থেকে অনুমান করে, তাই SRTF আসলে "শর্টেস্ট রিমেইনিং টাইম নেক্সট"।
মনে রাখার কৌশল SJF-র জন্য "ছোট আগে, লম্বা পরে"; FCFS-এর রোগ কনভয়; প্রায়োরিটির রোগ স্টারভেশন, আর তার ওষুধ এজিং — অপেক্ষার সময় বাড়লে কার্যকর অগ্রাধিকারাও বাড়ে।
এজিং ঠিকভাবে প্রতিটি অপেক্ষার ধাপ পর প্রসেসের কার্যকর অগ্রাধিকারা বাড়ানো যায়, অথবা "অনেক দিন ধরে অপেক্ষা করেছে" ধরে সেটিকে উন্নীত করা যায়। এজিং কেবল স্টারভেশন ঠিকায়: ডেডলকে এর কোনো প্রভাব নেই, কারণ সেখানে কিছুই এগোয় না এবং অগ্রাধিকারা পুনরায় মূল্যায়ন হয় না। এজিং ছাড়া খাঁটি প্রায়োরিটি সারি প্রায় সব বাস্তব নকশায় গ্রহণ করা হয় না।

OS · প্রক্রিয়া ও সিডিউলিংSRTF ও রাউন্ড রবিন

৯প্রিমপটিভ: SRTF ও রাউন্ড রবিন

গ্যান্ট চার্ট ★
সংজ্ঞা SRTF নতুন আসা কোনো কাজের বাকি সময় ছোট হলেই চলমান প্রসেসকে প্রিম্পট করে। রাউন্ড রবিন (Round Robin) একটি গোলাকার রেডি সারি রাখে এবং প্রতি টাইম কোয়ান্টাম q-এর পর প্রিম্পট করে; সময় অবশিষ্ট থাকলে প্রসেসটি সারির পিছনে যায়।
সমাধানকৃত উদাহরণ ১ ✍ রাউন্ড রবিন, q = 4 P1 = 24, P2 = 3, P3 = 3, সবাই 0-এ। গ্যান্ট: P1 0–4, P2 4–7, P3 7–10, এরপর P1 একাই 10–30। ওয়েটিং = সমাপ্তি − বার্স্ট: P1 = 30 − 24 = 6, P2 = 7 − 3 = 4, P3 = 10 − 3 = 7 → গড় 17/3 = 5.67 ms। এই সেটে SJF দিলে 0, 3, 6 → 3 ms; FCFS 17 ms।
সমাধানকৃত উদাহরণ ২ ✍ SRTF, ভিন্ন সময়ে অ্যারাইভাল P1 (0, 8), P2 (1, 4), P3 (2, 9), P4 (3, 5)। t = 1-এ P2 (4) হারায় P1-এর বাকি 7-কে → প্রিম্পট; t = 5-এ P4 (5) হারায় P1 (7) ও P3 (9)-কে; t = 10-এ P1 (7) হারায় P3 (9)-কে। গ্যান্ট: P1 0–1 | P2 1–5 | P4 5–10 | P1 10–17 | P3 17–26। সমাপ্তি 17, 5, 26, 10 → টার্নঅ্যারাউন্ড 17, 4, 24, 7 → গড় 13 ms; ওয়েটিং 9, 0, 15, 2 → গড় 6.5 ms।
টাইম কোয়ান্টাম qআচরণ
q বড় (q ≥ বার্স্ট)বাস্তবে প্রিম্পশন হয় না → RR আসলে FCFS হয়ে যায়
q ছোটঅনেক কনটেক্সট সুইচ; বেশি সময় সোয়াপেই যায়, থ্রুপুট কমে
গড় বার্স্টের সামান্য বেশিসাধারণ পছন্দ — ইন্টারঅ্যাক্টিভ থাকার মতো দ্রুত, আবার অধিকাংশ কাজ কয়েক পালায় শেষ
সবচেয়ে খারাপ রেসপন্সnটি রেডি প্রসেসে সীমাবদ্ধ (n − 1) × q
মনে রাখার কৌশল "কোয়ান্টাম আসলে অপেক্ষার একটা প্রতিশ্রুতি: ছোট q ন্যায্যতা ও দ্রুত প্রথম সাড়ার কথা বলে এবং সেজি খরচে চোখায়; বড় q দক্ষতার কথা বলে এবং রেসপন্স টাইমে ভরি করে।"
পরীক্ষার ফাঁদ (i) RR-তে ওয়েটিং টাইম হলো সমাপ্তি − অ্যারাইভাল − বার্স্ট, প্রতি কোয়ান্টাম গুনে "সারিতে থাকা সময়" নয়। (ii) কোয়ান্টামের ভেতরেই শেষ হয়ে গেলে প্রসেস আর অপেক্ষা করে না। (iii) RR প্রিমপটিভ; "স্লাইসে শেষ পর্যন্ত চালানো" বলে যা লেখা সেটা FCFS।
আবার থ্রেড বনাম প্রসেস শিডিউলিং প্রতিটি প্রসেসে একটি থ্রেড থাকলে RR প্রতিটি প্রসেসকে পালা দেয় — একটি প্রসেসের পঞ্চাশ থ্রেড থাকলে এটি অন্যায়। আধুনিক কার্নেল তাই থ্রেড শিডিউল করে, যাতে প্রতিটি চালনোগার্য থ্রেড নিজের পালা পায়।

OS · প্রক্রিয়া ও সিডিউলিংমাল্টিলেভেল ও রিয়েল-টাইম

১০মাল্টিলেভেল সারি, ফিডব্যাক ও রিয়েল-টাইম

অগ্রাসর ★
সংজ্ঞা একটি মাল্টিলেভেল সারি স্থায়ী শ্রেণি রাখে — সিস্টেম প্রসেস ছোট কোয়ান্টাম ও রাউন্ড রবিনে, ইউজার প্রসেড FCFS বা SJF-তে। একটি মাল্টিলেভেল ফিডব্যাক সারি (MLFQ) সরতে দেয়: পুরো কোয়ান্টাম খাটিয়ে ফেললে প্রসেস নিচে নামে, বেশি অপেক্ষা করলে উপরে ওঠে।
বিষয়মাল্টিলেভেল সারিমাল্টিলেভেল ফিডব্যাক সারি
চলাচলনেই — শ্রেণি স্থায়ীপ্রসেস উপরে-নিচে যায়
প্রতি সারির কোয়ান্টামপ্রতি শ্রেণিতে একটিঅগ্রাধিকারা কমলে বাড়ে
শক্তিসহজ ও সস্তা; প্রতি শ্রেণিতে আলাদা ভর্তি নীতিইন্টারঅ্যাক্টিভ ও CPU-বাউন্ড কাজ নিজে থেকেই আলাদা করে
দুর্বলতানিচের শ্রেণি স্টার্ভ হতে পারেস্টারভেশন এড়াতে প্রমোশন নিয়ম লাগে
রিয়েল-টাইম নীতিঅগ্রাধিকারার নিয়ম
রেট মনোটনিকস্থির: ছোট পিরিয়ড → বেশি অগ্রাধিকারা
EDFপরিবর্তনশীল: সবার আগে ডেডলাইন আছে যার
হার্ড রিয়েল-টাইম এক লাইনে এক প্রসেসরে nটি পিরিয়ডিক কাজের জন্য প্রতিটির C ≤ T লাগে এবং মোট ব্যবহার ≤ n(2^(1/n) − 1): ১ কাজ ১০০ %, ২ কাজ ৮৩ %, ৩ কাজ ৭৮ %।
পরীক্ষার ফাঁদ EDF সেরা — এটি কেবল তখনই ডেডলাইন বাদ দেয় যখন কোনো নির্ভেজ্ঞ সূচি-ই নেই। রেট মনোটনিক কেবল স্থির অগ্রাধিকারায় সেরা এবং ৭৬ %-এর বেশি ব্যবহারে EDF-এর কাছে হেরে যায়।
মনে রাখার কৌশল "স্থায়ী শ্রেণি সরে না; ফিডব্যাক সারি শিডিউলারকে শেখায়।" আর "রেট স্থির, ডেডলাইন প্রতি মুহূর্তে আবার পড়া হয়।"
পরীক্ষার ফাঁদ দীর্ঘ শিডিউলার খালি না থাকলে কেবল সর্বোচ্চ সারিতেই সেবা দেয়, তাই নিচের শ্রেণি অনির্দিষ্টকাল অপেক্ষায় থাকে — যা এজিং বা প্রমোশনই ঠিক করে।
সমাধানকৃত উদাহরণ ✍ দুটি পিরিয়ডিক কাজ একটি কন্ট্রোল লুপ প্রতি 40 ms-এ 10 ms চায়; একটি লগার প্রতি 100 ms-এ 5 ms চায়। (ক) ব্যবহার = 10/40 + 5/100 = 0.25 + 0.05 = 0.30। (খ) দুটি কাজ, তাই রেট মনোটনিক সীমা 2(2^(1/2) − 1) ≈ 0.828; 0.30 < 0.828, তাই সেটটি রেট মনোটনিকে চালানোর উপযোগী। (গ) EDF একই ডেডলাইন মেলায় অনেক বেশি ভার নিতে পারে। (ঘ) লুপের পিরিয়ড 12 ms হলে ব্যবহার ≈ 0.883 > 0.828, তখন রেট মনোটনিক আর নিশ্চয়তা দিতে পারে না, EDF ব্যবহার করতে হবে।

নিজস্ব স্ট্যাক ও রেজিস্টার

কার্নেল-লেভেল একটি থ্রেড থামায়

many-to-one · one-to-one · many-to-many

কার্নেল শুধু কার্নেল থ্রেড শিডিউল করে

IPC: shm, pipe, FIFO, queue, socket, signal

অ্যানোনিমাস পাইপ = সম্পর্কিত প্রসেস

সেমাফোর P = −1 (ব্লক হতে পারে), V = +1

মিউটেক্সের মালিক আছে, সেমাফোরের নেই

empty + full = বাফারের আকার N

প্রোডিউসার empty আগে, কনজিউমার full আগে

TAT = সমাপ্তি − অ্যারাইভাল

WT = TAT − বার্স্ট · রেসপন্স = প্রথম চাল − অ্যারাইভাল

SJF = ন্যূনতম গড় অপেক্ষা

FCFS = কনভয় · প্রায়োরিটি = স্টারভেশন

RR: q বড় → FCFS, q ছোট → সুইচ বেশি

RR-এ সবচেয়ে খারাপ রেসপন্স = (n − 1)q

MLFQ CPU-বাউন্ডকে নামায়, অপেক্ষাকারীকে ওঠায়

EDF সেরা · RM সীমা n(2^(1/n) − 1)

MCQ-র জন্য সেরা ১২টি এক-লাইনের কথা

  1. পাঁচটি অবস্থা, চার নয় — new আলাদা
  2. রেডি মানে শুধু CPU-র অপেক্ষা
  3. তিন শিডিউলার: দীর্ঘ, মধ্যবর্তী, স্বল্পমেয়াদি
  4. PCB একটি কার্নেল কাঠামো
  5. থ্রেড স্ট্যাক নয়, অ্যাড্রেস স্পেস ভাগ করে
  6. many-to-one: একটি ব্লকিং কল সব থ্রেড থামায়
  1. শেয়ার্ড মেমোরি দ্রুততম, কিন্তু নিজের লক লাগে
  2. P কমায়, V বাড়ায়
  3. SJF গড় অপেক্ষায় সেরা
  4. FCFS-এর রোগ কনভয়
  5. q বাড়লে RR → FCFS হয়ে যায়
  6. EDF সেরা; RM সীমা n(2^(1/n) − 1)

  1. প্রসেস ও PCB — মেমোরিতে তুলে চলা একটি প্রোগ্রাম, সঙ্গে কোড, ডেটা, প্রোগ্রাম কাউন্টার, রেজিস্টার ও খোলা ফাইল। PCB = প্রসেস স্টেট, প্রোগ্রাম কাউন্টার, CPU রেজিস্টার, CPU শিডিউলিং তথ্য, মেমোরি ম্যানেজমেন্ট তথ্য, অ্যাকাউন্টিং তথ্য। 3
  2. ডায়াগ্রাম — new → ready (ভর্তি); ready → running (পাঠানো); running → ready (ইন্টারাপ্ট বা স্লাইস শেষ); running → waiting (I/O বা ঘটনার অপেক্ষা); waiting → ready (সমাপ্তি); running → terminated; new → terminated (ভর্তি বাতিল)। শুধু CPU-এর অপেক্ষা মানে রেডি সারি, ডিভাইস সারি নয়। 3
  3. FCFS — P1 0–24, P2 24–27, P3 27–30। ওয়েটিং 0, 24, 27 → গড় 51/3 = 17 ms। 2
  4. RR, q = 4 — P1 0–4, P2 4–7, P3 7–10, এরপর P1 একাই 10–30। ওয়েটিং = সমাপ্তি − বার্স্ট: 6, 4, 7 → গড় 17/3 = 5.67 ms। গড় অপেক্ষায় সেরা: SJF (প্রিমপটিভ SRTF) — 0, 3, 6 → 3 ms। 2
