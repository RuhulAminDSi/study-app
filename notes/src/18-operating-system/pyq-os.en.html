1What Is an OS, and Why Do We Need It?

written
Q What is an operating system? Why do we need an operating system? · 38th BCS Written (2018)
Definition An operating system (OS) is the system software that manages the hardware resources and provides common services to programs; it sits between users/applications and the hardware (Windows, Linux, macOS, Android).
  1. Resource manager: shares CPU, memory, disks and I/O fairly among programs
  2. Extended machine: hides the hardware behind files, processes, virtual memory, used via system calls
  1. Protection: user/kernel mode, memory protection, access control
  2. Convenience, efficiency: CLI/GUI; multiprogramming keeps the CPU busy

Functions: process · memory · file · I/O device management · security · user interface · networking.

2OS ↔ Hardware Relationship

written
Q What is the relationship between the operating system and computer hardware? · 38th BCS Written (2018)
  • The OS is the only software that drives the hardware directly (drivers, interrupt handlers); programs reach it only through system calls.
  • Hardware keeps the OS in charge: mode bit (user/kernel), privileged instructions, timer interrupt, MMU protection.
  • Firmware (BIOS/UEFI) loads the kernel at boot; the OS is hardware-specific (drivers, HAL).

4Deadlock: Detection and Protection

written favourite
Q What is deadlock? Describe the ways of detecting and protecting against deadlock. · 38th BCS Written (2018)
Deadlock A set of processes is deadlocked when each waits for a resource that only another process in the set can release, so none can ever proceed.

Four necessary conditions (Coffman, 1971), all at once: mutual exclusion · hold and wait · no preemption · circular wait.

Protection (1): prevention, deny one condition

ConditionPrevent it by …
Mutual exclusionmake the resource sharable (read-only files, spooled printer); often impossible
Hold and waitrequest everything at start, or release all before asking again
No preemptiontake resources away from a process that has to wait
Circular waitnumber resource types; request only in increasing order
  • Protection (2), avoidance: processes declare their maximum need; grant a request only if the system stays in a safe state (Banker's algorithm, p. 4).
  • Detection, one instance per resource: wait-for graph; cycle ⇔ deadlock.
  • Detection, several instances: a cycle is only a warning; run the detection algorithm (Work = Available; finish any process with Request ≤ Work, add its Allocation). Processes left over are deadlocked.
  • Recovery: abort all deadlocked processes or one at a time; or preempt resources (pick a victim, roll it back, limit its rollbacks).
  • Ignore (ostrich approach): Windows and Linux leave rare deadlocks to the user.
Detection example ✍ A, B have 2 instances each, all allocated: Available (0, 0). Allocation / Request: P0 (1,0)/(0,1) · P1 (1,1)/(1,0) · P2 (0,1)/(0,0). P2 finishes → Work (0,1) → P0 → (1,1) → P1: no deadlock. If P2 requested (1,0) instead, nobody could start: P0, P1, P2 deadlocked.
Memory trick Conditions M-H-N-C: "My House, No Car". Handling P-A-D-R-I: prevent, avoid, detect, recover, ignore.
Exam trap List all four conditions, and answer "protecting" with prevention and avoidance; recovery alone is not protection.

5The Four Conditions Are Not Sufficient

written
Q The four necessary conditions for deadlock are mutual exclusion, hold and wait, no preemption and circular wait. Give an example showing that these conditions alone are not sufficient for a resource deadlock. · DPDC AM (ICT) 27.06.2025
  1. R1 and R2 have 2 instances each. R1 is held by P2 and P3, R2 by P1 and P4. P1 requests R1; P3 requests R2.
  2. All four conditions hold, including the circular wait P1 → R1 → P3 → R2 → P1.
  3. But P4 needs nothing more: it finishes and frees R2 → P3 gets it, finishes, frees R1 → P1 gets R1. No deadlock.
Conclusion With one instance per resource type a cycle is necessary and sufficient. With several instances the four conditions are only necessary: a process outside the cycle can release an instance and break it.

6Banker's Algorithm and Safe Counting

MCQ

Asked: the most prominent method to avoid deadlock → Banker's algorithm (Dijkstra). 49th BCS ICT (2025)
Need = Max − Allocation. Work = Available; repeatedly finish a process with Need ≤ Work and add its Allocation. All finish → safe.

Example ✍ 12 tape drives; holds/max: P0 5/10, P1 2/4, P2 2/9 → Available 3; Need 5, 2, 7. P1 → Work 5 → P0 → 10 → P2 → 12. Safe: ⟨P1, P0, P2⟩.
Asked MCQ ✍ "A system has 4 processes and 3 resources. To avoid deadlock, the maximum number of processes that can execute simultaneously is: 3 / 2 / 1 / 4." 49th BCS ICT (2025)
Standard reading: 3 identical instances, each process needs up to k = 2. Worst case each holds k − 1 = 1 and one spare must remain: n(k − 1) + 1 ≤ R → n + 1 ≤ 3 → n = 2, option (b).
Exam trap "3" is tempting, but then each of the 3 can hold one instance and wait for a second: all deadlock. If each needed only one instance there would be no hold-and-wait at all, so the question only makes sense with k = 2.

7Starvation by Repeated Preemption

fill in the blank

Asked: "If resources are always preempted from the same process, ____ can occur." → starvation. When recovering by preemption, add the number of rollbacks to the victim cost so the same process is not chosen forever. Deadlock: everyone in the cycle waits; starvation: one process waits while others run (cure: aging). asked in a recruitment paper

8Process vs Thread

bank written
Q Explain the fundamental difference between a process and a thread. · Bank Assistant Programmer (written)
Key difference A process is a program in execution with its own address space and resources; a thread is a unit of CPU execution inside a process with its own PC, registers and stack, sharing the process's code, data, heap and open files.

Q Give two distinct advantages of using threads over processes. · Bank Assistant Programmer (written)
  1. Economy: creating and switching threads is much cheaper: no new address space, page table or TLB flush.
  2. Resource sharing: threads share memory and files directly, so they communicate without IPC calls.

Also: responsiveness (the GUI stays live while a worker runs) and scalability on multicore CPUs.

9Process Control Block (PCB)

written + MCQ
Q Write the names of four pieces of information stored in a PCB. · RPGCL AM (ICT) 2022

The PCB is the kernel's record of one process, saved and reloaded at every context switch. Any four of:

  • PID and process state
  • program counter, CPU registers
  • scheduling info (priority, queues)
  • memory info (base/limit, page table), accounting, I/O status (open files)

MCQ "PCB includes PID / state / PC / all the above" → all the above. 49th BCS ICT (2025)

12Starvation in SJF

written
Q Explain starvation in SJF scheduling and name a starvation-free scheduling algorithm. · RPGCL AM (ICT) 2022

SJF always runs the shortest waiting job. If short jobs keep arriving, a long job is postponed indefinitely: starvation. Cure: aging, raising priority with waiting time, e.g. HRRN ratio (W + S) / S.

Starvation-free: Round Robin (wait ≤ (n − 1)·q), FCFS, HRRN. Priority scheduling starves like SJF.

Memory trick "Short jobs jump the queue; age the old ones." SJF gives the minimum average waiting time but needs the next burst, predicted by τn+1 = α tn + (1 − α) τn.

13The Producer–Consumer Problem

10 marks
Q Explain the producer–consumer problem in operating systems. What specific synchronization issue must be solved? 10 marks · Bank Assistant Programmer (written)
The problem Also called the bounded-buffer problem. A producer puts items into a shared buffer of N slots and a consumer removes them, concurrently and at different speeds. The producer must wait when the buffer is full, the consumer when it is empty, and only one may change the buffer at a time.

The synchronization issues

  1. Mutual exclusion (race condition): buffer and counter are shared; count++ is load–add–store, so interleaving corrupts it. Buffer access is a critical section.
  2. Condition synchronization: block the producer on a full buffer, the consumer on an empty one, without busy waiting.
  3. No deadlock or starvation: mutual exclusion, progress, bounded waiting.
Race on count = 5 ✍ P: r1 = count (5), r1 + 1 = 6 · C: r2 = count (5), r2 − 1 = 4 · P stores 6 · C stores 4: one item in and one out should leave 5.

Solution with three semaphores

semaphore mutex = 1, empty = N, full = 0; producer: while (1) { item = produce(); wait(empty); wait(mutex); buf[in] = item; in = (in+1) % N; signal(mutex); signal(full); }
consumer: while (1) { wait(full); wait(mutex); item = buf[out]; out = (out+1) % N; signal(mutex); signal(empty); consume(item); }
Exam trap If the producer does wait(mutex) before wait(empty), on a full buffer it sleeps holding the mutex; the consumer blocks on mutex: deadlock.
Memory trick "Count first, lock second": wait on empty/full, then mutex; signal in reverse. Start values 1, N, 0.

Also accepted: a monitor with condition variables (Java synchronized + wait/notify, BlockingQueue). Real uses: print spooler, keyboard buffer, message queues.

Total page faults = 6 (3 cold + 3), hits = 4 → fault rate 60%.

At ref 2 the frames hold 1, 7, 6, last used at refs 7, 5, 6 → 7 is least recent. At the next 7: 6 is least recent.

15Thrashing

MCQ

Asked: thrashing occurs when → processes spend more time swapping pages than executing.

Cause: the working sets of the active processes exceed the free frames → constant page faults → CPU utilization drops → a naive long-term scheduler admits more processes → worse.

Cures: working-set model (Σ WSS > frames → suspend a process), page-fault-frequency control, local replacement, more RAM.

16Spooling

asked twice

SPOOL = Simultaneous Peripheral Operations On-Line. Output for a slow device is first written to a queue on disk; the device takes jobs one by one, so the CPU never waits for the printer. Used for printer management (print queue), not CPU scheduling, deadlock detection or memory allocation. 49th BCS ICT (2025) and another paper

19Viva Rapid-Fire

say it in one breath

Q. What is a mobile operating system? Bank IT viva
An OS for phones and tablets that manages the hardware and apps, with touch UI, power management, telephony and app sandboxing. Android (Linux kernel) and iOS (XNU kernel).

Q. Kernel? The privileged core of the OS, always in memory.

Q. System call? A program's request to the kernel (open, read, fork); switches user → kernel mode.

Q. Context switch? Saving one process's state in its PCB and loading another's; pure overhead.

Q. Multiprogramming vs multitasking? Several jobs in memory to keep the CPU busy · time-sharing so users interact.

Q. Deadlock vs starvation? All wait on each other · one waits forever while others run.

Q. Semaphore vs mutex? Counting signal (0…N) · a lock owned by the thread that took it.

Q. Virtual memory? Running programs larger than RAM by keeping only needed pages in memory (demand paging).

Q. Page fault? A reference to a page not in RAM; the OS loads it from disk.

Q. Orphan process? Its parent ended first; PID 1 adopts it.

Q. Spooling vs buffering? Disk queue shared by many jobs · memory area that smooths one transfer.

Memory trick Viva answers: definition + one example + one contrast, in under 15 seconds.
