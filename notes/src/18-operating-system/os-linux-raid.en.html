OS ▸ Linux Permissionschmod & chown

2 File Permissions: chmod & chown ★ Highest-yield

Permission model Every file has 3 user classes: owner, group, others. Each gets r=4, w=2, x=1 bits. chmod NNN file — each digit = r×4+w×2+x×1.
CommandPurposeExample
chmod 755 fileowner=rwx, group=r-x, others=r-xstandard for executables
chmod 644 fileowner=rw-, group=r--, others=r--standard for data files
chmod 701 fileowner=rwx, group=---, others=--xgroup gets NO bits (0=---)
chown user:group filechange owner and groupchown www:www index.html
chgrp group filechange group onlychgrp dev project/
Memory trick r=4, w=2, x=1 → add them: rwx=7, rw-=6, r-x=5, r--=4, --x=1, ---=0. Write the 3-digit octal left to right: owner · group · others.
Exam trap chmod 701: middle digit is 0 = --- (no access for group), NOT --x. Many candidates write 701 as rwx--x--x — WRONG. 0 = ---, 1 = --x.
Worked example chmod 755 script.sh: 7=rwx(owner), 5=r-x(group), 5=r-x(others) → -rwxr-xr-x. Standard for web server directories.
Exam trap chown changes ownership. chmod changes permissions. They are separate operations — a common confusion in MCQs.

OS ▸ RAIDRedundant Array of Independent Disks

4 RAID: Concepts & Levels ★ Bank/PSU favourite

RAID = Redundant Array of Independent Disks. Combines multiple physical disks into one logical unit. Goals: performance (striping) or reliability (mirroring/parity) or both.
LevelTechniqueMin disksFault toleranceUsable capacityBest for
RAID 0Striping20N × diskSpeed (video editing)
RAID 1Mirroring21 drivedisk_sizeOS drives, critical data
RAID 5Dist. parity31 drive(N−1) × diskFile servers, NAS
RAID 6Double parity42 drives(N−2) × diskLarge arrays
RAID 10Mirror+stripe4 (even)1 per pairN/2 × diskBanking databases ★
Memory trick RAID 5 usable = (N−1)×disk. One disk "worth" of space goes to parity — distributed, but the math works as if one disk is consumed. Exams test this formula constantly.
Exam trap RAID ≠ backup. RAID protects against hardware disk failure only — not against ransomware, accidental deletion, or data corruption (those get mirrored too!).

OS ▸ RAIDCapacity Formulas & Numericals

5 RAID Capacity Formulas ★ Numerical favourite

Formula sheet Memorise these 5 formulas — they cover every RAID numerical in Bangladesh exams.
RAIDUsable capacity formula4 × 2 TB example
RAID 0N × disk_size4 × 2 = 8 TB
RAID 1disk_size (one copy)2 TB (regardless of N)
RAID 5(N − 1) × disk_size(4−1) × 2 = 6 TB
RAID 6(N − 2) × disk_size(4−2) × 2 = 4 TB
RAID 10(N / 2) × disk_size(4/2) × 2 = 4 TB
Worked example 1 BSCS AP 2026: You have 4 drives of 2 TB each. Calculate usable storage for RAID 0, RAID 5, and RAID 10.
  • RAID 0: 4 × 2 = 8 TB (no redundancy — any failure loses all data)
  • RAID 5: (4−1) × 2 = 6 TB (1 drive for parity; tolerates 1 failure)
  • RAID 10: (4/2) × 2 = 4 TB (2 mirrored pairs striped together)
Worked example 2 Combined Bank AME 2026: 5 drives × 4 TB each in RAID 5. Why not 20 TB?
  • Usable = (5−1) × 4 = 16 TB
  • 4 TB is consumed by distributed parity — one drive's equivalent across all 5
  • Parity enables reconstruction if exactly ONE drive fails
Memory trick For banking questions: which RAID? → RAID 10 (mirror pairs that stripe = best I/O performance + redundancy, no parity calculation delay). RAID 5 is acceptable for file/archive servers.
Exam trap RAID 10 needs an even number of disks (minimum 4). RAID 5 needs minimum 3. RAID 6 needs minimum 4. Confusing RAID 1 (min 2) with RAID 10 (min 4) is a common error.
Exam trap RAID 5 tolerates exactly 1 disk failure. Two simultaneous failures → data lost. Use RAID 6 for 2-drive tolerance.

OS ▸ RAIDFailure Recovery & Drive Types

6 RAID Failure Recovery & Drive Types

RAID failure recovery procedure

  1. Controller detects failure → array continues in degraded mode (using remaining disks + parity)
  2. Replace failed drive with a new drive of equal or greater capacity
  3. Controller rebuilds (reconstructs) lost data from parity/mirror onto new drive automatically
  4. During rebuild: array is vulnerable — a second failure in RAID 5 will lose all data

Linux root login

Root login is disabled by default for security:
① Attacker must guess both username AND password
② sudo logs every privileged action with username
③ Prevents accidental destructive root commands
→ Use sudo command for single commands
→ Use su - for full root shell (not recommended)

PUE formula

PUE = Total facility power / IT equipment power
PUE = 1.0 = perfect (impossible)
Industry average ≈ 1.5
Green data centres: PUE < 1.2
Lower PUE = more efficient
Memory trick Which RAID is best for a banking transaction server? → RAID 10: combines mirroring (full redundancy per pair) + striping (high throughput). No parity calculation penalty. Fast rebuild.
Exam trap RAID is NOT a backup. A RAID array protects against hardware disk failure. Ransomware, accidental deletion, and fire destroy all copies simultaneously. Always have a separate backup.

Written (5 marks): Explain RAID 0, 1, 5, and 10. Include usable capacity formula and fault tolerance for each. Which would you recommend for a Bangladesh bank's core transaction database and why?
Model answer:
RAID 0: N×disk, 0 fault — speed only, no redundancy.
RAID 1: disk_size, 1 fault — mirroring, 50% usable.
RAID 5: (N-1)×disk, 1 fault — distributed parity, min 3 disks, balance of space and safety.
RAID 10: N/2×disk, 1 per pair — mirror+stripe, min 4 disks.
Recommendation: RAID 10 for banking — high I/O throughput (striping) + full redundancy (mirroring) + no parity calculation delay + fast rebuild. RAID 5 for less critical storage (reports, archives).
