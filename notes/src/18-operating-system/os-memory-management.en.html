1The Hierarchy, Binding and Addresses

basics ★
Definition Memory management controls how memory is allocated to and reclaimed from processes. Its two goals: maximise memory utilisation and minimise the time spent swapping. It also supplies abstraction (memory looks like a flat list of addresses), protection (no process touches another's memory) and sharing.

Logical vs physical The logical (relative) address is what the program generates — counted from 0, unrelated to where the program sits. The physical (absolute) address is the address in the real RAM unit; only the memory hardware sees it. Translating one into the other is relocation: because it happens while the program runs, the OS may move a process at any moment.
Base + limit Relocation (base) register = where the partition begins; limit register = its size. Every logical address a is checked against the limit, then physical = logical + base. If a ≥ limit the CPU traps and aborts the process.
Memory trick "Compile = frozen, load = pinned, run = live." Only execution-time binding lets a program move without being recompiled — which is why every real machine has an MMU. Hold on to this: the program sees logical, only the chips see physical.
Exam trap (i) Binding at load time still needs relocatable code; execution time is what makes swapping and compaction possible. (ii) Absolute addresses mean recompiling for every new location. (iii) Base + limit belong to contiguous memory, the page table to paging.

OS · Memory ManagementFragmentation & swapping

2Fragmentation, Contiguous Allocation & Swapping

before paging ★
Definition Contiguous allocation gives each process one unbroken block of memory, guarded by a base (relocation) register and a limit register. Fragmentation is free memory that cannot be used: internal = space inside a block already handed out, external = free space between blocks, not contiguous enough for the next request. Internal waste can never be recovered; external waste is cured only by compaction.
StrategyPicks the hole that is…Verdict
First fitfirst big enough, from the startfast; slivers left at the end
Best fitsmallest hole that still fitsworst leftover slivers
Worst fitlargest hole availabledestroys the big block too soon
Next fitfirst that fits, resuming where it stoppedspreads the damage evenly
Exam trap (i) "Which suffers external fragmentation?" → contiguous and segmentation, never paging; "which internal?" → paging and fixed partitions. (ii) Compaction needs relocation hardware, i.e. execution-time binding. (iii) A swap can double the free space on paper and still leave no block big enough.
Swapping Swapping moves an entire process out to the swap device on disk and later brings it back, which lets the system run more processes than physical memory and is a convenient moment to compact. Its whole cost is disk I/O. Swapping ≠ paging: swapping moves a whole process on the OS's initiative; paging moves one page when the program itself references it, and is invisible to the process.
Worked example ✍ what does a swap cost? A disk transfers at 10 MB/s with ~10 ms seek. (a) A 1 MB process out and back = 200 ms + 20 ms = 220 ms. (b) A 33 MB process swapped twice each way = 132 MB ÷ 10 = 13.2 s. (c) One 4 KB page instead = 0.4 ms — 550× cheaper. (d) Paging, which moves only the pages actually needed, is therefore what keeps a machine responsive.
Memory trick "Inside = internal, outside = external." Compaction can only fix the outside kind — the inside kind is baked into the size you handed over. Contiguous allocation needs one whole free hole; paging never does, which is exactly why paging exists.
In practice Demand paging has almost killed classic swapping. A machine with plenty of RAM never swaps; when it does, the kernel pages out cold anonymous memory, and the swap file is a last resort, not a workspace.

3Paging: Pages, Frames, Page Table, Translation

most tested ★
Definition Paging divides both memories into fixed-size blocks: a process's logical memory into pages, physical memory into frames, page = frame in size. A process may then occupy any frames in any order — contiguity is gone. The page table is an array of page-table entries (PTEs), one per page, each holding a frame number plus control bits.
TermMeaning
Pagea fixed-size block of one process's logical memory
Framea fixed-size block of physical memory, same size as a page
Page tableper-process array of PTEs; it is the process's map
PTEframe number + valid / protection / dirty / reference
Free-frame listframes nobody is using, available at once
Exam trap (i) The offset is copied unchanged — never add it to anything but f·P. (ii) Paging removes external fragmentation only; the last page is usually part-full, wasting on average half a page per process. (iii) Frames are the unit of allocation, so nothing inside a frame can be shared.
The four formulas — every paging question is one of them

page number p = ⌊LA ÷ P⌋ = LA div P

offset d = LA mod P

physical address PA = f·P + d

pages in a process size ÷ P

If P = 2ⁿ bytes the offset needs exactly n = log₂P bits and the page number takes the rest of the address. 4 KB = 2¹², so a 32-bit address splits into 20-bit p + 12-bit d.

Worked example ✍ logical 3000, page 2 → frame 5 P = 1 KB = 1024. (a) p = 3000 div 1024 = 2 (2 × 1024 = 2048; 3 × 1024 = 3072 > 3000). (b) d = 3000 mod 1024 = 3000 − 2048 = 952. (c) PTE[2] = 5. (d) PA = 5 × 1024 + 952 = 5120 + 952 = 6072. (e) Check: 5 × 1024 = 5120 ≤ 6072 < 6144 ✓. (f) The offset travels from the logical address to the physical one completely untouched.
Memory trick "Page in, frame out." The page number is an index into the page table; the offset is a position inside the block. Paging swaps the index and keeps the position.
IT link Every x86-64 and ARM64 CPU walks exactly this table and caches recent PTEs in a TLB — the next sheet.

OS · Memory ManagementTLB, multilevel tables & PTE bits

4The TLB, Multilevel Page Tables & PTE Bits

high-yield ★
Definition Consulting the page table on every reference would make each access cost two trips. The translation lookaside buffer (TLB) is a small, very fast associative cache of recent PTEs inside the MMU. On a hit the frame number comes from the TLB and the data is fetched in one further access; on a miss the page table is read from memory and the TLB is refilled.
TLB cost

Let t = TLB lookup, m = one memory access, h = hit ratio.
EAT = h·(t + m) + (1 − h)·(t + 2m)

Scheme, 32-bit + 4 KB pagesSize
Single-level2²⁰ entries × 4 B = 4 MB per process
Two-level (10 + 10)outer 2¹⁰ × 4 B = 4 KB, plus 4 KB per inner table in use
What you savea process using 32 pages holds 4 KB + 128 B, not 4 MB
Worked example ✍ TLB timing A TLB lookup takes 20 ns, one memory access 100 ns, hit ratio 80 %. (a) Hit = 20 + 100 = 120 ns. (b) Miss = 20 + 100 (page table) + 100 (data) = 220 ns. (c) EAT = 0.8 × 120 + 0.2 × 220 = 96 + 44 = 140 ns. (d) Without a TLB it would be 200 ns. (e) Multilevel tables do not change this arithmetic — they only make the miss shorter, because a missing outer entry ends the walk at once.

Protectionread / write / execute okdenied → faultMMU, every ref
Dirtywritten to since loadingunchanged → no write-backreplacement

Exam trap (i) The TLB is hardware, not a table in memory — usually associative memory searched by content. (ii) Dirty = "changed", reference = "looked at"; swapping the two words loses the answer. (iii) A page can be valid and never written — validity is about presence, not modification.
Memory trick "Hit once, miss twice." And "D for Dirty, R for Referenced — dirty decides whether to write back, reference decides who goes out next." A TLB is a cache of the page table, so a huge table is still cheap while the working set of pages is small.

OS · Memory ManagementSegmentation

5Segmentation, and Segmentation with Paging

written favourite ★
Definition Segmentation divides memory into variable-length logical units — code, data, stack, heap — instead of equal blocks. A logical address is the pair (segment number, offset). The segment table holds, per segment, a base (starting physical address) and a limit (length), plus protection bits, so PA = Base[s] + d whenever d < Limit[s]; otherwise a segmentation fault.
PointPagingSegmentation
Block sizefixedvariable
Address(p, d)(s, d)
Table entryframe number + bitsbase + limit + bits
Fragmentationinternal onlyexternal only
Grows with data?noyes — heap, stack
Protection / sharingper page, awkwardnatural, per segment
Exam trap (i) Segmentation gives external and paging gives internal fragmentation — opposite diseases. (ii) A segment number is not a page number; segments have no fixed size, so an address cannot be split into bits. (iii) Sharing a whole segment is natural; sharing half a page is not.
Segmentation with paging (segmented paging)

Every segment is again divided into fixed-size pages and each segment gets its own page table; the segment-table entry now holds the base address of that segment's page table instead of a base+limit pair. A logical address (s, p, d) is translated in three steps — segment table → the page table of segment s → the frame of page p inside it — giving PA = f·P + d. The segment table itself can be small enough to sit in registers, so only the two memory hops cost anything.

Memory trick "Base adds, offset selects, limit refuses." In paging the frame number replaces the page number and the offset is copied; in segmentation the base is added to the offset.
What real machines do x86 real mode is pure segmentation; x86 protected mode is segmented paging — a selector picks a descriptor, which supplies the page-table base, then ordinary paging runs. ARM64 and Linux dropped segmentation entirely.
Exam trap The limit is a length, not an end address: with base 44 and limit 24 the last legal offset is 23, because d < Limit. A segmentation fault and a page fault are different traps with different causes.

OS · Memory ManagementVirtual memory & the page fault

6Virtual Memory, Demand Paging & the Page Fault

written question ★
Definition Virtual memory lets a process be executed while only part of it is in physical memory: the program works with its own virtual address space, which may be larger than RAM, and the OS keeps the unused part on the back store. Demand paging is the usual implementation — load a page only when it is first referenced, also called lazy loading. Each PTE carries a valid–invalid bit: valid = present in memory, invalid = not present.
Servicing a page fault — six steps, in order
  1. The MMU finds valid = 0 and traps to the OS; the process is blocked.
  2. The OS checks the reference is legal. Illegal → abort the process.
  3. Take a free frame; if there is none, run a page-replacement algorithm and write the victim out first if its dirty bit is set.
  4. Schedule a disk read of the required page into that frame; the process waits.
  5. When the read completes, update the page table: frame number, valid = 1, dirty = 0.
  6. Restart the instruction that caused the fault.
Worked example ✍ effective access time m = 100 ns per access, f = 10 ms per fault, p = fault rate. EAT = (1 − p)·m + p·f. (a) p = 10⁻⁶: EAT ≈ 100 + 10⁻⁶ × 10⁷ = 110 ns. (b) For the fault overhead to stay under one memory access, p·f < m, so p < 100 ns ÷ 10⁷ ns = 10⁻⁵. (c) p = 10⁻³ gives about 10 µs — a hundred times slower. (d) This is why a fault rate above roughly one in 100 000 is fatal, and why the working-set model exists.
Exam trap (i) A page fault is not an error — it is the normal way a page arrives. (ii) The dirty bit is checked before the disk read, and only a dirty victim is written back. (iii) "Invalid" means not in memory, not "broken". (iv) Virtual memory lets many processes share the RAM, not just one process exceed it.
Memory trick "Trap, test, take, read, write the PTE, retry." Six words, always in that order. And the last word is the giveaway: if you never restart the instruction, the process stays dead for ever.
In practice Reference counting and garbage collection are the same idea used for a different purpose: map a known-good image into memory, fault it in lazily, and page it out untouched. Linux calls the second case a minor fault — no disk I/O, just fill the PTE.

7Page Replacement: FIFO, Optimal, LRU, Clock

trace this ★
Definition Page replacement runs when a process needs a frame and none is free: the OS picks a resident page, writes it out if dirty, and reuses its frame. Page-fault rate PFR = page faults ÷ total references. No algorithm avoids the first reference to a page, and more frames is not always fewer faults — Belady's anomaly.

Exam trap Belady's anomaly: with the same string and four frames FIFO gives 10 faults — more than the 9 it gives with three. So "more frames means fewer faults" is false for FIFO and true for LRU and Optimal. Also, the first reference to each distinct page always faults, so at least 5 faults are unavoidable here.
Memory trick "MIN is the ceiling, FIFO is the floor." Exact LRU needs a timestamp or a stack per frame, so real systems use clock, which just walks the frames and clears reference bits. FIFO forgets use; LRU remembers it; clock remembers it cheaply.
IT link Linux approximates LRU with multi-gen LRU: page-table entries carry young/old bit pairs, so no scan is needed. Windows and macOS use a variant of clock. The exam name for all of them is still "an LRU approximation".

8Working Set, Thrashing & Its Control

the last topic ★
Definition The working set of process i at time t is WSSi(t) = the pages it referenced in the last Δ time units (Δ ≈ a few milliseconds, enough to cover its normal burstiness). Total demand is D(t) = Σ WSSi(t). If D(t) > the number of free frames, pages are thrown out only to be wanted again — thrashing.
Two ways to stop thrashing

1. Working-set policy. Keep each process allocated exactly its WSS. On a fault, if demand exceeds what is free, evict pages from a process whose WSS is shrinking, or suspend a whole process. Freed frames go to the process whose WSS is growing.

2. Page-fault-frequency (PFF) control. Measure each process's PFR over a window. If PFR > upper bound, give it a free frame; if PFR < lower bound, take one back. Direct, and needs no Δ.

SymptomMeaning
PFR climbingtoo few frames for the working set
CPU utilisation fallingthe busy process is spending its time in I/O — thrashing
Disk writes climbingdirty pages written out again and again
Worked example ✍ does it thrash? Four frames are free. (a) WSS(P1) = 6, WSS(P2) = 2, WSS(P3) = 3, so D = 11 > 4 → thrashing: suspend P3 until frames free up. (b) P3's working set then collapses to 1 page; D = 6 + 2 + 1 = 9, still > 4 → suspend P2, whose WSS has fallen to 0 → D = 7. (c) Reduce once more: D = 6 ≤ available frames → stable, utilisation climbs again. (d) PFF reading: P1 runs at 0.3 faults per reference, far above the upper bound — it is the culprit.
Exam trap (i) Thrashing ≠ deadlock: the system is busy, not stuck — pages fly in and out. (ii) Thrashing is high CPU utilisation → low; in a deadlock nothing moves at all. (iii) Adding processes always helps up to the point D > free frames, and hurts after it.
Memory trick "Demand over supply = thrashing." If the working sets will not fit, the OS either suspends a process or gives frames to the greediest one. And the cure that always works is the boring one: admit fewer processes.
