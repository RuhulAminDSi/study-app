1Routing: the Whole Picture

MCQ + written
Definition A routing algorithm is the network-layer (layer 3) software that decides which output line an arriving packet takes. Routing = building the routing table (control plane); forwarding = consulting that table for each packet (data plane).
Optimality principle If J lies on an optimal path from I to K, then the optimal path from J to K follows that same route. So all the best routes towards one destination together form a tree: a sink tree (no loops).
Static (non-adaptive)Dynamic (adaptive)
Route set bythe administrator, by handrouters running protocols
Failure · overhead · useno reaction · none · small netsself-correcting · bandwidth, CPU · big nets

Metric: hop count (RIP) · bandwidth · delay · load · reliability · MTU · cost (OSPF) · AS path / policy (BGP). The lower the metric, the better the route.

Memory trick "RIP counts hops, OSPF counts cost, BGP counts ASes (and that means policy)".
Exam trap The metric compares routes inside one protocol; the administrative distance (AD, how trusted a source is) chooses between different protocols, and the lower value wins. Cisco AD: connected 0 · static 1 · eBGP 20 · EIGRP 90 · OSPF 110 · IS-IS 115 · RIP 120 · iBGP 200. So whatever the hop count, an OSPF route beats a RIP route.

2Flooding

A static algorithm: every packet is sent on every line except the one it came in on. It is robust and always finds the shortest path (every path is tried), but the network fills with duplicate packets. Control it with a hop counter (starting at the network radius), sequence numbers (drop copies already seen) or selective flooding. Flooding is what spreads link-state packets.

3Link-State Routing and Dijkstra

high-yield
Core idea Every router knows a map of the whole topology and runs the Dijkstra algorithm (SPF) over it: "routing by map".
  1. Find the neighbours (HELLO) · measure every cost · build the link-state packet (LSP/LSA: ID, sequence no., age, neighbours + costs)
  2. Flood the LSP to every router · run Dijkstra over the whole map → shortest-path tree → routing table

Worked example: shortest path from A

StepPermanent setBCDE
0{A}2,A∞9,A∞
1{A,B}✓4,B9,A9,B
2{A,B,C}✓✓5,C8,C
3{A,B,C,D}✓✓✓6,D

"4,B" means distance 4, previous node B. At every step the smallest tentative node becomes permanent and its neighbours are relaxed. The next hop from A to every destination is B; A→E = A-B-C-D-E, cost 6 (not the obvious A-D-E = 10).

Memory trick OSPF in numbers: "89 · 110 · area 0 · 5/6 · 10/40" = protocol, AD, backbone, last digits of the multicast addresses, hello/dead.

IS-IS: the OSI link-state twin — not IP, it runs straight on layer 2. Dijkstra: O(N²).

Exam trap Negative edge costs make Dijkstra return a wrong answer; Bellman-Ford copes (as long as there is no negative cycle).

4Hierarchical Routing

Routers are grouped into regions (areas, ASes); a router knows every router in its own region but keeps only a single entry for each other region. Tables stay small, and paths can be slightly longer. Optimal: ln N levels, e·ln N entries.

Worked example ✍ 720 routers. Flat: 720 entries. 24 regions × 30 routers: 30 + 23 = 53. 8 clusters × 9 regions × 10 routers: 10 + 8 + 7 = 25.

5Distance-Vector Routing and Bellman-Ford

high-yield
Core idea Every router keeps the best distance (and line) it knows to each destination, and exchanges this vector periodically with its neighbours only. "Routing by rumour"; it ran ARPANET until 1979, and it runs RIP today.
Bellman-Ford equation  Dx(y) = minv { c(x, v) + Dv(y) }  over every neighbour v of x

7BGP: Routing Between Autonomous Systems

MCQ
  • A path vector protocol; BGP-4 is the Internet's inter-domain (EGP) protocol
  • runs on TCP port 179; eBGP between ASes, iBGP inside one AS
  • every route carries its whole AS_PATH; a router that finds its own AS in the path rejects it → no loops
  • it chooses by policy (LOCAL_PREF, AS_PATH length, MED), not by cost · messages: OPEN, UPDATE, KEEPALIVE, NOTIFICATION

8Broadcast and Multicast Routing

Broadcast: a separate copy per host (wasteful) · flooding · multidestination · a spanning tree (best) · reverse path forwarding (RPF): forward the copy only if it arrived on the very interface this router would use to reach the source itself. Multicast (224.0.0.0/4, IGMP): either a source-based tree (DVMRP, PIM-DM) or a shared core-based tree (CBT, PIM-SM).

9Congestion and Its Control

high-yield
Definition Congestion: too many packets in the network (or in some part of it), so delay rises and throughput falls. Congestion control is a whole-network matter (global); flow control is point-to-point (a fast sender, a slow receiver).

Causes: bursty traffic from several lines piling onto one line, slow routers, small buffers, low-bandwidth lines.

Infinite buffers make it worse: packets are delayed until they time out and are retransmitted, so the load rises further. Once capacity is passed the output can drop almost to zero: congestion collapse.

5
NET · Routing & CongestionCongestion control
Open loop (prevention)Closed loop (feedback, reaction)
Ideagood design, so congestion never startsmeasure, signal, then adjust
Meansprovisioning, admission control, traffic shaping (buckets), retransmission/ACK/discard policychoke packets, back-pressure, ECN, RED, TCP's AIMD window (transport note)
  • Admission control: on a virtual-circuit network a new VC is refused when it would congest the network (like the "busy" tone of a telephone).
  • Choke packet: the congested router sends a packet back to the source, and the source cuts its rate (say, in half). Hop-by-hop back-pressure: the choke packet is effective at every router along the path, so relief is immediate. (ICMP Source Quench is now obsolete.)
  • ECN: the router drops nothing; it marks 2 bits in the IP header, and the receiver reports it back (TCP ECE flag), so the sender slows down.
  • Load shedding: throwing packets away. Win (the older one is better: keep file transfer, drop the newcomer) against milk (the newer one is better: real-time media, drop the old).

RED (Random Early Detection, Floyd & Jacobson 1993): the router watches the average queue length. Below minth: nothing is dropped; between the two thresholds: drop with a probability rising to maxp; above maxth: drop everything. Dropping early and at random slows only a few TCP senders and avoids the global synchronisation of tail drop.

Exam trap Congestion control ≠ flow control: sending fast from a PC to a slow printer over an empty link is a flow-control problem; many hosts on one overloaded link is congestion.

10Traffic Shaping: Leaky and Token Buckets

written favourite
Traffic shaping limiting the rate and burstiness of the traffic a host sends, according to an agreement with the network (open loop). Policing = the network checks it and drops or marks whatever exceeds the agreement.

Example 1 ✍ C = 250 KB, M = 25 MB/s, ρ = 2 MB/s: S = 250 KB / 23 MB/s ≈ 11 ms at full rate, then 2 MB/s.
Example 2 ✍ A 1 MB burst (40 ms at 25 MB/s) through a leaky bucket with output 2 MB/s: the output takes 500 ms; the bucket must hold ≈ 0.92 MB.
Memory trick Leaky = a dripping tap: always the same drop. Token = a savings account: save when idle, spend in a burst, but never more than C.

Worked example ✍ A router with two interfaces: on one, a 24-port switch with 20 PCs; on the other, a hub with 6 PCs. Collision domains: 20 + 1 (the switch–router link) + 1 (the whole hub) = 22. Broadcast domains: 2 (one per router interface).
Exam trap A switch divides the collision domain but not the broadcast domain; only a router (or a VLAN) divides the broadcast domain. A hub is a layer-1 device however many ports it has.

Tunnelling

To cross a network of a different kind, the whole packet travels between two multiprotocol routers as the payload of that network's own packets. Examples: IPv6-in-IPv4 (protocol 41), GRE (protocol 47), IPsec VPN.

Delay formula message x bits, k hops, bit rate b, propagation d per hop, setup s, packet p bits (header excluded): circuit T = s + x/b + k·d · packet T = x/b + (k − 1)·p/b + k·d. Packet switching is faster when s > (k − 1)·p/b.
Example ✍ x = 10⁶ bits, b = 1 Mbps, k = 4, d = 5 ms, s = 200 ms, p = 10 000 bits: circuit 0.2 + 1 + 0.02 = 1.22 s; packet 1 + 3 × 0.01 + 0.02 = 1.05 s.
Exam trap A virtual circuit is really packet switching (the links are shared), not circuit switching; it only fixes the route at setup time.

ATM: 48 bytes was the compromise (the USA wanted 64, Europe 32). UNI header: GFC 4, VPI 8, VCI 16, PT 3, CLP 1, HEC 8 bits. The ATM network layer and AAL are in their own note.

MPLS ("layer 2.5", RFC 3031): the ingress LER puts the packet into a FEC and pushes a label; the core LSRs just swap labels (an exact match, very fast); at the egress the label is popped. That path is an LSP. Carriers use it for traffic engineering, QoS and L3 VPN; it carries any protocol.

Memory trick X.25 checks at every hop, Frame Relay checks nowhere, ATM cuts everything into 53. Frame Relay = "X.25 that throws away error control, because fibre is clean".
Exam trap ATM's HEC protects only the 5-byte header, not the payload. Frame Relay detects errors (FCS) but never corrects them: it drops the frame.

Example 2: the 8-byte trap ✍ MTU 1000, datagram 2400 B. 1000 − 20 = 980, which is not a multiple of 8 → take 976. Data 2380 = 976 + 976 + 428; offsets 0, 122, 244.
Example 3: reading a fragment ✍ offset 100, HLEN 5, total length 100 → first data byte = 100 × 8 = 800, data = 80 B, last byte 879.
  • MF = 1, offset = 0 → first fragment · MF = 0, offset ≠ 0 → last · MF = 0, offset = 0 → not fragmented at all
  • if one fragment is lost the whole datagram is discarded (the reassembly timer)
  • Path MTU discovery: send with DF = 1; a router that cannot forward drops the packet and returns ICMP type 3 code 4 "fragmentation needed" together with the next hop's MTU
  • IPv6: a router never fragments; only the source does (a Fragment header, 8 B, next header 44); if it is still too large → ICMPv6 "Packet Too Big"
Memory trick "offset × 8 = byte position": 2¹³ offsets × 8 bytes = 2¹⁶, which exactly covers a 65 535-byte datagram.

Written question Explain, with an example, the count-to-infinity problem of distance-vector routing, and describe two techniques that limit it. 8 marks
  1. A DV router only knows the distances held by its neighbours (Bellman-Ford), so it cannot tell whether the neighbour's route runs back through itself 1
  2. Chain A–B–C, each cost 1. B: A = 1; C: A = 2 (via B). The A–B link then fails 1
  3. B hears C say "A = 2", so it takes A = 3 via C; then C takes A = 4 via B; then 5, 6, … counting up to ∞ (16 in RIP), with a routing loop running throughout 3
  4. Split horizon: C does not advertise its A route back to B, the interface it learned it on; poison reverse: C advertises A = ∞ to B 2
  5. There are also the hold-down timer and triggered updates; none of them fully cures a loop of 3+ routers, which is why link state is preferred 1
