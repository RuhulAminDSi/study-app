1Routing: the Big Picture

MCQ + written
Definition A routing algorithm is the layer-3 software that decides which output line an incoming packet should leave by. Routing = building the table (control plane, slow); forwarding = looking one packet up in the table and sending it (data plane, done at line rate).
routing ≠ forwarding — an MCQ asks "router works at which layer?", not "what is the table called"
Static (non-adaptive)Dynamic (adaptive)
Routes come fromthe administrator, typed by handprotocol messages between routers
When a link diesnothing happens until someone editsthe routers re-converge by themselves
Overhead · best fornone · stub and lab netsbandwidth, CPU, memory · large nets

Metrics used to compare routes: hop count (RIP) · bandwidth · delay · load · reliability · MTU · cost (OSPF) · AS_PATH and policy (BGP). Lower metric wins.

Optimality principle If the optimal path from I to K runs through J, then the optimal sub-path from J to K is the rest of it. Hence all optimal routes out of one node form a tree — the sink tree — and it can never contain a loop.
Exam trap Metric compares routes inside one protocol; administrative distance (AD = how much the router trusts the source) picks between protocols, lowest wins. connected 0 · static 1 · eBGP 20 · EIGRP 90 · OSPF 110 · IS-IS 115 · RIP 120 · iBGP 200. An OSPF route beats a RIP route whatever the hop count.

2Flooding

static algorithm
Idea Send every packet out on every line except the one it arrived on. Every path is tried, so the shortest path is always found — but the network fills with duplicates.

Flooding is how link-state packets are spread: every router must get the same picture, so it is worth the duplicates.

3Distance Vector Routing & Bellman–Ford

most tested ★
Idea Each router keeps the best known distance to every destination and swaps the whole vector with its neighbours only, periodically. "Routing by rumour" — a router never sees the map, only its neighbours' opinions.
Bellman–Ford equation  Dx(y) = minv { c(x, v) + Dv(y) }  over every neighbour v of x. O(VE) time; works even with negative edge costs (but not negative cycles).
Worked example ✍ one DV exchange Router X links to A (cost 2), B (cost 5), C (cost 1). The vectors it just received:
fromto Yto Z

to Y: min(2+7, 5+2, 1+8) = 7 via B
to Z: min(2+3, 5+9, 1+6) = 5 via A

v1 classful, broadcast · v2 classless, multicast 224.0.0.9, MD5 auth
RIPv2 sends the mask · RIPng (IPv6) UDP 521
RIP designed for small nets: 15 hops ≈ a campus

C still advertises "A at 2" — a route that goes back through B — and B believes it, because B cannot see that path. Good news travels fast, bad news travels slowly.

FixHow it works

Exam trap Split horizon kills the two-router loop but not loops of three or more routers. And "RIP allows 16 hops" is wrong: the maximum path length is 15; 16 is the infinity marker.

5Link State Routing & Dijkstra

high-yield
Idea Every router learns the complete topology map and runs Dijkstra's shortest-path-first algorithm on it itself: "routing by map", not by rumour.
  1. Discover neighbours and measure the cost to each (HELLO packets), then build a link-state packet — LSA: router ID, sequence number, age, list of neighbours with costs
  2. Flood the LSA to every router, run Dijkstra over the whole map → shortest-path tree → routing table
StepPermanent setBCDE
0{A}5, A∞2, A∞
1{A,D}5, A9, D✓∞
2{A,D,B}✓6, B✓6, B
3{A,D,B,C}✓✓✓6, B
4all five✓✓✓✓

"6, B" = distance 6 through previous node B. Each step makes the smallest tentative node permanent and relaxes its neighbours. Result: A→D = 2, A→B = 5, A→C = 6 via B, A→E = 6 via B — the chain A-D-C-E would cost 13.

OSPF facts
RFC 2328 (IPv6 = OSPFv3) · runs directly on IP, protocol 89
cost = reference bandwidth ÷ link bandwidth (100 Mbps → 1)
areas; backbone = area 0; ABR, ASBR, DR/BDR
224.0.0.5 all routers · 224.0.0.6 DRs only
Hello 10 s, Dead 40 s · AD 110 · LSA every 30 min
IS-IS: the OSI twin, runs over layer 2, not IP. Dijkstra costs O(N²)
Memory trick OSPF in five numbers: "89 · 110 · area 0 · 5 and 6 · 10/40" = protocol, AD, backbone, multicast groups, hello/dead.
Exam trap Dijkstra needs non-negative edge costs; Bellman–Ford tolerates negative ones but not negative cycles. "OSPF uses UDP" is wrong — it has no transport header at all.

6Hierarchical Routing

Routers are grouped into regions (OSPF areas, ASes). A router keeps a full entry for every router of its own region but only one entry per other region. Tables shrink; paths can get slightly longer. Optimum: ln N levels, e·ln N table entries.

Worked example ✍ 720 routers flat: 720 entries.
24 regions × 30 routers: 30 + 23 = 53.
8 clusters × 9 regions × 10 routers: 10 + 8 + 7 = 25.
IT link A Linux host reads its routes with ip route get and writes them with ip route add; quagga/FRR replaces the kernel's static-table handling with OSPF or BGP. The "sink tree" of an FHRP cluster (VRRP/GLBP) is the same idea one level up: every host points at a virtual gateway.

the classic MCQ ★
Distance vectorLink state
Knows · algorithmneighbours' distances · Bellman–Fordwhole topology · Dijkstra

Memory trick "RIP counts hops, OSPF counts cost, BGP counts ASes." Or: DV is asking neighbours, LS is reading the map — and the map is why LS cannot loop.
Exam trap EIGRP is a hybrid, not a link-state protocol: it keeps DV tables but stores extra topology and converges instantly with DUAL.

8BGP & the Autonomous System

inter-AS ★
  • An autonomous system (AS) is one authority's network. Intra-AS routing = IGP (RIP, OSPF, IS-IS, EIGRP). Inter-AS routing = EGP — today only BGP-4.
  • BGP is a path vector protocol: every UPDATE carries the whole AS_PATH. A router drops any path that already contains its own AS ⇒ loops are impossible.
  • Runs over TCP port 179 — eBGP between ASes (AD 20), iBGP inside one (AD 200).
  • The reachable prefixes it advertises are NLRI; one UPDATE may list many of them.
Route choiceBGP attribute
best inside my AShighest LOCAL_PREF
shortest pathshortest AS_PATH
tie-break across ASeslowest MED
tie of a tielowest eBGP router ID, then IGP cost to it
Aggregation ✍ 10.1.0.0/24 … 10.1.7.0/24 are eight /24s that share a /21 prefix, so one advertisement 10.1.0.0/21 replaces all eight — fewer table entries, fewer updates. The incoming side advertises the most specific prefix it holds.
Exam trap BGP is not a shortest-path protocol: it picks by policy first (traffic engineering, peering agreements, cost of transit). Four message types only: OPEN, UPDATE, KEEPALIVE, NOTIFICATION.

9IPv4 Addressing: Classful → Classless → CIDR

written favourite ★
Why it matters A router needs the network part of an address to forward a packet. Classful addressing reads that part off the first bits — 8, 16 or 24 — and wastes address space. Classless (CIDR) puts an explicit prefix length /n in the routing table, so a block of any size can be advertised.

Worked example ✍ class of an address 172.20.5.4 in binary begins 1010 1100. The first two bits are 10 ⇒ class B ⇒ default mask 255.255.0.0, 16 network bits, 16 host bits ⇒ 2¹⁶ − 2 = 65 534 usable hosts. As a /8 it would be class A; the first octet decides.

172.32.1.1 begins 1010 0010 — still "10", so class B as well, but it is outside 172.16.0.0/12, so it is a public address: the private block is 172.16 – 172.31, not 172.0 – 172.255.
Memory trick Class = the first letter of the first octet written in binary: 0A 10B 110C 1110D 1111E. Private = "10… · 172.16–31 · 192.168" — the famous 172 range is the only one with a two-digit second octet.
Exam trap Classful networks borrow bits only from the host part, and old rules banned "subnet zero" and the all-ones subnet. CIDR abolished both. Also: the usable-host count is 2^h − 2, never 2^h.
IT link CIDR replaced classful routing in 1993 (RFC 1519 → RFC 3484). The /0 default route is just the largest possible prefix: 0.0.0.0/0 matches every IPv4 address in the table, and the longest-prefix match wins over everything else.

11ICMP — the Network Layer's Postman

MCQ staple
Definition ICMP carries error and diagnostic messages about IP packets. It rides inside IP with protocol number 1, it has no port numbers (it belongs to layer 3, not to a transport), and it never carries user data — ping, traceroute and path MTU discovery are all built on it.
TypeMessageWhat it means in an exam
0Echo Replythe answer to ping
3Destination Unreachablecodes: 0 network, 1 host, 3 port, 4 fragmentation needed & DF set, 13 admin-filtered
4Source Quench"slow down" — deprecated since RFC 6633
5Redirect"there is a better router for that network"
8Echo Requestthe ping itself
11Time Exceededcode 0 = TTL expired in transit (how traceroute works) · code 1 = fragment reassembly timed out
12Parameter Problema header field is malformed; the pointer byte says which
Memory trick Types worth remembering: 0/8 = echo, 3 = unreachable, 11 = time exceeded, 12 = bad header. "Time exceeded" is the traceroute message: it makes the TTL hit 0 one router further each time.
Exam trap ICMP has no ports and is not reliable — nothing is acknowledged or retransmitted. Source Quench (type 4) was the old "choke packet" mechanism; it is deprecated, so never answer with it in a modern exam.

12NAT — Network Address Translation

IPv4 only
Definition A router rewrites the source (and answer's destination) address on the way out and undoes it on the way back, so many private hosts share one public address. RFC 3022; it exists because IPv4 ran out of addresses.
TypeWhat it mapsUse
Staticone private host ⇄ one fixed public IPpublic servers, mail
Dynamica pool of public IPs, taken on demanda small office
PAT / NAT overloadprivate host + port number ⇒ public IP + porthome routers: hundreds of hosts on 1 IP

With 16-bit ports the well-known 0–1023 range is reserved, so one public IP can hold roughly 60 000 simultaneous translations — then the table overflows. PAT also breaks end-to-end: an inbound connection has nothing to map to, so a port forward or a VPN is required.

Exam trap NAT is a workaround, not a fix: it hides addresses but it is stateful, it breaks end-to-end addressing, and it interferes with IPsec and with peer-to-peer protocols. IPv6 removes the need for it altogether.

13Congestion Control

highest-yield ★
Definition Congestion = too many packets for the network to move, so delay climbs and throughput collapses. Congestion control is global (the whole network is overloaded); flow control is point-to-point (one fast sender, one slow receiver).
Open loop (prevention)Closed loop (feedback)
Ideadesign and policy so congestion never startsmeasure, signal, then react
Toolscapacity planning, admission control, traffic shaping (buckets), policingchoke packet, back-pressure, ECN, RED, TCP's congestion window
  • Admission control: in a virtual-circuit network refuse a new VC that would congest the network — the telephone network's "busy" tone.
  • Choke packet: a congested router sends a packet back to the source, which halves its rate; hop-by-hop back-pressure makes it bite at every router on the way. ECN (RFC 3168) is the modern replacement: the router marks 2 bits in the header instead of dropping, the receiver echoes the mark (TCP ECE flag), and only then does the sender slow down.
  • Load shedding: drop packets — wine (old is more valuable: file transfer, drop the newcomer) vs milk (new is more valuable: real-time voice, drop the oldest).
  • Infinite buffers make things worse: packets queue until they time out and are retransmitted, adding load. Past capacity the delivered throughput can fall towards zero — congestion collapse.
RED ✍ Random Early Detection (Floyd & Jacobson, 1993) The router tracks the average queue length. Below minth: nothing is dropped. Between the thresholds: drop with probability rising to maxp. Above maxth: drop everything. Dropping early and at random nudges a few TCP senders down gently instead of the burst that tail-drop causes.

14Traffic Shaping: Leaky & Token Bucket

written favourite
Token bucket arithmetic bucket capacity C, token rate ρ, maximum output rate M. In a burst of S seconds it can send C + ρS = MS ⇒ S = C / (M − ρ). In any interval t it can send at most C + ρt. Leaky bucket: output is always r, a full queue drops packets. Token bucket: idle host saves tokens, a full bucket drops tokens, so bursts survive.
Worked example ✍ C = 250 KB, ρ = 2 MB/s, M = 25 MB/s ⇒ S = 0.25 MB / 23 MB/s = 10.9 ms ≈ 11 ms at full speed, then 2 MB/s. A 1 MB burst into a leaky bucket with output 2 MB/s drains for 500 ms, so the bucket must hold ≈ 0.92 MB.
Memory trick Leaky = a dripping tap: the same drip whatever you do. Token = a savings account: save while idle, spend in a burst, never more than the balance C.
Exam trap A fast PC sending to a slow printer on an empty link is flow control, not congestion. Congestion needs a network-wide overload. Also: shaping buffers at the sender, policing drops or marks at the receiver's edge.

15Fragmentation, MTU & the DF Bit

written favourite ★
Why A datagram larger than the next link's MTU (the largest frame payload it will carry) is split into fragments, each a complete IP datagram with its own header. In IPv4 the source or any router may fragment; reassembly happens only at the final destination.
Header field (bits)Role
Identification (16)same value in every fragment
DF (1)Don't Fragment — drop it and complain instead
MF (1)More Fragments follow
Fragment offset (13)position in the original, in 8-byte units
Total length (16)header + data ≤ 65 535
LinkMTU (bytes)
Ethernet · PPP · PPPoE1500 · 1500 · 1492
IEEE 802.11 · FDDI2304 · 4352
X.25 (typical)576
IPv6 minimum link MTU1280
Worked example ✍ and the 8-byte trap 4000 B, MTU 1500: data 3980, per fragment 1500 − 20 = 1480 (a multiple of 8 ✓) ⇒ offsets 0, 185, 370, MF = 1, 1, 0. Now MTU 1000: 1000 − 20 = 980 is not a multiple of 8, so use 976; data 2380 = 976 + 976 + 428, offsets 0, 122, 244.
  • MF = 1, offset 0 ⇒ first · MF = 0, offset ≠ 0 ⇒ last · MF = 0, offset = 0 ⇒ not fragmented
  • One lost fragment ⇒ the whole datagram is dropped (reassembly timer expires)
  • Path MTU discovery: send with DF = 1; a router that cannot forward drops it and returns ICMP type 3 code 4 with the next-hop MTU
  • IPv6: routers never fragment — only the source, using the Fragment header (8 B, next header 44); too big ⇒ ICMPv6 "Packet Too Big"
Memory trick "Offset × 8 = byte position." 2¹³ offsets × 8 bytes = 2¹⁶ bytes, which exactly covers the 65 535-byte maximum datagram. And every fragment's data length must be a multiple of 8 except the last.
Exam trap Fragmentation is done by routers in IPv4 and only by the source in IPv6. A router never reassembles: that is the destination's job.

  1. Bits to borrow: 2ⁿ ≥ 4, so n = 2. The new prefix is /24 + 2 = /26. 2
  2. Mask: the last octet gets two 1s and six 0s, 11000000 = 192 ⇒ 255.255.255.192. 2
  3. Host count: host bits = 32 − 26 = 6, so 2⁶ = 64 addresses per subnet; subtract the network and the broadcast address ⇒ 62 usable hosts. 2
  4. Block size = 256 − 192 = 64, so the subnets start at 0, 64, 128, 192. 1
  5. The four subnets: 192.168.5.0 / .1 / .62 / .63 · 192.168.5.64 / .65 / .126 / .127 · 192.168.5.128 / .129 / .190 / .191 · 192.168.5.192 / .193 / .254 / .255. 2
  6. Why 8-byte units: 13 bits × 8 = 2¹⁶ = 65 536 byte positions, exactly enough to address every byte of the largest possible IPv4 datagram (65 535 bytes), and it makes the offset 13 bits instead of 16. 1
