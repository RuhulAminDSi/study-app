Networking · IP Layer & FirewallsFirewalls

1Firewalls

high-yield
Definition A firewall is hardware or software at a network boundary that permits or blocks traffic according to a rule set (security policy). All traffic between inside and outside must pass through it. The safe policy is default deny: whatever is not explicitly allowed is blocked.
TypeLayerDecides on+ / −
Packet filter (stateless)3–4IP addresses, ports, protocol, TCP flags; each packet alonefast, cheap (router ACL) / no state, fooled by spoofing
Stateful inspection3–4packet + state table of open connectionsreplies pass automatically / table can be flooded
Circuit-level gateway5validates the session set-up, then relays (SOCKS)hides inside hosts / no content check
Application gateway (proxy)7full content of one protocol (HTTP, FTP, SMTP), user login, logsstrongest control / slow, one proxy per service
NGFW (next-generation)3–7deep packet inspection, IPS, application and user identityall in one box / cost, latency

Architectures

  • Screening router: packet filtering only
  • Dual-homed host: bastion host, two NICs, forwarding off
  • Screened host: filtering router + bastion host
  • Screened subnet (DMZ): two firewalls or one three-legged firewall
  • Host-based (Windows Defender Firewall, iptables) vs network-based

ACL: first match wins

permit tcp any host 203.0.113.10 eq 443 permit tcp any host 203.0.113.25 eq 25 permit tcp any 10.0.0.0/8 established deny ip any any # implicit anyway

A broad permit above a narrow deny makes the deny useless.

Memory trick The packet filter reads the envelope, the stateful firewall remembers the conversation, the proxy opens the letter.
Exam trap A firewall cannot stop traffic that bypasses it (insider, USB stick, rogue Wi-Fi) or malware hidden in allowed, encrypted traffic. IDS only detects and alerts; IPS sits inline and blocks.

2The IPv4 Datagram Header

high-yield
IPv4 (RFC 791, 1981): a connectionless, best-effort network-layer protocol: no acknowledgements, no ordering, no retransmission (TCP adds those). Datagram = header (20–60 bytes) + data; maximum total size 65,535 bytes.
FieldBitsWhat to remember
Version4value 4 (0100); IPv6 packets carry 6
IHL (header length)4counts 32-bit words: 5–15 → 20–60 bytes
DSCP + ECN (old ToS)6 + 2QoS class (DiffServ) and congestion marking
Total length16header + data in bytes, max 2¹⁶ − 1 = 65,535
Identification, Flags, Fragment offset16, 3, 13fragmentation: flags = reserved, DF, MF; offset in 8-byte units
TTL (time to live)8−1 at every router; at 0 the packet is dropped and ICMP Time Exceeded is sent
Protocol81 ICMP · 6 TCP · 17 UDP · 2 IGMP · 41 IPv6 · 50 ESP · 51 AH · 89 OSPF
Header checksum16covers the header only; recomputed at every hop (TTL changes)
Source, Destination32 + 32IPv4 addresses; unchanged end to end (except by NAT)
0x45 = the usual first byte
Worked example ✍ First byte 0x45 → version 4, IHL 5 → header 5 × 4 = 20 bytes. If IHL = 8, header = 32 bytes, so 12 bytes are options. With total length 1500 and IHL 5, data = 1500 − 20 = 1480 bytes. Largest possible data in one datagram: 65,535 − 20 = 65,515 bytes.
Memory trick "IHL × 4, offset × 8": header length counts 4-byte words, fragment offset counts 8-byte blocks. Protocol numbers: "1 ping, 6 TCP, 17 UDP".
Exam trap The IPv4 checksum does not protect the data (TCP/UDP checksums do). TTL is in practice a hop count, not seconds. Offset/MF arithmetic: see the Fragmentation sheet of the Routing notes.

Exam trap 172.32.x.x and 192.169.x.x are public. 127 is kept for loopback, so usable class A first octets are 1–126, not 0–127.

4NAT (Network Address Translation)

The border router rewrites private source addresses to a public one (RFC 3022) and reverses it for replies.

  • Static NAT: 1 private ↔ 1 public (to publish a server)
  • Dynamic NAT: a shared pool of public addresses
  • PAT / NAPT ("overload"): many hosts → one public IP, told apart by port numbers
Memory trick Private = "10 · 172.16 to 31 · 192.168": one /8, sixteen class-B blocks, 256 class-C blocks.
Exam trap NAT is not a firewall, though it drops unsolicited inbound packets. It breaks end-to-end addressing: IPsec AH, active FTP and peer-to-peer need ALGs or NAT traversal.

5Subnetting, CIDR & VLSM

written favourite
The formulas prefix /n → host bits h = 32 − n · addresses per subnet = 2ʰ · usable hosts = 2ʰ − 2 (network and broadcast removed) · borrowing s bits gives 2ˢ subnets · block size = 256 − mask octet · network = largest multiple of the block ≤ the address · broadcast = next network − 1

/31 (RFC 3021) is used on point-to-point links: 2 addresses, both usable. /32 = a single host route.

Memory trick "Magic number = 256 − mask octet". Count up in magic numbers; the address falls in one block.
Example 1 ✍ 192.168.10.130/26 → block 64: blocks start .0, .64, .128, .192 → network 192.168.10.128, hosts .129–.190, broadcast .191, 2⁶ − 2 = 62 hosts.
Example 2 ✍ 172.16.45.200/20 → mask 255.255.240.0, block 16 in the third octet: 32 ≤ 45 < 48 → network 172.16.32.0, broadcast 172.16.47.255, hosts 172.16.32.1–172.16.47.254 (2¹² − 2 = 4,094).
Example 3: VLSM ✍ Split 192.168.1.0/24 for LAN A (100 hosts), LAN B (50 hosts) and a router link (2). Largest first:
  1. A needs 2⁷ − 2 = 126 ≥ 100 → /25: 192.168.1.0/25 (.1–.126, bcast .127)
  2. B needs 2⁶ − 2 = 62 ≥ 50 → /26: 192.168.1.128/26 (.129–.190, bcast .191)
  3. Link needs 2 → /30: 192.168.1.192/30 (.193, .194); .196–.255 is left free
Example 4: supernetting (route aggregation) ✍ 200.10.0.0/24, 200.10.1.0/24, 200.10.2.0/24, 200.10.3.0/24: third octets 0–3 = 00000000…00000011 share 16 + 6 = 22 bits → one route 200.10.0.0/22. Rule: a power-of-2 count of contiguous blocks, the first one divisible by that count.
Exam trap "Addresses" = 2ʰ but "usable hosts" = 2ʰ − 2. A /30 has only 2 usable hosts. Subnets = 2ˢ (old no-subnet-zero rule: 2ˢ − 2).

Networking · IP Layer & FirewallsIPv6 addresses

6IPv6 Addresses

high-yield
IPv6 (RFC 8200) has 128-bit addresses: 2¹²⁸ ≈ 3.4 × 10³⁸ (vast, not unlimited), as 8 groups of 4 hex digits (16 bits each) separated by colons: 2001:0db8:0000:0000:0000:ff00:0042:8329.

Abbreviation rules

  1. Drop leading zeros in each group: 0db8 → db8, 0042 → 42, 0000 → 0
  2. Replace one run of consecutive all-zero groups by :: (only once per address; use it for the longest run)
  3. Write hex in lowercase (RFC 5952); do not use :: for a single zero group
Compress ✍ 2001:0db8:0000:0000:0000:ff00:0042:8329
→ 2001:db8:0:0:0:ff00:42:8329
→ 2001:db8::ff00:42:8329
Expand ✍ fe80::1:2 shows 3 groups, so :: = 8 − 3 = 5 zero groups → fe80:0:0:0:0:0:1:2 = fe80:0000:0000:0000:0000:0000:0001:0002
TypePrefixNotes
Global unicast2000::/3public; 2001:db8::/32 = documentation
Link-localfe80::/10automatic on every interface; never routed
Unique localfc00::/7 (fd00::/8)like RFC 1918 private space
Loopback · unspecified::1/128 · ::/128like 127.0.0.1 · 0.0.0.0
Multicastff00::/8ff02::1 all nodes, ff02::2 all routers
Anycast(from unicast space)delivered to the nearest member of a group
IPv4-mapped::ffff:0:0/96::ffff:192.0.2.1 (dual-stack sockets)
EUI-64 ✍ MAC 00:1A:2B:3C:4D:5E → split in half and insert ff:fe → flip the 7th bit (U/L) of the first byte, 00 → 02 → interface ID 021a:2bff:fe3c:4d5e, address fe80::21a:2bff:fe3c:4d5e.
Memory trick "Double colon, single use": two :: make the length ambiguous. Prefixes: 2… global, fe80 link-local, ff multicast.
Exam trap 2001:db8::1::2 is invalid (two ::), so is a group of 5 hex digits. IPv6 has unicast, multicast and anycast, but no broadcast.

7The IPv6 Header (40 bytes, fixed)

MCQ + Written

Removed from IPv4: IHL, header checksum, identification/flags/offset (moved to the Fragment extension header), options. Renamed: TTL → Hop limit, Protocol → Next header, ToS → Traffic class.

Next-header values
0 Hop-by-Hop · 43 Routing · 44 Fragment
50 ESP · 51 AH · 60 Destination options
6 TCP · 17 UDP · 58 ICMPv6 · 59 none

Extension headers form a chain: each one's Next header names the one after it, ending in TCP/UDP. Routers normally read only the base header, so forwarding is faster.

Fragmentation is done only by the source after Path MTU Discovery; every link must carry at least 1280 bytes.

FeatureIPv4IPv6
Address32-bit, dotted decimal128-bit, colon hex
Header20–60 B, 12 fields + options40 B fixed, 8 fields + extension headers
Checksum / fragmentsyes / source + routersnone / source only
Resolution / configARP / manual, DHCPNDP (ICMPv6) / SLAAC, DHCPv6
IPsecoptional add-onbuilt in (AH/ESP); use still optional
QoS / broadcastDSCP / yestraffic class + flow label / none

8IPv4 → IPv6 Transition

  • Dual stack: devices run IPv4 and IPv6 side by side (most common)
  • Tunnelling: IPv6 inside IPv4 (protocol 41): 6in4, 6to4 (2002::/16), Teredo (UDP, through NAT), ISATAP
  • Translation: NAT64 + DNS64 (64:ff9b::/96): IPv6-only hosts reach IPv4 servers
Memory trick The three transition roads: "both, wrap, translate" = dual stack, tunnel, NAT64.
Exam trap IPv6 header: fewer fields but bigger than IPv4's minimum (40 vs 20 bytes).

9ARP (Address Resolution Protocol)

high-yield
ARP (RFC 826, 1982) finds the MAC address for a known IPv4 address on the same LAN. Request = broadcast, reply = unicast; results go in the ARP cache. EtherType 0x0806; never crosses a router.
ARP packet: 28 bytes (Ethernet/IPv4)
HW type 2 (1 = Ethernet) · protocol type 2 (0x0800) · HW len 1 (6) · protocol len 1 (4) · opcode 2: 1 request, 2 reply (RARP 3, 4) · sender MAC 6, IP 4 · target MAC 6 (zeros in a request), IP 4
  • Destination on another network → ARP for the default gateway's MAC, not the remote host's
  • Gratuitous ARP: announces its own IP · Proxy ARP: a router answers for another subnet
  • ARP spoofing: forged replies → man-in-the-middle; IPv6 uses NDP instead

11ICMP (Internet Control Message Protocol)

RFC 792; reports errors and answers queries for IP. Carried inside IP (protocol 1) yet counted as network layer. It reports problems but repairs nothing.

  • ping: Echo request 8 → Echo reply 0
  • traceroute: probes with TTL 1, 2, 3 … each draw a Time Exceeded from the next router
  • No error message about an ICMP error, a broadcast or a non-first fragment
TypeMessage
0 / 8Echo reply / request
3Dest. unreachable (0 net, 1 host,
3 port, 4 frag. needed + DF)
5Redirect (a better route)

12Parameter problem
Memory trick ARP asks "who has this IP?", RARP asks "who am I?". "Ping 8, pong 0; traceroute counts the 11s."
Exam trap ARP: IP → MAC; RARP: MAC → IP. RARP could not cross routers and gave no mask or gateway, so BOOTP and then DHCP replaced it.

12Mobile IP

MCQ + Written
Idea Mobile IP (RFC 5944) lets a mobile node keep its permanent home address while it moves, so peers and open connections keep working.
  • Mobile node (MN): the roaming host; correspondent node (CN): its peer
  • Home agent (HA): router on the home network; keeps the binding, tunnels packets on
  • Foreign agent (FA): router on the visited network; offers a CoA, unwraps packets
  • Care-of address (CoA): the temporary address; FA CoA (the FA's, shared) or co-located CoA (from DHCP; the MN unwraps itself)
  1. Agent discovery: agent advertisements (ICMP router-advertisement extension) or a solicitation
  2. Registration: MN → FA → HA on UDP 434; the HA binds home address ↔ CoA
  3. Tunnelling: the HA intercepts (proxy ARP) and sends IP-in-IP (protocol 4) to the CoA
Exam trap Replies go MN → CN directly, so traffic makes a triangle ("triangle routing"). Fixes: route optimisation (the CN learns the CoA), reverse tunnelling. Mobile IPv6 (RFC 6275) has no foreign agent.

13Network Layer of ATM

MCQ
Idea Connection-oriented, cell-switched: a virtual circuit is set up once, then 53-byte cells are switched by VPI/VCI labels under the agreed QoS; cells stay in order.
  • VPI: 256 paths at the UNI, 4,096 at the NNI; VCI: 65,536 per path
  • VP switch rewrites only the VPI; VC switch rewrites VPI and VCI; labels are local to each link
  • PVC (configured) or SVC (signalled, Q.2931)
  • ATM addresses (20-byte NSAP or E.164) are used only at set-up
Service classTypical use
CBRvoice, circuit emulation
rt-/nrt-VBRvideo / bursty data
ABRRM-cell feedback
UBRbest effort

Policing: GCRA (leaky bucket); CLP = 1 cells are dropped first.

Memory trick "Path is the motorway, channel is the lane": the VPI picks the bundle, the VCI the circuit inside it. HEC = CRC-8 over the header only; efficiency 48/53 ≈ 90.6%. Cell delineation: ATM data-link notes; AAL: transport notes.
