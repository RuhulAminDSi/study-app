1OOP over Structured Programming

written + viva
Q State the advantages of object-oriented programming (OOP) over structured programming.

38th BCS written · 2018  |  bank IT viva: "Advantages of OOP", "Difference between OOP and structured programming"

Structured programming splits a problem top-down into functions working on shared data (C, Pascal). OOP builds it from objects that bundle data with their methods (Java, C++, C#).

PointStructuredObject-oriented
Building blockfunction / procedureclass and object
Design approachtop-downbottom-up (model real entities)
Dataglobal; any function can change ithidden inside objects
Access controlnoneprivate / protected / public
Reusecall or copy functionsinheritance, composition
One name, many formsnot supportedoverloading, overriding
Adding a featureedit existing functionsadd a subclass, override

Model answer: eight advantages

  1. Modularity: each class is a self-contained unit, so a team can split the work cleanly.
  2. Reusability: inherit and extend tested classes instead of rewriting code.
  3. Data security: encapsulation hides data; only the object's own methods change it.
  4. Easy maintenance: a change stays inside one class.
  1. Extensibility: polymorphism lets a new subclass plug in without editing callers.
  2. Real-world modelling: Account, Customer, Loan map straight to classes.
  3. Faster debugging, higher quality: a fault is local to one class; classes are unit-tested alone.
  4. Scalability: suits large, evolving software (banking, ERP).

Balanced answer: add one limitation (larger, slightly slower programs; needs design up front). C++ is multi-paradigm, Java (almost) pure OO.

3Encapsulation (and Abstraction)

written + MCQ + viva
Q Explain encapsulation and inheritance in detail.

38th BCS written · 2018 · part (a) here, part (b) inheritance on sheet 4

Encapsulation Wrapping data and the methods that use it into one unit (a class) and restricting direct access with access specifiers: fields private, public methods that validate. Gains: data hiding, always-valid state, inner code can change without breaking callers.
class BankAccount { private double balance; // hidden public void deposit(double amt) { if (amt <= 0) throw new IllegalArgumentException( "amount must be > 0"); balance += amt; // controlled } public double getBalance() { return balance; // read-only } }

5Inheritance and Its Types

written ×2 + viva ×4
Q Explain the concept of inheritance used in OOP. Name and briefly describe three common types of inheritance. 10 marks

Bank Assistant Programmer written  |  also 38th BCS (2018) part (b): "Explain inheritance in detail"

Inheritance The mechanism by which a new class (subclass / derived / child) acquires the fields and methods of an existing class (superclass / base / parent) and may add new members or override inherited methods. It models an IS-A relation: a SavingsAccount is an Account.
  • Java: class Dog extends Animal (one class) · implements A, B (many interfaces)
  • C++: class Dog : public Animal
  • Not inherited: constructors; private members exist in the object but are not directly accessible
  • Benefits: code reuse, less duplication, extensibility, the basis of run-time polymorphism, natural class hierarchy
  • Superclass = the parent whose members are inherited; subclass = the child that inherits (viva)

Singleone base → one derived (Animal → Dog)YY

Hierarchicalone base → many derived (Shape → Circle, Square)YY

Hybrida mix of the above, e.g. the diamondN (interfaces: Y)Y
"three common types" = single, multilevel, hierarchical

Multiple inheritance & the diamond (viva)

If B and C both override A's method and D extends both, which copy does D get? Java bans multiple class inheritance; a class may implement many interfaces, and a clash of default methods must be overridden. C++ allows it and removes the duplicate A with virtual base classes.

6Complete the Java Program (Inheritance + super)

written: code
Q Complete the following Java program: class A (alpha, beta) has a constructor and display(); class Gamma extends A adds int gamma. Write Gamma's constructor, override display(), and write main that creates Gamma(3, 30, 10).

asked in a recruitment written paper

class A { // given int alpha; int beta; public A(int alpha, int beta) { this.alpha = alpha; this.beta = beta; } public void display() { System.out.println("Alpha" + alpha + "\nBeta" + beta); } } class Gamma extends A { // given int gamma;
public Gamma(int alpha, int beta, int gamma) { super(alpha, beta); // 1st line this.gamma = gamma; } @Override public void display() { super.display(); // A's part System.out.println("Gamma" + gamma); } } public class Main { public static void main(String[] args) { Gamma g = new Gamma(3, 30, 10); g.display(); } }
Output ✍
Alpha3
Beta30
Gamma10
Exam trap @Override needs a capital O (@override → "cannot find symbol"). The class header is public class Main { (brace, not bracket) and the file must be Main.java. super(…) must be the first statement; if you leave it out the compiler inserts super(), and A has no no-arg constructor → compile error.

Compiled and run with javac/java (JDK 21). With A ref = g; ref.display(); the output is the same three lines: the overridden method is chosen by the object's real class.

7Constructors & Where Objects Live

MCQ + viva

"What is invoked to create an object in Java?" → a constructor, called by new. (recruitment paper, short question)

  • same name as the class, no return type (not even void)
  • runs automatically once per object; may be overloaded
  • default no-arg constructor exists only if you write none
  • this(…) / super(…) chain constructors: first line only

"Where are objects created in Java?" → on the heap, by new. The variable g is only a reference kept in main's stack frame; the garbage collector frees the object once no reference reaches it.

Exam trap In C++ an object can live on the stack (Gamma g(3,30,10);) or on the heap (new Gamma(…), freed with delete). Java has only heap objects and no delete.

8Compile-time Polymorphism

written: code
Q What is compile-time polymorphism in OOP? Explain how it is achieved and illustrate the concept with a suitable code example.

BUET MSc (CSE) admission test · 03.10.2026

Definition Polymorphism = "many forms": one name (method, operator, interface) behaves differently in different contexts. In compile-time (static, early-binding) polymorphism the compiler decides which body runs from the signature (name + number, type and order of parameters), before the program runs.
class Calculator { int add(int a, int b) { return a + b; } int add(int a, int b, int c) { return a + b + c; } double add(double a, double b) { return a + b; } } public class Main { public static void main(String[] args) { Calculator c = new Calculator(); System.out.println(c.add(2, 3)); // 5 System.out.println(c.add(2, 3, 4)); // 9 System.out.println(c.add(2.5, 1.5)); // 4.0 } }

Achieved by:

  1. Method / function overloading (above)
  2. Operator overloading (C++): Complex operator+(const Complex&)
  3. Templates / generics (parametric)

Output checked with javac/java. Each call is bound while compiling, so there is no run-time lookup cost.

Exam trap A different return type alone does not overload: int f() and double f() in one class is a compile error. Overloading needs a different parameter list.

10Ambiguous Overloads in C++

written
Q Why are the following two overloaded functions inherently ambiguous?
int f(int a, int b = 5);    int f(int &a);

38th BCS written · 2018

  1. Both declarations are legal: their parameter lists differ, so the error appears only at a call.
  2. Take int x = 3; f(x);. Because of the default argument b = 5, f(int, int) can be called with one argument; passing x by value is an exact match.
  3. f(int&) binds the reference directly to the lvalue x: also an exact match.
  4. Same rank, no tie-breaker → error: call to f is ambiguous. The call syntax for a value parameter and a reference parameter is identical, so the caller can never write f(x) in a way that picks one: the pair is inherently ambiguous.
CallResult
f(x)error: ambiguous
f(10)f(int, int=5) → 15 (a literal can't bind to int&)
f(x + 1)f(int, int=5): x + 1 is an rvalue
f(x, 7)f(int, int): only it takes 2 args
Exam trap The default value b = 5 belongs in the question: it is what makes the two-parameter version a one-argument candidate. Delete = 5 and f(x) calls f(int&) without trouble. Fix: drop the default, rename one function, or take a pointer f(int*) called as f(&x).

11Pure Virtual Functions & final

MCQ: 49th BCS

Pure virtual = virtual void f() = 0; A class with one is abstract: it cannot be instantiated, and a derived class must override f() or stay abstract. Java's equivalent: abstract void f();

void f() = 0; without virtual is a compile error · virtual void f(); is an ordinary virtual function · "pure virtual f();" is not C++.

class Shape { // abstract public: virtual void draw() = 0; // pure virtual virtual ~Shape() {} }; class Circle : public Shape { public: void draw() override { cout << "Circle\n"; } }; Shape* p = new Circle(); p->draw(); // Circle
Exam trap C++ overriding without virtual is only hiding: with Base* b = new Derived(); b->print(); a non-virtual print() prints Base. Mark the base method virtual to get Derived (run-time polymorphism).

Java final (49th BCS, 2025): the keyword that stops a method being overridden is final. final variable = constant · final method = no override (javac: "overridden method is final") · final class = no subclass (String). const is reserved but unused; static methods are hidden, not overridden; synchronized is for threads.

12The Facade Design Pattern

written: name + code
Q We are going to create a Shape interface and concrete classes implementing it. A facade class ShapeMaker uses the concrete classes to delegate user calls to them. FacadePatternDemo, the demo class, uses ShapeMaker to show the results. Which design pattern is being described? Implement it.

BPDB Assistant Engineer (CSE) · 24.02.2023

Answer: Facade (structural, GoF) A facade gives one simple, unified interface to a set of classes in a subsystem. The client talks only to the facade; the facade creates the subsystem objects and delegates calls to them.
// Shape.java public interface Shape { void draw(); } // Circle.java public class Circle implements Shape { @Override public void draw() { System.out.println("Circle::draw()"); } } // Rectangle.java, Square.java: the same, // printing "Rectangle::draw()" and // "Square::draw()"
// ShapeMaker.java (the facade) public class ShapeMaker { private Shape circle, rectangle, square; public ShapeMaker() { circle = new Circle(); rectangle = new Rectangle(); square = new Square(); } public void drawCircle() { circle.draw(); } public void drawRectangle() { rectangle.draw(); } public void drawSquare() { square.draw(); } }
// FacadePatternDemo.java public class FacadePatternDemo { public static void main(String[] args) { ShapeMaker shapeMaker = new ShapeMaker(); shapeMaker.drawCircle(); shapeMaker.drawRectangle(); shapeMaker.drawSquare(); } }
Output ✍ (compiled with javac)
Circle::draw()
Rectangle::draw()
Square::draw()
Exam trap ShapeMaker creates objects, but it is not a Factory: a factory hands a new object back to the client; a facade hides the objects and simplifies the calls. An Adapter converts one interface into another; a facade simplifies many.
Memory trick Facade = a building's front face: one reception desk for the whole office. GoF has 23 patterns: creational 5, structural 7, behavioural 11.

13Class Diagram: Token-Ring LAN

written: diagram
Q Draw a class diagram. A token-ring based LAN is a network of nodes in which packets are sent around. Every node has a unique name within the network and refers to its next node. Workstations originate messages; servers and printers are nodes that can receive messages. Packets contain an originator, a destination and content, and are sent around the network. A LAN is a circular configuration of nodes.
  1. Classes (nouns): LAN, Node, Workstation, Server, Printer, Packet.
  2. Generalization: Workstation, Server and Printer are Nodes → Node is an abstract superclass.
  3. Self-association "next": each Node refers to exactly one next Node; following next round the LAN returns to the start (ring).
  4. Aggregation: a LAN consists of 1..* Nodes; a Node passes on 0..1 Packet at a time; a Workstation creates Packets.
Exam trap The text puts "servers and printers" side by side as nodes that receive, so Printer is a subclass of Node, not of Server. "Refers to its next node" is a self-association of Node, not a separate class.
Marks plan correct classes · attributes with types · operations · generalization · self-association with role "next" · multiplicities · the ring constraint.

UML class-diagram notation (asked as MCQs too)

Multiplicity: 1 exactly one · 0..1 optional · * or 0..* many · 1..* at least one. Composition = the part dies with the whole (Order ◆ OrderLine); aggregation = the part can live alone (LAN ◇ Node).
