1Polymorphism: Compile-time vs Run-time; Overloading

most tested ★
Definition Polymorphism ("one interface, many forms") lets the same name do different work depending on the types involved. Binding = connecting a call to a function body. Early (static) binding happens at compile time — overloading and templates. Late (dynamic) binding happens at run time — overriding through a base pointer or reference.
Function overloading rules Same name, same scope; parameter lists differ in number, type or order. Return type alone is not enough: int f(int) + double f(int) = compile error. The compiler ranks: exact match → promotion (char→int, float→double) → standard conversion → user conversion; two equally good matches = ambiguity error. Java also lets a subclass overload an inherited method.

class Complex { double re, im; public: Complex(double r=0, double i=0) : re(r), im(i) {} Complex operator+(const Complex& c) const { return Complex(re + c.re, im + c.im); } }; Complex a(1,2), b(3,4); Complex c = a + b; // a.operator+(b) → 4+6i

Rules Precedence, associativity and arity never change; no new operators (**); one operand must be a user type.

2Virtual Functions, vtable and Overriding

output questions ★
Definition Overriding = a derived class redefines an inherited method with the same signature. A C++ virtual function is resolved by the object's type, not the pointer's, so Base* p = new Derived; p->f(); runs Derived::f. Without virtual the pointer's type decides (static binding). The compiler implements this with a vtable per class and a hidden vptr per object.
class Base { public: void show() { cout << "Base "; } virtual void print() { cout << "BasePrint"; } }; class Derived : public Base { public: void show() { cout << "Derived "; } void print() override { cout << "DerivedPrint"; } }; Base* p = new Derived; p->show(); // Base (static) p->print(); // DerivedPrint (dynamic) // output: Base DerivedPrint

Access (Java)anysame or wider, never narrower
static / private / finalcan be overloadednot overridable; static is hidden

Memory trick "The pointer picks the menu; with virtual, the object picks the dish."
Exam trap Constructors cannot be virtual; a virtual call inside one runs the base version. Java overriding may not reduce access or throw broader checked exceptions.
Worked example ✍ sizeof 64-bit: class A { int x; }; → 4. Add one virtual function → 16 (8-byte vptr + 4 + padding). More virtual functions: still one vptr.

3Abstract Classes and Virtual Destructors

high-yield ★
Definition A pure virtual function is declared with = 0 — virtual double area() = 0; — and says "every subclass must supply this". A class with at least one pure virtual function is an abstract class: no objects of it can be created, but pointers and references to it can. A derived class that does not override every pure virtual function is abstract too. Java and C# use the keyword abstract.
class Shape { public: virtual double area() = 0; // pure virtual ~Shape() {} // virtual dtor }; class Circle : public Shape { double r; public: Circle(double r) : r(r) {} double area() override { return 3.14159*r*r; } }; Shape* s[2] = { new Circle(1), new Rect(2, 3) }; double total = 0; for (auto x : s) total += x->area(); // Shape t; → error: abstract class
Can an abstract class …C++Java
have constructors, fields, normal methods?yes (derived class runs the constructor)yes
have zero abstract methods?no — abstract only if ≥ 1 pure virtualyes, if marked abstract
give the abstract method a body?yes, defined outside: Shape::area()no
Same in Java abstract class Shape { abstract double area(); } · class Circle extends Shape {…} · Shape s = new Circle(1); is legal — the reference type may be abstract.
Virtual destructor Base* p = new Derived; delete p; — if ~Base() is not virtual, only the base destructor runs (formally undefined behaviour) and the derived part leaks. Rule: a class with any virtual function needs a virtual destructor. Order with it: ~Derived() then ~Base().
Object slicing Derived d; Base b = d; copies only the Base part; the derived fields are "sliced off" and b.print() calls Base::print. Polymorphism works only through pointers or references, never by value. Java has no slicing: variables hold references.
Memory trick "= 0 means zero objects." Put = 0 anywhere in a class and it can no longer be built.
Exam trap "Abstract class contains only abstract methods" is false. C++ has no abstract keyword. Abstract class vs interface: first lesson.
Worked example ✍ total area Circle(1) + Rect(2,3) = 3.14159 + 6 = 9.14, each area() chosen at run time.

4Exception Handling: C++ and Java

output questions ★
Definition An exception is an abnormal event at run time (divide by zero, bad index, missing file) that breaks the normal flow. try guards a block, throw raises an exception object, catch handles a matching type. A throw triggers stack unwinding: frames are popped and their locals destroyed until a handler matches; none → std::terminate() (C++) or the thread dies with a stack trace (Java).
double divide(int a, int b) { if (b == 0) throw runtime_error("b = 0"); return (double)a / b; } try { cout << divide(10, 0); // skipped } catch (const runtime_error& e) { cout << e.what(); // b = 0 } catch (...) { // any type cout << "unknown"; }

Java classKindExamples

Checked = the compiler forces you to catch it or declare it with throws. C++: std::exception → logic_error (out_of_range, invalid_argument), runtime_error (overflow_error, underflow_error), bad_alloc, bad_cast; all have what().

Memory trick "Catch the child before the parent." The first matching handler wins, so derived types go first. "Checked = Compiler-checked."
Exam trap catch (Exception e) above a subclass catch = compile error in Java. finally is skipped only by System.exit() or a crash; a return in finally overrides the try's.
Worked example ✍ trace int[] a = new int[3]; try { a[3]=10; print("X"); } catch {print("Y");} finally {print("Z");} print("W"); → YZW

5Template Functions and Classes; Java Generics

programming question ★
Definition A template is a blueprint written once with a type parameter T. When code uses it with a concrete type, the compiler instantiates it — generates a separate function or class for that type — at compile time. This is parametric (generic) polymorphism; the whole STL (vector<T>, sort, map<K,V>) is built on it.
template <typename T> T maxOf(T a, T b) { return a > b ? a : b; } cout << maxOf(3, 7) // T = int << " " << maxOf(2.5, 1.5) << " " << maxOf('a', 'z'); // output: 7 2.5 z // maxOf(3, 2.5) → error: T int or double? // maxOf<double>(3, 2.5) → 3
template <class T, int N = 100> class Stack { T data[N]; int top = -1; public: void push(const T& x) { if (top == N - 1) throw overflow_error("full"); data[++top] = x; } T pop() { if (top < 0) throw underflow_error("empty"); return data[top--]; } }; Stack<int> si; Stack<string, 10> ss;
Specialization A full specialization replaces the template for one exact type: template<> const char* maxOf(const char* a, const char* b) using strcmp — without it two C strings are compared by address. Class templates may also be partially specialized (Stack<T*>); function templates cannot. Template code lives in the header: the compiler needs the full body to instantiate it.
PointC++ templateJava generics

Memory trick "Templates are cookie cutters": one cutter, a new cookie for every dough (type). Java generics: one cookie with a label.
Exam trap Java generics are not templates: after erasure List<String> and List<Integer> share one class, so new T() is illegal.
Worked example ✍ Java static <T> void show(T v): show(100) autoboxes to Integer. Box<String> b = new Box<>(); — the diamond infers String.

7Threads: Creation and Life Cycle

high-yield ★
Definition A thread is the smallest unit of CPU scheduling — a "lightweight process". Multi-threading runs two or more threads inside one process; they share its code, data and heap, but each has its own stack, registers and program counter. One core: threads run concurrently (interleaved); many cores: in parallel. Uses: responsive GUIs, servers, background downloads.

// Way 1: extend Thread class MyThread extends Thread { public void run() { System.out.println("T1"); } } // Way 2: implement Runnable (preferred) class Task implements Runnable { public void run() { System.out.println("T2"); } } new MyThread().start(); new Thread(new Task()).start(); new Thread(() -> System.out.println("T3")) .start(); // lambda (Java 8)
start() vs run() start() asks the JVM for a new thread, which then calls run(). Calling run() directly is an ordinary call on the current thread. start() twice → IllegalThreadStateException. Runnable is preferred: the class can still extend another class (single inheritance), and one task can be shared by many threads. The order in which threads print is not guaranteed.

Memory trick "New Runners Block, Wait, Time-wait, Terminate" — the six Java states in enum order.
Exam trap Java has no RUNNING state: RUNNABLE = ready + running. Waiting for a lock = BLOCKED; wait()/join() = WAITING; sleep(ms) = TIMED_WAITING.
Worked example ✍ t.run(); print("M"); → run's output always first (same thread). t.start(); print("M"); → order unpredictable.

8Synchronization, Race Conditions and Deadlock

written favourite ★
Definition A race condition occurs when two threads access shared data, at least one writes, and the result depends on the timing. The code that touches shared data is the critical section; synchronization guarantees mutual exclusion — only one thread in it at a time. count++ looks like one step but is three (read, add, write), so two threads can lose an update.
// Java: monitor lock on 'this' class Counter { private int count = 0; public synchronized void increment() { count++; } public int get() { return count; } } // or: synchronized (lock) { count++; } // or: AtomicInteger c; c.incrementAndGet();
// C++11: <thread>, <mutex> int count = 0; mutex m; void work() { for (int i = 0; i < 1000; i++) { lock_guard<mutex> g(m); // RAII lock count++; } } thread t1(work), t2(work); t1.join(); t2.join(); // wait for both cout << count; // always 2000
ToolWhat it gives
Mutex (lock)one owner at a time; the locker must unlock
Semaphorecounter: up to n threads; binary semaphore ≈ mutex (but no ownership)
Monitorlock + waiting in one object: synchronized + wait/notify
volatile (Java)visibility of the latest value; not atomicity — count++ still races
join / detach (C++)wait for it / let it run alone; neither → std::terminate
Deadlock: 4 Coffman conditions ① Mutual exclusion — a resource is held by one thread. ② Hold and wait — hold one, wait for another. ③ No preemption — a lock cannot be taken away. ④ Circular wait — T1 → T2 → … → T1. All four are needed; break one and deadlock is impossible — usually a fixed lock order (always A before B). Starvation = never gets a turn; livelock = busy but no progress.
Memory trick Coffman = "My Hat, No Coat": Mutual exclusion, Hold & wait, No preemption, Circular wait.
Exam trap wait()/notify() are Object methods, called only while holding the lock (else IllegalMonitorStateException).
Worked example ✍ lost update count = 5. T1 reads 5, T2 reads 5, T1 writes 6, T2 writes 6 → final 6, not 7. Without the lock, two × 1000 increments give ≤ 2000.

Written question Distinguish compile-time and run-time polymorphism. Explain how a virtual function gives run-time polymorphism in C++, with an example and the vtable mechanism. Why should the destructor of a polymorphic base class be virtual? 10 marks
  1. Distinction (3) — compile-time: overloading / templates, chosen from the argument list, early binding, fast; run-time: overriding of virtual functions through a base pointer or reference, chosen by the object's type, late binding, needs inheritance. 3
  2. Example (3) — Base with virtual void print(), Derived overriding it; Base* p = new Derived; p->print(); prints the derived version; without virtual, the base version. 3
  3. Mechanism (2) — each class with virtual functions has a vtable of function addresses; each object has a hidden vptr to its class's vtable; the call reads vptr, indexes the table and jumps. 2
  4. Virtual destructor (2) — delete p with a non-virtual ~Base runs only the base destructor (undefined behaviour, leak); a virtual one runs ~Derived then ~Base. 2
