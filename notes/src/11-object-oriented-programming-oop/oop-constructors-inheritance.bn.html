সংজ্ঞা কনস্ট্রাক্টর (Constructor) একটি বিশেষ মেম্বার ফাংশন, যা অবজেক্ট তৈরির সময় স্বয়ংক্রিয়ভাবে চলে এবং অবজেক্টকে একটি বৈধ প্রাথমিক অবস্থায় আনে। এর নাম ক্লাসের নামের সমান এবং কোনো রিটার্ন টাইপ নেই — void-ও নয়। এটি ওভারলোড করা যায়, private হতে পারে (সিঙ্গেলটন), কিন্তু C++-এ virtual বা static হতে পারে না, Java-তে final, static বা abstract হতে পারে না। এটি ইনহেরিট হয় না।

২কপি কনস্ট্রাক্টর; শ্যালো বনাম ডিপ কপি

লিখিত প্রশ্নের প্রিয় ★
সংজ্ঞা কপি কনস্ট্রাক্টর (Copy constructor) একই ক্লাসের বিদ্যমান অবজেক্টের কপি হিসেবে একটি নতুন অবজেক্ট তৈরি করে। C++ রূপ: ClassName(const ClassName& other)। এটি চলে যখন একটি অবজেক্টকে আরেকটি থেকে ইনিশিয়ালাইজ করা হয় (A b = a;, A b(a);), যখন অবজেক্ট পাস বাই ভ্যালু হয়, এবং যখন রিটার্ন বাই ভ্যালু হয় (প্রায়ই বাদ পড়ে)। কম্পাইলারের সংস্করণ মেম্বার ধরে ধরে কপি করে — শ্যালো কপি (Shallow copy)।
class Str { char* p; public: Str(const char* s) { p = new char[strlen(s) + 1]; strcpy(p, s); } Str(const Str& o) { // deep copy p = new char[strlen(o.p) + 1]; strcpy(p, o.p); } ~Str() { delete[] p; } }; Str a("Dhaka"); Str b = a; // copy ctor: own buffer

কেন const A&? রেফারেন্সে: বাই-ভ্যালু প্যারামিটার হলে কপি বানাতে আরেকটি কপি লাগত → অসীম পুনরাবৃত্তি, তাই C++ A(A a) নাকচ করে। const: const অবজেক্ট ও টেম্পোরারি কপি করা যায়, আর উৎস না বদলানোর প্রতিশ্রুতি। রুল অব থ্রি (Rule of three): যে ক্লাসের নিজস্ব ডিস্ট্রাক্টর লাগে, তার নিজস্ব কপি কনস্ট্রাক্টর ও কপি অ্যাসাইনমেন্টও লাগে।
Java-তে ডিফল্ট কপি কনস্ট্রাক্টর নেই নিজে লেখো: Student(Student s) { name = s.name; age = s.age; }, অথবা clone() ওভাররাইড করো। Object.clone() শ্যালো, protected, আর ক্লাস implements Cloneable না করলে CloneNotSupportedException ছোড়ে।

পরীক্ষার ফাঁদ b আগে থেকেই থাকলে b = a; ডাকে অ্যাসাইনমেন্ট অপারেটর, কপি কনস্ট্রাক্টর নয়। A b = a; ইনিশিয়ালাইজেশন → কপি কনস্ট্রাক্টর।

আউটপুট প্রশ্ন ★
সংজ্ঞা C++-এর মেম্বার ইনিশিয়ালাইজার লিস্ট (Member initializer list) (A(int v) : x(v), Base(v) {}) বডি চলার আগেই বেস ও মেম্বার ইনিশিয়ালাইজ করে। const মেম্বার, রেফারেন্স মেম্বার, ডিফল্ট কনস্ট্রাক্টরহীন ক্লাসের মেম্বার এবং আর্গুমেন্ট-চাওয়া বেস ক্লাসের জন্য এটি বাধ্যতামূলক। কনস্ট্রাক্টর চেইনিং (Constructor chaining) মানে এক কনস্ট্রাক্টর থেকে আরেকটি ডাকা: Java this(…) (একই ক্লাস) ও super(…) (প্যারেন্ট), C++ : Base(…) এবং C++11 থেকে ডেলিগেটিং A() : A(0) {}।
class Point { // C++ const int x; int& r; public: Point(int a, int& b) : x(a), r(b) {} // must }; class P3 : public Point { int z; public: P3(int a, int& b, int c) : Point(a, b), z(c) {} P3(int& b) : P3(0, b, 0) {} }; // C++11 delegating ctor
class A { // Java A() { System.out.print("A"); } A(int x) { this(); // 1st line System.out.print(x); } } class B extends A { B() { super(5); // 1st line System.out.print("B"); } } new B(); // prints A5B

৭ইনহেরিট্যান্স: is-a ও পাঁচটি প্রকার

সর্বোচ্চ হাই-ইল্ড ★
সংজ্ঞা ইনহেরিট্যান্স (Inheritance) একটি নতুন ডিরাইভড (চাইল্ড, সাব) ক্লাসকে বিদ্যমান বেস (প্যারেন্ট, সুপার) ক্লাসের মেম্বার পেতে দেয়, তারপর সে নিজের মেম্বার যোগ বা পুনঃসংজ্ঞায়িত করে। এটি is-a সম্পর্ক বোঝায় (Car is-a Vehicle), কোড পুনর্ব্যবহার দেয় এবং রান-টাইম পলিমরফিজমের ভিত্তি। সিনট্যাক্স: C++ class Car : public Vehicle {…}; · Java class Car extends Vehicle {…}।
প্রকারআকৃতিC++ উদাহরণC++ / Java ক্লাস
সিঙ্গেল (Single)A → Bclass B : public A✓ / ✓ extends
মাল্টিলেভেল (Multilevel)চেইন A → B → CB : A, C : B✓ / ✓
হায়ারার্কিক্যাল (Hierarchical)A → B, A → CB : A, C : A✓ / ✓
মাল্টিপল (Multiple)A, B → CC : public A, public B✓ / ✗ (ইন্টারফেসে ✓)
হাইব্রিড (Hybrid)মিশ্রণ, যেমন ডায়মন্ডA; B, C : A; D : B, C✓ / কেবল ইন্টারফেসে
যা ইনহেরিট হয় না কনস্ট্রাক্টর ও ডিস্ট্রাক্টর (C++11-এ using Base::Base; দিয়ে নেওয়া যায়) · কপি অ্যাসাইনমেন্ট অপারেটর (ডিরাইভডেরটি লুকিয়ে দেয়) · friend ফাংশন — বন্ধুত্ব উত্তরাধিকারে যায় না · private মেম্বার: C++-এ ডিরাইভড অবজেক্টের ভেতরে থাকে কিন্তু নাম ধরে ব্যবহার করা যায় না; Java বলে এগুলো ইনহেরিট হয় না। final ক্লাস (যেমন String) এক্সটেন্ড করা যায় না।

টেবিল + আউটপুট ★
সংজ্ঞা C++-এ ইনহেরিট্যান্স মোড (Inheritance mode) — public, protected বা private — একটি ছাদ: ইনহেরিট হওয়া মেম্বার কম দৃশ্যমান হতে পারে, বেশি কখনো নয়। বেসের private মেম্বার ডিরাইভড ক্লাসে কখনো অ্যাক্সেসযোগ্য নয়, মোড যা-ই হোক। ডিফল্ট মোড: class → private, struct → public। Java-তে মোড একটিই: extends প্রতিটি অ্যাক্সেস লেভেল যেমন আছে তেমন রাখে।

  1. আগে ভার্চুয়াল বেস ক্লাস (প্রতিটি একবার), তারপর সরাসরি বেস বেস-লিস্টের ক্রমে — class C : public B, public A আগে B, পরে A গড়ে, ইনিশিয়ালাইজার লিস্টে যা-ই লেখা থাক।
  2. তারপর মেম্বার অবজেক্ট ঘোষণার ক্রমে, শেষে কনস্ট্রাক্টর বডি। ধ্বংস হুবহু উল্টো।
  3. Java: static ব্লক ক্লাস লোডের সময় একবার (প্যারেন্ট আগে); প্রতি new-এ: super() চেইন Object পর্যন্ত, তারপর ফিল্ড ইনিশিয়ালাইজার ও বডি, প্যারেন্ট আগে।
class A { int a; // private protected: int b; public: int c; }; class B : private A { void f() { a = 1; // ✗ base-private b = 2; // ✓ now private in B c = 3; } }; // ✓ private in B class C : public B { void g() { c = 4; } }; // ✗ private in B B obj; obj.c = 5; // ✗ in main
সমাধানকৃত উদাহরণ ✍ টেবিল পড়ো B : private A A-র b ও c-কে B-তে private করে দেয়: B-র মেথড এগুলো ব্যবহার করতে পারে; B-র চাইল্ড C ও main পারে না; A-র a B-র ভেতরেও অনাগম্য। B : public A হলে obj.c ও c = 4 কম্পাইল হয়; a তবুও তালাবদ্ধ।
মনে রাখার কৌশল "মোড হলো ছাদ।" public রেখে দেয়, protected public-কে protected-এ নামায়, private সবকিছুকে private-এ নামায়; বেসের private তালাবদ্ধই থাকে।
পরীক্ষার ফাঁদ class B : protected A, A-তে public f(): main-এ B b; b.f(); → কম্পাইল এরর; B-র নিজের মেথডে f() চলে।

সংজ্ঞা ডায়মন্ড সমস্যা (Diamond problem): B ও C দুটোই A-কে ইনহেরিট করে, আর D ইনহেরিট করে B ও C-কে। সাধারণ D অবজেক্টে তখন A-র দুটি কপি থাকে, তাই d.x অস্পষ্ট (ambiguous) (কম্পাইল এরর)। C++ সমাধান করে ভার্চুয়াল বেস ক্লাস (Virtual base class) দিয়ে: class B : virtual public A ও class C : virtual public A ভাগ করে একটি A। Java অবস্থার (state) ক্ষেত্রে এটি এড়ায় কেবল একটি প্যারেন্ট ক্লাস দিয়ে।
class A { public: int x; A() { cout << "A"; } }; class B : virtual public A { public: B() { cout << "B"; } }; class C : virtual public A { public: C() { cout << "C"; } }; class D : public B, public C { public: D() { cout << "D"; } }; D d; // prints ABCD d.x = 5; // OK: one shared A // without virtual: ABACD, and // d.x is ambiguous (use d.B::x)
