1Constructors: Rules and Types

most tested ★
Definition A constructor is a special member function that runs automatically when an object is created and puts it in a valid initial state. It has the same name as the class and no return type — not even void. It can be overloaded, can be private (singleton), but cannot be virtual or static in C++, and cannot be final, static or abstract in Java. It is not inherited.
class Student { // C++ string name; int age; public: Student() { // default name = "Unknown"; age = 0; } Student(string n, int a) { // param. name = n; age = a; } Student(const Student& s) { // copy name = s.name; age = s.age; } }; Student s1; // default Student s2("Alice", 20); // parameterized Student s3 = s2; // copy

2Copy Constructor; Shallow vs Deep Copy

written favourite ★
Definition A copy constructor creates a new object as a copy of an existing object of the same class. C++ form: ClassName(const ClassName& other). It runs when an object is initialised from another (A b = a;, A b(a);), when an object is passed by value, and when one is returned by value (often elided). The compiler's version copies member by member — a shallow copy.
class Str { char* p; public: Str(const char* s) { p = new char[strlen(s) + 1]; strcpy(p, s); } Str(const Str& o) { // deep copy p = new char[strlen(o.p) + 1]; strcpy(p, o.p); } ~Str() { delete[] p; } }; Str a("Dhaka"); Str b = a; // copy ctor: own buffer

Copiesthe pointer (address)the data the pointer points to

After copychange via b shows in aobjects independent
Dangerdouble delete, dangling pointerslower, more memory
Fine whenno pointer/handle membersclass owns heap memory, file, socket
Why const A&? By reference: a by-value parameter would need a copy to make the copy → endless recursion, so C++ rejects A(A a). const: lets you copy const objects and temporaries, and promises not to change the source. Rule of three: a class that needs its own destructor also needs its own copy constructor and copy assignment.
Java has no copy constructor by default Write one yourself: Student(Student s) { name = s.name; age = s.age; }, or override clone(). Object.clone() is shallow, is protected, and throws CloneNotSupportedException unless the class implements Cloneable.
Memory trick "Shallow copies the address; deep copies the house." Two people with one house key fight over the furniture.
Exam trap b = a; when b already exists calls the assignment operator, not the copy constructor. A b = a; is initialisation → copy constructor.
Worked example ✍ count copies void f(A x){}; A a; A b = a; A c(a); f(a); b = c; → copy ctor: 3 calls; last is assignment.

3Initializer List and Constructor Chaining

output questions ★
Definition C++'s member initializer list (A(int v) : x(v), Base(v) {}) initialises bases and members before the body runs. It is mandatory for const members, reference members, members whose class has no default constructor, and a base class that needs arguments. Constructor chaining is one constructor calling another: Java this(…) (same class) and super(…) (parent), C++ : Base(…) and, since C++11, delegating A() : A(0) {}.
class Point { // C++ const int x; int& r; public: Point(int a, int& b) : x(a), r(b) {} // must }; class P3 : public Point { int z; public: P3(int a, int& b, int c) : Point(a, b), z(c) {} P3(int& b) : P3(0, b, 0) {} }; // C++11 delegating ctor
class A { // Java A() { System.out.print("A"); } A(int x) { this(); // 1st line System.out.print(x); } } class B extends A { B() { super(5); // 1st line System.out.print("B"); } } new B(); // prints A5B
JobC++Java
Call parent ctor: Base(args) in the listsuper(args), first line
Call own other ctor: A(args) (C++11)this(args), first line
Write neitherbase default ctor runscompiler adds super();

Memory trick "Parents are built before children": super goes first, the body last. Calls travel up, prints come back down.
Exam trap Parent has only A(int); class B extends A { B(){} } → compile error: the hidden super() finds no A(). Fix: super(0);.
Worked example ✍ list order int a, b; then T() : b(1), a(b) {} → a is set first, from unset b: garbage.

4Destructors and Object Lifetime

MCQ + output ★
Definition A destructor (~ClassName()) runs automatically when an object's lifetime ends, to release what it holds — heap memory, files, sockets, locks. Rules: tilde + class name; no parameters, no return type; therefore cannot be overloaded — exactly one per class; not inherited; may be virtual (a constructor never can). Objects are destroyed in the reverse order of construction.

Virtual destructor (C++) Base* p = new Derived; delete p; — if ~Base() is not virtual, only ~Base runs (undefined behaviour; the Derived part leaks). Declare virtual ~Base() in any class meant to be a base. How virtual dispatch works: next lesson.
Java: no destructors The garbage collector frees unreachable objects at a time you cannot predict; System.gc() is only a request. finalize() ran at most once, maybe never, and is deprecated (Java 9; for removal since 18). Close files with try-with-resources (AutoCloseable).
Memory trick "Plates on a stack: the last plate put on is the first taken off." Tilde ~ = the wave goodbye.
Exam trap Garbage collection is not a destructor: it reclaims memory only, at no fixed time. finalize() is not guaranteed to run.
Worked example ✍ trace { A a(1); A b(2); A* p = new A(3); } → built 1 2 3; at }: ~2 ~1; object 3 is never destroyed (leak).

5Arrays of Objects

C++ vs Java trap ★
Definition An array of objects is an array whose elements are objects of a class. In C++, Student s[3]; creates three objects and calls the default constructor three times, so the class needs an accessible default constructor (or every element must be initialised). In Java, new Student[3] creates one array of three null references — no Student object, no constructor call — until you new each element.
// C++ Student s[3]; // 3 x Student() Student t[2] = { Student("A", 20), Student("B", 22) }; Student* p = new Student[n]; p[0].display(); delete[] p; // [] required
// Java Student[] s = new Student[3]; // nulls s[0].display(); // NullPointerException for (int i = 0; i < s.length; i++) s[i] = new Student(); s[0].name = "Alice"; s[0].display(); // now fine

Exam trap new A[n] must be freed with delete[]; plain delete is undefined behaviour. C++ A* q[3]; is an array of pointers: no objects.
Worked example ✍ output A(){cout<<"A";} ~A(){cout<<"~";} and { A arr[3]; } → AAA~~~. Java new A[3] with the same print: nothing.

6Object Pointers, this, new/delete, References

MCQ facts ★
Definition An object pointer holds an object's address: Student* p = &s;. Members are reached with the arrow: p->display() ≡ (*p).display(). new creates an object on the heap and returns its address; delete destroys it. Every non-static member function gets a hidden pointer this to the object it was called on. Java has no explicit pointers: every object variable is a reference.
class Counter { int n = 0; public: Counter& inc() { ++this->n; // this->n == n return *this; // allows chaining } int get() const { return n; } }; Counter* c = new Counter; c->inc().inc().inc(); cout << c->get(); // 3 delete c; c = nullptr;

Worked example ✍ Java alias Student s = new Student(); s.age = 20; Student r = s; r.age = 21; → s.age is 21: one object, two references.

7Inheritance: is-a and the Five Types

highest-yield ★
Definition Inheritance lets a new derived (child, sub) class acquire the members of an existing base (parent, super) class, then add or redefine its own. It models an is-a relationship (Car is-a Vehicle) and gives code reuse and the basis for run-time polymorphism. Syntax: C++ class Car : public Vehicle {…}; · Java class Car extends Vehicle {…}.

A final class (e.g. String) cannot be extended.

Worked example ✍ classify C : A, B → multiple. B : A; C : B → multilevel. B : A; C : A → hierarchical.

8Inheritance Access Modes and Build Order

table + output ★
Definition In C++ the inheritance mode — public, protected or private — is a ceiling: an inherited member can become less visible, never more. Base private members are never accessible in the derived class, whatever the mode. Default mode: class → private, struct → public. Java has one mode only: extends keeps every access level as it is.
In base ↓public inheritanceprotected inheritanceprivate inheritance

class X { public: X() { cout << "X"; } ~X() { cout << "~X"; } }; class Y { public: Y() { cout << "Y"; } ~Y() { cout << "~Y"; } }; class Z : public X { Y y; // member public: Z() { cout << "Z"; } ~Z() { cout << "~Z"; } }; int main() { Z z; } // XYZ~Z~Y~X
  1. Virtual base classes first (once each), then direct bases in the order of the base list — class C : public B, public A builds B before A, whatever the initializer list says.
  2. Member objects in declaration order, then the constructor body. Destruction runs the exact reverse.
  3. Java: static blocks once at class load (parent first); per new: the super() chain up to Object, then field initialisers and body, parent first.
class A { int a; // private protected: int b; public: int c; }; class B : private A { void f() { a = 1; // ✗ base-private b = 2; // ✓ now private in B c = 3; } }; // ✓ private in B class C : public B { void g() { c = 4; } }; // ✗ private in B B obj; obj.c = 5; // ✗ in main
Worked example ✍ read the table B : private A makes A's b and c private in B: B's methods may use them; B's child C and main may not; A's a is unreachable even in B. With B : public A, obj.c and c = 4 compile; a is still locked.
Memory trick "The mode is a ceiling." public keeps, protected lowers public to protected, private lowers everything to private; base-private stays locked.
Exam trap class B : protected A, A has public f(): B b; b.f(); in main → compile error; inside B's own methods f() is fine.
Worked example ✍ output A(){cout<<"A";} ~A(){cout<<"a";}, same for B with "B"/"b", class B : public A, B obj; → ABba.

9Diamond Problem and Virtual Base Class

frequently tested ★
Definition The diamond problem: B and C both inherit A, and D inherits B and C. A plain D object then holds two copies of A, so d.x is ambiguous (compile error). C++ fixes it with a virtual base class: class B : virtual public A and class C : virtual public A share one A. Java avoids it for state by allowing only one parent class.
class A { public: int x; A() { cout << "A"; } }; class B : virtual public A { public: B() { cout << "B"; } }; class C : virtual public A { public: C() { cout << "C"; } }; class D : public B, public C { public: D() { cout << "D"; } }; D d; // prints ABCD d.x = 5; // OK: one shared A // without virtual: ABACD, and // d.x is ambiguous (use d.B::x)
PointPlain multiple inheritanceWith virtual base

d.xambiguous → d.B::x or d.C::xfine
Who constructs AB and C, each its own Athe most-derived class D, first

interface Fly { default void go() { System.out.print("fly"); } } interface Swim { default void go() { System.out.print("swim"); } } class Duck implements Fly, Swim { public void go() { // must override Fly.super.go(); // pick one } }
Java: interfaces instead One extends, many implements: class Car extends Vehicle implements Horn, Gps. Since Java 8 interfaces may carry default methods, so a method-level diamond is possible: two defaults with the same signature → compile error until the class overrides, optionally calling Fly.super.go(). A class method beats an interface default.
Memory trick "Virtual base = one shared grandparent." Two parents, one grandmother at the family dinner, not two.
Exam trap virtual goes on the middle classes (B and C), not on D. A virtual base class is not a virtual function; the latter is next lesson.
Worked example ✍ size view With 4-byte int x, a plain diamond D carries 2 copies of x; the virtual version carries 1 (plus hidden base pointers).

Written question What is a copy constructor? When is it called? Explain shallow and deep copy with a C++ class that owns heap memory, and state the order of constructor and destructor calls in multilevel inheritance. 10 marks
  1. Definition (2) — a constructor A(const A& o) that builds a new object from an existing one; by reference (by value would recurse), const to accept const objects and temporaries. 2
  2. When called (2) — A b = a; / A b(a);, pass by value, return by value; not for b = a; (assignment operator). 2
  3. Shallow vs deep (4) — default copy copies the pointer → shared buffer, double delete; deep copy allocates a new buffer and copies the data (the Str class with new char[], strcpy, delete[]); rule of three. 4
  4. Order (2) — for A → B → C: constructors A, B, C; destructors ~C, ~B, ~A. 2
