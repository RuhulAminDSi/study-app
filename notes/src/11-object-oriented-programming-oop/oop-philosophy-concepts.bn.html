১OOP-এর দর্শন: অবজেক্ট ও মেসেজ

ভিত্তি ★
সংজ্ঞা অবজেক্ট ওরিয়েন্টেড প্রোগ্রামিং (OOP) এমন একটি প্যারাডাইম যেখানে প্রোগ্রাম গড়া হয় অবজেক্ট (Object) দিয়ে — প্রতিটি অবজেক্ট নিজের ডেটা ও সেই ডেটার ওপর কাজ করার অপারেশন একসঙ্গে রাখে — এবং অবজেক্টগুলো একে অপরকে মেসেজ পাঠিয়ে (Message passing) কাজ করে। এক লাইনে দর্শন: "বাস্তব জগৎকে যেভাবে ভাবি, সেভাবেই প্রোগ্রাম লেখো।" গাড়ি, ছাত্র বা ব্যাংক অ্যাকাউন্টের কিছু আছে (স্টেট) এবং সেগুলো কিছু করে (বিহেভিয়ার); OOP ঠিক সেভাবেই লেখে।
ডেটা + কোড একসঙ্গে চলে
অবজেক্টের তিনটি জিনিস (Booch) আইডেন্টিটি (Identity) — যা একে এই অবজেক্ট বানায়: একই owner ও balance-এর দুটি অ্যাকাউন্টও দুটি আলাদা অবজেক্ট (ভিন্ন ঠিকানা / রেফারেন্স)।
স্টেট (State) — অ্যাট্রিবিউটগুলোর (ফিল্ড, ডেটা মেম্বার) বর্তমান মান।
বিহেভিয়ার (Behaviour) — অবজেক্ট যা করতে পারে: তার মেথড (মেম্বার ফাংশন), যা স্টেট পড়ে বা বদলায়।
মেসেজ পাসিং — acc1.deposit(500) রিসিভার acc1-কে "deposit 500" মেসেজ পাঠায়: রিসিভার + মেথডের নাম + আর্গুমেন্ট। কীভাবে সাড়া দেবে, তা রিসিভারই ঠিক করে।
বাস্তব জিনিসস্টেট (আছে)বিহেভিয়ার (করে)কোডে
গাড়িরং, ইঞ্জিন, গতিচালু, থামা, গতি বাড়ানোCar-এর ফিল্ড + মেথড
ছাত্রনাম, আইডি, গ্রেডপড়া, পরীক্ষা দেওয়াStudent-এর ফিল্ড + মেথড
ব্যাংক অ্যাকাউন্টমালিক, ব্যালেন্সজমা, উত্তোলনAccount-এর ফিল্ড + মেথড
মনে রাখার কৌশল "বিশেষ্য হয় ক্লাস, বিশেষণ হয় ফিল্ড, ক্রিয়া হয় মেথড।" সমস্যার বিবরণ জোরে পড়লেই প্রথম ক্লাস ডিজাইন হাতে আসে।
পরীক্ষার ফাঁদ আইডেন্টিটি আর স্টেট এক নয়। সমান ফিল্ডের দুটি অবজেক্ট সমান, কিন্তু অভিন্ন নয়: Java-তে a == b আইডেন্টিটি, a.equals(b) স্টেট তুলনা করে।
সমাধানকৃত উদাহরণ ✍ অংশ চেনো "লাইব্রেরি সদস্যদের বই ধার দেয়।" ক্লাস: Library, Book, Member। Book-এর স্টেট: title, isbn, onLoan। মেসেজ: lib.lend(book, member) → রিসিভার lib।
কোথা থেকে এল শব্দটির প্রবর্তক অ্যালান কে (Alan Kay) OOP-কে বলেছিলেন "মেসেজিং, স্টেট নিজের কাছে রাখা ও লুকানো, এবং লেট বাইন্ডিং"। এই তিন ধারণাই নিচে ফিরে আসে মেসেজ পাসিং, এনক্যাপসুলেশন ও পলিমরফিজম নামে।

২OOP-এর চারটি স্তম্ভ

সবচেয়ে বেশি আসে ★
সংজ্ঞা চারটি নীতি একটি ভাষাকে অবজেক্ট ওরিয়েন্টেড করে: অ্যাবস্ট্রাকশন (Abstraction) (কী করে দেখাও, কীভাবে লুকাও), এনক্যাপসুলেশন (Encapsulation) (ডেটা ও তার কোড একসঙ্গে বেঁধে অ্যাক্সেস নিয়ন্ত্রণ), ইনহেরিট্যান্স (Inheritance) (নতুন ক্লাস পুরোনো ক্লাসের মেম্বার পায়) ও পলিমরফিজম (Polymorphism) ("এক ইন্টারফেস, অনেক রূপ")। ক্লাস ও অবজেক্ট হলো ইট; স্তম্ভগুলো তার ওপর গড়া নীতি।
স্তম্ভএক লাইনে অর্থJava / C++-এ উপায়দৈনন্দিন ছবি
অ্যাবস্ট্রাকশনজরুরি বৈশিষ্ট্য দেখাও, বাস্তবায়ন লুকাওabstract class, interface, public মেথডস্টিয়ারিং + ব্রেক, ইঞ্জিন লুকানো
এনক্যাপসুলেশনডেটা + মেথড এক ইউনিটে; অ্যাক্সেস নিয়ন্ত্রিতclass + private ফিল্ড + মেথডওষুধের ক্যাপসুল
ইনহেরিট্যান্সচাইল্ড ক্লাস প্যারেন্টকে নেয় ও বাড়ায়extends (Java), : public (C++)Car is-a Vehicle
পলিমরফিজমএকই কল, টাইপভেদে ভিন্ন আচরণওভারলোডিং (কম্পাইল টাইম), ওভাররাইডিং (রান টাইম)বৃত্ত বনাম বর্গে draw()
স্তম্ভ পর্যায়ে ইনহেরিট্যান্স একটি ক্লাস বেস ক্লাস থেকে ডিরাইভড হয়ে তার মেম্বার পায়: is-a সম্পর্ক (Dog is-a Animal); এর বিপরীতে has-a = কম্পোজিশন (Car has-a Engine)। প্রকারভেদ ও কনস্ট্রাক্টরের ক্রম: পরের লেসন। Java-তে একটি ক্লাস কেবল একটি ক্লাস extends করে, কিন্তু অনেক interface implements করতে পারে।
স্তম্ভ পর্যায়ে পলিমরফিজম কম্পাইল-টাইম (স্ট্যাটিক বাইন্ডিং): ফাংশন / অপারেটর ওভারলোডিং — আর্গুমেন্ট তালিকা দেখে বাছাই। রান-টাইম (ডাইনামিক বাইন্ডিং): বেস-ক্লাস রেফারেন্স বা পয়েন্টারের মাধ্যমে ওভাররাইডিং; C++-এ ফাংশনটিকে virtual হতে হয়। বিস্তারিত: পরের একটি লেসন।
মনে রাখার কৌশল A PIE = Abstraction, Polymorphism, Inheritance, Encapsulation। "কোনটি স্তম্ভ নয়?" — ওভারলোডিং, ক্লাস, অবজেক্ট, কম্পাইলেশন।
পরীক্ষার ফাঁদ কিছু বই মাত্র তিনটি স্তম্ভ ধরে (অ্যাবস্ট্রাকশন বাদে)। অপশন বাধ্য না করলে চারটিই নাও। ক্লাস ও অবজেক্ট স্তম্ভ নয়।
সমাধানকৃত উদাহরণ ✍ স্তম্ভ চেনো private int pin; → এনক্যাপসুলেশন। Savings extends Account → ইনহেরিট্যান্স। ভিন্ন প্যারামিটারের দুটি add() → পলিমরফিজম।

৩অ্যাবস্ট্রাকশন বনাম এনক্যাপসুলেশন বনাম ডেটা হাইডিং

প্রায়ই গুলিয়ে যায় ★
সংজ্ঞা তিন শব্দ, তিন কাজ। অ্যাবস্ট্রাকশন একটি ডিজাইন ধারণা: বাইরের জগতের কোন বৈশিষ্ট্য দরকার তা ঠিক করো, বাকিটা উপেক্ষা করো। এনক্যাপসুলেশন একটি বাস্তবায়ন কৌশল: ডেটা ও তা ব্যবহারকারী মেথড এক ক্লাসে মোড়ানো। ডেটা হাইডিং (Data hiding) এনক্যাপসুলেশনের ভেতরের সুরক্ষা ধাপ: ডেটাকে private করা, যাতে কেবল ক্লাসের নিজের মেথডই তা ছুঁতে পারে।

ভিত্তি ★
সংজ্ঞা ক্লাস (Class) হলো ইউজার-ডিফাইন্ড টাইপ: একটি ব্লুপ্রিন্ট, যা ডেটা মেম্বার (অ্যাট্রিবিউট) ও মেম্বার ফাংশন (মেথড) ঘোষণা করে। অবজেক্ট হলো ক্লাসের একটি ইনস্ট্যান্স (Instance) — মেমোরির একটি অংশ, যেখানে ওই অ্যাট্রিবিউটগুলোর এক সেট থাকে। ক্লাস লজিক্যাল সত্তা; অবজেক্ট ফিজিক্যাল। ইনস্ট্যান্স ডেটার মেমোরি বরাদ্দ হয় প্রতিটি অবজেক্টে, ক্লাস ঘোষণার সময় নয়।
class Student { String name; // state int age; // state void display() { // behaviour System.out.println("Name: " + name + ", Age: " + age); } } public class Main { public static void main(String[] args) { Student s1 = new Student(); // object s1.name = "Alice"; s1.age = 20; s1.display(); // Name: Alice, Age: 20 } }

৭অ্যাক্সেস স্পেসিফায়ার: Java ও C++

সর্বোচ্চ হাই-ইল্ড ★
সংজ্ঞা অ্যাক্সেস স্পেসিফায়ার (Access specifier) (Java-তে access modifier) ঠিক করে কে একটি মেম্বার ব্যবহার করতে পারবে। এভাবেই ক্লাস ডেটা হাইডিং কার্যকর করে। Java-তে চারটি স্তর — private, default (কিওয়ার্ড নেই, "package-private"), protected, public; C++-এ তিনটি কিওয়ার্ড — private, protected, public, সঙ্গে ব্যতিক্রম দিতে friend।
Java মডিফায়ারএকই ক্লাসএকই প্যাকেজঅন্য প্যাকেজের সাবক্লাসঅন্য প্যাকেজ
private✓✗✗✗
default (নেই)✓✓✗✗
protected✓✓✓*✗
public✓✓✓✓

* কেবল ইনহেরিট্যান্সের মাধ্যমে — সাবক্লাসের নিজের রেফারেন্স দিয়ে (this বা সাবক্লাস অবজেক্ট), সাধারণ প্যারেন্ট অবজেক্ট দিয়ে নয়।

C++ স্পেসিফায়ারনিজ ক্লাস + friendডিরাইভড ক্লাসবাইরে
private✓✗✗
protected✓✓✗
public✓✓✓
কিছু না লিখলে ডিফল্টমেম্বারইনহেরিট্যান্স মোড
C++ classprivateprivate (class D : B)
C++ structpublicpublic (struct D : B)
Java মেম্বারpackage-private (default)— (সবসময় extends)
Java টপ-লেভেল ক্লাসকেবল public বা default চলেপ্রতি .java ফাইলে একটি public ক্লাস
মনে রাখার কৌশল Java, সংকীর্ণ থেকে প্রশস্ত: "Private Dogs Protect People" = private → default → protected → public। C++: "class গোপন রাখে, struct সব বলে দেয়।"
পরীক্ষার ফাঁদ Java default ≠ C++ default। Java default = প্যাকেজ; C++ class default = private। Java protected default-এর চেয়ে প্রশস্ত (অন্য প্যাকেজের সাবক্লাস যোগ হয়)। static, final, friend অ্যাক্সেস স্পেসিফায়ার নয়।
সমাধানকৃত উদাহরণ ✍ x কে পড়তে পারে? package a; public class P { protected int x; } a-র ক্লাস Q: পারে। প্যাকেজ b-তে R extends P: this.x হিসেবে পারে; new P().x দিয়ে নয়। b-র সাবক্লাস নয় এমন S: পারে না।

সংজ্ঞা এনক্যাপসুলেশন = ডেটা ও তার ওপর কাজ করা মেথড এক ক্লাসে বাঁধা এবং ডেটায় সরাসরি প্রবেশ সীমিত করা। প্রচলিত রেসিপি: প্রতিটি ফিল্ড private, পড়ার জন্য public getter (accessor), বদলানোর জন্য setter বা অপারেশন মেথড (mutator), আর তার ভেতরে যাচাই (Validation) — যাতে অবজেক্ট কখনো অবৈধ স্টেটে না থাকে।
class BankAccount { private String owner; private double balance; // hidden public BankAccount(String o, double b) { owner = o; balance = b > 0 ? b : 0; } public void deposit(double amt) { if (amt > 0) balance += amt; } public boolean withdraw(double amt) { if (amt <= 0 || amt > balance) return false; // refused balance -= amt; return true; } public double getBalance() { return balance; } public String getOwner() { return owner; } public void setOwner(String o) { if (o != null && !o.isEmpty()) owner = o; } }
সমাধানকৃত উদাহরণ ✍ ব্যালেন্স ট্রেস BankAccount a = new BankAccount("Rahim", 1000);
a.deposit(500); → 1500
a.withdraw(2000); → false, এখনো 1500
a.withdraw(300); → 1200
a.deposit(-50); → উপেক্ষিত, 1200
a.balance = 9999; → কম্পাইল এরর: balance private
শেষে a.getBalance() = 1200.0
এনক্যাপসুলেশনে যা পাই অখণ্ডতা — ঋণাত্মক ব্যালেন্স কখনো হয় না। রিড-অনলি ফিল্ড — getter আছে, setter নেই। বদলানোর স্বাধীনতা — কাল balance পয়সায় long হিসেবে রাখলেও getBalance()-এর কলার টের পায় না। ডিবাগের এক জায়গা — সব পরিবর্তন তিনটি মেথড দিয়ে যায়।
মেম্বারঅ্যাক্সেসধরনকেন
balance, ownerprivateফিল্ডডেটা হাইডিং
getBalance(), getOwner()publicgetter / accessorফিল্ড উন্মুক্ত না করে পড়া
deposit(), withdraw(), setOwner()publicmutatorযাচাইয়ের পরেই বদল
মনে রাখার কৌশল "ফিল্ড private, মেথড public, যাচাই ভেতরে।" প্রতিটি এনক্যাপসুলেশন প্রোগ্রামের তিন শব্দ।
পরীক্ষার ফাঁদ যাচাইহীন public setter নামেই এনক্যাপসুলেশন। private ক্লাসভিত্তিক, অবজেক্টভিত্তিক নয়: Account-এর একটি মেথড অন্য Account-এর balance পড়তে পারে।
C++ সংস্করণ একই নকশা: class BankAccount { double balance; public: … }; — balance ডিফল্টভাবে private; getter-টি const।

সংজ্ঞা স্ট্যাটিক (static) মেম্বার ক্লাসের: একটিই কপি, সব অবজেক্ট ভাগ করে, কোনো অবজেক্ট না থাকলেও থাকে, ব্যবহার হয় ClassName.member হিসেবে। নন-স্ট্যাটিক (ইনস্ট্যান্স) মেম্বার প্রতিটি অবজেক্টের: প্রতিটি অবজেক্টের নিজস্ব কপি। স্ট্যাটিক মেথডে this নেই, তাই তা ইনস্ট্যান্স মেম্বার ছুঁতে পারে না সরাসরি।
class Counter { static int count = 0; // one, shared int id; // one per object Counter() { count++; id = count; } } // in main(): Counter c1 = new Counter(); Counter c2 = new Counter(); Counter c3 = new Counter(); System.out.print(c1.id + " " + c3.id + " " + Counter.count); // Output: 1 3 3

সমাধানকৃত উদাহরণ ✍ sizeof class A { int x; static int y; void f(); }; 4-বাইট int ধরে: sizeof(A) = 4 — static y ও ফাংশন f অবজেক্টে থাকে না। ফাঁকা ক্লাস: 1।
