1Positional Number Systems

MCQ
Definition A positional (weighted) system of base (radix) r has digits 0 … r − 1; place i has weight rⁱ: N = Σ dᵢ · rⁱ (i < 0 for the fraction). Leftmost bit = MSB, rightmost = LSB.
SystemBaseDigitsExampleWhere you meet it
Binary20, 1(1011)₂ = 11all hardware, bit masks
Octal80 – 7(157)₈ = 111Unix permissions: chmod 755
Decimal100 – 9(111)₁₀human input/output
Hexadecimal160 – 9, A – F(6F)₁₆ = 111addresses, MAC, colour #FF8800

1 nibble = 4 bits · 1 byte = 8 bits · n bits give 2ⁿ patterns; N values need ⌈log₂ N⌉ bits (e.g. 1000 values → 10 bits).

Common misconception "All number systems are positional" is false: Roman numerals (XIV) are non-positional. The four computer bases are positional.

3Signed Number Representations

high-yield
Definition Hardware has no "−" sign, so the MSB is used as the sign bit (0 = +, 1 = −). Positive numbers look the same in all three forms; they differ only in how −N is written:
  • Sign-magnitude (SM): set the sign bit, keep the magnitude
  • 1's complement: invert every bit of +N  (= (2ⁿ − 1) − N)
  • 2's complement: invert every bit, then add 1  (= 2ⁿ − N)
Worked example ✍ −45 in 8 bits (+45 = 0010 1101): SM = 1010 1101 · 1's = 1101 0010 · 2's = 1101 0010 + 1 = 1101 0011

DLD · Number Systems2's complement in hardware

4Why Every CPU Uses 2's Complement

high-yield
  • One zero (no ±0 to test)
  • A − B = A + B′ + 1: one adder
  • Carry out of MSB simply dropped
  • Sign extension = copy the MSB
Weighted view The MSB has weight −2ⁿ⁻¹:
1101 0011 = −128 + 64 + 16 + 2 + 1 = −45
Memory trick: the shortcut Scan from the right: copy every bit up to and including the first 1, invert the rest: 0110 1000 (104) → 1001 1000 (−104) ✓

5Sign Extension

To widen a 2's-complement number, copy the sign bit into every new high bit; the value is unchanged.
−5: 1011 → 1111 1011 · +5: 0101 → 0000 0101
(x86: MOVSX sign-extends, MOVZX zero-extends)

Exam trap Padding a negative number with 0s changes it: 1011 (−5) → 0000 1011 = +11. Zero-extension is only for unsigned numbers.

8Subtraction by Complements: M − N

written favourite
Using r's complement
  1. Pad N to M's length
  2. Add M + r's compl. of N
  3. End carry → drop it (+)
  4. No carry → −(r's compl. of sum)
Using (r − 1)'s complement
  1. Add M + (r − 1)'s compl. of N
  2. End carry → add 1 at the LSB (end-around carry)
  3. No carry → −((r − 1)'s compl. of sum)
Worked example 1: decimal ✍ 72532 − 3250: 10's complement of 03250 = 96750; 72532 + 96750 = 169282 → drop carry → 69282.
3250 − 72532: 03250 + 27468 = 30718, no carry → −(10's complement of 30718) = −69282.
Worked example 2: binary ✍ X = 1010100 (84), Y = 1000011 (67)
TaskWorkingResult
X − Y, 2's1010100 + 0111101 = 1 0010001 → drop carry0010001 = 17
X − Y, 1's1010100 + 0111100 = 1 0010000 → + 1 (end-around)0010001 = 17

10Gray Code (Reflected Binary)

Successive values differ in exactly one bit (also last → first). Non-weighted: not for arithmetic.

Binary → Gray: gMSB = bMSB; gi = bi+1 ⊕ bi  (G = B ⊕ (B >> 1))
1011 → 1, 1⊕0, 0⊕1, 1⊕1 = 1110

Gray → binary: bMSB = gMSB; bi = bi+1 ⊕ gi (XOR with the binary bit just found)
1101 → 1, 1⊕1 = 0, 0⊕0 = 0, 0⊕1 = 1 → 1001

Used in: K-map order, rotary/shaft encoders, async FIFO pointers.

Memory trick B → G: "copy the first, then XOR neighbours". G → B: "copy the first, then XOR the new binary bit with the next Gray bit" (diagonal).

11BCD Addition: the +6 Correction

written favourite
Rule Add the BCD digits as plain binary. If the 4-bit sum is > 9 (1010–1111) or a carry comes out, add 0110 (6) and send the carry to the next digit. Why 6? 16 − 10 = 6 skips the six invalid codes.
SumBinary sumValid?CorrectionBCD result
4 + 50100 + 0101 = 1001yes (9)none0000 1001 = 9
8 + 71000 + 0111 = 1111> 9+ 0110 → 1 01010001 0101 = 15
9 + 91001 + 1001 = 1 0010carry+ 0110 → 1 10000001 1000 = 18
Worked example ✍ 59 + 38 in BCD
  1. Units: 1001 + 1000 = 1 0001 → carry, so + 0110 = 0111, carry 1
  2. Tens: 0101 + 0011 + 1 = 1001 (valid)
  3. Answer 1001 0111 = 97 ✓

Correction: C = K + Z₈Z₄ + Z₈Z₂ (K = carry out, Z = sum bits)

Exam trap 9 + 9 = 1 0010 looks valid (0010) but the carry out still forces + 6. Check both conditions. Excess-3 addition uses a different fix: carry → +0011, no carry → −0011.

DLD · Number SystemsError detection & correction

13Parity: Error Detection

MCQ
Definition A parity bit makes the total number of 1s even (even parity) or odd (odd parity). Generator/checker = XOR of all bits (an XOR tree, see Logic Gates notes).

Data 1011001 has four 1s → even-parity bit 0, odd-parity bit 1. Sent with even parity: 10110010.
Detects any odd number of flipped bits; misses 2, 4 … errors; cannot locate or correct anything.

Exam trap Two bits flipped in the same byte keep the parity unchanged: simple parity cannot detect it. 2-D (row + column) parity can correct a single error.
Hamming distance d = number of positions in which two code words differ. A code with minimum distance dmin can detect up to dmin − 1 errors and correct up to ⌊(dmin − 1)/2⌋. Parity: d = 2 (detect 1) · Hamming(7,4): d = 3 (correct 1) · SEC-DED: d = 4.

14Hamming Code: Single-Error Correction

written favourite

Parity bits needed: smallest p with 2ᵖ ≥ m + p + 1 (m data bits).

m48163264
p34567
code(7,4)(12,8)(21,16)(38,32)(71,64)

Positions: parity bits at 1, 2, 4, 8 … (powers of 2), data in the rest. P1 checks 1, 3, 5, 7 · P2 checks 2, 3, 6, 7 · P4 checks 4, 5, 6, 7 (index has that bit set).

Worked example ✍ Even parity, data 1101 → D3 = 1, D5 = 1, D6 = 0, D7 = 1
  1. P1 = D3⊕D5⊕D7 = 1 · P2 = D3⊕D6⊕D7 = 0 · P4 = D5⊕D6⊕D7 = 0
  2. Code word (positions 1 → 7): 1 0 1 0 1 0 1
  3. Received 1000101: C1 = b1⊕b3⊕b5⊕b7 = 1 · C2 = b2⊕b3⊕b6⊕b7 = 1 · C4 = b4⊕b5⊕b6⊕b7 = 0
  4. Syndrome C4C2C1 = 011 = 3 → flip bit 3 → 1010101 ✓ (000 = no error)
Memory trick "Parity bits live at powers of two; the syndrome is the address of the bad bit."
IT link Server ECC RAM = SEC-DED (72,64): Hamming(71,64) + 1 overall parity bit. Ethernet uses CRC-32; TCP/IP use checksums.

15Fixed Point vs Floating Point

Definition Fixed point: the binary point sits at a fixed place (integers, Q-format). Floating point: value = sign × mantissa × 2exponent, so the point "floats"; huge range at limited precision. A number is normalized when the mantissa is 1.f, so the leading 1 need not be stored (hidden bit).

Fact sheet

N = Σ dᵢ rⁱ · n bits → 2ⁿ patterns

Oct = 3 bits, Hex = 4 bits per digit

Integer: ÷ r, remainders up

Fraction: × r, integer parts down

1's: flip · 2's: flip + 1 = 2ⁿ − N

2's range −2ⁿ⁻¹ … 2ⁿ⁻¹ − 1

SM, 1's range ±(2ⁿ⁻¹ − 1), two zeros

MSB weight in 2's = −2ⁿ⁻¹

V = Cn−1 ⊕ Cn

Sign extension: copy the MSB

r's = rⁿ − N · (r−1)'s = rⁿ − 1 − N

(r−1)'s: end-around carry

BCD: > 9 or carry → + 0110

XS-3 = BCD + 0011

G = B ⊕ (B >> 1)

Hamming 2ᵖ ≥ m + p + 1

detect d − 1, correct ⌊(d − 1)/2⌋

IEEE: (−1)ˢ × 1.F × 2E − bias
