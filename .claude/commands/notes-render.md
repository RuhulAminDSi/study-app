# `/notes-render` — HTML to PDF

Target from `$ARGUMENTS`: `<slug>` — e.g. `os-deadlock`. `CH/SLUG` is also accepted; the
chapter part is only a hint, use the slug.

**One lesson per invocation.** If given a chapter or chapter number, list its lessons and ask
which one — or render one at a time only if the user insists. Never loop silently over a
whole chapter.

Scope: **rendering only.** Do not edit note sources here; if a source needs a change, say so
and point at `/notes-prep` or `/notes-check`. Nothing else — no manifest, no publish.

To resolve a slug to a chapter folder: check `server/data/notes/manifest.json` for the slug's
`chapterNumber`, else find `notes/src/*/<slug>.en.html`. `chapterDir()` in
`server/src/db/applyNotes.ts` decides the canonical folder name.

## Run it

```bash
node notes/build/render.mjs <slug>
```

Headless Chrome, A4, backgrounds on. Writes `notes/pdf/<NN-chapter>/<slug>.<lang>.pdf`.

`render.mjs` reads **only** `notes/src/**/<slug>.<lang>.html`. It does **not** read
`notes/md/**` — the Markdown companion is consumed later by `/notes-publish`, which builds the
`.note.pdf` and `.note.cover.jpg` from it. So editing a `.md` file does not require a re-render,
and a stale `.md` will not be caught here; it surfaces as a stale `.note.pdf` at publish time.

## Rules

- **Only sources that have a PDF are publishable.** Any source edited after its last render —
  including a `<title>` fix — must be re-rendered here.
- Re-render the whole set if any file in it changed. Partial renders leave two languages of the
  same note showing different content.
- An English-only set has no `.bn.html`, so `render.mjs` produces one PDF and one PNG-free
  language. That is expected, not a skip to report as a failure.
- Verify after rendering: every PDF exists, has a `%PDF-` header, and its page count equals
  the sheet count from `check.mjs`. A PDF with a wrong page count was rendered from a source
  that no longer matches.
- If `render.mjs` skipped a file, report the reason rather than moving on silently — a missing
  PDF surfaces later as `skipped … not published yet` from `notes:apply`.

## Never

Edit `notes/assets/hw.css`, a build script, or `public/notes/` by hand — `public/notes/` is
generated by `/notes-publish`. Never run `git commit` unless explicitly asked.

## Report

Per slug and language: the PDF path, its byte size, its page count, and the sheet count from
the last `check.mjs` run so the two are visibly equal. List anything skipped and why. Then
state the next step: `/notes-manifest` if entries are missing, otherwise `/notes-publish`.
