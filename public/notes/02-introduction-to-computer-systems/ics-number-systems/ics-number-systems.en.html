1Positional Number Systems

MCQ + Written
Definition A number system represents quantities with a fixed set of digits and a base (radix) r = the number of distinct digits, including 0. Digits run from 0 to r − 1. In a positional system each digit's value = digit × rposition.
Value N = dn−1rn−1 + … + d1r + d0 + d−1r−1 + d−2r−2 + …  (d = digit, r = base)
SystemBaseDigitsLargest digitExampleOther notations
Binary20, 11(1011)21011B · 0b1011
Octal80 – 77(157)8157Q · 0157 (C) · 0o157
Decimal100 – 99(245)10245D
Hexadecimal160 – 9, A – FF = 15(2F)162FH · 0x2F

Hex letters: A = 10, B = 11, C = 12, D = 13, E = 14, F = 15

Why binary? Electronic devices have two stable states (on/off, high/low voltage, magnetised or not). Two levels are easy to make, hard to confuse and map directly onto Boolean logic.
Exam trap (10)r = r in every base: 102 = 2, 108 = 8, 1016 = 16. Roman numerals are non-positional and have no zero.
Memory trick "Base = how many digits; biggest digit = base − 1." So 8 or 9 never appears in octal and 2 never appears in binary: (189)8 is invalid.

3Any Base → Decimal

written favourite
Method Write the place value under each digit (r0, r1, … to the left; r−1, r−2, … to the right of the point), multiply and add.
Worked examples ✍
  1. (1011.101)2 = 8 + 0 + 2 + 1 + 0.5 + 0 + 0.125 = 11.625
  2. (157.4)8 = 1×64 + 5×8 + 7×1 + 4×0.125 = 64 + 40 + 7 + 0.5 = 111.5
  3. (3A7)16 = 3×256 + 10×16 + 7 = 768 + 160 + 7 = 935
  4. (2F.8)16 = 2×16 + 15 + 8/16 = 47.5  ·  (212)3 = 2×9 + 1×3 + 2 = 23
Memory trick: Horner "Double and add" left to right. (11001)2: 1 → 3 → 6 → 12 → 25. For base r: multiply by r, add the next digit.
Speed check A binary number ending in 0 is even; the leftmost 1 tells the size: 1xxxx2 lies in 16 … 31.

4Decimal → Any Base

high-yield
Integer part Divide by r repeatedly; write each remainder; stop at quotient 0. Read remainders bottom → top (first remainder = LSD).
Fraction part Multiply by r repeatedly; take the integer part each time; stop at 0 (or enough digits). Read top → bottom (first = MSD).
Integer examples ✍
  1. 245 ÷ 8: 30 r 5, 3 r 6, 0 r 3 → (365)8
  2. 245 ÷ 16: 15 r 5, 0 r 15 = F → (F5)16
  3. 1000 ÷ 16: 62 r 8, 3 r E, 0 r 3 → (3E8)16
  4. 25 → (11001)2 · check: 16 + 8 + 1 = 25
Shortcut For small numbers, subtract the largest power of 2: 100 = 64 + 32 + 4 → (1100100)2.
Fraction examples ✍
0.625 × 2digit0.375 × 8digit0.375 × 16digit
1.2513.036.06

0.5 × 2 = 1.01
0.625 = (0.101)2 · so 25.375 = (11001.011)2 = (31.3)8 = (19.6)16
Exam trap (0.1)10 = (0.00011 0011 0011 …)2 never terminates. A fraction terminates in binary only if its denominator is a power of 2 (0.5, 0.25, 0.375 …). That is why 0.1 + 0.2 != 0.3 in floating point.
Memory trick "Divide → read Up, Multiply → read Down" (D-U, M-D). Integers grow from the point leftward, fractions grow from the point rightward.
Base r → base s ✍ Go through decimal (or through binary when both are powers of 2): (212)3 → 23 → (10111)2; (0.6875)10 × 8 → 5.5, 4.0 → (0.54)8.
Precision k fraction bits resolve steps of 2−k. 0.1 cut to 8 bits = (0.00011001)2 = 0.09765625, so stored values are rounded.

5Binary ↔ Octal ↔ Hexadecimal

high-yield
Rule 8 = 23 and 16 = 24, so one octal digit = 3 bits and one hex digit = 4 bits. Group from the radix point outwards: integer bits leftwards, fraction bits rightwards; pad with 0s at the outer ends only.
Worked examples ✍
  1. (10110001)2: 10|110|001 = (261)8; 1011|0001 = (B1)16
  2. (157)8 → 001 101 111 → 0110 1111 = (6F)16 (= 111)
  3. (3FA)16 → 0011 1111 1010 → 001 111 111 010 = (1772)8 (= 1018)
  4. (A5)16 = 1010 0101 = (245)8 = 165
Exam trap Fraction bits are padded on the right: .1011 → .101 100 = .548, not .001 011 = .138. Octal ↔ hex has no direct grouping: go through binary.
Memory trick "Oct-3, Hex-4": the exponent of 2 is the group size. Base 4 = 22 → groups of 2; base 32 = 25 → groups of 5.

Digit counts: an n-bit number needs ⌈n/3⌉ octal and ⌈n/4⌉ hex digits: 32 bits = 8 hex digits, 11 octal digits.

9Binary Multiplication & Division

× rules = AND: 0×0 = 0×1 = 1×0 = 0, 1×1 = 1. Method: shift and add.

÷ = long division; at each step the divisor "goes" once or not at all.

(110110)2 ÷ (110)2 = (1001)2 · 100111 ÷ 101 = 111 r 100 (39 ÷ 5 = 7 r 4)

Shift rule Shift left k places = × 2k; shift right = ÷ 2k (integer part). 1011 << 2 = 101100 (11 → 44).
Exam trap (1101)2 × (101)2 is 1000001, not 1000011. Convert to decimal and check (13 × 5 = 65 = 64 + 1).

10Octal & Hexadecimal Arithmetic

high-yield
Rule Add column by column in decimal. If the sum ≥ base, write sum − base, carry 1. When subtracting, a borrow adds 8 (octal) or 16 (hex) to the column.
Octal ✍
  1. 457 + 365: 7 + 5 = 12 = 8 + 4 c1 · 5 + 6 + 1 = 12 → 4 c1 · 4 + 3 + 1 = 8 → 0 c1 → (1044)8 (303 + 245 = 548)
  2. 712 − 345: 2 − 5 → 10 − 5 = 5 · 0 − 4 → 8 − 4 = 4 · 6 − 3 = 3 → (345)8
  3. (64)8 × 7: 4×7 = 28 = 3×8 + 4 · 6×7 + 3 = 45 = 5×8 + 5 → (554)8
Hex ✍
  1. 9A + 7C: A + C = 22 = 16 + 6 c1 · 9 + 7 + 1 = 17 → 1 c1 → (116)16 (154 + 124 = 278)
  2. 3A2 − 1F7: 2 − 7 → 18 − 7 = B · 9 − F → 25 − 15 = A · 2 − 1 = 1 → (1AB)16 (930 − 503 = 427)
  3. (2A)16 × 3 = 42 × 3 = 126 = (7E)16
Memory trick Think in decimal, write in the base: "over 7? take 8 away; over 15? take 16 away", and carry 1.
Exam trap (FF)16 + 1 = (100)16 = 256, and (77)8 + 1 = (100)8 = 64. "10" in hex is sixteen.

13Subtraction by Complements

written favourite
2's complement method A − B = A + (2's complement of B). End carry → discard it, the result is positive. No end carry → the result is negative; take its 2's complement for the magnitude.
25 − 13 (8-bit) ✍
25 = 00011001, −13 = 11110011
00011001 + 11110011 = 1 00001100
carry out → discard → 00001100 = +12
13 − 25 (8-bit) ✍
13 = 00001101, −25 = 11100111
00001101 + 11100111 = 11110100 (no carry)
negative → 2's comp = 00001100 → −12
1's complement method ✍ 1011 − 0110 (11 − 6): 1011 + 1001 = 1 0100 → end-around carry: 0100 + 1 = 0101 = 5. No carry → negative, answer = −(1's complement of the sum).
10's complement ✍ 725 − 318 = 725 + 682 = 1407 → drop the carry → 407. (682 = 10's complement of 318.)
Why computers use 2's complement one adder does both + and − · only one zero · no end-around carry · the sign falls out automatically.

14Overflow

high-yield
Rule Overflow = the true result is outside the n-bit range. In 2's complement it happens only when two numbers of the same sign give a result of the opposite sign; equivalently carry into MSB ≠ carry out of MSB. Adding numbers of opposite signs never overflows.
Example ✍ 100 + 64: 01100100 + 01000000 = 10100100: two positives gave a negative (−92) → overflow.
Example ✍ (−100) + (−64): 10011100 + 11000000 = 1 01011100 (+92): two negatives gave a positive → overflow.
Exam trap Carry ≠ overflow. For unsigned numbers the carry-out of the MSB signals overflow; for 2's complement a carry-out is normal (25 − 13 above) and is simply discarded.
