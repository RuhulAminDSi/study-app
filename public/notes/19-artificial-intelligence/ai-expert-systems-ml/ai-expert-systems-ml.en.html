AI · Expert Systems & MLWhat is an expert system

1What is an Expert System?

definition ★
Definition An expert system is a program that reproduces the reasoning of a human expert inside one narrow domain. It stores that domain's facts and rules, reasons over them to advise, diagnose or recommend, and — crucially — explains how it reached the conclusion.
knowledge-based · rule-based · symbolic

The domain must be narrow enough to be written down: bacteraemia, tax computation, one family of computers. It need not be easy — a hard domain is fine as long as every judgement can be stated. What disqualifies a domain is not difficulty but tacit knowledge: everything the expert does without noticing.

CharacteristicWhat it meansExample
Domain-specificone narrow field onlybacterial infection
Rule-basedproduction rules IF–THENIF fever > 38 °C THEN flu
Uncertaintycertainty factors, fuzzy logicMYCIN's certainty factors
Self-explainingprints the rules that fired"because X and Y ⇒ Z"
Does not learnrules hand-encoded by peoplenothing fitted at run time
Memory trick Four verbs, four parts: it stores what it knows, works out what follows, explains why, and asks you for the rest.
Exam trap It is not a learning system — nothing is learnt from data while it runs. It is also not general purpose: narrowness is the design.
Worked example ✍ one rule base, three cycles R1 IF temperature > 38 °C AND cough AND white-cell count > 6000 THEN influenza (0.8) · R2 IF influenza AND shortness of breath THEN pneumonia (0.9) · R3 IF temperature > 38 °C AND rash AND no cough THEN measles (0.7).
Working memory after the dialogue: temperature 39, cough true, white-cell count 7200, shortness of breath true. Cycle 1: only R1 matches → fire → add influenza 0.8. Cycle 2: R2 now matches → fire → add pneumonia 0.9. Cycle 3: R3 fails (no rash, cough present). Output: pneumonia, explained as "influenza, from fever, cough and raised white cells, plus shortness of breath". One rule fired per cycle — that is all of expert-system reasoning.
IT link Every loan-scoring rule, tax bracket and fraud rule in production is a miniature expert system: a store of rules, an engine that matches them, a log that explains it — a policy engine.

AI · Expert Systems & MLArchitecture

2Architecture of an Expert System

most tested ★
Definition The knowledge base stores the domain's facts, rules and heuristics. The inference engine matches rules against what is known and fires the ones that match. The working memory holds the facts of the case in hand. The user interface is the dialogue. The explanation facility prints the reasoning.
ComponentJobThe question it answers
Knowledge basefacts + rules + heuristics"what is known?"
Inference enginematches, fires, updates"what follows from it?"
Working memoryfacts of this case"what do we know now?"
User interfaceasks, takes answers"what do you need?"
Explanation facilitytraces the rules fired"why did you say that?"
Knowledge acquisitionelicits and adds rules"how does a rule arrive?"
Memory trick Ask the four questions in order — what is known (knowledge base), so what follows (inference engine), why (explanation), what else do I need (interface).
Exam trap The inference engine does not store the rules — the knowledge base does; the engine only matches and fires. The explanation facility is not the user interface.
Worked example ✍ which part answers which question? (a) "Is this chest pain a heart attack?" — asked by the user interface, decided by the inference engine. (b) "Why do you think so?" — the explanation facility. (c) "How much do you weigh?" — interface, and the answer goes into working memory. (d) "Rules 1 and 4 both match; which wins?" — conflict resolution inside the engine.
IT link The same five boxes appear in every config-driven system: a router's access-list matcher, a tax engine, a spam rule list — the explanation facility replaced by an audit log.

AI · Expert Systems & MLRules & inference

3Rules, the Cycle & the Two Chainings

written favourite ★
Definition A production rule reads IF <antecedent> THEN <consequent>, the antecedent being a conjunction of conditions on working-memory facts. The inference cycle is match → fire → update → test: match every rule against working memory, fire the ones that match, copy each conclusion into working memory, then test the goal.
Part of a ruleExample
Antecedent (IF)temperature > 38 °C
ConnectivesAND / OR / NOT
Consequent (THEN)influenza, CF 0.8
Certainty factorMYCIN: −1 … +1
Firingcopy the THEN into memory
FeatureForward chaining — data-drivenBackward chaining — goal-driven
Starts fromthe facts in working memorya goal / hypothesis
Search stylebreadth-first, bottom-updepth-first, top-down
Answers"what else can be derived?""is this goal provable?"
Best formonitoring, predictiondiagnosis, planning
Weaknessexplores every ruleno rule for the goal
Classic userXCON (configuration)MYCIN (diagnosis)
Memory trick "The milk is here, so the milk is off" — forward. "Is the milk off? Then check the date" — backward. Facts push conclusions out; the goal pulls facts in.
Exam trap Forward chaining can never prove a negative: no rule fires on "there is no rash", so "not measles" is never derived.
Worked example ✍ trace both ways on the rules of page 2 Facts: temperature 39, cough true, white-cell count 7200, shortness of breath true. Forward: cycle 1 fires R1 → add influenza 0.8; cycle 2 fires R2 → add pneumonia 0.9; cycle 3 R3 fails. Result: pneumonia. Backward: goal = pneumonia → only R2 concludes it → it needs influenza → only R1 concludes that → it needs temperature, cough, white-cell count → three questions to the user, all yes → R1 proved → R2 satisfied. R3 is never looked at.

4The Classic Systems & the Bottleneck

history ★
Definition The knowledge-acquisition bottleneck is the hard part of any expert system: an expert's knowledge is tacit, verbal and full of unstated context, and turning it into explicit rules takes interviews, months of work and endless validation. The chain runs domain expert ⇄ knowledge engineer ⇄ rule base; nothing in it learns by itself.
SystemDomain, reasoning and datesLimitation / fate
DENDRAL
1965–1972		chemistry — infers a molecular structure from a mass spectrum, by splitting the molecule into substructuresfirst expert system; hours of computer time where a chemist needed minutes
MYCIN
1960s–77
EMYCIN 1977		medicine — bacteraemia diagnosis and therapy, ≈ 600 rules, backward chaining + certainty factors; EMYCIN is the same engine with those rules removed≈ 65 % correct in blind tests, above the physicians who tested it; never used clinically — but EMYCIN proved the engine is reusable
XCON (R1)
1980		DEC — configures VAX-11/780 systems from a customer order, forward chaining; pilot 1978–80one company, one product family; reported to save tens of millions of dollars a year
Worked example ✍ a viva on MYCIN Q. Why was MYCIN never used in hospitals? A. Because of its bottleneck and its sociology, not its accuracy: the rule base was elicited by hand from a few specialists, it knew nothing outside infectious disease, and liability, ethics and consent blocked a therapy-recommending machine.
Exam trap DENDRAL was chemistry, not medicine. MYCIN did not learn from patient records. XCON is not general purpose.
LimitationWhat it means
Knowledge acquisitionslow, costly, hand-made
Narrow domainoutside it, unanswerable
Brittlenessfails, never degrades
No learningnew facts = new interview
No common senseno world model at all
Memory trick "DENDRAL for structure, MYCIN for symptoms, XCON for a configuration". All three are dead code today: the bottleneck, not the silicon, ended expert systems.

5Machine Learning & Three Paradigms

definition ★
Definition Machine learning is the branch of AI in which a system improves its performance on a task by working through data, instead of having every rule written down in advance. Samuel used the term in 1959; Mitchell's definition: a program learns from experience E with respect to a task T, measured by P, if its performance at T improves with E.

Trainingfitting the parametersPredictionrunning the frozen model
Loss / costminimised while fittingEpochone pass over training
AspectSupervisedUnsupervisedReinforcement
Datalabelled (X, y)unlabelled Xreward after acting
Goalpredict a known answerdiscover structuremaximise the reward
Tasksclassification, regressionclustering, PCAcontrol, games, motion
Algorithmstree, k-NN, naive Bayes, SVMk-means, PCA, DBSCANQ-learning, policy gradient
Examplespam filter, credit scoringmarket segmentationa robot learning to walk
Memory trick "Labels in, prediction out. No labels, groups out. A number afterwards, behaviour out." Ask of any algorithm only this: where does the feedback come from?
Worked example ✍ which paradigm? (a) predict a house price → regression, supervised; (b) label an e-mail spam / not spam → classification, supervised; (c) split a million customers into segments → clustering, unsupervised; (d) cut 900 columns to 20 → dimensionality reduction; (e) a robot learning to walk from a per-step reward → reinforcement.
Exam trap ML is a subset of AI; an expert system that never learns is still AI. k-means stays unsupervised even if you afterwards name the clusters.

6Supervised Learning & the Process

classification ★
Definition Supervised learning fits a mapping f : X → y from labelled examples (X, y). Classification predicts a discrete label — spam / not spam, disease A / B / C. Regression predicts a continuous number — price, rainfall, demand. The label is known in the training data only.
AspectClassificationRegression
Outputone class from a finite seta real number
Examplesspam filter, tumour type, fraudhouse price, rainfall, demand
Error measured byaccuracy, precision, recall, F1MAE, MSE, RMSE, R²
Typical losscross-entropysquared error
Typical modelstree, k-NN, naive Bayes, SVMlinear regression, tree regression
Answers"which one?""how much?"
Eight steps — two are the ones candidates forget
  1. Collect labelled data — most of the work
  2. Preprocess — missing values, duplicates
  3. Engineer features — keep the signal
  4. Split — shuffle, then 60 / 20 / 20
  5. Choose a model — start simple
  6. Train — fit on training data only
  7. Evaluate — k-fold CV beats one split
  8. Deploy and monitor — data drifts
Worked example ✍ a mini-run 1 000 labelled e-mails, 12 features. Split 600 / 200 / 200. A depth-3 tree: 96 % train, 84 % validation. A depth-12 tree: 100 % train, 79 % validation — memorised noise, so keep depth 3. Open the test set once: 85 %. Quote 85 %.
Memory trick "Collect, clean, features, split, fit, evaluate, deploy." The two steps everyone forgets — the split and the monitor.
Exam trap The test set is never tuned on. Scaling after the split leaks test information. More trees is not automatically better: depth past the signal is overfitting.
IT link Real projects spend most of their time in steps 1–3. A model is a one-line object; a clean labelled dataset with a defensible split is the actual asset.

7Split, Overfitting & Bias–Variance

most tested ★
Definition Split the data: training to fit, validation to choose the model and its settings, test to report the final number once. A common split is 60 / 20 / 20; k-fold cross-validation (k = 5 or 10) repeats the split k times so one lucky partition cannot decide the answer.
SetShareUsed forNever used for
Training60 %fitting the parametersscoring the model
Validation20 %choosing model, hyper-parametersfitting parameters
Test20 %the one final reportany choice at all
Model complexityTrain errorValidation errorVerdict
1 feature, linear14 %15 %underfitting — high bias
depth-3 tree4 %6 %just right — best choice
depth-20 tree + noise0.5 %22 %overfitting — high variance
Underfitting & overfitting Overfitting: the model fits the training data so closely that it memorises its noise — training error ≪ test error, high variance, no generalisation. Underfitting: too simple to capture the structure — both errors high, high bias. Expected test error = bias² + variance + irreducible noise; complexity trades the first two against each other.
Worked example ✍ choosing between two models Model A: bias² = 0.09, variance = 0.02, noise = 0.01 → total 0.12. Model B: bias² = 0.01, variance = 0.16, noise = 0.01 → total 0.18. A wins: B is the flexible model that memorised noise. More data shrinks B's variance but cannot shrink its bias.
Exam trap 99 % training accuracy is not success — a card that memorises the answers also gets 100 % on them. More data reduces variance only; reducing bias needs a more expressive model.
How overfitting is reduced more and better data · regularisation (L1 / L2) · k-fold cross-validation · a simpler model · pruning a decision tree · early stopping · dropout · feature selection.

8Evaluating a Model: Confusion Matrix

MCQ staple ★
Definition The confusion matrix counts what a classifier actually did, for a binary task: true positives, false positives, true negatives, false negatives. Every classification metric in the exam is one line of arithmetic on these four numbers.
Predicted positivePredicted negative
TP = 45 — flagged, truly badTN = 140 — cleared, truly good185 correct
FN = 5 — missed, truly badFP = 10 — wrongly accused15 wrong
The five numbers, one line each

Accuracy = (TP + TN) / total

Precision = TP / (TP + FP)

Recall (sensitivity) = TP / (TP + FN)

Specificity = TN / (TN + FP)

F1 = 2 · P · R / (P + R)

MAE = Σ|y − ŷ| / n

For regression: RMSE = √(Σ(y − ŷ)²/n) and R² = 1 − Σ(y − ŷ)² / Σ(y − ȳ)², which is 1 for a perfect fit and ≤ 0 for a model worse than predicting the mean.
Worked example ✍ a fraud filter, 200 cases TP = 45, FN = 5, TN = 140, FP = 10, total 200.
Accuracy = 185/200 = 92.5 % · Precision = 45/55 = 81.8 % · Recall = 45/50 = 90 % · Specificity = 140/150 = 93.3 % · F1 = 2(0.818)(0.900)/(1.718) = 85.7 %. Read the story: 92.5 % accuracy looks excellent, but the filter misses 5 real frauds and harrasses 10 innocent customers. Push the threshold and recall rises while precision falls.
Exam trap Accuracy is the wrong single number on an imbalanced set: if 99 % of cases are negative, "always predict negative" scores 99 % and is useless. Recall is what a doctor wants; precision is what a bank wants before accusing someone.
Memory trick "Precision is how many of the things I accused were guilty; recall is how many of the guilty things I caught." F1 is the harmonic mean, so it is only high when both are high.
IT link These four numbers are what a model's report card contains, and what the ROC curve is built from (recall against 1 − specificity, swept over the decision threshold). The threshold is a business choice, not a modelling one.

9Three Classic Learners, by Hand

written question ★
Definition Three supervised algorithms that need no calculus and no software to score: the decision tree splits the data greedily to reduce impurity, k-NN copies the answer of the k nearest training points, and naive Bayes applies Bayes' theorem assuming the features are independent given the class.
PropertyDecision treek-NNNaive Bayes
Learns bysplits on impuritystoring the datacounting values
Predict costa few comparisonsdistance to all pointsone multiply / feature
Key knobdepth, leaf sizek, distance metricLaplace smoothing
Weaknessoverfits noisy tablesneeds scaling, high dim.independence assumed
Readinessa flow of questionsnone (lazy learner)scale-independent
The two formulas you must be able to write

Impurity. Gini = 1 − Σ pᵢ² · Entropy H = − Σ pᵢ log₂ pᵢ. Split on the largest information gain = H(parent) − Σ (nᵢ/n) H(childᵢ).

Naive Bayes. P(c|x) ∝ P(c) · ∏i P(xᵢ | c). Conditional independence is the assumption; Laplace smoothing stops an unseen value zeroing the product.

Worked example 1 ✍ the tree 10 applicants: 6 approved, 4 rejected. Root Gini = 1 − (0.6² + 0.4²) = 0.48. Split on income → the 5 high-income are all approved (Gini 0), the 5 low-income are 1 approved and 4 rejected (Gini 0.32); weighted Gini = 0.16. Split those five on credit score ≥ 700 → Gini 0. 10/10 on the training table, yet a high-income applicant with a terrible score would still be approved: overfitting.
Worked example 2 ✍ k-NN The three nearest labelled neighbours of a new applicant in (income, score) space are approved, approved, rejected. With k = 3 the majority vote is approve. With k = 1 you copy the nearest point and inherit its noise; with k = 200 you predict the file's majority class and nothing useful. k-NN is a lazy learner: it computes nothing at fit time.
Worked example 3 ✍ naive Bayes, 14 days of tennis weather P(yes) = 9/14 and P(no) = 5/14. Query: sunny, hot, high humidity, strong wind.   yes: 0.643 × 0.222 × 0.222 × 0.333 × 0.333 = 0.0035  ·  no: 0.357 × 0.600 × 0.600 × 0.800 × 0.625 = 0.0643 ⟹ do not play, roughly 18 : 1.
Memory trick Tree = ask questions. k-NN = ask the neighbours. Naive Bayes = multiply the odds — and naive warns that the features are assumed independent.
Exam trap k-NN is a supervised learner, not unsupervised — the labels exist, they are just not used at fit time. Entropy is not a probability.

Written question Explain the architecture of an expert system with a labelled diagram, and forward vs backward chaining with examples. What is overfitting, how does the bias–variance tradeoff explain it, and how is it reduced? 10
  1. Architecture (3). Knowledge base = the domain's facts, rules, heuristics. Inference engine = matches rules against working memory, fires them, returns the conclusions. User interface = asks the questions. Explanation facility = prints why. Cycle: match → fire → update → test. 3
  2. Forward chaining (2). Data-driven, bottom-up: start from the facts, fire every rule whose antecedent matches, add each conclusion, repeat until no rule fires. Breadth-first; monitoring and prediction; XCON. 2
  3. Backward chaining (2). Goal-driven, top-down: start from a hypothesis, find the rule concluding it, recurse on its conditions, ask the user for what is missing. Depth-first; diagnosis; MYCIN. 2
  4. Overfitting and bias–variance (3). The model fits the training data so closely that it memorises noise, so training error ≪ test error — high variance. Expected test error = bias² + variance + noise. Remedies: more data, regularisation, k-fold CV, a simpler model, pruning, early stopping, dropout. 3
