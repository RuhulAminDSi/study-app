AI · Knowledge RepresentationDefinition & desiderata

1What is Knowledge Representation?

foundation ★
Definition Knowledge Representation (KR) is the process of formally encoding information about the world in a form an AI system can store and use to reason, infer and decide. The knowledge is explicit and machine-processable instead of being hidden inside program code.
The four building blocks Fact — a basic assertion, e.g. Human(Socrates) · Rule — a conditional linking facts, e.g. Human(x) → Mortal(x) · Ontology — the formal set of concepts and their relations in a domain · Inference — deriving new knowledge from existing facts and rules
KR vsAnswer
dataKR gives data structure and meaning
AIKR is a part of AI; AI also searches, learns
a databasea database stores; KR permits inference
Property a good scheme needsThe question it answers
Representational adequacycan it describe everything the domain needs?
Inferential adequacycan the required conclusions be derived?
Inferential efficiencyhow fast is a conclusion produced?
Acquisitional efficiencyhow cheap is it to add a new fact?
Ease of acquisitioncan a human read, check and correct it?
Memory trick "Representation on the left, reasoning on the right." KR decides how knowledge is stored; the inference engine decides how it is used.
Exam trap KR is not the same as knowledge, nor a database. "Knowledge" here is declarative — a statement of what is true — while the procedure that uses it belongs to the inference engine.
Worked example ✍ the smallest possible expert system Knowledge base: fact Human(Socrates), rule Human(x) → Mortal(x). Unify x with Socrates, apply the rule, get Mortal(Socrates), then store the conclusion back in the base — that loop is inference.
Why it matters in practice Two systems can hold identical facts and behave completely differently because their representation differs. A rule base lets you explain every answer; a neural network cannot. When an exam asks for two desirable properties, the table above is the answer.

AI · Knowledge RepresentationThe schemes

2The Knowledge Representation Schemes

most tested ★
Definition A KR scheme is the notation and structure used to encode knowledge. Every scheme is a compromise: it says a great deal about some kinds of fact and very little about others. The classic comparison has six schemes — logical, semantic network, frame, production rule, script and ontology.
Where they appear in real systems Semantic networks and ontologies are the same idea at two scales — an early AI representation, and the machinery of the Semantic Web (RDF, OWL) and of modern knowledge graphs. Frames are the ancestor of every class-based object model; production rules of every expert system.
SchemeCore ideaStrengthWeakness
Logical (PL, FOL)facts and rules as formulasexact and provableverbose, no partial knowledge
Semantic networknodes = concepts, arcs = relationsfacts inherit automaticallyno formal semantics, cannot prove
Framea stereotyped object: slots, facetshandles defaults and exceptionsrigid and verbose, no computation
Production ruleIF–THEN rules on a working memorymodular, easy to extendslow, needs a conflict strategy
Scripta stereotyped sequence of eventsreads situations wellcannot compute, no surprises
Ontologyaxioms over classes, vocabularyreuse and consistencyexpensive to build and maintain
Memory trick Match the question to the scheme: is it true? → logic · how related? → net · what does it have? → frame · what if…? → rule · in what order? → script · what vocabulary? → ontology.
Exam trap An ontology is not a sixth cousin of the others — it is the vocabulary plus the constraints they are written in. A script is not a plan: a script is what usually happens, a plan is what this agent intends.
Worked example ✍ pick a scheme "birds fly" → frame (default + exception penguin). "if temperature > 100 °C then alarm" → production rule. "enter → order → eat → pay → leave" → script. "if it rains the ground is wet" → propositional logic. "dog is-a animal" → semantic network.

AI · Knowledge RepresentationSemantic networks

3Semantic Networks & Inheritance

MCQ favourite ★
Definition A semantic network represents knowledge as a directed graph whose nodes are objects, concepts, events or properties and whose labelled arcs are the relations between them. Introduced by M. R. Quillian, 1968 as a model of associative memory; the direct ancestor of the knowledge graph.
Arc familyTypical labels
StructuralIS-A, HAS-A, PART-OF, AKO
Semanticsynonym, antonym, hyponym
Proceduralarcs attached to an action
HAS-A means "has a part", IS-A means "is a kind of" — swap the two and the label flips!
Inheritance An object takes the properties of its class without restating them. Two kinds: default inheritance (assume the general case unless told otherwise) and specific inheritance (an override always wins). Inheritance is transitive — it travels down the whole chain.
PropertySemantic network
Facts inherit for freeyes — add a property to a class and every subclass gains it
Formal semanticsnone — the arcs have no logical meaning
Consistencynot guaranteed — two arcs can contradict
Inferencetraversal only: inheritance and graph search
Memory trick "IS-A is a class arrow, HAS-A is an ownership arrow." You may say "a dog IS-A mammal"; you may never say "a mammal IS-A dog". Reversing an IS-A arc is the commonest mistake in an exam diagram.
Exam trap A semantic network is not a truth table and not a production system — it answers "what is related to what", not "what follows from what". And it cannot prove anything.
Worked example ✍ inheritance with an exception Store Animal → breathes = true, Mammal IS-A Animal, Dog IS-A Mammal, Fido IS-A Dog, plus Fido → legs = 4. Ask for Fido → breathes: the engine walks the chain Fido → Dog → Mammal → Animal and answers true without Fido ever storing it. Now add Fido → legs = 3 — the specific value 3 must win, which is exactly the conflict-resolution problem frames solve explicitly.

AI · Knowledge RepresentationFrames & scripts

4Frames and Scripts

slot / facet ★
Frame — Minsky, 1975 A frame describes a stereotyped object, class or situation as a named set of slots. Each slot holds a value, a facet (default, range, if-needed procedure) or a link to another frame. A frame for a class is a schema; filling one in gives an instance.
Script — Schank & Abelson, 1977 A script is a stereotyped ordered sequence of events that normally takes place in a situation. It stores what is typical, so a story becomes predictable and cheap to understand.
The five parts of a script ① initial conditions ② a sequence of states and events ③ transitions, each with a condition so steps can be skipped ④ resulting conditions ⑤ props — the roles played by objects: customer, waiter, food. A frame instead has a name, slots, values and facets — no time line at all.
Point of comparisonFrameScript
What it describesan object or class and its attributesa situation and its events in order
Internal structurename + slots + values + facetsinitial + states + transitions + props
Organised bya class / instance hierarchya time line of states
Handles exceptionsyes — default overriddenpartly — a step may be skipped
Memory trick "Frame = furniture, script = theatre." A frame is a thing you point at; a script is something that happens to it in a fixed order. Facets live only in frames; props live only in scripts.
Exam trap Frames are not a record format with typed columns — a slot may hold a value, a default, a range or a procedure. And a script is not a production rule: a rule is a guarantee, a script is only an expectation.
Worked example ✍ a frame doing real work Open the frame CAR and ask for the colour of "my car". No slot has been filled, so the engine takes the default facet and answers white. Ask for the engine of a car that has been scrapped: the if-needed procedure runs instead of returning a value. That is why frames are said to carry procedural attachments.

5Propositional Logic: Syntax & Connectives

highest-yield ★
Definition Propositional (or sentential) logic treats every whole statement as a single proposition that is either true (T) or false (F), joined by logical connectives. An atomic proposition is a single letter P; a compound proposition is built from atoms and connectives.
ConnectiveSymbolTrue exactly when
negation, NOT¬PP is false
conjunction, ANDP ∧ Qboth P and Q are true
disjunction, OR, inclusiveP ∨ Qat least one of P, Q is true
implication, IF–THENP → Qanything except P true and Q false
biconditional, IFFP ↔ QP and Q have the same truth value
PQP ∧ QP ∨ Q¬PP → QP ↔ Q
TTTTFTT
TFFTFFF
FTFTTTF
FFFFTTT
Precedence, tightest first ¬ → ∧ → ∨ → → → ↔. Brackets beat everything: ¬(P ∧ Q) is not the same as (¬P) ∧ Q.
Limitation Propositional logic cannot express variables, quantifiers or relations between objects. Nothing is shared between "Socrates is human" and "Plato is human" — the base grows as a flat list and inference cannot generalise.
Worked example ✍ build and read a formula "If it rains and I carry an umbrella, the ground stays dry." Let R = rain, U = umbrella, D = ground dry. The formula is (R ∧ U) → D. If R = T, U = T, D = F the implication is false — the one and only combination that breaks it. If R = F the formula is true whatever else happens: an implication is not a biconditional.
Memory trick "→ only looks backwards once." P → Q is false in exactly one row, so read it as "everything is fine unless P happens and Q does not." Write P → Q as ¬P ∨ Q and it becomes obvious.
Exam trap (i) OR is inclusive: P ∨ P = P, not P. (ii) P → Q is not P ← Q. (iii) "P is false and Q is true" makes P → Q true, not false. (iv) A proposition is an entire sentence — you may not split "Socrates is a man" into two.

AI · Knowledge RepresentationValidity & inference

6Validity, Satisfiability & Inference Rules

written favourite ★
Definitions — all four are about the truth table A tautology (valid) formula is true for every assignment · a contradiction (unsatisfiable) is false for every assignment · a satisfiable formula is true for at least one assignment. "P ⊨ Q" means the truth table of P → Q is a tautology. n propositions need 2ⁿ rows.
Rule of inferenceFromConclude
Modus ponensP, P → QQ
Modus tollens¬Q, P → Q¬P
Hypothetical syllogismP → Q, Q → RP → R
Disjunctive syllogismP ∨ Q, ¬PQ
AdditionPP ∨ Q
SimplificationP ∧ QP
ResolutionP ∨ Q, ¬P ∨ RQ ∨ R
Worked example 1 ✍ classify four formulas (a) P ∨ ¬P — T in every row ⟹ tautology. (b) P ∧ ¬P — F in every row ⟹ contradiction. (c) P → (Q ∨ ¬Q) — consequent always true ⟹ tautology. (d) (P ∨ Q) ∧ ¬P — true when P = F, Q = T ⟹ satisfiable, not valid.
Worked example 2 ✍ modus tollens in the clinic From P → Q = "if the patient took the drug, the rash clears" and ¬Q = "the rash has not cleared", modus tollens gives ¬P: the patient did not take the drug.
Why resolution wins Modus ponens needs a matching fact at every step; resolution needs only two clauses, and it alone works on disjunctions — hence automated theorem proving (Robinson, 1965).
Memory trick "Tautology always, satisfiable sometimes, contradiction never." Tautology = true always; contradiction = true never.
Exam trap "Valid" and "true" are not the same: valid only if every assignment makes it true. P ⊨ Q does not give Q.

7First-Order Logic, Predicates & Quantifiers

most written ★
Definition First-order logic (FOL) extends propositional logic with objects, predicates over them, functions and quantifiers. A formula is built from atomic formulas P(t₁,…,tₙ) using connectives and quantifiers.
ComponentWhat it isExample
Constantone named individualSocrates
Variablean arbitrary individualx, y
Functionindividual → individualFatherOf(x)
Predicateproperty or n-place relationHuman(x), Loves(a,b)
Quantifierranges the variable∀x, ∃y
The two quantifiers ∀ "for all x …" · ∃ "there exists x such that …". Their order matters. A WFF is any well-formed formula; a sentence is a WFF with no free variables.
English sentenceFirst-order formFeaturePropositionalFirst-order
All humans are mortal∀x (Human(x) → Mortal(x))Talks aboutwhole statementsobjects, relations
Someone loves everyone∃x ∀y Loves(x, y)Quantifiersnone∀ and ∃
Everyone loves someone∀x ∃y Loves(x, y)Costcheap, 2ⁿ rowsexpensive
Memory trick "∀ says every, ∃ says at least one." The → inside the ∀ is what keeps "all humans are mortal" true even when some x is not a human: Human(x) → Mortal(x) never asserts Mortality of a non-human.
Exam trap ∀x P(x) is not P(a). And "all humans are mortal" must not be written ∀x (Human(x) ∧ Mortal(x)) — that would claim everybody is both human and mortal.
Worked example ✍ why the order matters Committee rule: "every member has at least one car" = ∀x (Member(x) → ∃y (Car(y) ∧ Owns(x,y))). The two quantifiers can pick different cars for different members, so the base stays consistent — but as soon as the committee shrinks to one member and no cars, ∀x∃y fails while its negation is still available, which is exactly the case a resolution engine detects automatically.

AI · Knowledge RepresentationUnification & resolution

8Unification, Resolution & Horn Clauses

Robinson 1965 ★
Algorithm Walk the atoms left to right. Equal constants → go on. A variable on either side → bind it to the other term. Different constants → clash. Never bind a variable to a term that already contains it (occurs check): X = f(X) has no solution.
Unification Unification is finding a substitution for the variables of two atoms so that they become identical. The result is the most general unifier (MGU); when no substitution exists the two atoms clash.
Atom pairMost general unifier
Loves(x, Bob) , Loves(Alice, y){x↦Alice, y↦Bob}
Human(x) , Human(Socrates){x↦Socrates}
P(x) , Q(y)clash — none
P(x, y) , P(y, z){y↦x, z↦x}
Refutation by resolution To prove goal φ, convert every statement to clause form, add the negated goal, and resolve clauses repeatedly. Two clauses that resolve to the empty clause prove the goal. Sound, and complete for FOL by Robinson's theorem.
Worked example ✍ prove Mortal(Socrates) by resolution
  1. KB: Human(Socrates) · Human(x) → Mortal(x)
  2. Clause form: C₁ = Human(Socrates), C₂ = ¬Human(x) ∨ Mortal(x); add the negated goal C₃ = ¬Mortal(Socrates)
  3. Resolve C₁ with C₂ — Human and ¬Human disappear: C₄ = Mortal(Socrates)
  4. Resolve C₄ with C₃ — Mortal and ¬Mortal disappear ⟹ the empty clause, so the goal is proved
Memory trick "Prove by not-proving." Refutation: add ¬goal and search for a contradiction. Resolution is the only rule that consumes a disjunction, and every formula can be turned into a disjunction of disjunctions.
Exam trap Resolving (P ∨ Q) with (¬P ∨ R) gives Q ∨ R — you drop the complementary pair P, ¬P and keep both remaining literals joined by ∨, never ∧. Horn clauses, next box, cannot express a disjunction in the head at all.
Horn clauses — why the exam loves them A Horn clause has at most one positive literal, i.e. H ← B₁ ∧ B₂ ∧ … ∧ Bₙ. Three consequences: forward chaining is complete for Horn knowledge · backward chaining is complete as well · the logic is monotonic — adding facts never removes conclusions. Horn logic is exactly what Datalog and every production system run on.

AI · Knowledge RepresentationForward vs backward

9Forward and Backward Chaining

the classic question ★
Forward chaining Data-driven, bottom-up. Start from the facts, fire every rule whose antecedents are satisfied, and add each conclusion to the working memory. Repeat until nothing fires.
Backward chaining Goal-driven, top-down. Start from the goal, find the rule whose head matches it, and recurse on that rule's antecedents until only facts remain.
Point of comparisonForward chainingBackward chaining
Starts fromthe facts (data-driven)the goal (goal-driven)
Answerseverything derivableonly what the goal needs
Costmay explode: many firings, irrelevant factscheap when the goal is specific
Explainabilityfull — you can print the whole chainpartial — only the proof needed
Best whenmonitoring, all facts known, many questionsdiagnosis, one clear question, missing facts
Complete forHorn knowledgeHorn knowledge
Memory trick "Forward looks up, backward looks down." Forward climbs from data to conclusions; backward descends from the question to the data. "Forward is thorough, backward is targeted" is the one-line answer to the written question.
Exam trap Backward chaining does not invent facts — if the knowledge base does not support the goal it simply fails; it never guesses. When several rules fire at once the engine needs a conflict-resolution strategy (breadth-first, depth-first, most-specific, most-recent).
Worked example ✍ choose the direction (a) A bank must flag every transaction above 10 000 taka as it happens — all facts are known and there is no single question: forward chaining. (b) A doctor types "diagnosis?" and the system must justify one answer from thousands of symptoms: backward chaining. (c) The knowledge base contains a disjunction P ∨ Q, which is not Horn: neither chaining is complete, and resolution is the answer.
