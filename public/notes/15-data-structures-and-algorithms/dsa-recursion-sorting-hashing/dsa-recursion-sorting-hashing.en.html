1Recursion & the Call Stack

foundation ★
Definition A recursive function solves a problem by calling itself on a smaller instance. It needs a base case that stops without a call and a recursive case that moves strictly towards it. Every call pushes an activation record (parameters, locals, return address) on the stack, so recursion depth d costs O(d) space.

/* not tail-recursive: × after return */ int fact(int n) { if (n == 0) return 1; /* base */ return n * fact(n - 1); } /* tail-recursive: call is the last act */ int factT(int n, int acc) { if (n == 0) return acc; return factT(n - 1, n * acc); }
Kinds of recursion Direct: f calls f. Indirect: f → g → f. Linear: one call per activation (factorial). Tree: two or more (Fibonacci, Hanoi). Tail: the call is the final action, so a compiler can reuse the frame (tail-call elimination) → O(1) stack. Every recursion can be rewritten as a loop with an explicit stack.
Worked example ✍ Tower of Hanoi Move n − 1 discs A → B (via C), the largest A → C, then n − 1 discs B → C. So M(n) = 2M(n−1) + 1 ⇒ M(n) + 1 = 2[M(n−1) + 1] ⇒ M(n) + 1 = 2ⁿ ⇒ M(n) = 2ⁿ − 1. n = 3: A→C, A→B, C→B, A→C, B→A, B→C, A→C = 7 moves; n = 4 → 15; n = 64 → 2⁶⁴ − 1 ≈ 1.8 × 10¹⁹. The smallest disc moves on every odd step.
Memory trick "Base first, smaller next." Write the stop condition before the self-call, and check that the argument shrinks. Naive fib(n) makes 2F(n+1) − 1 calls: fib(4) → 9, fib(5) → 15.
Exam trap A missing base case gives stack overflow, not an endless loop. Recursion is usually slower than the equivalent loop (call overhead). C and Java do not guarantee tail-call elimination. Recursion depth of naive fib(n) is only n, even though calls are exponential.

Growth ladder 1 < log log n < log n < √n < n < n log n < n² < n³ < 2ⁿ < n! < nⁿ. Log base does not matter (logₐn = Θ(log_b n)), but exponent base does: 2ⁿ = o(3ⁿ). log(n!) = Θ(n log n); 1 + 2 + … + n = Θ(n²); 1 + ½ + … + 1/n ≈ ln n.
Worked example ✍ prove a Θ bound f(n) = 3n² + 5n + 2. For n ≥ 1: 3n² ≤ f(n) ≤ 3n² + 5n² + 2n² = 10n². So c₁ = 3, c₂ = 10, n₀ = 1 ⇒ f = Θ(n²). Also 2ⁿ⁺¹ = O(2ⁿ) (c = 2) but 2²ⁿ = 4ⁿ ≠ O(2ⁿ).

Common misconception O ≠ worst case, Ω ≠ best case, Θ ≠ average case. Notations bound a function; cases pick the input. Insertion sort: worst case Θ(n²), best case Θ(n); so its running time is O(n²) and Ω(n), but not Θ(n²) for every input.
Best · average · worst Worst = maximum steps over all inputs of size n (a guarantee). Best = minimum. Average = expected steps under a stated input distribution, e.g. linear search: (n + 1)/2 comparisons if the key is equally likely anywhere.
Amortized analysis The worst-case total of a sequence of n operations divided by n — no probability. Dynamic array that doubles when full: n pushes cost ≤ n + (1 + 2 + 4 + … + n) < 3n ⇒ O(1) amortized per push, though one push costs O(n). Methods: aggregate, accounting (banker's), potential.
Memory trick "Oh = ceiling, Omega = floor, Theta = both walls." Little o / ω are the strict versions — like < and >. To compare two functions, take lim f/g: 0 → o, constant → Θ, ∞ → ω. Space complexity is analysed the same way, counting memory cells.

3Recurrences & the Master Theorem

most tested ★
Definition A recurrence gives T(n) in terms of T on smaller inputs. Solve it by substitution (guess, prove by induction), iteration / recursion tree (add the cost of every level), or the Master theorem for divide-and-conquer forms T(n) = a·T(n/b) + f(n), a ≥ 1, b > 1.
Master theorem Compare f(n) with n^(log_b a), the total cost of the leaves.
  1. Case 1 — f(n) = O(n^(log_b a − ε)) for some ε > 0 (leaves dominate) ⇒ T(n) = Θ(n^(log_b a)).
  2. Case 2 — f(n) = Θ(n^(log_b a)) (every level equal) ⇒ T(n) = Θ(n^(log_b a) · log n). Extended: f = Θ(n^(log_b a) logᵏ n) ⇒ Θ(n^(log_b a) logᵏ⁺¹ n).
  3. Case 3 — f(n) = Ω(n^(log_b a + ε)) and regularity a·f(n/b) ≤ c·f(n) for some c < 1 (root dominates) ⇒ T(n) = Θ(f(n)).
Short form for f(n) = Θ(nᵈ): log_b a > d → Θ(n^(log_b a)); = d → Θ(nᵈ log n); < d → Θ(nᵈ).

Worked example ✍ substitution Guess T(n) ≤ c·n log₂ n for T(n) = 2T(n/2) + n. Then T(n) ≤ 2·c(n/2)log₂(n/2) + n = c·n log₂ n − c·n + n ≤ c·n log₂ n whenever c ≥ 1 ✓. Hence T(n) = O(n log n).
Memory trick "Leaves vs root." Work out n^(log_b a) first. Leaves bigger → case 1, answer = leaves. Tie → multiply by log n. Root bigger → answer = f(n).
Exam trap The Master theorem does not apply to T(n−1) forms, a < 1, non-constant a (e.g. 2ⁿT(n/2)), or a non-polynomial gap like n log n vs n. Case 3 also needs regularity.

4Simple, Heap & Linear-Time Sorts

properties ★
Vocabulary Stable: equal keys keep their input order. In-place: O(1) extra memory (O(log n) stack is usually allowed). Adaptive: faster on nearly sorted input. Online: can sort as data arrives. An inversion is a pair i < j with a[i] > a[j]; at most n(n−1)/2.
SortIdeaKey facts
Bubbleswap adjacent pairs; pass i floats the i-th largest to the end≤ n(n−1)/2 comparisons; swaps = inversions; O(n) best only with a "no swap → stop" flag
Selectionfind the minimum of the rest, swap it to the frontalways n(n−1)/2 comparisons, ≤ n − 1 swaps; not stable, not adaptive
Insertioninsert a[i] into the sorted prefix by shiftingn − 1 comparisons if sorted; shifts = inversions; stable, adaptive, online
Shell (1959)insertion sort on gaps h, shrinking to 1gaps n/2, n/4… → O(n²); Knuth 1, 4, 13, 40 → O(n^1.5); not stable
Heapbuild max-heap O(n), then n − 1 × (swap root, sift-down)Θ(n log n) always, O(1) space, not stable

Linear-time (non-comparison) sorts Counting sort (keys 0..k): count each key, prefix-sum the counts, place elements scanning right to left (keeps it stable) → Θ(n + k) time and space. A = 2 5 3 0 2 3 0 3: counts 2 0 2 3 0 1 → prefix 2 2 4 7 7 8 → 0 0 2 2 3 3 3 5. Radix sort (LSD): stable counting sort on each of d digits → Θ(d(n + k)). Bucket sort: uniform input in [0, 1) into n buckets, insertion-sort each → Θ(n) average, O(n²) worst.
Worked example ✍ LSD radix sort 170 45 75 90 802 24 2 66 → by units: 170 90 802 2 24 45 75 66 → by tens: 802 2 24 45 66 170 75 90 → by hundreds: 2 24 45 66 75 90 170 802. Each pass must be stable, or the earlier digit order is lost.
Memory trick "Selection Swaps least, Insertion Shifts." Fewest writes → selection (n − 1 swaps). Nearly sorted or tiny → insertion (used inside Timsort and introsort).
Exam trap Every comparison sort needs Ω(n log n) comparisons in the worst case (log₂ n! — proof in the NP-Completeness lesson). Counting and radix sort beat it only because they never compare keys.

5Merge Sort, Quick Sort & the Sort Table

written favourite ★
Merge sort Split in half, sort both, merge in linear time: T(n) = 2T(n/2) + Θ(n) = Θ(n log n) in every case. Merging lists of m and k items takes at most m + k − 1 comparisons (at least min(m, k)). Stable if ties take from the left (≤). Θ(n) extra array; ideal for linked lists and external (k-way) sorting.
Quick sort (Hoare, 1961) Pick a pivot, partition so smaller keys sit left and larger right, recurse on both sides. Best/average Θ(n log n) (≈ 1.39 n log₂ n comparisons); worst Θ(n²) when the pivot is always the min or max, e.g. sorted input with first/last pivot: T(n) = T(n−1) + Θ(n). Fix: random or median-of-three pivot.

Exam trap (i) Quick sort's log n space is the average stack (naive worst O(n); recurse on the smaller side first). (ii) Selection sort is Θ(n²) even on sorted input. (iii) "Fastest in practice" for RAM arrays → quick sort; "guaranteed n log n and stable" → merge sort; "guaranteed n log n in O(1) space" → heap sort.

int bsearch(const int a[], int n, int key) { int lo = 0, hi = n - 1; while (lo <= hi) { int mid = lo + (hi - lo) / 2; if (a[mid] == key) return mid; if (a[mid] < key) lo = mid + 1; else hi = mid - 1; } return -1; /* not found */ }
Worked example ✍ trace and count a = 3 8 15 23 42 57 91 (indices 0–6). key 42: (lo, hi, mid) = (0, 6, 3) → 23 < 42 → lo = 4; (4, 6, 5) → 57 > 42 → hi = 4; (4, 4, 4) → found at index 4 after 3 probes. key 10: mid 3 (23) → hi = 2; mid 1 (8) → lo = 2; mid 2 (15) → hi = 1; lo > hi → −1, also 3 probes. Maximum probes = ⌊log₂ n⌋ + 1 = ⌈log₂(n + 1)⌉: n = 7 → 3, n = 1000 → 10, n = 1024 → 11, n = 10⁶ → 20.
The others in one line Interpolation: pos = lo + (key − a[lo])·(hi − lo) / (a[hi] − a[lo]) — guesses like a dictionary. Ternary: two mids split into thirds; fewer iterations but more comparisons than binary, so binary wins on arrays — ternary is for the max/min of a unimodal function. Jump: step √n, then linear. Exponential: probe 1, 2, 4, 8 … then binary.
Exam trap Binary search on a linked list is O(n) — no random access. On unsorted data it is simply wrong. mid = (lo + hi)/2 can overflow int; use lo + (hi − lo)/2. Linear search unsuccessful = n comparisons (n + 1 with a sentinel).
Memory trick "Halve until one: count the doublings." 2¹⁰ ≈ 1000, 2²⁰ ≈ 10⁶, 2³⁰ ≈ 10⁹ → 10, 20, 30 probes. Best case O(1): the key sits at the first mid. Used in C bsearch, Python bisect, B-tree node search, git bisect.

7Hashing & Collision Resolution

numerical ★
Definition Hashing maps a key k to a slot h(k) ∈ {0 … m − 1} of a table of size m, giving search/insert/delete in O(1) average (O(n) worst). Two keys with the same slot collide. Load factor α = n / m (keys ÷ slots) decides the speed.

Exam trap Open addressing cannot simply empty a slot on delete — later keys become unreachable; mark it DELETED (tombstone). Quadratic probing may miss free slots unless m is prime and α ≤ ½. Rehash (double m) when α passes a threshold (0.75 in Java's HashMap).
Memory trick "Linear Lumps, Quadratic Quietens, Double Disperses." Probe count blows up near α = 1: α = 0.9 → 10 probes for a miss. Uses: symbol tables, DB hash indexes, caches (Redis, Memcached), sets/dictionaries.

8Storage Management & Garbage Collection

syllabus line ★
Definition Storage management hands out and takes back heap blocks (malloc/free, new/delete). Free blocks sit on a free list; a placement policy serves each request and freed neighbours are coalesced. The enemies: fragmentation and garbage (unreachable, unreleased blocks).
Placement policies First fit: first hole big enough — fastest. Next fit: first fit resumed where the last search stopped. Best fit: the smallest hole that fits — scans the whole list, leaves tiny slivers. Worst fit: the largest hole — leaves big leftovers. In the example below only best fit places all four.
Worked example ✍ holes 100, 500, 200, 300, 600 KB; requests 212, 417, 112, 426

Fragmentation External: enough free memory in total but no single hole is large enough — cured by compaction (slide live blocks together; needs run-time relocation, costly). Internal: a block larger than the request — the unused tail is wasted (buddy system, fixed partitions, paging).
Buddy system Blocks are powers of 2. A request is rounded up to 2ᵏ; a larger block is split into two halves (buddies) until it fits. On free, a block merges with its buddy if the buddy is free; buddy address = addr XOR size. Fast split/merge, but internal fragmentation up to ~50%.

Exam trap Two unreachable objects pointing at each other keep count 1 → leak under pure reference counting. Dangling pointer = freed but still used; leak = unused but never freed. Compaction cures external fragmentation only.
Memory trick "First is Fast, Best leaves Bits, Worst leaves Wide." GC: "count, mark, copy" — counting misses cycles, copying needs twice the room.
