ভিত্তি ★
সংজ্ঞা রিকার্সিভ (Recursive) ফাংশন একটি সমস্যাকে তার ছোট সংস্করণে নিজেকে কল করে সমাধান করে। এর লাগে একটি বেস কেস (কল ছাড়াই থামে) এবং একটি রিকার্সিভ কেস, যা ধাপে ধাপে বেস কেসের দিকে এগোয়। প্রতিটি কল স্ট্যাকে একটি অ্যাক্টিভেশন রেকর্ড (প্যারামিটার, লোকাল, রিটার্ন অ্যাড্রেস) পুশ করে, তাই গভীরতা d হলে O(d) মেমরি।

রিকার্শনের প্রকার প্রত্যক্ষ (Direct): f কল করে f-কে। পরোক্ষ (Indirect): f → g → f। লিনিয়ার: প্রতি অ্যাক্টিভেশনে একটি কল (ফ্যাক্টরিয়াল)। ট্রি: দুই বা ততোধিক (ফিবোনাচ্চি, হ্যানয়)। টেইল (Tail): কলটিই শেষ কাজ, তাই কম্পাইলার একই ফ্রেম আবার ব্যবহার করতে পারে (টেইল-কল এলিমিনেশন) → O(1) স্ট্যাক। যেকোনো রিকার্শনকে একটি স্পষ্ট স্ট্যাকসহ লুপে রূপান্তর করা যায়।
সমাধানকৃত উদাহরণ ✍ টাওয়ার অব হ্যানয় n − 1টি চাকতি A → B (C-এর সাহায্যে), সবচেয়ে বড়টি A → C, তারপর n − 1টি B → C। তাই M(n) = 2M(n−1) + 1 ⇒ M(n) + 1 = 2[M(n−1) + 1] ⇒ M(n) + 1 = 2ⁿ ⇒ M(n) = 2ⁿ − 1। n = 3: A→C, A→B, C→B, A→C, B→A, B→C, A→C = ৭ চাল; n = 4 → 15; n = 64 → 2⁶⁴ − 1 ≈ 1.8 × 10¹⁹। সবচেয়ে ছোট চাকতি প্রতিটি বিজোড় ধাপে সরে।
মনে রাখার কৌশল "আগে বেস, পরে ছোট।" নিজেকে কল করার আগে থামার শর্ত লেখো, আর দেখো আর্গুমেন্ট ছোট হচ্ছে কি না। সরল fib(n) মোট 2F(n+1) − 1টি কল করে: fib(4) → 9, fib(5) → 15।
পরীক্ষার ফাঁদ বেস কেস না থাকলে হয় স্ট্যাক ওভারফ্লো, অসীম লুপ নয়। রিকার্শন সাধারণত সমতুল্য লুপের চেয়ে ধীর (কলের ওভারহেড)। C ও Java টেইল-কল এলিমিনেশনের নিশ্চয়তা দেয় না। সরল fib(n)-এ কল সূচকীয় হলেও গভীরতা মাত্র n।

সবচেয়ে বেশি আসে ★
সংজ্ঞা রিকারেন্স (Recurrence) T(n)-কে ছোট ইনপুটের T দিয়ে প্রকাশ করে। সমাধান: সাবস্টিটিউশন (অনুমান করে ইনডাকশনে প্রমাণ), ইটারেশন / রিকার্শন ট্রি (প্রতি স্তরের খরচ যোগ), অথবা ডিভাইড-অ্যান্ড-কনকার রূপ T(n) = a·T(n/b) + f(n), a ≥ 1, b > 1-এর জন্য মাস্টার থিওরেম।
মাস্টার থিওরেম f(n)-কে তুলনা করো n^(log_b a)-এর সঙ্গে, যা লিফগুলোর মোট খরচ।
  1. কেস ১ — কোনো ε > 0-এর জন্য f(n) = O(n^(log_b a − ε)) (লিফ প্রধান) ⇒ T(n) = Θ(n^(log_b a))।
  2. কেস ২ — f(n) = Θ(n^(log_b a)) (প্রতিটি স্তর সমান) ⇒ T(n) = Θ(n^(log_b a) · log n)। বর্ধিত রূপ: f = Θ(n^(log_b a) logᵏ n) ⇒ Θ(n^(log_b a) logᵏ⁺¹ n)।
  3. কেস ৩ — f(n) = Ω(n^(log_b a + ε)) এবং রেগুলারিটি a·f(n/b) ≤ c·f(n), কোনো c < 1 (রুট প্রধান) ⇒ T(n) = Θ(f(n))।
f(n) = Θ(nᵈ) হলে সংক্ষেপে: log_b a > d → Θ(n^(log_b a)); = d → Θ(nᵈ log n); < d → Θ(nᵈ)।

লিনিয়ার-টাইম (তুলনাহীন) সর্ট কাউন্টিং সর্ট (key 0..k): প্রতিটি key গুনো, গণনার প্রিফিক্স-যোগফল নাও, ডান থেকে বামে স্ক্যান করে বসাও (তাই স্টেবল) → Θ(n + k) সময় ও মেমরি। A = 2 5 3 0 2 3 0 3: গণনা 2 0 2 3 0 1 → প্রিফিক্স 2 2 4 7 7 8 → 0 0 2 2 3 3 3 5। র‍্যাডিক্স সর্ট (LSD): d টি অঙ্কের প্রতিটিতে স্টেবল কাউন্টিং সর্ট → Θ(d(n + k))। বাকেট সর্ট: [0, 1)-এ সুষম ইনপুট n টি বাকেটে, প্রতিটিতে ইনসার্শন সর্ট → গড়ে Θ(n), worst O(n²)।

মনে রাখার কৌশল "সিলেকশন কম Swap, ইনসার্শন Shift।" সবচেয়ে কম লেখা → সিলেকশন (n − 1 swap)। প্রায়-সাজানো বা ছোট → ইনসার্শন (Timsort ও introsort-এর ভেতরে)।
পরীক্ষার ফাঁদ যেকোনো তুলনাভিত্তিক সর্টে worst case-এ Ω(n log n) তুলনা লাগে (log₂ n! — প্রমাণ NP-কমপ্লিটনেস লেসনে)। কাউন্টিং ও র‍্যাডিক্স সর্ট একে হারায় শুধু কারণ এরা key তুলনাই করে না।

লিখিত প্রশ্নের প্রিয় ★
মার্জ সর্ট অর্ধেকে ভাগ, দুই অংশ সাজাও, লিনিয়ার সময়ে মার্জ: T(n) = 2T(n/2) + Θ(n) = Θ(n log n), সব ক্ষেত্রে। m ও k উপাদানের দুটি তালিকা মার্জে সর্বোচ্চ m + k − 1 তুলনা (কমপক্ষে min(m, k))। সমান হলে বাম থেকে নিলে (≤) স্টেবল। Θ(n) অতিরিক্ত অ্যারে; লিংকড লিস্ট ও এক্সটার্নাল (k-way) সর্টিংয়ে আদর্শ।
কুইক সর্ট (Hoare, 1961) একটি পিভট নাও, পার্টিশন করো যাতে ছোট key বামে ও বড় ডানে, তারপর দুই দিকে রিকার্শন। Best/average Θ(n log n) (≈ 1.39 n log₂ n তুলনা); worst Θ(n²) যখন পিভট সবসময় সর্বনিম্ন বা সর্বোচ্চ, যেমন সাজানো ইনপুটে প্রথম/শেষ পিভট: T(n) = T(n−1) + Θ(n)। প্রতিকার: র‍্যান্ডম বা মিডিয়ান-অব-থ্রি পিভট।
