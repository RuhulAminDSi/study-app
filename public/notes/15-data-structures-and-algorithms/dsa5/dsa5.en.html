1Flow Networks: Source, Sink, Capacity, Flow — and the Residual Graph

the vocabulary ★
Definition A flow network is a directed graph G = (V, E) in which every edge (u, v) has a capacity c(u, v) ≥ 0, with two special vertices: the source s, where flow originates, and the sink t, where it is absorbed. A flow f assigns to each edge the amount actually passing through it. Water pipes, road lanes, network links and conveyor belts are all the same model: how much can travel from s to t per unit time?
RuleStatementMeaning
Capacity constraint0 ≤ f(u,v) ≤ c(u,v)No edge carries more than its capacity, and never a negative amount.
Flow conservationΣ f(·, v) = Σ f(v, ·) for every v ≠ s, tWhat enters a vertex leaves it — only s and t are exempt.
Value of the flow|f| = Σ f(s, v) − Σ f(v, s)Net flow out of the source = net flow into the sink.
Bottleneckc_f(p) = min residual capacity on path pThe amount one augmenting path can add.
Residual graph G_f ✍ For every edge carrying f of capacity c, the residual graph has a forward edge with c_f(u,v) = c(u,v) − f(u,v) (room left) and a backward edge with c_f(v,u) = f(u,v) (flow that may be cancelled). An augmenting path is any s→t path in G_f; edges with c_f = 0 are dropped.
Exam trap ✍ three 1. Conservation does not hold at s and t — that is where the flow value is measured. 2. The backward edge is not a real pipe; pushing along it means cancelling flow already sent. 3. A saturated edge (f = c) disappears forward but still exists backward.
Memory trick "Forward = room left, backward = regret." Every unit you send buys you the right to change your mind about it later — that is the residual graph in one line.

2Ford–Fulkerson, Edmonds–Karp, Dinic and Push–Relabel

the complexity table ★
FORD-FULKERSON(G, s, t) for each edge (u,v): f(u,v) = 0 while an s→t path p exists in G_f: b = min{ c_f(u,v) : (u,v) on p } for each (u,v) on p: if (u,v) ∈ E: f(u,v) += b else: f(v,u) -= b return f // |f| is maximum
The method in four steps 1. Start with zero flow. 2. Find any augmenting path in the residual graph. 3. Push its bottleneck b along it and update residual capacities (forward −b, backward +b). 4. Repeat until no s→t path remains; the flow is then maximum. FF is a method: it does not say how to find the path.
AlgorithmHow the path / flow is chosenTime
Ford–Fulkerson (1956)Any augmenting path (often DFS). Needs integer capacities to be sure of stopping.O(E·|f*|)
Edmonds–Karp (1972)FF with BFS = shortest augmenting path (fewest edges). O(VE) augmentations × O(E) per BFS.O(VE²)
Dinic (1970)BFS builds a level graph; DFS pushes a blocking flow; at most V−1 phases.O(V²E); unit capacity O(E·min(V^⅔, E^½))
Push–Relabel (Goldberg–Tarjan)Not path-based: keeps a preflow, pushes excess downhill, relabels heights.generic O(V²E); FIFO O(V³)
Hopcroft–KarpDinic specialised to bipartite matching.O(E√V)
Exam trap ✍ three corrections 1. Dinic is O(V²E) in general. The bound O(E·min(V^⅔, E^½)) holds only for unit-capacity networks — quoting it as the general bound is wrong. 2. O(E·|f*|) assumes integer capacities: each augmentation adds ≥ 1. With irrational capacities plain FF may never terminate (and may even converge to a wrong value). 3. Edmonds–Karp's bound is independent of the capacities — that is exactly why BFS is used.
Memory trick "Ford finds any road, Edmonds–Karp takes the shortest, Dinic floods by levels, push–relabel lets water run downhill." Complexities pair up: E-K = VE², Dinic = V²E — the squares swap places.
Integrality theorem With integer capacities, FF returns a max flow in which every edge carries an integer. This is what makes the matching reduction (sheet 5) give a real matching, not fractions.
Worked example ✍ why the path choice matters s→u 1000, s→v 1000, u→v 1, u→t 1000, v→t 1000. A careless FF can alternate s→u→v→t and s→v→u→t (through the backward edge v→u), adding 1 each time: 2000 augmentations. Edmonds–Karp picks the 2-edge paths s→u→t and s→v→t first: 2 augmentations, same max flow 2000.

4The Max-Flow Min-Cut Theorem, and Where Flow Is Used

one theorem, many problems ★
Definitions An s–t cut (S, T) splits V into two parts with s ∈ S and t ∈ T. Its capacity is c(S,T) = Σ c(u,v) over edges u ∈ S, v ∈ T — forward edges only. The net flow across it is forward flow minus backward flow, and for every cut it equals |f|.
Max-flow min-cut theorem (Ford–Fulkerson, 1956) ✍ The following are equivalent: (1) f is a maximum flow; (2) the residual graph G_f has no augmenting path; (3) |f| = c(S, T) for some cut. Hence max |f| = min c(S,T). The easy half (weak duality): every flow ≤ every cut, because all flow must cross the cut.
Bipartite matching as a flow ✍ Left set L, right set R. Add s → every u ∈ L and every v ∈ R → t, orient each L–R edge left to right, and give every edge capacity 1. By the integrality theorem the max flow is 0/1 on each edge, and the edges L→R carrying flow form a maximum matching: max matching = max flow.
Worked example Workers W1, W2, W3; jobs J1, J2, J3. W1 can do J1, J2; W2 only J1; W3 J2, J3. Paths s→W1→J1→t, s→W3→J2→t give 2; then s→W2→J1 is blocked forward, but the residual edge J1→W1 lets s→W2→J1→W1→J2→W3→J3→t re-route: flow 3 = W1–J2, W2–J1, W3–J3.
ApplicationWhat s, t, edges and capacities stand for
Network routing / bandwidthRouters are vertices, links carry Mbps capacities; max flow = the most traffic s can send to t; the min cut is the set of links whose failure disconnects them cheapest.
Transportation & logisticsDepots, roads with truck limits, warehouses — how many tonnes per day can reach the port.
Image segmentationPixels are vertices; s = "foreground", t = "background"; edge weights = similarity. The min cut is the cheapest boundary between object and background (graph cuts).
Disjoint paths (Menger)Unit capacities: max flow = number of edge-disjoint s–t paths = fewest links whose removal disconnects s from t.
Scheduling / assignmentCrews to flights, students to projects — matching with capacities; also project selection and baseball elimination.
Exam trap Max flow equals the minimum cut, not "the sum of all capacities" nor "the largest edge". A flow network can have several minimum cuts but only one max-flow value.
Memory trick "A chain is as strong as its weakest link — a network is as wide as its narrowest cut."

5Approximation Algorithms: the Ratio ρ, and Vertex Cover

provably close, provably fast ★
Definition An approximation algorithm runs in polynomial time on an NP-hard optimisation problem and returns a solution with a proven guarantee of how far it can be from the optimum. (Why the exact answer is out of reach — NP-hardness — is the subject of the next lesson.) A heuristic with no guarantee is not an approximation algorithm.
Problem typeApproximation ratio ρ(n)Reading it
Minimisation (cover, tour)ρ = C / C* ≥ 1C = algorithm's cost, C* = optimal. ρ = 2: never more than twice the optimum.
Maximisation (knapsack, cut)ρ = C* / C ≥ 1ρ = 2: never less than half the optimum.
Combined (CLRS)max(C/C*, C*/C) ≤ ρ(n)ρ = 1 means exact; the nearer to 1, the better.
ProblemAlgorithmRatioNote
Vertex covertake both ends of a maximal matching2sheet below
Metric TSPMST, preorder walk, shortcut2Christofides 1.5
Set covergreedy: most uncovered elementsH(n) ≈ ln n≤ ln n + 1
0/1 knapsackvalue-scaling DP1 + εFPTAS
APPROX-VERTEX-COVER(G) C = ∅; E' = E while E' ≠ ∅: pick any edge (u,v) in E' C = C ∪ {u, v} delete from E' every edge touching u or v return C // O(V + E)
Why ratio 2 ✍ proof The picked edges form a matching M (no two share a vertex), and |C| = 2|M|. Any cover — the optimal C* too — must contain at least one endpoint of each edge of M, and those endpoints are all different, so |C*| ≥ |M|. Hence |C| = 2|M| ≤ 2|C*|.
Exam trap ✍ two 1. The "pick the highest-degree vertex" greedy is not a 2-approximation — its ratio grows like log n. The 2 belongs to the both-endpoints rule. 2. A minimisation ratio of 2 allows up to 2 × OPT, never below OPT.
Memory trick "Grab the whole edge, pay double at most." One endpoint of each grabbed edge was needed anyway; the other is the price of not knowing which.

6Metric TSP, Set Cover, Knapsack — and PTAS vs FPTAS

the classic ratios ★
Metric TSP: the MST tour ✍ Distances obey the triangle inequality d(u,w) ≤ d(u,v) + d(v,w). 1. Build an MST T (Prim/Kruskal, previous lesson). 2. Walk it in DFS preorder: the full walk uses each MST edge twice, cost 2·w(T). 3. Shortcut repeated vertices — by the triangle inequality this never adds cost. Since deleting one edge of the optimal tour leaves a spanning tree, w(T) ≤ OPT, so tour ≤ 2·w(T) ≤ 2·OPT.
Beyond 2 — Christofides (1976) MST + a minimum-weight perfect matching on the odd-degree MST vertices gives an Eulerian graph; shortcut its Euler tour → ratio 1.5 for metric TSP. General TSP (no triangle inequality) has no constant-ratio approximation unless P = NP.
Set cover: greedy Universe U of n elements, a family of subsets; choose the fewest subsets covering U. Greedy: repeatedly take the set covering the most still-uncovered elements. Ratio H(n) = 1 + ½ + … + 1/n ≤ ln n + 1 — essentially the best possible in polynomial time (unless P = NP).
Worked example U = {1,…,6}; S1 = {1,2,3,4}, S2 = {4,5}, S3 = {5,6}, S4 = {1,6}. Greedy takes S1 (4 new), then S3 (5, 6: 2 new) → 2 sets, all covered. Here greedy is optimal; on adversarial inputs it can be ≈ ln n times worse.
0/1 knapsack: FPTAS ✍ The exact DP is O(nW) — pseudo-polynomial. Scale every value down: v′ = ⌊v / K⌋ with K = ε·v_max / n, run the DP indexed by value in O(n³/ε), and the answer is ≥ (1 − ε)·OPT. Simpler: max(greedy by value/weight, best single item) is a 2-approximation. (Fractional knapsack needs none of this — greedy is exact.)
SchemeGuaranteeRunning timeExample
PTASwithin (1 + ε) for every fixed ε > 0polynomial in n, may be exponential in 1/ε, e.g. O(n^{1/ε})Euclidean TSP, bin-packing variants
FPTASwithin (1 + ε)polynomial in n and 1/ε, e.g. O(n³/ε)0/1 knapsack, subset sum
Exam trap ✍ three 1. Every FPTAS is a PTAS, not the reverse. 2. A strongly NP-hard problem has no FPTAS unless P = NP; knapsack is only weakly NP-hard. 3. "Set cover greedy ratio 2" is wrong — it is ln n.
Memory trick "Cover 2, Tour 2 then 1.5, Set ln n, Knapsack 1+ε." And "FPTAS is Fully polynomial — in both n and 1/ε."

7Parallel Algorithms: Speedup, Efficiency, Granularity, Amdahl's Law

the formula sheet ★
Definition A parallel algorithm divides a problem into sub-problems solved simultaneously on several processors, then combines the results. Its quality is measured against the best sequential algorithm, not against itself on one processor.
MeasureFormulaMeaning
Speedup SS = T₁ / TₚT₁ = best sequential time, Tₚ = time on p processors. Ideal (linear): S = p.
Efficiency EE = S / pFraction of processor time doing useful work; 0 < E ≤ 1 normally.
Costp × TₚCost-optimal if p·Tₚ = Θ(T₁).
Granularitycomputation / communicationFine-grained: many small tasks, much communication. Coarse-grained: few large tasks.
Work–spanTₚ ≥ T₁/p, Tₚ ≥ T∞T∞ (span) = longest dependency chain; parallelism = T₁/T∞; Brent: Tₚ ≤ T₁/p + T∞.
Data vs task parallelism Data: the same operation on different pieces of data — vector addition, matrix multiply, image filters (SIMD, GPUs). Task: different operations at once — pipeline stages, a web server's independent requests (MIMD).
Flynn's taxonomy SISD classic uniprocessor · SIMD vector units, GPUs · MISD rare (fault-tolerant pipelines) · MIMD multicores, clusters. PRAM models: EREW, CREW, CRCW (exclusive/concurrent read/write).
Amdahl's law (fixed problem size) ✍ If a fraction P of the work can run in parallel on N processors and 1 − P stays serial: S(N) = 1 / ((1 − P) + P/N). As N → ∞, S → 1 / (1 − P) — the serial part caps the speedup.
Worked example P = 0.9, N = 10: S = 1 / (0.1 + 0.09) = 1/0.19 ≈ 5.26; E = 5.26/10 ≈ 53%; limit 1/0.1 = 10, however many processors. P = 0.8, N = 4: S = 1/(0.2 + 0.2) = 2.5; limit 5.
Gustafson's law (scaled size) When the problem grows with N: S = (1 − P) + P·N (P = parallel share of the parallel run). P = 0.9, N = 10 → 0.1 + 9 = 9.1. Amdahl is pessimistic, Gustafson optimistic.
Exam trap In Amdahl's law P is the parallel fraction; mixing it with the serial fraction inverts every answer. Speedup above p (superlinear) can occur through cache effects, but is not the norm.
Memory trick "The slowest part sets the pace." Ten percent serial ⇒ never more than ten times faster.

8Parallel Sorting, Matrix Multiplication, BFS — and the Pitfalls

the standard algorithms ★
ProblemParallel approachCost / time
Reduction (sum of n)Pairwise tree: n/2 adds, then n/4, …O(log n) steps, n/2 processors
Parallel merge sortSplit among p processors, sort locally, merge in a tree of log p levels.O((n/p) log(n/p)) local sort + merging
Bitonic sortSorting network: build bitonic sequences, then bitonic-merge with compare–exchange; n a power of 2.O(log² n) time, O(n log² n) comparisons
Matrix multiplyBlock decomposition; Cannon's algorithm on a √p × √p processor grid.O(n³/p) compute, √p shift steps
Graph searchLevel-synchronous BFS: expand the whole frontier in parallel; also parallel Dijkstra (Δ-stepping).rounds = depth of the BFS tree
Worked example: parallel merge sort Array [38, 27, 43, 3, 9, 82, 10] on 2 processors. P0 gets [38, 27, 43] → sorts to [27, 38, 43]; P1 gets [3, 9, 82, 10] → [3, 9, 10, 82] — both at the same time. One merge step → [3, 9, 10, 27, 38, 43, 82]. With p processors the merge tree has log₂ p levels.
Bitonic half-cleaner ✍ A bitonic sequence rises then falls (or a rotation of one). Compare item i with item i + n/2 and swap if out of order: [2, 5, 8, 9 | 7, 6, 3, 1] → low [2, 5, 3, 1], high [7, 6, 8, 9]. Every low ≤ every high, and each half is bitonic again — recurse. n = 8 needs 3·4/2 = 6 compare stages.
Cannon's algorithm Processor P(i,j) holds blocks A(i,j), B(i,j). Skew: shift row i of A left by i, column j of B up by j. Then √p times: multiply-add local blocks, shift A one left and B one up. Each processor stores only one block of each matrix at a time.
ChallengeWhat goes wrong / the remedy
Communication overheadSending data costs time; fine granularity can make Tₚ worse than T₁.
Load balancingUneven pieces leave processors idle — dynamic scheduling, work stealing.
Synchronisation, races, deadlocksBarriers make fast processors wait; unordered updates race (BFS "visited" flag → atomic compare-and-swap); circular lock waits deadlock.
Applications Scientific simulation (weather, physics) · big data: Hadoop MapReduce, Apache Spark · graphics rendering on GPUs · distributed ML training (data-parallel gradients, all-reduce).
Exam trap Bitonic sort does more comparisons than merge sort (n log² n vs n log n) — it wins because its compare pattern is fixed, ideal for hardware and GPUs.
