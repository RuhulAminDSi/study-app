1Transform-and-Conquer and Horner's Rule

rewrite, then solve ★
Definition Algebraic simplification / transformation means rewriting a problem or its formula into an equivalent form that is cheaper to compute: same answer, fewer operations. The strategy is called transform-and-conquer; it has three flavours.

Horner's rule Factor x out again and again: p(x) = aₙxⁿ + … + a₁x + a₀ = (…((aₙx + aₙ₋₁)x + aₙ₋₂)x + … )x + a₀. One pass from the leading coefficient: n multiplications + n additions for degree n, with no powers computed at all.

Exam trap ✍ three 1. Degree n has n + 1 coefficients, but Horner does n multiplications, not n + 1 or 2n. 2. Horner is proved optimal: no general method uses fewer than n multiplications. 3. The last value is p(x₀) (remainder theorem); the rest are the quotient.
Evaluation ↔ interpolation A degree-n polynomial is fixed by its n + 1 coefficients or by its values at n + 1 distinct points. Evaluation at n + 1 points by Horner: O(n²). Interpolation (Lagrange / Newton): O(n²). Products are O(n) in point-value form — the FFT idea.
Memory trick "Horner = nested brackets = n and n." Binary 1101 → ((1·2 + 1)·2 + 0)·2 + 1 = 13 is Horner with x = 2.

2Fast Power, Karatsuba, Strassen and the FFT

save one multiplication ★
Fast (binary) exponentiation xⁿ = (x^(n/2))² (n even) or x·(x^((n−1)/2))² (n odd): one squaring per bit, at most 2⌊log₂ n⌋ multiplications instead of n − 1 ⇒ O(log n). x¹³ (13 = 1101₂): x → x² → x³ → x⁶ → x¹² → x¹³ = 5 multiplications, not 12.
Worked: modular power ✍ 3¹³ mod 7: 3¹ = 3, 3² = 9 ≡ 2, 3⁴ ≡ 4, 3⁸ ≡ 16 ≡ 2. 13 = 8 + 4 + 1 ⇒ 3¹³ ≡ 2·4·3 = 24 ≡ 3 (mod 7). Reducing after every step keeps numbers small — this is how RSA and Diffie–Hellman compute huge powers.
Karatsuba multiplication (1960) Split two n-digit numbers: x = a·10^m + b, y = c·10^m + d. Schoolbook needs four products ac, ad, bc, bd. The algebraic trick ad + bc = (a + b)(c + d) − ac − bd needs only three. T(n) = 3T(n/2) + O(n) ⇒ Θ(n^log₂3) ≈ Θ(n^1.585): the recursion tree has 3ᵏ calls at depth k, so the n^log₂3 leaves dominate.
Worked example ✍ 1234 × 5678 a = 12, b = 34, c = 56, d = 78 (m = 2). ac = 672, bd = 2652, (a + b)(c + d) = 46 × 134 = 6164 ⇒ ad + bc = 6164 − 672 − 2652 = 2840. Result = 672·10⁴ + 2840·10² + 2652 = 7,006,652 ✓ with three products.
Strassen (1969) Split n × n matrices into four n/2 blocks. Block multiplication needs 8 products; Strassen's identities need 7 products (plus 18 block additions). T(n) = 7T(n/2) + Θ(n²) ⇒ Θ(n^log₂7) ≈ Θ(n^2.81) vs Θ(n³). Worth it only for large n; less numerically stable.
FFT polynomial multiplication Coefficient form: Θ(n²). Instead evaluate both at 2n complex roots of unity (FFT), multiply pointwise (O(n)), interpolate back (inverse FFT) ⇒ O(n log n). FFT: T(n) = 2T(n/2) + O(n) (Cooley–Tukey, 1965).

Exam trap ✍ Strassen's exponent is log₂ 7 ≈ 2.807, not 2.376 (that is the impractical Coppersmith–Winograd line). With 4 and 8 half-size products the exponent stays 2 and 3 — the saving is the one product dropped. Matrix product's trivial lower bound is Ω(n²).
Memory trick "Save one multiplication, lower the exponent." a half-size subproblems with cheap combining ⇒ n^log₂ a (master theorem): 4 → 3 gives log₂ 3 ≈ 1.585; 8 → 7 gives log₂ 7 ≈ 2.807.

4Asymptotic Bounds: O, Ω, Θ Stated Correctly

Ω ≠ best case ★
Definitions f = O(g): ∃ c > 0, n₀ with f(n) ≤ c·g(n) for all n ≥ n₀ (upper bound).
f = Ω(g): ∃ c > 0, n₀ with f(n) ≥ c·g(n) for all n ≥ n₀ (lower bound).
f = Θ(g): both — c₁g(n) ≤ f(n) ≤ c₂g(n) (tight). Strict versions: o and ω.
Common misconception ✍ "Ω means best case, O means worst case" is wrong. O, Ω and Θ bound functions; the best, average and worst case are three different functions, and each can be given an O, Ω or Θ. Insertion sort: worst case Θ(n²) (so it is also Ω(n²)), best case Θ(n). A lower bound of a problem is an Ω on the worst case of every algorithm — next sheet.

5Lower Bound Theory and the Decision-Tree Argument

a fact about the problem ★
Definition A lower bound L(n) of a problem is a cost that every algorithm must pay in the worst case, in a stated model (e.g. "comparisons only"). It is a statement about the problem, not one algorithm. The upper bound is the cost of the best known algorithm. When they meet, that algorithm is optimal (merge sort, heapsort: Θ(n log n) comparisons). A gap is an open problem: matrix product has Ω(n²) vs O(n^2.37…).

The proof ✍ 4 marks Any comparison sort on n distinct keys is a binary decision tree. It must reach a different leaf for each of the n! orderings ⇒ ≥ n! leaves. A binary tree of height h has ≤ 2ʰ leaves ⇒ 2ʰ ≥ n! ⇒ h ≥ log₂(n!). Since n! ≥ (n/2)^(n/2), log₂ n! ≥ (n/2)·log₂(n/2) = Ω(n log n). (Stirling: log₂ n! ≈ n log₂ n − 1.44n.)

6Adversary Arguments and Proven Lower Bounds

⌈3n/2⌉ − 2 ★
Adversary argument Picture the algorithm asking questions ("is aᵢ < aⱼ?") and a malicious adversary answering them — always consistently with some input, but choosing the answer that tells the algorithm least. If the adversary can keep two different answers possible for k − 1 questions, every algorithm needs k. Max of n: each of the n − 1 non-maximum elements must lose at least one comparison, and one comparison makes only one loser ⇒ n − 1, which a linear scan achieves.
Max and min together: the pairwise method Doing them separately costs (n − 1) + (n − 1) = 2n − 2. Better: compare the elements in pairs (n/2 comparisons); the max is among the winners (n/2 − 1 more), the min among the losers (n/2 − 1 more). Total 3n/2 − 2 for even n; for odd n start max = min = first element and pair the rest ⇒ in general ⌈3n/2⌉ − 2, and an adversary argument proves no algorithm does better.

Worked ✍ n = 100 Max + min: ⌈300/2⌉ − 2 = 148 (50 pairs + 49 + 49), not 198. Second largest: 100 + ⌈log₂ 100⌉ − 2 = 100 + 7 − 2 = 105. With n = 8: 7 games find the champion, who beat 3 players; the best of those 3 needs 2 more ⇒ 9 = 8 + 3 − 2.
Exam trap 2n − 2 (or 2n − 3) for max + min is the naive count, not the bound. Do not confuse ⌈3n/2⌉ − 2 (max + min) with n + ⌈log₂ n⌉ − 2 (second largest). "Minimum comparisons in the worst case" means the lower bound, not the lucky best case.

7P, NP, co-NP, NP-Hard and NP-Complete

draw the right picture ★
ClassDefinition (yes/no decision problems)Examples
Psolved deterministically in polynomial time O(nᵏ)sorting, MST, shortest path, 2-SAT, LP, primality
NPa "yes" has a certificate verifiable in polynomial time (= nondeterministic poly time)all of P; SAT, Ham. cycle, subset sum, factoring
co-NPcomplements: "no" answers have short certificatesTAUTOLOGY, UNSAT
NP-hardevery NP problem ≤p it; need not be in NP or decidableHalting problem, TSP-optimisation
NP-completein NP and NP-hard — the hardest of NPSAT, 3-SAT, clique, vertex cover, TSP-decision
Common misconception ✍ A nested picture with P inside NP inside NP-complete inside NP-hard is wrong. NP-complete is not a superset of NP: it is the part of NP that is also NP-hard, and NP-hard spills outside NP. P ⊆ NP is proven (a solver is its own verifier); whether P = NP is open.
Decision vs optimisation TSP-decision: "is there a tour of cost ≤ k?" — in NP, NP-complete. TSP-optimisation: "find the cheapest tour" — NP-hard, not in NP (not a yes/no problem). Same for knapsack, clique, vertex cover. Solving the optimisation version solves the decision version, so it is at least as hard.
What a certificate looks like ✍ SAT: a truth assignment — plug it in, O(formula length). Hamiltonian cycle: an ordering of the n vertices — check n edges exist and nobody repeats. Subset sum: the subset — add it up. Finding is hard; checking is easy.
Memory trick "P: solve fast. NP: check fast. NP-hard: at least as hard as all of NP. NP-complete: hard and checkable." And NP = Nondeterministic Polynomial, never "Non-Polynomial" — every P problem is in NP.
Where famous problems sit P ⊆ NP ∩ co-NP. Primality is in P (AKS, 2002) — testing is easy, while factoring is in NP ∩ co-NP but not known to be in P or NP-complete. Graph isomorphism: in NP, not known NP-complete (quasi-polynomial, 2015). If P ≠ NP, Ladner's theorem says such in-between problems must exist.

8Reductions and the Cook–Levin Theorem

direction matters ★
Reduction A ≤p B A polynomial-time computable function f with x ∈ A ⇔ f(x) ∈ B for every instance x. Read it as "A is no harder than B": a fast algorithm for B gives one for A. Two consequences: B ∈ P ⇒ A ∈ P, and A NP-hard ⇒ B NP-hard. Reductions compose: A ≤p B and B ≤p C ⇒ A ≤p C.
Cook–Levin theorem SAT is NP-complete — Stephen Cook (1971), Leonid Levin independently (1973). It was the first problem proved NP-complete, directly from the definition: any polynomial-time nondeterministic machine's run is encoded as a Boolean formula. Karp (1972) then reduced SAT to 21 classic problems.
Proving X NP-complete ✍ 4 steps 1. X ∈ NP: give a certificate and a polynomial-time verifier. 2. Pick a known NP-complete A. 3. Build f from A-instances to X-instances in polynomial time. 4. Prove x ∈ A ⇔ f(x) ∈ X (both directions). Steps 2–4 alone prove X NP-hard.
Worked ✍ Clique ≤p Vertex cover S is an independent set of G ⇔ V − S is a vertex cover of G, and S is a clique of G ⇔ S is independent in the complement Ḡ. So (G, k) ↦ (Ḡ, |V| − k). Example: V = {1,2,3,4}, edges 12, 13, 23, 34; clique {1,2,3} (k = 3). Ḡ has edges 14, 24 — covered by {4}, size 4 − 3 = 1 ✓.
Worked ✍ Ham. cycle ≤p TSP From G with n vertices build a complete graph: weight 1 on G's edges, 2 on non-edges. G has a Hamiltonian cycle ⇔ there is a tour of cost ≤ n. Building the n² weights is polynomial, so TSP-decision is NP-hard; a tour is checkable, so it is NP-complete.
Exam trap ✍ the direction To show X is hard, reduce a known NP-complete problem to X: A ≤p X. Reducing X to SAT (X ≤p SAT) only shows X is no harder than SAT (so X ∈ NP) — nothing about hardness. "Hard problem → new problem", never the reverse.
2-SAT vs 3-SAT Clauses of two literals: build the implication graph (a ∨ b gives a′ → b and b′ → a); satisfiable ⇔ no variable shares a strongly connected component with its negation ⇒ 2-SAT ∈ P, linear time. With three literals per clause the problem is NP-complete. One extra literal crosses the line.

P vs NP If any one NP-complete problem has a polynomial algorithm, then P = NP and every NP problem does. If P ≠ NP, no NP-complete problem is in P (and, by Ladner's theorem, some NP problems are neither in P nor NP-complete — factoring and graph isomorphism are suspects). The question is one of the seven Clay Millennium Prize Problems (2000, US$1 million); most researchers believe P ≠ NP.
The IT link Public-key cryptography relies on problems believed hard (factoring for RSA, discrete log for Diffie–Hellman). They lie in NP, so a proof of P = NP with a practical algorithm would break them. Timetabling, vehicle routing, register allocation (graph colouring) and chip layout are NP-hard problems solved daily by the methods below.

Exam trap ✍ pseudo-polynomial Knapsack's DP is O(nW), yet knapsack is NP-complete — no contradiction. W is written in log₂ W bits, so nW is exponential in the input length. Doubling the bits of W squares W. Such problems are called weakly NP-complete.
Memory trick "Euler edges, Hamilton heads." Every edge once is easy (degree check), every vertex once (the "heads") is NP-complete. Same pattern: shortest easy, longest hard; 2 easy, 3 hard. Ratio-guaranteed methods are taught in the approximation-algorithms lesson.
