1Graph Foundations: Vertices, Edges & Degree

definition ★
Definition A graph G = (V, E) is an ordered pair of sets: V = the vertices (nodes), E = the edges, each edge joining exactly two vertices. Write |V| = n (order) and |E| = m (size). A graph is simple when it has no loop and no pair of parallel edges; a multigraph allows both. An edge is incident to a vertex when it has that endpoint.
NameWhat it is
Simple graphno loop, no parallel edge; deg(v) ≤ n − 1
Complete Knevery pair joined; deg n−1; |E| = n(n−1)/2
Cycle Cnn vertices in a ring; every degree 2
Path Pnvertices in a line; exactly two of degree 1
r-regularevery vertex of degree r, so m = nr/2
BipartiteV = V₁ ∪ V₂, every edge across the split
Two ways to store a graph Adjacency matrix — an n × n table, A[i][j] = 1 when (vi, vj) is an edge: O(V²) space and build time, and deg(vi) is the count of 1s in row i. Adjacency list — one neighbour list per vertex, O(V + E): it wins on sparse graphs.

Memory trick "Walks are Wild, Trails have Tight edges, Paths are Pure." Each rule removes one freedom — walk ⊂ trail ⊂ path, and a cycle is a path that closed up, so it is the strongest of the four.
Exam trap (i) A cycle needs length ≥ 3 in a simple graph — u, v, u is a walk, not a cycle. (ii) "Starts and ends at the same vertex" is only half the definition; no other vertex may repeat. (iii) An isolated vertex has degree 0. (iv) Isomorphic needs a bijection preserving edges — same n, m and degree sequence is not enough.

2Euler Paths & Circuits

most tested ★
Definition An Euler trail uses every edge exactly once; an Euler circuit is one that also returns to its start. Vertices may repeat as often as needed — edges are what count. For a connected undirected graph: Euler circuit ⇔ every degree even; Euler path but no circuit ⇔ exactly two odd degrees; more than two odd degrees ⇒ no Euler trail at all, and a disconnected graph never has one however even its degrees.
Connected undirected graphWhat exists
every deg evenEuler circuit — and therefore also a path
exactly two odd degEuler path only; it must start at one odd vertex and end at the other
more than two odd degno Euler trail
Exam trap "All degrees even" is necessary and sufficient, not a shortcut. In a directed graph the rule changes: an Euler circuit exists iff the graph is connected and in-degree = out-degree at every vertex.

3Hamilton Paths & Circuits

the classic distinction ★
Definition A Hamilton path visits every vertex exactly once; a Hamilton circuit closes up. Here it is the vertices that count and edges may not repeat. There is no cheap test like Euler's — the problem is NP-complete in general. Useful sufficient conditions: Dirac's theorem — deg(v) ≥ n/2 at every vertex ⇒ Hamilton circuit; Ore's theorem — deg(u) + deg(v) ≥ n for every non-adjacent pair ⇒ Hamilton circuit. Every Kn is Hamiltonian.
Exam trap — the line that decides the MCQ Euler is about EDGES; Hamilton is about VERTICES. K4: deg = 3, all odd ⇒ no Euler circuit, yet it is complete ⇒ Hamilton circuit ✔. So Kn has an Euler circuit exactly when n is odd. In practice an Euler circuit is the postal-carrier round (polynomial) while a Hamilton circuit is the travelling-salesman problem (NP-complete).
Worked example ✍ read sheet 2's graph V = {A, B, C, D, E}, edges AB, BC, AD, DE, CE, BD — deg(A) = 2, deg(B) = 3, deg(C) = 2, deg(D) = 3, deg(E) = 2. (a) Two odd vertices (B, D) ⇒ an Euler path, no circuit; it starts at B and ends at D. (b) Hamilton path? A → B → C → E → D visits all five once ⇒ yes. (c) Hamilton circuit? It would need 12 edge-ends = 6 edges, i.e. every edge — impossible, since B and D would have to drop from degree 3 to 2 ⇒ no.

4Bipartite & Planar Graphs

formula sheet ★
Definition A graph is bipartite if V = V₁ ∪ V₂ and every edge joins a vertex of V₁ to one of V₂ — equivalently, if it can be coloured with two colours so that no edge is monochromatic. It is planar if it can be drawn in the plane with no edge crossings. A bipartite graph contains no odd cycle; Kn is bipartite only for n ≤ 2, and K3,3 is bipartite but not planar.
Euler's formula for planar graphs Connected: V − E + F = 2 · with C components: V − E + F = 1 + C · simple planar, V ≥ 3: E ≤ 3V − 6 · simple planar and bipartite, V ≥ 3: E ≤ 2V − 4.
Worked example ✍ V = 5, E = 7 ⇒ F = 2 − 5 + 7 = 4. If that graph were bipartite and planar, E ≤ 2(5) − 4 = 6, so 7 edges would already be impossible — it has an odd cycle, hence is not bipartite. For V = 6 the two ceilings are 3·6 − 6 = 12 and 2·6 − 4 = 8.
Graph colouring A proper colouring gives adjacent vertices different colours; the fewest colours is the chromatic number χ(G). χ(bipartite) ≤ 2; χ(Kn) = n; χ(tree) = 2. The four-colour theorem (Appel & Haken, 1976, computer-assisted): every planar graph is colourable with at most four colours, and K4 shows four are really needed. K5 is not planar and needs five.
Exam trap (i) "Every planar graph can be coloured with three colours" is false — that was the disproved claim. (ii) Planarity is a property of the graph, not of one bad drawing: K5 cannot be drawn planarly at all. (iii) E ≤ 3V − 6 needs V ≥ 3. (iv) "Connected and E ≥ V" is exactly the threshold for containing a cycle.
IT link A dependency graph (module A needs module B) is a digraph; if it has a cycle the build breaks, so build tools topologically sort it — the DFS of sheet 5. A routing table is a weighted graph, and a cheapest route with non-negative costs is exactly Dijkstra.

5Trees

every property asked ★
Definition A tree is a connected acyclic graph. These are all equivalent, and exam questions use them interchangeably: n vertices ⇒ exactly n − 1 edges · exactly one path between any two vertices · no cycle · adding any edge creates a cycle · deleting any edge disconnects it · every degree-1 vertex is a leaf, and a tree always has at least two leaves.
Memory trick "Tree = n − 1." Read it as a budget: start from n isolated vertices, i.e. n components; each edge merges exactly two components, so it costs one merge. Going from n components to one therefore takes exactly n − 1 merges — which is also why a connected graph cannot have fewer than n − 1 edges.
Exam trap (i) A tree on n vertices has n − 1 edges, not n; a forest on n vertices with c components has n − c. (ii) Acyclic ≠ complete — a tree has no cycle but also no triangle. (iii) A rooted tree adds a chosen root with a depth; an isomorphism needs a degree sequence and the structure to match, so two trees with the same number of edges need not be isomorphic.

6Traversal: BFS & DFS

most tested ★
Definition Both BFS (breadth-first, a queue) and DFS (depth-first, a stack or recursion) visit every reachable vertex once, each returns a spanning tree of the component it reached, and a spanning tree on n vertices always has exactly n − 1 edges. Both run in O(V + E); only the order differs, and that order is the whole answer to "which one do I use".
 BFSDFS
Structurequeue — expand level by levelstack / recursion — go as deep as possible
Givesshortest path by edge counta DFS forest plus finishing times
Shortest path?yes, on an unweighted graphno, weighted or not
Used forlevel order, hop counts, nearest nodecycle detection, topological sort
Cycle test In an undirected graph a DFS finds a back edge to a vertex still on the recursion stack ⇒ a cycle exists. In a digraph BFS detects a cycle when an already-discovered vertex is met again. Neither test needs weights, so neither gives a shortest path on a weighted graph.
Worked example ✍ V = 6, E = 7 (a) Connected? A graph on n vertices with E ≥ n − 1 may be connected; here 7 ≥ 5, so connectivity is possible but not guaranteed. (b) Cycle? E ≥ V (7 ≥ 6) ⇒ if it is connected it must contain a cycle. (c) A spanning tree on 6 vertices keeps exactly 5 of those 7 edges.

7Minimum Spanning Tree & Shortest Path

algorithms ★
Minimum spanning tree A spanning tree connects every vertex with no cycle; an MST does it with the smallest total edge weight. Always n − 1 edges, and unique only when all weights differ.
 KruskalPrim
Strategysort edges ↑, take each joining two different componentsgrow one tree, add the cheapest edge leaving it
Dataunion–find / disjoint setsa min priority queue
Feeds onsparse graphsdense graphs
CostO(E log E)O(E log V)
Dijkstra — single-source shortest path Greedy and correct only when every edge weight is ≥ 0. Keep dist[v] for each vertex; repeatedly finalise the unvisited vertex with the smallest dist and relax its edges: if dist[u] + w(u,v) < dist[v], set dist[v] = dist[u] + w(u,v) and parent[v] = u. Cost O(V²), or O((V+E) log V) with a heap. Bellman–Ford relaxes every edge |V| − 1 times, handles negative weights, and detects a negative-weight cycle.
Worked example ✍ Dijkstra on V = {A, B, C, D} Edges A–B = 4, A–C = 1, C–B = 2, B–D = 3, C–D = 5. (1) dist = (A 0, B 4, C 1, D ∞). Smallest unsettled is C at 1; settle it. Relax C–B: 1 + 2 = 3 < 4 ⇒ dist[B] = 3. Relax C–D: 1 + 5 = 6 ⇒ dist[D] = 6. (2) Smallest unsettled is B at 3; settle it. Relax B–D: 3 + 3 = 6, not < 6 ⇒ dist[D] stays 6 (a tie — the route A–C–D also costs 6). (3) Settle D at 6. Final: d(A) = 0, d(C) = 1, d(B) = 3, d(D) = 6, with parents C ← A, B ← C. Kruskal on the same graph: sorted AC(1), BC(2), BD(3), AB(4), CD(5) — take AC, then BC, then BD. Three edges = n − 1, no cycle ⇒ an MST of weight 1 + 2 + 3 = 6.
Exam trap Dijkstra finds a shortest path; Kruskal and Prim find a minimum spanning tree. They are different questions and on a general graph they choose different edges. An MST exists only for a connected graph — on a disconnected one both algorithms return a minimum spanning forest.
Memory trick "Kruskal goes Kayaking over Krossed-out edges" — take the cheapest, throw away anything that would close a loop. "Prim stays Put" — it never leaves the tree it has already grown. And "negative breaks Dijkstra" — the moment a cheaper path lies behind you, a settled vertex is never revisited.
Why Dijkstra breaks on a negative edge — the one-line proof Dijkstra declares a vertex final when it is cheapest among the unsettled ones. If a later edge could still improve that vertex, it must run through some unsettled vertex whose distance is not smaller — impossible when every weight added is ≥ 0. A single negative edge destroys exactly that inequality, so the "final" verdict is wrong.

8Propositional Calculus: Connectives

foundation ★
Definition A proposition is a declarative sentence that is either true or false, and nothing else — no "maybe", no dependence on an unknown. "2 + 2 = 4" is a proposition; "x + 2 = 5" is an open sentence, not a proposition until x is given a value. A compound proposition is built from simple ones with logical connectives.

Three classifications Tautology — always T (P ∨ ¬P, P → P) · Contradiction — always F (P ∧ ¬P, P ⊕ P) · Contingency — T in some rows and F in others (P ∨ Q). Test: build the column; if every entry matches, it is one of the first two.
Exam trap (i) p → q is false only at p = T, q = F; the other three rows are true, so a false hypothesis still yields a true implication. (ii) P ⊕ Q is true when exactly one is true — with both true it is false. (iii) P ↔ Q is an operator; P ≡ Q states equivalence — the first is built from P and Q, the second compares two whole formulas. (iv) Precedence ¬ > ∧ > ∨ > → > ↔, so ¬P ∧ Q means (¬P) ∧ Q.
Memory trick "Minus Again Makes Nothing" — the one connective that turns a false hypothesis into a true conclusion. "xor is nothing-or-something": P ⊕ Q ≡ ¬(P ↔ Q). Implication is the only connective that is not symmetric, while ↔ and ≡ are the only genuine equivalences.
Building a truth table — the routine that earns the marks Write the formula with parentheses already inserted by precedence. One row per combination: n variables give 2ⁿ rows and the column order must be fixed across all of them. Fill each column top to bottom. Then read the last column: all T = tautology, all F = contradiction, mixed = contingency. For 2ⁿ > 8 rows, first push everything to CNF or use the laws instead of the table.

9Equivalence, Laws & Canonical Forms

written favourite ★
Definition Two formulas P and Q are logically equivalent, written P ≡ Q, when they have the same truth value in every row — equivalently when P ↔ Q is a tautology. A truth table proves it; the laws below prove it in one line.
LawStatement
IdentityP ∧ T ≡ P,   P ∨ F ≡ P
DominationP ∧ F ≡ F,   P ∨ T ≡ T
IdempotentP ∧ P ≡ P,   P ∨ P ≡ P
ComplementP ∧ ¬P ≡ F,   P ∨ ¬P ≡ T,   ¬¬P ≡ P
CommutativeP ∧ Q ≡ Q ∧ P,   P ∨ Q ≡ Q ∨ P
Associative(P ∧ Q) ∧ R ≡ P ∧ (Q ∧ R) — and for ∨
DistributiveP ∧ (Q ∨ R) ≡ (P ∧ Q) ∨ (P ∧ R);   P ∨ (Q ∧ R) ≡ (P ∨ Q) ∧ (P ∨ R)
De Morgan¬(P ∧ Q) ≡ ¬P ∨ ¬Q,   ¬(P ∨ Q) ≡ ¬P ∧ ¬Q
AbsorptionP ∨ (P ∧ Q) ≡ P,   P ∧ (P ∨ Q) ≡ P
The five forms to know by heart P → Q ≡ ¬P ∨ Q · ¬Q → ¬P ≡ P → Q (the contrapositive) · Q → P is the converse and ¬P → ¬Q the inverse, neither equivalent, though converse ≡ inverse · P ↔ Q ≡ (P ∧ Q) ∨ (¬P ∧ ¬Q) ≡ (P → Q) ∧ (Q → P) · P ⊕ Q ≡ ¬(P ↔ Q).
Worked example ✍ exportation P → (Q → R) ≡ ¬P ∨ (¬Q ∨ R) ≡ (¬P ∨ ¬Q) ∨ R ≡ ¬(P ∧ Q) ∨ R ≡ (P ∧ Q) → R. With P = F, Q = F, R = F the chained form (P → Q) → R is false while the original is true, so implication is the one connective that is not associative.
Canonical (normal) forms A formula in DNF (sum of products) is a disjunction of conjunctions; in CNF (product of sums) it is a conjunction of disjunctions. Every formula has both, read off its truth table by taking exactly one minterm per row: DNF takes the rows where it is true, CNF the rows where it is false. DNF of P → Q is (¬P) ∨ (P ∧ Q); CNF is (¬P ∨ Q).
Resolution — the one automated rule It applies to CNF only. From (P ∨ Q) and (¬P ∨ R) cancel P and take the resolvent (Q ∨ R). Resolution is sound — it never draws a false conclusion — but not complete on non-CNF input, which is why automated theorem provers convert everything to CNF first.
  1. Write every premise as a clause, i.e. in CNF.
  2. Find two clauses sharing one variable in opposite polarity.
  3. Drop that variable and join the rest — the resolvent; the empty clause □ means the premises contradict.

10Predicate Calculus: Quantifiers

most tested ★
Definition Predicate logic adds variables, predicates and quantifiers to propositional logic, so it can speak about a statement's internal structure. A predicate P(x) is a property of x; the set of values x may take is its domain. A variable is bound if a quantifier covers it and free otherwise: only a bound formula is a proposition.
WordsFormulaRead
For every / there exists∀x P(x)  ·  ∃x P(x)P(x) holds for every x, or for at least one x
Every … some, vs some … every∀x ∃y vs ∃x ∀y P(x, y)the y may depend on x, or one x works for all y
The four quantifier laws ¬∀x P(x) ≡ ∃x ¬P(x) · ¬∃x P(x) ≡ ∀x ¬P(x) · ∀x (P ∧ Q) ≡ (∀x P) ∧ (∀x Q) · ∃x (P ∨ Q) ≡ (∃x P) ∨ (∃x Q) — while ∀x (P ∨ Q) ≢ (∀x P) ∨ (∀x Q) and its dual.
Exam trap (i) "All humans are mortal" is ∀x (Human(x) → Mortal(x)) — with an implication, never ∀x(Human ∧ Mortal), which would absurdly claim every object is human. (ii) "There is a prime greater than 100" is ∃x (Prime(x) ∧ x > 100). (iii) ∀x ∃y ≠ ∃x ∀y — "everyone has a friend" is the first. In SQL, ∀x P(x) is SELECT … WHERE with no GROUP BY, ∃x P(x) is EXISTS, and ∀x ∃y is a correlated subquery returning a different y per row while ∃x ∀y forces one row that works for all.

Exam trap — the classic fallacies Affirming the consequent: P → Q, P ∴ Q — invalid ("if it rains the road is wet" + "the road is wet" does not prove rain). Denying the antecedent: P → Q, ¬P ∴ ¬Q — invalid. Undistributed middle: all A are B, all C are B ∴ all A are C — invalid.
Worked examples ✍ (a) ∀x(H(x) → M(x)) with H(s): UI then modus ponens ⇒ M(s). (b) Premises (P ∨ Q), (¬P ∨ R), (¬R): resolve the last two ⇒ ¬P, with the first ⇒ Q.
