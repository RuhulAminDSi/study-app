1Alphabet, String, Language

MCQ foundation
Definition Language theory studies formal languages: sets of strings built from a fixed finite alphabet. A machine accepts a language if it says "yes" for exactly its strings and "no" for all others. Everything else in this chapter is a machine for deciding one such set.
TermMeaningExample with Σ = {0, 1}
Alphabet Σfinite, non-empty set of symbolsΣ = {0, 1}
String wfinite sequence of symbols; |w| = lengthw = 1010, |w| = 4
εthe empty string, |ε| = 0, ε ∈ Σ*no symbols at all
Σ*all strings over Σ, ε included{ε, 0, 1, 00, 01, 10, 11, …}
Language Lany subset of Σ*L = {w | w ends with 0}
Σⁿstrings of length exactly n; |Σⁿ| = |Σ|ⁿΣ² = {00, 01, 10, 11}

Regular expressions: four operators

OperatorMeansReads as
a + bunion: a or b"plus = or"

(a+b)* = a*b* = (a+b)+ U {e} (a+b)+ = Sigma* \ {e} ab*a = {a, aa, aba, abba, ...}
Memory trick star = zero or more, plus = one or more. So (a+b)* includes ε and (a+b)+ does not.
Exam trap ab*a = an a, then zero or more b's, then an a — so with zero b's the string is aa. And "w contains 01" ≠ "w ends with 01": a finite automaton can remember a suffix, never an arbitrary earlier occurrence.
Operations on languages Languages are sets, so they take set operations: L₁ ∪ L₂, L₁ ∩ L₂, Lᶜ = Σ* − L (always over the same Σ), L₁ · L₂ = {xy | x ∈ L₁, y ∈ L₂} and L* (ε included). Complement is taken over Σ*, never "over the machine": for Σ = {0,1}, the complement of "ends with 0" is "ends with 1 or is empty".
L is any subset of Σ* — including ∅ and Σ*

2Chomsky's Hierarchy: Four Types

high-yield
Definition Chomsky's classification of formal languages into four nested classes, each defined by a kind of grammar and matched by a kind of machine. Type n sits inside Type n−1: every regular language is also context-free, and so on up the ladder.
TypeGrammarAutomatonExample language
Type 0 recursively enumerableunrestrictedTuring machine{w # w | w ∈ {0,1}*}
Type 1 context-sensitivelinear bounded (LBA)LBA{aⁿ bⁿ cⁿ | n ≥ 1}
Type 2 context-freecontext-free (CFG)pushdown automaton{aⁿ bⁿ | n ≥ 0}
Type 3 regularregularfinite automaton{w | w ends with 01}
Machine ↔ language, the one-line answer
FA (DFA / NFA) ⇒ regular = Type 3  ·  PDA ⇒ context-free = Type 2
LBA ⇒ context-sensitive = Type 1  ·  TM ⇒ recursively enumerable = Type 0
Memory trick Read the table upwards: each step adds one kind of memory — none (FA) → stack (PDA) → tape (LBA, TM). More memory ⇒ more languages.
Exam trap {aⁿ bⁿ cⁿ} needs a linear bounded automaton, not a PDA: one stack counts only one balance, so it accepts aⁿbⁿ but never aⁿbⁿcⁿ. Type 0's example needs the "#" to find the middle.
Neighbouring lessons Context-free grammars (productions, derivation trees, parsing) are in the CFL & CFG lesson; Turing machines, configurations and computability in the Turing Machines lesson. Both name the same Type 2 and Type 1 languages that this chapter's automata accept.
IT link The regex engines inside grep, RegExp and lex are finite automata in disguise: the syntax of a language is a regular (Type 3) language, while its grammar is context-free (Type 2) — which is exactly why parsing needs a stack.

3Finite Automaton: the 5-tuple

high-yield
Definition A finite automaton M = (Q, Σ, δ, q₀, F) reads a string left to right, changing state at each symbol, then accepts or rejects. It has no memory beyond its current state — which is why it recognises only regular languages.
PartIsMeaning
Qfinite non-empty set of states, |Q| = nthe boxes in the diagram; q₀ ∈ Q
Σinput alphabet (finite, non-empty)the symbols the tape may carry
δtransition function, δ: Q × Σ → Q (DFA)the arrows: read a symbol, move state
q₀the single start statewhere the head begins
Fset of final / accepting states, F ⊆ Qaccept iff the run ends in F
Memory trick Five parts in order: Questions (states), Σymbols, the δecision rule, the quest0 entry, the Finish states. A PDA adds Γ (stack alphabet) and Z₀ (bottom marker) = 7.

4Deterministic Finite Automaton (DFA)

written favourite
Definition For every pair (state, symbol) there is exactly one next state: δ: Q × Σ → Q is total. No ε-move, no guessing.

L = {w | w ends with 0}

Stateon 0on 1meaning
→ q₀q₁q₀last symbol was 1
* q₁q₁q₀last symbol was 0

over Σ = {0,1}. → start · * accepting. 1100: q₀ -1→ q₀ -1→ q₀ -0→ q₁ -0→ q₁ ∈ F ⇒ accept. 1111: ends in q₀ ∉ F ⇒ reject.

Accept / reject, formally Extend δ to strings: δ*(q₀, w) = the state reached after the whole w is read, so w ∈ L ⇔ δ*(q₀, w) ∈ F. A missing move means rejection — which is why a blank cell needs a trap state.
Exam trap A DFA has exactly one transition per (state, symbol); "zero or more" and ε-moves belong to an NFA. A blank cell means an incomplete machine — add the trap state d.
Memory trick Input 1 separates q₀ from q₁, so this 2-state DFA is already minimal.

5Nondeterministic Finite Automaton (NFA)

high-yield
Definition For a (state, symbol) pair an NFA may have zero, one or many next states — δ: Q × (Σ ∪ {ε}) → P(Q) — and it may take an ε-move: change state without consuming input. It accepts if some path reaches a final state when the input runs out.

L = {w | w contains 01}

Fromon 0on 1
→ q₀q₀ and q₁q₀
q₁—q₂
* q₂q₂q₂

q₀ guesses "a 0 may have just arrived"; a following 1 confirms it and q₂ keeps that memory for good. 0110: q₀ -0→ {q₀,q₁} -1→ {q₀,q₂} -1→ {q₀,q₂} -0→ {q₀,q₂} ∋ q₂ ⇒ accept. 110: q₀ -1→ q₀ -1→ q₀ -0→ {q₀,q₁} ⇒ reject.

When an ε-move really helps: L = {w | w contains ab}

The machine must not commit to the position of "ab", so it runs two branches at once: q₀ keeps scanning with a 0,1 loop, and the ε-move lets a copy jump to q₁, whose only job is to expect the b that confirms the a. An ε-move is the NFA's way of cloning — it costs no input, only a state change.

q0 --a--> q0 q0 --b--> q0 q0 --e--> q1 q1 --b--> q2* q2 --0,1--> q2
Exam trap "zero or more transitions" and "ε allowed" are NFA features. An NFA with no ε-move and one move per pair is a DFA written differently — which is the whole content of the next sheet.
Worked trace ✍ the ε-NFA on "aab" start {q₀} → a: q₀ -a-> q₀ plus the ε-copy q₁ ⇒ {q₀, q₁} · a: only q₀ has an a-move ⇒ {q₀, q₁} · b: q₀ -b-> q₀ and q₁ -b-> q₂ ⇒ {q₀, q₂} ∋ q₂ ⇒ accept. A branch with no defined move simply dies — the "zero transitions" case.
How an NFA is really run Carry a set of states, never a single one: start with {q₀}; on each symbol a, replace the set by the union of the successors of every member; accept iff the final set meets F. That is why the trace above reads {q₀,q₁} then {q₀,q₂} — and it is exactly the object the next sheet turns into a DFA state.

6Equivalence of DFA and NFA

written favourite
Theorem (high-yield) DFA and NFA have exactly the same expressive power: both accept exactly the regular languages. So DFA → NFA is trivial (an NFA may have one move per pair, so a DFA already is an NFA), NFA → DFA is always possible, an NFA can be exponentially smaller, and a DFA runs faster because there is no guessing to backtrack.
Proof sketch (both directions) DFA ⇒ NFA: keep the same states and arrows — the NFA definition already allows zero or one move per pair. NFA ⇒ DFA: let one DFA state stand for the whole set of NFA states the NFA could occupy after the same prefix; then w is accepted iff that set holds an accepting state. ∎

Subset (powerset) construction

  1. One DFA state = a set of NFA states; start with ε-closure(q₀) = q₀ plus every state reachable by ε-moves alone
  2. next = ε-closure(move(S, a)) — the union of the successors of every member of S; a set accepts if it contains an accepting NFA state, and the empty set ∅ is the dead state
Size bound An n-state NFA gives at most 2ⁿ DFA states (2ⁿ subsets), and the bound is tight — some languages force every subset to appear.
Exam trap {q₀, q₂} and {q₀, q₁, q₂} in the table below have identical moves, so they merge: the minimal DFA has 3 states, not 4.
Worked conversion ✍ the "contains 01" NFA:
DFA state = a seton 0on 1accepting?

{q₀, q₁}{q₀, q₁}{q₀, q₂}no

Trace 0101: {q₀} -0→ {q₀,q₁} -1→ {q₀,q₂} -0→ {q₀,q₁,q₂} -1→ {q₀,q₂} ⇒ accept (four sets, far below 2ⁿ = 16).
IT link grep -E builds an NFA, simulates all its states at once (Thompson), then converts it to a DFA table: cheap description, fast machine.
Memory trick NFA = "maybe, at once"; DFA = "exactly this one". Count the tuple to name the machine: 5 = FA, 7 = PDA.

7Minimisation & the Pumping Lemma

high-yield

Minimising a DFA (table filling)

  1. Drop unreachable states (no path from q₀)
  2. Mark every (accepting, non-accepting) pair, then repeat: mark (p, q) if some symbol sends them to a marked pair
  3. Unmarked pairs are indistinguishable ⇒ merge, then rebuild the table; the answer is unique up to renaming

Pumping lemma (regular languages)

If L is regular then some length p exists such that every w ∈ L with |w| ≥ p splits as w = xyz with |xy| < p, |y| > 0 and xyⁿz ∈ L for every n ≥ 0. Its only use is the contrapositive: find one w that fails to pump ⇒ L is not regular.

Exam trap Satisfying the lemma does not prove regularity — some non-regular languages also satisfy it. "Prove it is regular" is not a pumping-lemma question.
Language over {a,b}Regular?Machine / states

even number of a'syesDFA, 2 states (parity)
w ends in abyesDFA, 3 states
{aⁿ bⁿ | n ≥ 0}noPDA needed
{w | #a = #b}noPDA needed
{aⁿ bⁿ cⁿ | n ≥ 1}nonot even CF — LBA / TM
Worked example ✍ binary divisible by 5

Read a binary number MSB first; accept when its value ≡ 0 (mod 5), with ε counting as the value 0. Use one state per remainder r ∈ {0,1,2,3,4} and move r → (2r + b) mod 5: r = 0: 0→0, 1→1 · r = 1: 0→2, 1→3 · r = 2: 0→4, 1→0 · r = 3: 0→1, 1→2 · r = 4: 0→3, 1→4. State 0 is both the start and the only accepting state.

Trace 1111 (= 15): 0 -1→ 1 -1→ 3 -1→ 2 -1→ 0 ⇒ accept, since 15 mod 5 = 0.

5 states, and minimal: 2 is invertible mod 5, so powers of 2 reach every non-zero residue and any two different remainders can be separated by some suffix of 1s.

8Pushdown Automaton (PDA)

high-yield
Definition A pushdown automaton is a finite automaton plus a stack (LIFO memory) — M = (Q, Σ, Γ, δ, q₀, Z₀, F). Each move reads at most one input symbol and one stack symbol, then pushes or pops. One stack remembers one unbounded count, so a PDA accepts exactly the context-free languages.
PartMeaning
Q, Σ, q₀, Fexactly as in the FA 5-tuple: states, input alphabet, start state, final states
Γ  (new)the stack alphabet: what may sit in the stack
Z₀  (new)bottom marker, Z₀ ∈ Γ; the stack begins as Z₀ and is "bare" when only Z₀ is left
δδ: Q × (Σ ∪ {ε}) × Γ → P(Q × Γ*) — read a symbol (or ε) and a stack top, then replace the top by a string

L = {aⁿ bⁿ | n ≥ 0}, with Σ = {a, b} and Γ = {A, Z₀}

stateinputtopreplaces toprole
q₀aZ₀A Z₀push for the first a
q₀aAA Apush for every further a
q₀ → q₁bAεfirst pop — now counting down
q₁bAεkeep popping
q₁εAεinput over and stack bare ⇒ accept
q₀ → q₂εZ₀Z₀n = 0: also accept the empty input
input: a a a b b b stack: Z0 -> AZ0 -> AAZ0 -> AAAZ0 -> AAZ0 -> AZ0 -> Z0 (q2, accept)
Exam trap The five moves above, on their own, reject the empty string — from q₀ with a bare stack there is no ε-move, yet the language reads {aⁿbⁿ | n ≥ 0}. So add δ(q₀, ε, Z₀) → (q₂, Z₀), as in the last row, or accept by empty stack. n ≥ 0 in the statement and no ε-move out of q₀ cannot both be true.
Memory trick Push on the a's, pop on the b's, accept only when the stack is bare. "Pushes must equal pops."
Common misconception A deterministic PDA does not match a nondeterministic one — the opposite of DFA vs NFA: {aⁿbⁿ}, {w c wᴿ} are deterministic, {w wᴿ} needs an NPDA.

The ladder of power

Finite automaton ⊂ pushdown automaton ⊂ linear bounded automaton ⊂ Turing machine. Every step up adds memory and accepts strictly more: no PDA accepts a non-context-free language, no FA accepts aⁿbⁿ.

Memory trick "**FA** = **f**ixation (one state), **PDA** = **p**ile (a stack), **TM** = **t**ape (unbounded, read and write)."
IT link A text editor matches brackets with a stack — the PDA of sheet 8. Whether a while/if nests correctly is not a finite-automaton property.
Exam trap The inequality students forget: DPDA ≠ NPDA, while DFA = NFA. Both statements appear in the same paper.
