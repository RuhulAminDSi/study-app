1Routing: the Big Picture

MCQ + Written
Definition A routing algorithm is the network-layer (layer 3) software that decides on which output line an incoming packet should be sent. Routing = building the routing table (control plane); forwarding = looking up each packet in that table and sending it out (data plane).
Optimality principle If J is on the optimal path from I to K, the optimal path from J to K follows the same route. So all optimal routes to one destination form a tree: the sink tree (no loops).
Static (non-adaptive)Dynamic (adaptive)
Routes set byadministrator, by handprotocol exchanges between routers
On failure · overhead · useno reaction · none · small/stub networksre-routes itself · bandwidth, CPU · large networks

Metrics: hop count (RIP) · bandwidth · delay · load · reliability · MTU · cost (OSPF) · AS path / policy (BGP). Lower metric = better route.

Memory trick "RIP counts hops, OSPF counts cost, BGP counts ASes (and obeys policy)".
Exam trap Metric compares routes within one protocol; administrative distance (AD, trustworthiness) chooses between protocols, lower wins. Cisco AD: connected 0 · static 1 · eBGP 20 · EIGRP 90 · OSPF 110 · IS-IS 115 · RIP 120 · iBGP 200. So an OSPF route beats a RIP route whatever the hop count.

2Flooding

A static algorithm: send every packet out on every line except the one it arrived on. Robust, and always finds the shortest path (every path is tried), but floods the network with duplicates. Damp it with a hop counter (start at the diameter), sequence numbers (drop copies already seen) or selective flooding. Used to distribute link-state packets.

3Link State Routing & Dijkstra

high-yield
Idea Every router learns the complete topology map and runs Dijkstra's algorithm (SPF) on it itself: "routing by map".
  1. Discover neighbours (HELLO) · measure the cost to each · build a link state packet (LSP/LSA: ID, sequence no., age, neighbours + costs)
  2. Flood the LSP to all routers · run Dijkstra on the full map → shortest-path tree → routing table

Worked example: shortest paths from A

StepPermanent setBCDE
0{A}2,A∞9,A∞
1{A,B}✓4,B9,A9,B
2{A,B,C}✓✓5,C8,C
3{A,B,C,D}✓✓✓6,D

"4,B" = distance 4 via previous node B. Each step makes the smallest tentative node permanent and relaxes its neighbours. Every route from A leaves via next hop B; A→E = A-B-C-D-E, cost 6 (not the direct-looking A-D-E = 10).

Memory trick OSPF in numbers: "89 · 110 · area 0 · 5/6 · 10/40" = protocol, AD, backbone, multicast ends, hello/dead.

IS-IS: OSI link-state twin, runs over layer 2, not IP. Dijkstra: O(N²).

Exam trap Dijkstra fails with negative edge costs; Bellman-Ford handles them (but not negative cycles).

4Hierarchical Routing

Routers are grouped into regions (areas, ASes); a router keeps every router of its own region but only one entry per other region. Smaller tables, slightly longer paths. Optimum: ln N levels, e·ln N entries.

Worked example ✍ 720 routers. Flat: 720 entries. 24 regions × 30 routers: 30 + 23 = 53. 8 clusters × 9 regions × 10 routers: 10 + 8 + 7 = 25.

5Distance Vector Routing & Bellman-Ford

high-yield
Idea Each router keeps the best known distance (and line) to every destination and swaps this vector only with its neighbours, periodically. "Routing by rumour"; ARPANET until 1979, then RIP.
Bellman-Ford equation  Dx(y) = minv { c(x, v) + Dv(y) }  over all neighbours v of x

7BGP: Routing Between Autonomous Systems

MCQ
  • Path vector protocol; BGP-4 is the Internet's inter-domain (EGP) protocol
  • runs over TCP port 179; eBGP between ASes, iBGP inside one
  • a route carries its full AS_PATH; a router rejects a path that holds its own AS → no loops
  • chooses by policy (LOCAL_PREF, AS_PATH length, MED), not by cost · messages: OPEN, UPDATE, KEEPALIVE, NOTIFICATION

8Broadcast & Multicast Routing

Broadcast: separate copies (wasteful) · flooding · multidestination · spanning tree (optimal) · reverse path forwarding (RPF): forward a copy only if it arrived on the line this router uses to reach the source. Multicast (224.0.0.0/4, IGMP): source-based trees (DVMRP, PIM-DM) or shared core-based trees (CBT, PIM-SM).

9Congestion & Its Control

high-yield
Definition Congestion: too many packets in (part of) the network, so delay rises and throughput falls. Congestion control is global (the whole network); flow control is point-to-point (fast sender, slow receiver).

Causes: bursty input converging on one line, slow routers, too few buffers, low-bandwidth lines.

Infinite buffers make it worse: packets queue so long they time out and are retransmitted, adding load. Past capacity output can fall towards 0: congestion collapse.

5
Networking · Routing & WANCongestion control
Open loop (prevention)Closed loop (feedback, reaction)
Ideagood design so congestion never startsmonitor, signal, then adjust
Toolsprovisioning, admission control, traffic shaping (buckets), retransmission/ACK/discard policieschoke packets, back-pressure, ECN, RED, TCP's AIMD window (transport notes)
  • Admission control: in virtual-circuit networks, refuse a new VC that would congest the network (the telephone "busy" tone).
  • Choke packet: a congested router sends a packet back to the source, which cuts its rate (e.g. by half). Hop-by-hop back-pressure: the choke takes effect at every router it passes, so relief is immediate. (ICMP Source Quench is now deprecated.)
  • ECN: the router marks 2 bits in the IP header instead of dropping; the receiver echoes it (TCP ECE flag), the sender slows down.
  • Load shedding: drop packets. Wine (old is better: file transfer, drop the new) vs milk (new is better: real-time media, drop the old).

RED (Random Early Detection, Floyd & Jacobson 1993): the router tracks the average queue length. Below minth: no drop; between thresholds: drop with probability rising to maxp; above maxth: drop all. Dropping early and at random slows a few TCP senders and avoids tail-drop's global synchronisation.

Exam trap Congestion control ≠ flow control: a fast PC sending to a slow printer on an idle link is a flow-control problem; many hosts on one overloaded link is congestion.

10Traffic Shaping: Leaky & Token Bucket

written favourite
Traffic shaping regulating the rate and burstiness of the traffic a host sends, as agreed with the network (open loop). Policing = the network checking it and dropping or marking the excess.

Burst length Full bucket C bytes, token rate ρ, maximum output rate M. During a burst of S seconds: C + ρS = MS ⇒ S = C / (M − ρ)
Example 1 ✍ C = 250 KB, M = 25 MB/s, ρ = 2 MB/s: S = 250 KB / 23 MB/s ≈ 11 ms at full speed, then 2 MB/s.
Example 2 ✍ 1 MB burst (25 MB/s for 40 ms) into a leaky bucket, output 2 MB/s: output lasts 500 ms; bucket must hold ≈ 0.92 MB.
Memory trick Leaky = a dripping tap: always the same drip. Token = a savings account: save while idle, spend in a burst, never more than the balance C.

Worked example ✍ A router with 2 interfaces: one to a 24-port switch with 20 PCs, one to a hub with 6 PCs. Collision domains: 20 + 1 (switch–router link) + 1 (whole hub side) = 22. Broadcast domains: 2 (one per router interface).
Exam trap A switch breaks collision domains but not broadcast domains; only a router (or VLANs) splits broadcast domains. A hub is a layer-1 device even though it has many ports.

Tunnelling

To cross a network of a different type, the whole packet travels as the payload of the foreign network's packet between two multiprotocol routers. Examples: IPv6-in-IPv4 (protocol 41), GRE (protocol 47), IPsec VPN.

Delay formulas message x bits, k hops, bit rate b, propagation d per hop, setup s, packet p bits (headers ignored): circuit T = s + x/b + k·d · packet T = x/b + (k − 1)·p/b + k·d. Packet switching wins when s > (k − 1)·p/b.
Example ✍ x = 10⁶ bits, b = 1 Mbps, k = 4, d = 5 ms, s = 200 ms, p = 10 000 bits: circuit 0.2 + 1 + 0.02 = 1.22 s; packet 1 + 3 × 0.01 + 0.02 = 1.05 s.
Exam trap A virtual circuit is packet switching (links are shared), not circuit switching; it only fixes the route at setup.

ATM: 48 bytes was a compromise (USA wanted 64, Europe 32). UNI header: GFC 4, VPI 8, VCI 16, PT 3, CLP 1, HEC 8 bits. The ATM network layer and AAL are in their own notes.

MPLS ("layer 2.5", RFC 3031): the ingress LER classifies a packet into a FEC and pushes a label; core LSRs swap labels (exact match, fast); the egress pops it. The path is an LSP. Carriers use it for traffic engineering, QoS and L3 VPNs; it carries any protocol.

Memory trick X.25 checks every hop, Frame Relay checks none, ATM chops everything into 53. Frame Relay = "X.25 with the error control thrown out, because fibre is clean".
Exam trap ATM's HEC protects only the 5-byte header, not the payload. Frame Relay does detect errors (FCS) but never corrects them: it discards the frame.

Example 2: the 8-byte trap ✍ MTU 1000, datagram 2400 B. 1000 − 20 = 980, not a multiple of 8 → use 976. Data 2380 = 976 + 976 + 428; offsets 0, 122, 244.
Example 3: read a fragment ✍ offset 100, HLEN 5, total length 100 → first data byte = 100 × 8 = 800, data = 80 B, last byte 879.
  • MF = 1, offset = 0 → first fragment · MF = 0, offset ≠ 0 → last · MF = 0, offset = 0 → not fragmented
  • One fragment lost → the whole datagram is discarded (reassembly timer)
  • Path MTU discovery: send with DF = 1; a router that cannot forward drops it and returns ICMP type 3 code 4 "fragmentation needed" with the next-hop MTU
  • IPv6: routers never fragment; only the source (Fragment header, 8 B, next header 44); too big → ICMPv6 "Packet Too Big"
Memory trick "Offset × 8 = byte position": 2¹³ offsets × 8 bytes = 2¹⁶, which covers the 65 535-byte datagram.

Written question Explain the count-to-infinity problem of distance vector routing with an example, and describe two techniques that reduce it. 8 marks
  1. DV routers know only neighbours' distances (Bellman-Ford), so they cannot tell whether a neighbour's route passes back through themselves 1
  2. Chain A–B–C, costs 1. B: A = 1; C: A = 2 (via B). Link A–B fails 1
  3. B hears C's "A = 2", sets A = 3 via C; C then sets A = 4 via B; they count up 5, 6, … to ∞ (16 in RIP), with a routing loop the whole time 3
  4. Split horizon: C does not advertise A back to B, the line it learned it from; poison reverse: it advertises A = ∞ to B 2
  5. Also hold-down timers and triggered updates; none fully solves loops of 3+ routers, which is why link state is preferred 1
