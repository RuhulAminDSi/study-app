1The Transport Layer

MCQ + Written
Definition Layer 4 (OSI) gives process-to-process (end-to-end) delivery; the network layer (IP) gives only host-to-host delivery. Services: multiplexing/demultiplexing by port, segmentation and reassembly, and (in TCP) reliability, ordering, flow control and congestion control. It runs only in the end hosts, never in routers.

Port = 16-bit number → 0–65,535

  • Well-known 0–1023 (servers)
  • Registered 1024–49,151
  • Dynamic / ephemeral 49,152–65,535 (clients)

Socket = IP address + port. A TCP connection is identified by the 4-tuple (src IP, src port, dst IP, dst port).

PDU: TCP segment · UDP datagram. IP protocol no. TCP = 6, UDP = 17

2TCP Segment Header

high-yield
  • HLEN counts 32-bit words: 5 → 20 B, 15 → 60 B
  • Seq no. numbers bytes; the ISN is random
  • Ack no. = next byte expected (cumulative)
  • Window = receiver's free buffer, ≤ 65,535 B unless scaled
  • Checksum: mandatory, covers a pseudo-header
Memory trick: flags "Unskilled Attackers Pester Real Security Folks" = URG ACK PSH RST SYN FIN, in header order.
Exam trap HLEN = 8 means 8 × 4 = 32 bytes of header, not 8.

Networking · Transport & CryptoConnection management

3TCP Connection Management

high-yield
3-way handshake both sides choose and confirm their initial sequence numbers. SYN and FIN each consume one sequence number; a pure ACK consumes none.
4-way close TCP is full duplex, so each direction is closed separately (FIN + ACK each way). Server ACK and FIN may be combined → 3 segments.
States TCP has 11 states. The active closer waits in TIME_WAIT for 2 MSL so a lost final ACK can be resent and old duplicates die out.
StateMeaningStateMeaning
LISTENserver waits for a SYN (passive open)CLOSE_WAITgot peer's FIN; app not closed yet
SYN_SENTclient sent SYN (active open)LAST_ACKsent own FIN, awaits its ACK
SYN_RCVDhalf-open: SYN+ACK sentCLOSINGboth sides sent FIN at once

Why three segments, not two? Each side must have its own ISN acknowledged; a two-way exchange would let an old, delayed SYN open a ghost connection.

Worked example ✍ Client ISN = 1000, server ISN = 5000. ① SYN seq = 1000 ② SYN+ACK seq = 5000, ack = 1001 ③ ACK seq = 1001, ack = 5001. Client now sends 400 bytes: seq = 1001 (bytes 1001–1400); server replies ack = 1401.
Exam trap RST aborts a connection at once (no 4-way exchange). SYN flood: the attacker never sends the final ACK, filling the server's half-open (SYN_RCVD) queue; defence = SYN cookies.
Memory trick Open = "knock, knock-back, enter". Close = two goodbyes and two nods. Whoever says goodbye first waits at the door (TIME_WAIT).

4Flow Control: the Sliding Window

MCQ + Written
Idea The receiver advertises rwnd (free buffer) in every segment; the sender keeps unacknowledged bytes ≤ window. Effective window = min(rwnd, cwnd): flow control protects the receiver, congestion control protects the network.
Worked example ✍ Max throughput ≈ window / RTT. Window 65,535 B, RTT 100 ms → 65,535 × 8 / 0.1 ≈ 5.24 Mbps, whatever the link speed. That is why the window-scale option (shift up to 14, window up to 230 B ≈ 1 GB) exists for long fat networks.

Transmission policy (efficiency)

Delayed ACKwait (≤ 500 ms, typically 200 ms) to piggyback or combine ACKs
Zero windowsender stops; probes with the persist timer

5TCP Timer Management

  • Retransmission (RTO): resend if no ACK in time
  • Persist: breaks the zero-window deadlock with window probes
  • Keepalive: checks an idle peer (default 2 hours)
  • TIME_WAIT: 2 × MSL after an active close
RTO: Jacobson / Karn
SRTT = ⅞ SRTT + ⅛ R
RTTVAR = ¾ RTTVAR + ¼ |SRTT − R|
RTO = SRTT + 4 × RTTVAR
Karn: no RTT sample from a retransmitted segment; double RTO on every timeout
Worked example ✍ SRTT = 100 ms, RTTVAR = 20 ms, new sample R = 120 ms. RTTVAR = 15 + ¼(20) = 20 ms; SRTT = 87.5 + 15 = 102.5 ms; RTO = 102.5 + 80 = 182.5 ms (RFC 6298 then applies a 1 s floor).

6TCP Congestion Control

high-yield
Idea The sender keeps a congestion window (cwnd), counted in MSS, and a threshold ssthresh. Loss is taken as the sign of congestion. Overall rule: AIMD: additive increase, multiplicative decrease.

7UDP: User Datagram Protocol

MCQ favourite
Definition UDP (RFC 768, 1980) is a connectionless, unreliable transport: no handshake, no ACKs, no retransmission, no ordering, no flow or congestion control. It adds only ports and a checksum to IP, and preserves message boundaries.
  • Header fixed at 8 bytes (TCP: 20–60)
  • Length = header + data, minimum 8
  • Checksum optional in IPv4 (0 = unused), mandatory in IPv6
  • Max payload over IPv4: 65,535 − 20 − 8 = 65,507 B
  • Only UDP supports broadcast and multicast

Used by: DNS queries, DHCP, TFTP, SNMP, RIP (520), NTP (123), VoIP/RTP, live streaming, online games, and QUIC (HTTP/3 over UDP 443).

Other transport protocols

SCTP reliable and message-oriented, with multi-streaming and multi-homing; 4-way handshake (INIT, INIT-ACK, COOKIE-ECHO, COOKIE-ACK); used for telecom signalling (SIGTRAN).
DCCP unreliable datagrams with congestion control, for streaming media. RTP runs over UDP and adds timestamps and sequence numbers for real-time audio/video.
Exam trap "UDP is unreliable" means it gives no delivery guarantee, not that it corrupts data: the checksum still detects errors. DNS uses TCP 53 for zone transfers and large replies.

9ATM Adaptation Layer (AAL)

MCQ
Role An ATM cell is 53 bytes (5 header + 48 payload). The AAL, above the ATM layer, adapts upper-layer data to cells through two sublayers: CS (convergence) and SAR (segmentation and reassembly).
AALClassTrafficPayload / cellTypical use
AAL1ACBR, timed47 Bcircuit emulation, voice
AAL2BVBR, timedmini-packetscompressed voice/video
AAL3/4C, Ddata (conn. / connless)44 BSMDS, legacy data

Worked example ✍ 1500-byte IP packet over AAL5: 1500 + 8 = 1508 → ⌈1508/48⌉ = 32 cells (pad 28 B). On the wire 32 × 53 = 1696 B, efficiency 1500/1696 ≈ 88.4%. Trailer: UU, CPI, length, CRC-32; the PTI bit marks the last cell.
Memory trick "1 = Constant, 2 = Variable, 3/4 = old data, 5 = the data workhorse." Class letters A → D follow the AAL numbers.

Networking · Transport & CryptoSymmetric ciphers

11Classical Ciphers

Substitution ✍ replace each letter. Caesar (shift 3): ATTACK → DWWDFN. Monoalphabetic: 26! keys, but broken by letter frequency. Polyalphabetic: Vigenère, Playfair. One-time pad: perfect secrecy.
Transposition ✍ reorder the letters. Rail fence (2 rails): ATTACKATDAWN → row 1 ATCADW + row 2 TAKTAN = ATCADWTAKTAN. Letter frequencies stay unchanged.

Shannon: a strong cipher needs confusion (substitution, S-boxes) and diffusion (permutation, P-boxes). Block ciphers (DES, AES) encrypt fixed blocks; stream ciphers (RC4, ChaCha20) encrypt bit by bit or byte by byte.

12DES and Triple DES

high-yield
  • IBM (from Lucifer), FIPS 46, 1977
  • Block 64 bits; key 64 bits, 56 effective (8 parity)
  • 16 Feistel rounds, 48-bit round keys; IP … IP⁻¹
  • f: expand 32 → 48, XOR key, 8 S-boxes (6 → 4 bits), P-box
  • S-boxes = the only non-linear part
  • Brute-forced: EFF "Deep Crack", 1998 (56 h)
3DES (EDE) C = EK3(DK2(EK1(P))). 3 keys: 168-bit key, ≈ 112-bit strength; 2 keys (K1 = K3): 112-bit key. K1 = K2 = K3 → single DES. Double DES ≈ 57 bits only (meet-in-the-middle).

13IDEA and AES

IDEA: Lai & Massey (ETH Zürich). AES: Rijndael (Daemen & Rijmen), FIPS 197; each round = SubBytes, ShiftRows, MixColumns, AddRoundKey.

14Public-Key Cryptography

high-yield
Idea Each user has a public key (published) and a private key (secret). For confidentiality: encrypt with the receiver's public key, decrypt with the receiver's private key. Security rests on a hard problem: factoring (RSA) or the discrete logarithm (Diffie–Hellman, ElGamal, ECC). Diffie–Hellman (1976) came first, RSA (1977) next.

RSA (Rivest, Shamir, Adleman, 1977)

  1. Choose primes p, q; n = p × q
  2. φ(n) = (p − 1)(q − 1)
  3. Choose e with 1 < e < φ(n), gcd(e, φ(n)) = 1
  4. d = e⁻¹ mod φ(n), i.e. e · d ≡ 1 (mod φ(n))
  5. Public key (e, n) · private key (d, n)
  6. Encrypt C = Me mod n · decrypt M = Cd mod n
Worked example ✍ p = 3, q = 11 → n = 33, φ = 2 × 10 = 20.
e = 7 (gcd(7, 20) = 1). 7d ≡ 1 (mod 20): 7 × 3 = 21 = 20 + 1 → d = 3.
M = 2: C = 27 mod 33 = 128 − 99 = 29.
Check: 293 mod 33; 29 ≡ −4, (−4)3 = −64 ≡ −64 + 66 = 2 ✓

Real keys: n of 2048 bits or more. RSA is slow, so it is used to exchange a session key or to sign (see the Authentication & Digital Signatures lesson), while AES encrypts the bulk data: the hybrid scheme used by TLS and PGP.

Diffie–Hellman key exchange

Check the arithmetic ✍ 5⁴ = 625 = 27 × 23 + 4 → A = 4. 5³ = 125 = 5 × 23 + 10 → B = 10. Alice: 10² = 100 ≡ 8, 8² = 64 ≡ 18. Bob: 4³ = 64 ≡ 18 ✓
Exam trap Plain Diffie–Hellman agrees on a key; it does not encrypt and has no authentication, so it falls to a man-in-the-middle attack. A and B are public values, not the key.
Memory trick RSA: "Public Encrypts, Private Decrypts" for secrecy. ECC: 256-bit ECC ≈ 3072-bit RSA ≈ AES-128 strength, so much smaller keys.
