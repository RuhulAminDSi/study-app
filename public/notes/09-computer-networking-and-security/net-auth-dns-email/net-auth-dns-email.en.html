1What Authentication Means

MCQ + Written
Definition Authentication proves that a user, device or process is who it claims to be; authorization decides what it may do; accounting logs it. Together: AAA.
FactorExamples
Something you knowpassword, PIN, security question
Something you haveOTP token, phone (SMS/app), smart card
Something you arefingerprint, iris, face, voice
Exam trap Password + PIN is not two-factor: both are "something you know". MFA needs factors of different types (password + OTP from a phone).

2Passwords & One-Time Passwords

  • Store a salted hash H(salt ∥ password), never the password; a per-user salt defeats rainbow tables. Slow hashes (bcrypt, PBKDF2, Argon2) slow down dictionary attacks.
  • OTP: HOTP (counter) and TOTP (a new code every 30 s); a captured OTP is useless later, so OTPs defeat replay.

3Challenge–Response (Shared Secret Key)

Bob sends a fresh random nonce ("number used once"); only a holder of KAB can return it encrypted. ④–⑤ repeat it the other way: mutual authentication. The key never crosses the network.

Exam trap: reflection attack The 3-message shortcut lets Trudy open a second session and make Bob encrypt his own challenge for her. Fix: the initiator proves itself first; separate keys per direction.
Memory trick "Fresh question, secret answer": nonce = no replay, key = proof.
AAA servers RADIUS UDP 1812 · TACACS+ TCP 49 · EAP/802.1X Wi-Fi

4Key Distribution Centre & Needham–Schroeder

high-yield
KDC A trusted server that shares one secret key with every user (KA, KB …). With N users, N keys are enough instead of N(N − 1)/2 pairwise keys. The KDC hands out a fresh session key KS for each conversation.

② proves the reply is fresh (it holds RA) and gives A the ticket, which only B can open. ④–⑤ convince each side that the other holds KS.

Exam trap: the flaw Message ③ has no freshness. If an old KS ever leaks, Trudy can replay the old ticket and pose as A (Denning–Sacco, 1981). Fixes: timestamps (Kerberos) or the Otway–Rees protocol.

5Kerberos

written favourite

From MIT Project Athena; v5 (RFC 4120) is the login of Windows Active Directory. Symmetric keys, port 88, single sign-on: one password, tickets for every service.

  1. C → AS: user name (no password sent)
  2. AS → C: KC(KS, TGT); KC is derived from the password, so only the real user can open it
  3. C → TGS: TGT + KS(timestamp) + "I want V"
  4. TGS → C: KS(KCV) + service ticket KV(C, KCV)
  5. C → V: service ticket + KCV(timestamp)
  6. V → C: KCV(timestamp + 1): mutual authentication
Memory trick "AS lets you in, TGS gives tickets." TGT = a cinema wristband; each service ticket = a seat for one film. The wristband (TGT) lasts the day (≈ 10 h).
Exam trap Kerberos needs synchronised clocks (default skew ≤ 5 min) because it uses timestamps against replay. The KDC is a single point of failure; it does not use public-key cryptography in its basic form.

6Cryptographic Hash Functions (Message Digests)

high-yield
Definition A hash function H maps a message of any length to a fixed-length digest. It uses no key, is fast to compute, and changing one input bit changes about half the output bits (avalanche effect).
  1. Pre-image resistance (one-way): from H(m), finding m is infeasible
  2. Second pre-image resistance: given m, finding m′ ≠ m with H(m′) = H(m) is infeasible
  3. Collision resistance: finding any pair m ≠ m′ with equal hashes is infeasible

7Message Authentication Code (MAC) & HMAC

MAC tag = C(K, M) from the message and a shared key; the receiver recomputes it. Proves integrity + origin: without K no valid tag.
HMAC (RFC 2104) H((K ⊕ opad) ∥ H((K ⊕ ipad) ∥ M))
ipad = 0x36…, opad = 0x5C… · HMAC-SHA256 in TLS, IPsec

Exam trap A MAC gives no non-repudiation: Bob knows K too, so he could have made the tag. A hash is not encryption: no key, no reversing.

8Digital Signatures

high-yield
Definition A digital signature is a value computed from a message with the signer's private key that anyone can check with the signer's public key. It gives authentication, integrity and non-repudiation, but not confidentiality.

Requirements: ① the receiver can verify the sender's identity; ② the sender cannot deny it later; ③ the receiver cannot forge or alter it.

Why sign the hash?

  • Public-key operations are slow; a 256-bit digest is tiny
  • The signature size stays fixed whatever the message length
  • The message can stay readable (plain text + signature)
AlgorithmBased on
RSAfactoring; most widely used
DSA (DSS, FIPS 186, 1994)discrete log; NIST, signing only
ECDSA, EdDSAelliptic curves: smaller keys
Worked example: RSA signature ✍ Keys n = 33, e = 3 (public), d = 7 (private), since 3 × 7 = 21 ≡ 1 (mod φ = 20). Digest h = 4.
  1. Sign: s = hd mod n = 47 mod 33 = 16384 mod 33 = 16  33 × 496 = 16368
  2. Verify: se mod n = 163 mod 33 = 4096 mod 33 = 4 = h ✓  33 × 124 = 4092
Exam trap Sign with the sender's private key, verify with the sender's public key. Encrypt for secrecy with the receiver's public key. For both: sign first, then encrypt.
Memory trick "Private signs, public checks." Only you hold your pen (private key); everyone can compare it with your specimen signature (public key).
Without public keys a trusted arbiter ("Big Brother", BB) signs for users who share keys with it, keeping KBB(A, t, P) as proof. Uses: code signing, TLS certificates, S/MIME, PGP, blockchain.

9Why Certificates?

MCQ + Written
The problem A public key on its own says nothing about its owner. Trudy can publish her key under Bob's name (man-in-the-middle). A certificate is a document that binds a name to a public key, digitally signed by a trusted Certification Authority (CA).

PKI = CAs + RAs (check identity) + certificates + directories + revocation. The root CA's certificate is self-signed and pre-installed in browsers and OSs.

Revocation (stolen key): a CRL (revocation list) or a live OCSP check.

PGP uses a web of trust instead: users sign each other's keys.

Bangladesh link ICT Act 2006: digital signatures are legal; the CCA (Controller of Certifying Authorities) licenses CAs.

How a browser checks www.bank.bd ✍
  1. Server sends its certificate + the intermediate's
  2. Check its signature with the intermediate CA's public key, then the intermediate with the root

Memory trick Certificate = passport: subject = holder, key = photo, issuer = government, CA signature = stamp.
Exam trap It holds the subject's public key only, and is signed with the CA's private key.

11Gigabit Ethernet (1000 Mbps)

high-yield
Definition Ethernet at 1 Gbps (10 × Fast Ethernet) with the same frame format (64–1518 bytes), so it works with older Ethernet. Standards: 802.3z (1998, fibre + short copper) and 802.3ab (1999, 1000BASE-T).
NameStandardMediumMax lengthCoding
1000BASE-SX802.3zmultimode fibre, 850 nm220–550 m8B/10B
1000BASE-LX802.3zsingle-mode fibre, 1310 nm5 km8B/10B
1000BASE-CX802.3zshielded twinax copper25 m8B/10B
1000BASE-T802.3abCat 5e UTP, all 4 pairs100 mPAM-5

8B/10B → line rate 1.25 Gbaud. 1000BASE-T: 4 pairs × 250 Mbps, each pair both ways (echo cancellation). LX also runs 550 m on multimode.

Half duplex: carrier extension & frame bursting

At 1 Gbps a 64-byte frame lasts 0.512 µs, so CSMA/CD would limit the network to about 25 m. Two fixes, half-duplex only:

Carrier extension pad every short frame so it fills at least 512 bytes (4096 bit times) → about 200 m. Cost: a 64-byte frame is only 1/8 useful.
Frame bursting after one extended frame, send several short frames back to back without releasing the line, up to 8192 bytes.
Exam trap Real Gigabit links are full duplex through switches: no collisions, no extension. The minimum frame stays 64 bytes; only the minimum slot grows to 512 bytes.

13Domain Name System (DNS)

high-yield
Definition A hierarchical, distributed database mapping names to IP addresses, mail servers and aliases (Mockapetris; RFC 1034/1035, 1987). Port 53: UDP for queries, TCP for zone transfers and replies over 512 bytes.

Zone = the part of the tree one organisation runs: a primary server plus secondaries that copy it by zone transfer (AXFR, TCP). Label ≤ 63 chars, name ≤ 255 bytes.

Recursive vs iterative resolution

Recursive: the server does the whole job and returns the final answer (host → resolver). Iterative: the server returns a referral and the asker continues (resolver → root → TLD → authoritative). Caching by TTL means most lookups never reach the root.

Memory trick "Quad-A = four times the A": AAAA holds 128 bits, four times A's 32. MX = Mail eXchange; PTR = poin-T-er back.
Exam trap DNS is not UDP-only: TCP 53 for zone transfers. Cache poisoning plants false records; DNSSEC signs records (integrity), it does not encrypt them.

15MIME: Beyond 7-bit ASCII

RFC 822 mail was 7-bit ASCII only. MIME (RFC 2045–2049) adds headers for Bangla (UTF-8), images, PDFs and multi-part mail:

  • MIME-Version: 1.0
  • Content-Type: text/plain, image/jpeg, application/pdf, multipart/mixed
  • Content-Transfer-Encoding: 7bit, 8bit, base64, quoted-printable
Worked example: base64 ✍ "Man" = 77, 97, 110 = 01001101 01100001 01101110
6-bit groups: 010011 · 010110 · 000101 · 101110 = 19, 22, 5, 46 → TWFu
3 bytes → 4 characters: a 3 MB attachment grows to about 4 MB (+33%).
Memory trick Ports in order of the mail's journey: 25 → 110 → 143 (send, pop it down, keep it on the server). TLS twins: 465, 995, 993.
Anti-spoofing (DNS TXT records) SPF lists the servers allowed to send for a domain · DKIM signs headers with a key published in DNS · DMARC says what to do when they fail.

16Email Privacy: PGP & S/MIME

high-yield

Threats: eavesdropping, tampering, spoofing (forged From:). TLS/STARTTLS protects each hop only; end-to-end privacy needs PGP or S/MIME.

PGP (Phil Zimmermann, 1991; OpenPGP RFC 4880). Originally IDEA (128-bit) for the text, RSA for keys, MD5 digest; today AES, SHA-256, RSA/ECC.

  1. Sign the digest with Alice's private key
  2. Compress (ZIP)
  3. Encrypt with a one-time session key, which goes encrypted with Bob's public key
  4. Radix-64 (base64) for SMTP

Written question Explain with a diagram how Kerberos authenticates a client to a server. How does it give mutual authentication, and why does it need synchronised clocks? 8 marks
  1. AS + TGS = the KDC, which shares a secret key with every user and server; diagram as on sheet 3 1
  2. C → AS: user name. AS → C: KC(KS, TGT); KC comes from the password, which never crosses the network 2
  3. C → TGS: TGT + KS(timestamp) + server name. TGS → C: KS(KCV) + ticket KV(C, KCV) 2

  5. Timestamps stop replay, so clocks must agree within ≈ 5 min 1
