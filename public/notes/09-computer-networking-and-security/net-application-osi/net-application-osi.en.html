1Layers & the OSI Reference Model

high-yield
Protocol hierarchy Network software is split into layers; each layer gives a service to the layer above through an interface and talks to its peer layer on the other host by a protocol. Only layer 1 really moves bits; the others talk to their peers virtually. A layer can change (Wi-Fi ↔ Ethernet) without touching the rest.

OSI = Open Systems Interconnection, by ISO (ISO 7498, 1984; also ITU-T X.200). 7 layers; a reference model: its own protocols never caught on, but its vocabulary is used everywhere.

Memory trick 7 → 1: "All People Seem To Need Data Processing".
1 → 7: "Please Do Not Throw Sausage Pizza Away".
PDU trick L4 → L1: "Some People Fear Birthdays" = Segment, Packet, Frame, Bit.
Exam trap Layers 4–7 are end-to-end: they exist only in the two hosts. A router implements only layers 1–3, a switch 1–2, a hub 1. "Layer 3 device" = router; "Layer 2 device" = switch.

3The TCP/IP (Internet) Model

high-yield
Definition The model the Internet actually runs on, from the US DoD/ARPANET work (Cerf & Kahn, 1974); ARPANET switched to TCP/IP on 1 Jan 1983. RFC 1122 defines 4 layers: Application (HTTP, DNS, SMTP, DHCP, SNMP) · Transport (TCP, UDP) · Internet (IP, ICMP, IGMP) · Link (Ethernet, Wi-Fi, PPP, ARP). Textbooks often use a 5-layer hybrid: Link split into Data Link + Physical.

Layers74 (5 in the hybrid)

Memory trick "3-1-1-2": OSI's top 3 → TCP/IP Application, 1 → Transport, 1 → Internet, bottom 2 → Link. So OSI Network = TCP/IP Internet; "Network Access" = OSI L1 + L2, not L3.

4Encapsulation & Decapsulation

written favourite
Definition Going down, each layer treats what it gets as its payload (SDU) and adds its own header (the data link layer also adds a trailer) to form its PDU. Going up at the receiver, each layer reads and strips its own header: decapsulation.

Worked example ✍ Ethernet MTU = 1500 B (the IP packet). TCP payload per frame = 1500 − 20 − 20 = 1460 B (the usual MSS). Frame = 1460 + 20 + 20 + 14 + 4 = 1518 B → efficiency 1460/1518 ≈ 96.2%.
Exam trap At every router the frame is stripped and a new one built: MAC addresses change each hop, the IP addresses stay the same end to end (unless NAT), and TTL drops by 1. Russian dolls: each layer opens only its own doll.

5What Happens When You Open a URL

written favourite

You type https://www.example.com/index.html. The PC already has its IP, mask, gateway and DNS server from DHCP.

  1. Parse URL: scheme https → port 443; host www.example.com; path /index.html. Check browser and OS caches.
  2. DNS (UDP 53): ask the resolver for the A/AAAA record → the server's IP. (details: DNS notes)
  3. ARP: the server is on another network, so the PC needs the gateway's MAC, not the server's (ARP request = broadcast, reply = unicast).
  4. TCP 3-way handshake to port 443: SYN → SYN-ACK → ACK (1 RTT); the client uses an ephemeral port, e.g. 52814.
  5. TLS handshake: certificate check, key agreement (TLS 1.3: 1 RTT) → session keys.
  6. HTTP GET /index.html (encrypted) → segment → packet → frame → bits.
  7. Routing hop by hop: each router decrements TTL, looks up the destination network, re-frames. tracert / traceroute lists the hops using TTL expiry + ICMP.
  8. Server decapsulates upward, replies 200 OK + HTML; the browser then fetches CSS, JS and images on the same connection.
  9. Close with FIN/ACK, or keep the connection alive for reuse.
Memory trick "D-A-T-T-H": DNS, ARP, TCP, TLS, HTTP: the order of first contact.
Exam trap IP fragments are reassembled by the destination's IP layer; out-of-order segments are reordered by TCP.

6HTTP: HyperText Transfer Protocol

high-yield
Definition Application-layer, client–server, request–response protocol of the Web, over TCP port 80 (HTTPS: 443). It is stateless: the server keeps no memory of earlier requests; cookies (Set-Cookie → Cookie headers) add state for logins and carts.
MethodUseSafeIdem.
GETread✓✓
HEADheaders only✓✓
POSTsubmit/create✗✗
PUTreplace✗✓
PATCHpartial edit✗✗
DELETEremove✗✓
ClassMeaning · examples
1xxinformational · 100, 101
2xxsuccess · 200 OK, 201, 204
3xxredirect · 301, 302, 304
4xxclient error · 401, 403, 404
5xxserver error · 500, 502, 503

Safe = changes nothing on the server; Idem. (idempotent) = repeating it gives the same result. 401 = not authenticated (log in) · 403 = authenticated but forbidden · 301 = moved permanently · 304 = not modified (use cache) · 503 = service unavailable.

Persistent vs non-persistent

Non-persistent (HTTP/1.0 default): a new TCP connection per object, 2 RTT + transfer time each. Persistent (HTTP/1.1 default, keep-alive): one connection serves many objects; pipelining sends requests back to back.

Worked example ✍ 1 HTML + 10 images, ignore transfer time:
non-persistent, serial: 11 × 2 = 22 RTT
persistent, no pipelining: 2 + 10 = 12 RTT
persistent, pipelined: 2 + 1 = 3 RTT
VersionYear · RFCWhat is new
HTTP/1.01996 · 1945headers, status codes; a new connection per object
HTTP/1.11997 · 2068persistent by default, pipelining, Host header required
HTTP/22015 · 7540binary framing, multiplexed streams on one TCP connection, HPACK
HTTP/32022 · 9114over QUIC on UDP; no TCP head-of-line blocking; TLS 1.3 built in
Exam trap HTTPS is not a separate protocol: it is HTTP inside TLS (SSL is its deprecated predecessor) on port 443, giving confidentiality, integrity and server authentication by certificate.

7The World Wide Web

MCQ favourite
Definition A distributed system of hypertext documents linked by URLs, served over HTTP and shown by a browser. Proposed by Tim Berners-Lee at CERN in 1989; first server and browser 1990–91; Mosaic (1993) made it popular; W3C founded 1994. Three pillars: HTML (the page), URL (its address), HTTP (the transfer). Web servers: Apache, Nginx, IIS.

URL anatomy

URL = where a resource is; URN = its name (urn:isbn:…); both are URIs. The default port comes from the scheme (http 80, https 443). The #fragment is never sent to the server.

AspectInternetWorld Wide Web
Whatglobal network of networks (infrastructure)one service running on the Internet
Made ofrouters, links + TCP/IPpages, browsers, servers + HTTP
OriginARPANET, 1969CERN, 1989
Carriesweb, email, FTP, VoIP, SSH …web pages only
Memory trick Internet = the roads; the Web = one kind of traffic on them. Email is another kind on the same roads.
Exam trap Internet ≠ WWW. HTML is a markup language, not a programming language. A static page is the same file for all; a dynamic page is built per request (PHP, Node).

8FTP, Telnet, SSH

FTP TCP, two connections: control on 21 (stays open: "out-of-band" control), data on 20 in active mode (a new connection per file). Passive mode: the server names a port and the client connects (firewall friendly). Plain text. TFTP: UDP 69, no login.
Telnet vs SSH Both give a remote terminal. Telnet: TCP 23, everything, password included, in plain text. SSH: TCP 22, encrypted and authenticated (key or password); also carries SCP/SFTP and tunnels.

9DHCP

DHCP Gives a host its IP, mask, gateway and DNS server automatically for a lease time. UDP: server 67, client 68. Four messages, DORA: Discover (broadcast) → Offer → Request (broadcast) → Ack. A relay agent forwards them across routers. Successor of BOOTP.

Worked example ✍ A firewall must allow a user to browse securely, fetch mail by IMAP over TLS and log in to a router safely. Open: TCP 443 (and UDP 443 for HTTP/3), TCP 993, TCP 22; block Telnet 23 because it sends the password in plain text.

11SNMP: Simple Network Management Protocol

high-yield
Definition Application-layer protocol over UDP to monitor and configure routers, switches, servers, printers and UPSs. A manager polls agents; agents can also report events on their own. The agent listens on UDP 161; the manager receives traps on UDP 162.
  • Manager / NMS: the monitoring station
  • Agent: software inside each managed device
  • MIB (Management Information Base): the agent's database of managed objects, e.g. MIB-II
  • OID: an object's dotted address in a global tree, e.g. sysDescr = 1.3.6.1.2.1.1.1
  • SMI: rules for naming and typing objects, written in ASN.1, encoded with BER
PDU (operation)DirectionPurposeSince

GetNextRequestmanager → agentread the next OID (walk a table)v1
SetRequestmanager → agentchange a value (configure)v1
Responseagent → manageranswer to Get/Set (v1: GetResponse)v1
Trapagent → managerunsolicited alert, not acknowledgedv1
GetBulkRequestmanager → agentmany objects in one requestv2
InformRequestagent → managera notification that is acknowledgedv2
VersionSecurityNotes
SNMPv1 (1990)community string, plain textdefaults "public" (read), "private" (write)
SNMPv2cstill community stringadds GetBulk, Inform, 64-bit counters
SNMPv3USM: authentication + privacy (encryption); VACM access controlthe only secure version
Memory trick "Agent one-six-one listens; manager one-six-two hears the trouble." Polling = the manager asks; a trap = the agent shouts.
Exam trap SNMP runs over UDP, not TCP. Encryption arrives only in v3; the "c" in v2c means community.
IT link v3 security levels: noAuthNoPriv · authNoPriv · authPriv (authenticated and encrypted). Reading a router's name from a Linux shell: snmpget -v2c -c public 10.0.0.1 1.3.6.1.2.1.1.5.0 (sysName); snmpwalk repeats GetNext down the tree.

Written question With a diagram, explain how data is encapsulated as it moves down the OSI layers when a browser requests a web page, naming the PDU and the header added at each layer. How does decapsulation work at the receiver? 10 marks
  1. Draw the 7-layer stacks for client and server with the physical link between them; peer layers talk virtually 2
  2. L7–L5: the HTTP request (GET, Host header) is the data; L6 may encrypt it (TLS) 2
  3. L4 adds a TCP header (ports 52814 → 443, seq/ack) → segment; L3 adds an IP header (IPs, TTL) → packet; L2 adds the Ethernet header (MACs, EtherType) + FCS → frame; L1 sends bits 4
  4. Receiver: each layer checks and removes its own header (FCS check, IP address, port → process) and passes the payload up; routers in between work only up to L3 and re-frame 2
