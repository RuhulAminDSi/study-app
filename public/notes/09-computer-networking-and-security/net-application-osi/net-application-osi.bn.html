১স্তর ও OSI রেফারেন্স মডেল

হাই-ইল্ড
প্রোটোকল হায়ারার্কি (Protocol hierarchy) নেটওয়ার্ক সফটওয়্যারকে কয়েকটি স্তরে (layer) ভাগ করা হয়; প্রতিটি স্তর একটি ইন্টারফেস-এর মাধ্যমে ওপরের স্তরকে সার্ভিস দেয় এবং অন্য হোস্টের সমপর্যায়ের পিয়ার (peer) স্তরের সাথে প্রোটোকল মেনে কথা বলে। আসলে বিট পাঠায় শুধু স্তর 1; বাকিরা পিয়ারের সাথে ভার্চুয়ালি যোগাযোগ করে। একটি স্তর বদলালেও (Wi-Fi ↔ Ethernet) বাকিগুলো বদলাতে হয় না।

OSI = Open Systems Interconnection, প্রণেতা ISO (ISO 7498, ১৯৮৪; ITU-T X.200 নামেও)। ৭টি স্তর; এটি একটি রেফারেন্স মডেল: এর নিজস্ব প্রোটোকলগুলো চালু হয়নি, কিন্তু এর পরিভাষা সবখানে ব্যবহৃত হয়।

৩TCP/IP (ইন্টারনেট) মডেল

হাই-ইল্ড
সংজ্ঞা ইন্টারনেট আসলে যে মডেলে চলে; যুক্তরাষ্ট্রের DoD/ARPANET-এর কাজ থেকে এসেছে (Cerf ও Kahn, ১৯৭৪); ARPANET TCP/IP-তে চলে যায় ১ জানুয়ারি ১৯৮৩। RFC 1122 অনুযায়ী ৪টি স্তর: অ্যাপ্লিকেশন (HTTP, DNS, SMTP, DHCP, SNMP) · ট্রান্সপোর্ট (TCP, UDP) · ইন্টারনেট (IP, ICMP, IGMP) · লিংক (Ethernet, Wi-Fi, PPP, ARP)। অনেক বইয়ে ৫ স্তরের মিশ্র মডেল থাকে: লিংককে ডেটা লিংক + ফিজিক্যালে ভাগ করা হয়।

সমাধানকৃত উদাহরণ ✍ Ethernet MTU = 1500 B (IP প্যাকেট)। প্রতি ফ্রেমে TCP পেলোড = 1500 − 20 − 20 = 1460 B (সাধারণ MSS)। ফ্রেম = 1460 + 20 + 20 + 14 + 4 = 1518 B → দক্ষতা 1460/1518 ≈ 96.2%।
পরীক্ষার ফাঁদ প্রতিটি রাউটারে ফ্রেম খুলে নতুন ফ্রেম বানানো হয়: প্রতি হপে MAC অ্যাড্রেস বদলায়, কিন্তু IP অ্যাড্রেস শুরু থেকে শেষ পর্যন্ত একই থাকে (NAT না থাকলে), আর TTL ১ করে কমে। রাশিয়ান পুতুলের মতো: প্রতিটি স্তর শুধু নিজের পুতুলটি খোলে।

৫একটি URL খুললে কী কী ঘটে

লিখিত প্রশ্নে প্রিয়

তুমি লিখলে https://www.example.com/index.html। DHCP থেকে পিসি আগেই নিজের IP, মাস্ক, গেটওয়ে ও DNS সার্ভারের ঠিকানা পেয়ে গেছে।

  1. URL পার্স: স্কিম https → পোর্ট 443; হোস্ট www.example.com; পাথ /index.html। ব্রাউজার ও OS-এর ক্যাশ দেখা হয়।
  2. DNS (UDP 53): রিজলভারের কাছে A/AAAA রেকর্ড চাওয়া → সার্ভারের IP। (বিস্তারিত: DNS নোট)
  3. ARP: সার্ভার অন্য নেটওয়ার্কে, তাই পিসির দরকার গেটওয়ের MAC, সার্ভারের নয় (ARP রিকোয়েস্ট = ব্রডকাস্ট, রিপ্লাই = ইউনিকাস্ট)।
  4. পোর্ট 443-এ TCP থ্রি-ওয়ে হ্যান্ডশেক: SYN → SYN-ACK → ACK (১ RTT); ক্লায়েন্ট একটি ক্ষণস্থায়ী (ephemeral) পোর্ট নেয়, যেমন 52814।
  5. TLS হ্যান্ডশেক: সার্টিফিকেট যাচাই, কী বিনিময় (TLS 1.3: ১ RTT) → সেশন কী।
  6. HTTP GET /index.html (এনক্রিপ্টেড) → সেগমেন্ট → প্যাকেট → ফ্রেম → বিট।
  7. হপে হপে রাউটিং: প্রতিটি রাউটার TTL ১ কমায়, গন্তব্য নেটওয়ার্ক খোঁজে, নতুন ফ্রেম বানায়। tracert / traceroute TTL শেষ হওয়া + ICMP কাজে লাগিয়ে হপগুলোর তালিকা দেখায়।
  8. সার্ভার ওপরের দিকে ডিক্যাপসুলেট করে 200 OK + HTML পাঠায়; এরপর ব্রাউজার একই কানেকশনে CSS, JS ও ছবি আনে।
  9. FIN/ACK দিয়ে কানেকশন বন্ধ, অথবা পুনর্ব্যবহারের জন্য খোলা রাখা হয়।
মনে রাখার কৌশল "D-A-T-T-H": DNS, ARP, TCP, TLS, HTTP: প্রথম যোগাযোগের ক্রম।
পরীক্ষার ফাঁদ IP ফ্র্যাগমেন্ট জোড়া লাগায় গন্তব্যের IP স্তর; এলোমেলো ক্রমে আসা সেগমেন্ট সাজায় TCP।

নন-পারসিস্টেন্ট (HTTP/1.0-এর ডিফল্ট): প্রতিটি অবজেক্টের জন্য নতুন TCP কানেকশন, প্রতিটিতে 2 RTT + ট্রান্সফার টাইম। পারসিস্টেন্ট (HTTP/1.1-এর ডিফল্ট, keep-alive): এক কানেকশনেই অনেক অবজেক্ট; পাইপলাইনিং-এ রিকোয়েস্টগুলো একটানা পাঠানো হয়।

৭ওয়ার্ল্ড ওয়াইড ওয়েব (WWW)

MCQ-তে প্রিয়
সংজ্ঞা URL দিয়ে পরস্পর যুক্ত হাইপারটেক্সট ডকুমেন্টের একটি বিস্তৃত (distributed) ব্যবস্থা, যা HTTP-তে পরিবেশিত হয় এবং ব্রাউজারে দেখা যায়। প্রস্তাব করেন টিম বার্নার্স-লি, CERN-এ, ১৯৮৯ সালে; প্রথম সার্ভার ও ব্রাউজার ১৯৯০–৯১; Mosaic (১৯৯৩) একে জনপ্রিয় করে; W3C প্রতিষ্ঠিত ১৯৯৪। তিন ভিত্তি: HTML (পেজ), URL (ঠিকানা), HTTP (আদান-প্রদান)। ওয়েব সার্ভার: Apache, Nginx, IIS।

URL-এর গঠন

URL = রিসোর্সটি কোথায় আছে; URN = তার নাম (urn:isbn:…); দুটোই URI-এর প্রকার। ডিফল্ট পোর্ট স্কিম থেকেই বোঝা যায় (http 80, https 443)। #fragment কখনো সার্ভারে পাঠানো হয় না।

৮FTP, Telnet, SSH

FTP TCP, দুটি কানেকশন: কন্ট্রোল পোর্ট 21-এ (সারাক্ষণ খোলা: "আউট-অব-ব্যান্ড" কন্ট্রোল), অ্যাক্টিভ মোডে ডেটা পোর্ট 20-এ (প্রতি ফাইলে নতুন কানেকশন)। প্যাসিভ মোড: সার্ভার একটি পোর্ট জানায়, ক্লায়েন্ট সেখানে যুক্ত হয় (ফায়ারওয়ালের জন্য সুবিধাজনক)। সব প্লেইন টেক্সট। TFTP: UDP 69, লগইন নেই।
Telnet বনাম SSH দুটোই রিমোট টার্মিনাল দেয়। Telnet: TCP 23, পাসওয়ার্ডসহ সবকিছু প্লেইন টেক্সটে। SSH: TCP 22, এনক্রিপ্টেড ও অথেনটিকেটেড (কী বা পাসওয়ার্ড); SCP/SFTP ও টানেলও বহন করে।

৯DHCP

DHCP একটি নির্দিষ্ট লিজ (lease) সময়ের জন্য হোস্টকে স্বয়ংক্রিয়ভাবে IP, মাস্ক, গেটওয়ে ও DNS সার্ভারের ঠিকানা দেয়। UDP: সার্ভার 67, ক্লায়েন্ট 68। চারটি বার্তা, DORA: Discover (ব্রডকাস্ট) → Offer → Request (ব্রডকাস্ট) → Ack। রাউটার পেরিয়ে এগুলো পৌঁছে দেয় রিলে এজেন্ট। BOOTP-র উত্তরসূরি।

১১SNMP: Simple Network Management Protocol

হাই-ইল্ড
সংজ্ঞা রাউটার, সুইচ, সার্ভার, প্রিন্টার ও UPS পর্যবেক্ষণ (monitor) ও কনফিগার করার অ্যাপ্লিকেশন-স্তরের প্রোটোকল, চলে UDP-র ওপর। একটি ম্যানেজার এজেন্টদের কাছে তথ্য চায় (পোলিং); এজেন্টও নিজে থেকে ঘটনা জানাতে পারে। এজেন্ট শোনে UDP 161-এ; ম্যানেজার ট্র্যাপ গ্রহণ করে UDP 162-এ।
  • ম্যানেজার / NMS: পর্যবেক্ষণ স্টেশন
  • এজেন্ট: প্রতিটি পরিচালিত ডিভাইসের ভেতরের সফটওয়্যার
  • MIB (Management Information Base): পরিচালিত অবজেক্টগুলোর এজেন্টের ডেটাবেস, যেমন MIB-II
  • OID: বৈশ্বিক ট্রি-তে একটি অবজেক্টের ডট-যুক্ত ঠিকানা, যেমন sysDescr = 1.3.6.1.2.1.1.1
  • SMI: অবজেক্টের নাম ও টাইপ নির্ধারণের নিয়ম, ASN.1-এ লেখা, BER-এ এনকোড করা

লিখিত প্রশ্ন ব্রাউজার একটি ওয়েব পেজ চাইলে ডেটা OSI স্তরগুলো বেয়ে নামার সময় কীভাবে এনক্যাপসুলেট হয়, চিত্রসহ ব্যাখ্যা করো; প্রতিটি স্তরের PDU ও যোগ হওয়া হেডারের নাম লেখো। গ্রাহক প্রান্তে ডিক্যাপসুলেশন কীভাবে হয়? ১০ নম্বর
  1. ক্লায়েন্ট ও সার্ভারের ৭ স্তরের স্ট্যাক আঁকো, মাঝে ফিজিক্যাল লিংক; পিয়ার স্তরগুলো ভার্চুয়ালি কথা বলে ২
  2. L7–L5: HTTP রিকোয়েস্ট (GET, Host হেডার) হলো ডেটা; L6 একে এনক্রিপ্ট করতে পারে (TLS) ২
  3. L4 TCP হেডার জোড়ে (পোর্ট 52814 → 443, seq/ack) → সেগমেন্ট; L3 IP হেডার জোড়ে (IP, TTL) → প্যাকেট; L2 Ethernet হেডার (MAC, EtherType) + FCS জোড়ে → ফ্রেম; L1 পাঠায় বিট ৪
  4. গ্রাহক: প্রতিটি স্তর নিজের হেডার যাচাই করে খুলে ফেলে (FCS যাচাই, IP অ্যাড্রেস, পোর্ট → প্রসেস) এবং পেলোড ওপরে পাঠায়; মাঝের রাউটার শুধু L3 পর্যন্ত কাজ করে, নতুন ফ্রেম বানায় ২
