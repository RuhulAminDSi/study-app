1Why the 8086 Needs Support Chips

concept
Idea Address and data share pins (AD0–AD15, to fit 40 pins), each pin drives only ~10 74LS loads, and there is no on-chip oscillator. So a board adds the 8284A clock, 74LS373 latches, 74LS245 transceivers and, in maximum mode, the 8288 bus controller.

29–31WR, HLDA, HOLDLOCK, RQ/GT1, RQ/GT0
Usesingle CPU makes its own controls8087 / multiprocessor: 8288 makes them

Unchanged in both modes: RD, READY, RESET, CLK, BHE/S7. On the 8088, pin 28 is IO/M (opposite sense).

28284A Clock Generator

high-yield
Definition An 18-pin chip that turns a crystal into CLK, PCLK and OSC and synchronises READY and RESET with the clock. CLK = fcrystal ÷ 3 with a 33% duty cycle.
Worked example ✍ 15 MHz crystal → CLK = 5 MHz (T = 200 ns), PCLK = 2.5 MHz, OSC = 15 MHz. An 8086-2 (8 MHz) needs a 24 MHz crystal; an 8086-1 (10 MHz) a 30 MHz one.
Memory trick "OSC ÷ 1, CLK ÷ 3, PCLK ÷ 6" (all from the crystal). F/C = 0 uses the crystal, 1 the external EFI input.
Exam trap CLK duty is 33%; PCLK is the 50% one. RESET must stay HIGH ≥ 4 clocks; then CS = FFFFH, IP = 0000H, so the first fetch is at FFFF0H: the boot EPROM sits at the top of memory (p. 6).

3The Bus Cycle: T1–T4 and Wait States

high-yield
Definition One memory or I/O read/write = a bus cycle of 4 clocks, T1–T4. A slow memory or port pulls READY low and the CPU inserts wait states (Tw), one clock each.
StateWhat happens
T1address on AD0–AD15, A16–A19, BHE; ALE pulses; M/IO, DT/R set
T2address removed; RD or WR low; DEN low; write data out
T3memory/port drives the data; READY is checked
Twrepeated while READY = 0; one clock each; signals frozen
T4CPU takes read data; RD/WR go high; cycle ends
Worked example ✍ 5 MHz: T = 200 ns, cycle = 4T = 800 ns; 1 Tw → 1000 ns. Peak rate = 2 bytes / 800 ns = 2.5 MB/s.
Exam trap Brey puts Tw between T2 and T3, Intel between T3 and T4; either way READY low ⇒ +1 clock per Tw.

5Demultiplexing the Address/Data Bus

high-yield
Definition AD0–AD15 carry the address in T1 and data in T2–T4. ALE (Address Latch Enable) is high in T1; a latch passes the address while ALE = 1 and holds it from ALE's falling edge to the end of the cycle. The latched lines form the system address bus A0–A19.

74LS244octal 3-state buffer, one wayaddress/control buffer, input port
74LS245 (8286)octal transceiver, two waydata bus: DIR ← DT/R, G ← DEN
74LS245 truth
G = 0, DIR = 1 → A → B (CPU writes)
G = 0, DIR = 0 → B → A (CPU reads)
G = 1 → both sides Z (isolated)
DT/R: 1 = transmit, 0 = receive
Chip count ✍
8086: 21 lines to latch (AD0–15, A16–19, BHE) → 3 × 373; 16 data lines → 2 × 245
8088: only AD0–AD7 multiplexed → 2 × 373, A8–A15 via a 244, 1 × 245
Memory trick "ALE → Address latch; DEN → Data enable; DT/R → Direction". 373 latch, 244 one-way, 245 both ways.
Exam trap Buffers are for fan-out (> ~10 LS loads) and for floating the bus during DMA. The 16-bit 8086 needs two 245s; the 8088 one.

8Address Decoding: Full vs Partial

written favourite
Idea The low address lines go straight to the chip (13 lines for an 8 KB chip). The high lines go to a decoder that drives the chip's CS, so each chip answers only in its own address block.
Full decoding every high line is decoded → each location has exactly one address. Needed for a clean, expandable memory map.
Partial decoding some high lines ignored → cheaper, but each location repeats at 2ᵏ addresses (k = ignored lines): fold-back / aliasing / mirror images.

The 74LS138 3-to-8 decoder

Worked example: memory map ✍ 8088, eight 2764 EPROMs (8K × 8) filling F0000H–FFFFFH.
  1. 8K = 2¹³ → A0–A12 to every chip
  2. A13–A15 → C B A inputs pick 1 of 8 chips
  3. A16–A19 must be 1111 → NAND → G2A; IO/M = 0 for memory → G2B
  4. 13 + 3 + 4 = 20 lines used → full decoding

Partial decoding ✍ A 2K RAM (6116) with CS = A19 only: A0–A10 on chip, A11–A18 ignored (8 lines) → 2⁸ = 256 images: 00000–007FFH, 00800–00FFFH … 7F800–7FFFFH.
Memory trick "Size picks the low lines, the decoder gets the rest." Lines on chip + decoded lines = 20 → full; fewer → partial.
Exam trap Images = 2k, not 2k. Boot ROM must cover FFFF0H (reset vector), so EPROM goes at the top, RAM from 00000H (IVT).

IN AL, 60H ; fixed port 00H–FFH IN AX, DX ; DX = 0000H–FFFFH OUT 43H, AL ; byte to port 43H MOV DX, 0378H ; port above FFH: OUT DX, AL ; must use DX

Fixed port → 256 ports (A8–A15 = 00H). DX → 65,536 ports. A16–A19 = 0 in every I/O cycle.

Exam trap IN BL, 60H is illegal (only AL/AX); OUT 378H, AL is illegal (port > FFH needs DX). Memory-mapped I/O has no IN/OUT cycles at all.

10I/O Port Decoding & Types of I/O

Decoding ✍ Ports F8H–FFH on an 8088: A7–A3 = 11111 → 74LS30 NAND → G2A; IO/M (1 for I/O) → G1; A2 A1 A0 → C B A, so Yn = port F8H + n. A8–A15 are ignored (partial decoding for DX ports). Input port: a 74LS244 enabled only by its IORC; output port: a 74LS374 latch clocked by IOWC.

118255A Programmable Peripheral Interface

high-yield
Definition A 40-pin chip with 24 I/O lines in three 8-bit ports A, B, C. Group A = Port A + PC7–PC4 (upper C); Group B = Port B + PC3–PC0 (lower C). A control word sets each port's direction and mode.
A1 A0Selects8088 / 8086
0 0Port A60H / 80H
0 1Port B61H / 82H
1 0Port C62H / 84H
1 1Control register63H / 86H

(CS = 0.) On an 8086 the 8255A sits on D0–D7, so CPU A1, A2 drive its A0, A1 → even port addresses (80H, 82H, 84H, 86H).

RESET → all 24 lines become inputs (mode 0), so nothing is driven by accident at power-on.

12The Three Modes (+ BSR)

ModeNamePortsKey points
0Basic I/OA, B, C upper, C lowerno handshake; outputs latched, inputs not; 16 in/out combinations
1Strobed I/OA and Bhandshake on Port C: A uses PC3–PC5 (in) or PC3, PC6, PC7 (out); B uses PC0–PC2

Memory trick "A-B-C = 3-2-1": Port A has 3 modes (0, 1, 2), Port B 2 (0, 1), Port C 1 (mode 0) plus BSR.
Exam trap Port C has no handshake mode of its own; in modes 1/2 some of its lines become handshake pins and the leftover lines stay normal I/O.
