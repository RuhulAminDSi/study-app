1Stored Program: von Neumann vs Harvard

high-yield
Stored-program concept Instructions sit in the same read-write memory as data and are fetched and executed in sequence under the program counter. John von Neumann, 1945, "First Draft of a Report on the EDVAC".
Pointvon NeumannHarvard
Memoryone memory for code and dataseparate code and data memories
Busesone shared settwo sets: fetch + data in parallel
Speed / costslower (bottleneck), cheaperfaster, more wiring, costlier
Used inPCs (main memory), EDVAC, IASDSPs, PIC/AVR MCUs, Mark I (1944)
Exam trap The von Neumann bottleneck is the limited transfer rate between CPU and memory over the single path (term popularised by John Backus, 1977), not a slow ALU.
Modern CPUs = modified Harvard: split L1 instruction and data caches, but one unified main memory (see Memory Hierarchy).

2Inside the CPU: ALU, CU, Registers

MCQ
  • ALU: arithmetic (add, subtract, increment, compare) and logic (AND, OR, XOR, NOT, shift); sets the flags.
  • Control unit (CU): fetches and decodes instructions and issues the timing and control signals that make the ALU, registers, memory and I/O act. It directs; the ALU and datapath execute.
  • Registers: the fastest storage, inside the CPU (next sheet). ALU + registers + internal buses = the datapath.

0-address code is just the postfix (RPN) form AB+CD+× read left to right: operand → PUSH, operator → pop two, push the result.

Field sizing ✍ 32-bit instruction, 64 registers, 64K-word memory, format opcode | reg | address.
reg = log₂64 = 6 bits · address = log₂65536 = 16 bits

8Control Unit: Hardwired vs Microprogrammed

high-yield

Hardwired: control signals come from a fixed logic circuit: sequence counter + decoders + gates (or a PLA/FSM).

Microprogrammed: each machine instruction runs a small microprogram of microinstructions stored in control memory (ROM); CAR = control address register, CDR = control data register.

PointHardwiredMicroprogrammed
Speedfasterslower (control-memory read each step)
Change / debugredesign the circuitrewrite the microcode: flexible
Complex ISAhard, costlyeasy
Used byRISCCISC
Microinstruction styles Horizontal: 1 bit per control signal, wide, much parallelism, no decoding. Vertical: encoded fields, narrow, needs decoders, slower.
Datapath designs Single-cycle: CPI = 1, but clock = slowest instruction (load). Multicycle: short clock, CPI 3–5, units reused across steps.
Memory trick "Hard = Hurry, Micro = Modify": hardwired is fast and rigid; microprogrammed is slow and editable.

CA · CPU OrganizationPipelining

9Instruction Pipelining

very high-yield
Definition Split instruction execution into k stages and overlap them, like an assembly line: while one instruction executes, the next is decoded and the one after is fetched. The classic RISC pipeline has 5 stages: IF fetch, ID decode + read registers, EX ALU, MEM memory access, WB write back.
Formulas (k stages, n instructions, clock τ)

Pipelined time = (k + n − 1) τ

Non-pipelined = n · tn (tn = k τ if balanced)

Speedup S = n k / (k + n − 1) → k

Efficiency η = n / (k + n − 1) = S / k

Throughput = n / ((k + n − 1) τ) → 1/τ

τ = slowest stage + latch delay

Example 1 ✍ k = 5, n = 100, one cycle per stage, no stalls → 5 + 99 = 104 cycles; non-pipelined 500 cycles; S = 500 / 104 ≈ 4.81; η = 100 / 104 ≈ 96%.
Example 2: unequal stages ✍ Stage delays 60, 50, 90, 80 ns; latch 10 ns; n = 1000.
τ = 90 + 10 = 100 ns · pipelined = (4 + 999) × 100 = 100 300 ns · non-pipelined = 1000 × (60 + 50 + 90 + 80) = 280 000 ns · S ≈ 2.79, far below 4 because the stages are unbalanced.
Example 3 ✍ IF 200, ID 100, EX 200, MEM 200, WB 100 ps. Single-cycle clock = 800 ps (a load uses all five); pipelined clock = 200 ps → ideal speedup 800 / 200 = 4, not 5.
Exam trap Pipelining raises throughput; it does not shorten one instruction's latency (latches even lengthen it a little).
Memory trick "Fill once, then one per tick": k cycles for the first result, then 1 more per instruction → k + n − 1.

Pipeline registers (IF/ID, ID/EX, EX/MEM, MEM/WB) between stages hold each instruction's data and control bits; control signals are generated in ID and travel down the pipe with the instruction.

10Pipeline Hazards & Their Cures

very high-yield
Hazard A condition that stops the next instruction entering its stage on time, forcing a stall (bubble). Real CPI = 1 + stall cycles per instruction.
HazardCauseExampleCures
Structuraltwo instr. need one unitone memory portsplit I/D cache, stall
Dataneeds an unfinished resultADD R1,R2,R3 → SUB R4,R1,R5forwarding, stall
Controlnext PC unknownBEQ, JMP, CALLbranch prediction

Data hazard types (i before j):

  • RAW read after write: true dependence, the common one
  • WAR write after read: anti-dependence
  • WAW write after write: output dependence

WAR and WAW occur only with out-of-order execution; register renaming removes them.

Exam trap: load-use LW R1, 0(R2) followed by ADD R3, R1, R4 still needs 1 stall even with forwarding: the loaded value exists only after MEM. Without forwarding a RAW on the next instruction costs 2 stalls (register file written in the first half of WB, read in the second half).

Control hazard cures: static prediction (always not-taken; backward-taken/forward-not-taken), dynamic prediction with a 1-bit or 2-bit saturating counter per branch + a branch target buffer (BTB), delayed branch (compiler fills the slot after a branch with a useful instruction), resolving the branch early in ID, flushing wrongly fetched instructions.

Worked: CPI with stalls ✍ 5-stage pipeline, 20% branches with a 2-cycle penalty, 30% loads of which 25% are followed by a use (1 stall).
CPI = 1 + 0.2 × 2 + 0.3 × 0.25 × 1 = 1.475 → speedup over unpipelined ≈ 5 / 1.475 ≈ 3.39.
With a predictor 90% right and a 3-cycle mispredict penalty: CPI = 1 + 0.2 × 0.1 × 3 = 1.06.
Memory trick Hazards = "SDC": Share a unit, Depend on data, Change the PC. Cures in the same order: duplicate, forward, predict.

11Measuring Performance

calculation
The CPU performance equation
CPU time = IC × CPI × T = IC × CPI / f  (IC = instruction count, T = 1/f)
Average CPI = Σ (fractioni × CPIi) · MIPS = f / (CPI × 10⁶) = IC / (time × 10⁶) · Performance = 1 / time · Speedup = timeold / timenew
FactorICCPIClock rate f
Set byprogram, compiler, ISAISA, pipeline, cachetechnology, organisation
Example 1 ✍ Mix: 50% ALU (CPI 1), 30% load/store (CPI 2), 20% branch (CPI 3).
CPI = 0.5 + 0.6 + 0.6 = 1.7
IC = 5 × 10⁸, f = 2 GHz → time = 5×10⁸ × 1.7 / 2×10⁹ = 0.425 s; MIPS = 2000 / 1.7 ≈ 1176
Example 2 ✍ Same program. A: 2 GHz, CPI 2.0. B: 3 GHz, CPI 3.6.
A: IC × 2 / 2×10⁹ = 1.0 IC ns
B: IC × 3.6 / 3×10⁹ = 1.2 IC ns
A is 1.2× faster despite the slower clock.
Example 3: MIPS ✍ 400 MHz, CPI 2 → MIPS = 400 × 10⁶ / (2 × 10⁶) = 200. Clock period of 400 MHz = 1 / (4 × 10⁸) = 2.5 ns.
Exam trap Neither clock rate nor MIPS alone measures performance: MIPS ignores how much work an instruction does (compare RISC and CISC). Only execution time of real programs (e.g. SPEC benchmarks) is fair.

12Amdahl's Law

high-yield

If a fraction f of the time is sped up s times:

S = 1 / ((1 − f) + f / s)  → max 1 / (1 − f)

  • f = 0.4, s = 10 → 1 / (0.6 + 0.04) = 1.56
  • 90% parallel on 10 cores → 1 / (0.1 + 0.09) = 5.26 (limit 10)
  • Overall 2× with f = 0.8: 0.2 + 0.8/s = 0.5 → s = 2.67
Memory trick "Speed up the common case": the part you do not improve (1 − f) sets the ceiling.
Exam trap f is a fraction of time, not of instructions. With f = 0.5, even s = ∞ gives only 2×.

13ALU Design & Fixed-Point Arithmetic

A 1-bit ALU slice computes AND, OR and a full-adder sum in parallel; a multiplexer picks one by the operation-select bits. 32 slices with chained carries = a 32-bit ripple-carry ALU; a carry-lookahead adder removes the slow carry chain.

Subtract: A − B = A + B′ + 1 (invert B, carry-in = 1).

n-bit two's complement range −2ⁿ⁻¹ … 2ⁿ⁻¹ − 1 (8-bit: −128 … +127). Overflow V = Cin(MSB) ⊕ Cout(MSB): two same-sign operands give an opposite-sign result.
Overflow ✍ 0110 0100 (+100) + 0100 0000 (+64) = 1010 0100 = −92 in 8 bits. Carry into MSB = 1, out of MSB = 0 → V = 1.

Multiplication: shift-and-add; Booth's algorithm handles signed (two's complement) operands and skips runs of 1s (pairs 10 → subtract, 01 → add). Division: restoring / non-restoring.

CA · CPU OrganizationParallelism · I/O

15Beyond the Basic Pipeline

  • Superscalar: several pipelines; issues 2+ instructions per cycle, so CPI < 1 (IPC > 1). Superpipelining: more, shorter stages. VLIW: the compiler packs parallel operations into one long word.
  • Dynamic pipelining = out-of-order execution: reservation stations (Tomasulo), register renaming, a reorder buffer for in-order commit.
  • Exceptions (overflow, undefined opcode, page fault) arise inside the CPU; interrupts come from I/O. A precise exception saves the faulting PC (EPC), records the cause and flushes later instructions.
