Graph · TreesDefinition & properties

1Trees

definition ★
Definition A tree is a connected, acyclic undirected graph. Equivalently: a graph with no cycles in which every pair of vertices is joined by exactly one path. A forest is a disjoint union of trees — an acyclic graph whose components are trees.
PropertyDescription
EdgesIf a tree has n vertices, it has n − 1 edges
Unique pathExactly one path between any two vertices
Adding edgeAdding any edge creates exactly one cycle
Removing edgeRemoving any edge disconnects the graph
LeavesEvery tree with n ≥ 2 has at least 2 leaves (deg 1)
Forestn vertices, k trees → n − k edges
Memory trick "A tree never loops — it only branches." No cycles, no shortcuts, just one road between any two nodes. That is why trees are the skeleton of every network: minimum edges for maximum reach.
Exam trap (i) A tree is not just "acyclic" — it must also be connected. An acyclic graph with 4 vertices and 2 edges is a forest, not a tree. (ii) A single vertex (n = 1) is a tree with 0 edges — the formula n − 1 still holds. (iii) "Leaves = degree 1" — the root of a rooted tree may have degree 1 and still count as a leaf in the underlying unrooted tree.
Worked example ✍ verify tree properties A graph has 8 vertices and 7 edges. Is it necessarily a tree? No — it could be disconnected (e.g. a triangle + 5 isolated vertices has 3 edges, not 7). A connected graph with n vertices and n − 1 edges is a tree. Here: if we confirm connectivity, then yes — 8 vertices, 7 edges, connected ⟹ tree.

Graph · TreesSpanning trees

2Spanning Trees

application ★
Definition A spanning tree of a connected graph G = (V, E) is a subgraph T = (V, E') such that: (i) T includes all vertices of G, and (ii) T is a tree (connected and acyclic). Any spanning tree has exactly |V| − 1 edges.
Key facts
  • Every connected graph has at least one spanning tree
  • A graph with cycles can have many spanning trees
  • Number of edges in any spanning tree = |V| − 1
  • Removing one edge from each cycle in G yields a spanning tree
Cayley's formula The number of distinct labelled spanning trees of the complete graph Kₙ is nⁿ⁻². For K₄ this gives 4² = 16 spanning trees. For K₅ this gives 5³ = 125.
Worked example ✍ spanning trees of C₄ A cycle C₄ has 4 vertices and 4 edges. Removing any one edge breaks the cycle while keeping the graph connected, giving a spanning tree. Since there are 4 edges, C₄ has exactly 4 spanning trees. For K₄ (6 edges), Cayley gives 4² = 16 labelled spanning trees.
Exam trap (i) A spanning tree of G is not a subgraph of every spanning tree — it is a spanning tree of G. Different spanning trees share vertices but may differ in edges. (ii) A disconnected graph has no spanning tree — only a spanning forest. (iii) K₄ has 4⁴⁻² = 16 spanning trees, not 6. K₅ has 5³ = 125.
Memory trick "Spanning tree = skeleton." It touches every vertex (spans all) and uses the fewest possible edges (tree) to keep everything connected. Think of it as the minimum-cable wiring to link all computers in a network.
IT link Minimum-spanning-tree algorithms (Kruskal's, Prim's) are used in network design, cluster analysis, and approximating the Traveling Salesman Problem.

Graph · TreesDistance, eccentricity, diameter

3Distance in Graphs

metrics ★
Definition The distance d(u, v) between two vertices u and v is the length (number of edges) of a shortest path connecting them. If no path exists, d(u, v) = ∞.
PropertyDescription
d(u, v) = 0If and only if u = v
d(u, v) = d(v, u)Symmetric in undirected graphs
Triangle inequalityd(u, w) ≤ d(u, v) + d(v, w)
Infinite distanceIf u and v are in different components
Derived metrics
  • Eccentricity: ecc(v) = max{d(v, u) | u ∈ V}
  • Diameter: diam(G) = max{ecc(v) | v ∈ V}
  • Radius: rad(G) = min{ecc(v) | v ∈ V}
  • Center: {v | ecc(v) = rad(G)}
  • Periphery: {v | ecc(v) = diam(G)}
Worked example ✍ P₅ path graph Vertices A–B–C–D–E in a line. Distances from A: d(A,B)=1, d(A,C)=2, d(A,D)=3, d(A,E)=4, so ecc(A)=4. Similarly ecc(B)=3, ecc(C)=2, ecc(D)=3, ecc(E)=4. Diameter = max ecc = 4. Radius = min ecc = 2. Center = {C}. Periphery = {A, E}.
Exam trap (i) Diameter is the maximum eccentricity, not the maximum degree. (ii) The center may contain one or two adjacent vertices — e.g. P₄ has center {B, C}. (iii) In a disconnected graph, distance is ∞ between components, so diameter is often defined only for connected graphs.
Worked example ✍ star graph S₄ Center vertex c joined to leaves a, b, d. Distances: d(c,a)=d(c,b)=d(c,d)=1, d(a,b)=d(a,d)=d(b,d)=2. Eccentricities: ecc(c)=1, ecc(a)=ecc(b)=ecc(d)=2. Diameter = 2, Radius = 1, Center = {c}, Periphery = {a, b, d}. Note: radius ≠ diameter here — only paths and cycles can have rad = diam/2 approximately.

Graph · TreesComplementary graphs

4Complementary Graphs

construction ★
Definition The complement of a graph G = (V, E), denoted G̅, has the same vertex set V, and an edge {u, v} is in G̅ if and only if {u, v} is not in E. Thus G and G̅ partition the edges of the complete graph Kₙ.
PropertyDescription
G ∪ G̅Complete graph Kₙ (edge-disjoint union)
G̿G (complement of complement is original)
Edges|E(G̅)| = n(n−1)/2 − |E(G)|
Self-compl.G ≅ G̅; requires n ≡ 0 or 1 (mod 4)
Self-complementary A graph isomorphic to its complement. Example: P₄ (path on 4 vertices) is self-complementary. For a self-complementary graph on n vertices, |E| = n(n−1)/4. A self-complementary graph on 8 vertices has 8·7/4 = 14 edges.
Exam trap (i) G and G̅ never share an edge — their edge sets are complementary within Kₙ. (ii) Both G and G̅ cannot be disconnected for n ≥ 2 — at least one is connected. (iii) A self-complementary graph on n vertices has exactly n(n−1)/4 edges, so n(n−1) must be divisible by 4 — this means n ≡ 0 or 1 (mod 4).
Memory trick "Complement = the rest." Take Kₙ, remove G's edges, what remains is G̅. For a self-complementary graph, G and G̅ are mirror images in edge space — each gets exactly half of Kₙ's edges.

Graph · TreesCut-vertices

5Cut-Vertices (Articulation Points)

weak point ★
Definition A vertex v is a cut-vertex (articulation point) if removing v and all incident edges increases the number of connected components. A graph with no cut-vertices is 2-connected (or non-separable).
Key properties
  • Bridges and cut-vertices are weak points in networks
  • Leaves are not cut-vertices (except in K₂)
  • Every cycle has no cut-vertices
  • A block is a maximal subgraph without cut-vertices
  • A tree with n ≥ 3 has n − 2 cut-vertices (all non-leaf vertices)
Exam trap A leaf (degree-1 vertex) is never a cut-vertex in a tree with ≥ 3 vertices — removing it leaves the rest still connected. Only in K₂ does the single edge's endpoint count as a cut-vertex. Also: a graph with a cut-vertex has κ(G) = 1, so it is not 2-connected.
Memory trick "A cut-vertex is a bottleneck." Remove it and the network falls apart into more pieces. Think of a bridge city on a river — close it and the two banks are isolated.
Worked example ✍ find cut-vertices Graph: A—B—C with D attached to B (B is centre). Removing B gives components {A}, {C}, {D} — 3 components (was 1). So B is a cut-vertex. A, C, D are leaves — removing any one leaves 2 vertices still connected, so they are not cut-vertices. In a path P₅ (A–B–C–D–E), the cut-vertices are B, C, D (3 of them); A and E are leaves, not cut-vertices.
IT link Cut-vertices identify single points of failure in communication networks, power grids, and road systems — locations where one outage isolates entire regions.

Graph · TreesBridges (cut-edges)

6Bridges (Cut-Edges)

critical edge ★
Definition An edge e is a bridge (cut-edge) if removing e increases the number of connected components. Equivalently: e is a bridge if and only if it belongs to no cycle in G.
Key facts
  • Every edge in a tree is a bridge
  • An edge is a bridge ⟺ it is not in any cycle
  • Removing a bridge disconnects the graph
  • Bridges are the edge-analogue of cut-vertices
  • A graph with no bridges is 2-edge-connected
DFS bridge-finding algorithm Compute discovery time disc[u] and low-link value low[u] = min(discover time of u, discover time of ancestor reachable via back-edge from subtree of u). Edge (u, v) (u = parent of v) is a bridge if low[v] > disc[u].
Exam trap (i) An edge in a cycle is never a bridge — removing one edge from a cycle leaves a path, still connected. (ii) Every tree edge is a bridge, but not every bridge is in a tree — bridges exist in graphs with cycles too. (iii) low[v] > disc[u] (strictly greater); low[v] = disc[u] means there is a back-edge, so (u,v) is not a bridge.
Memory trick "No cycle = bridge." If you can绕 (go around) from v back to u without using edge (u,v), then (u,v) is safe — it is not a bridge. If not, it is a bridge.
Worked example ✍ bridges in a triangle with a tail Graph: A—B—C forms a triangle (A-B, B-C, C-A), and C—D is a tail. Edge C—D is a bridge (removing it isolates D). Edges A-B, B-C, C-A are not bridges — each lies on the triangle cycle. Removing any one triangle edge leaves a path A-B-C, still connected. So this graph has exactly 1 bridge: C—D.

Graph · TreesBlocks & k-connected graphs

7Blocks & k-Connected Graphs

connectivity ★
Block A block is a maximal connected subgraph with no cut-vertex. Blocks are either: (i) a maximal 2-connected subgraph, (ii) a bridge (single edge that is a block), or (iii) an isolated vertex. A block tree (BC-tree) has nodes for blocks and cut-vertices, with edges linking each cut-vertex to the blocks it belongs to.
k-connected A graph is k-connected if |V| > k and removing any set of fewer than k vertices leaves the graph connected. The vertex connectivity κ(G) is the minimum number of vertices whose removal disconnects G (or makes it trivial).
Edge connectivity The edge connectivity λ(G) is the minimum number of edges whose removal disconnects G. Whitney's Theorem: κ(G) ≤ λ(G) ≤ δ(G), where δ(G) is the minimum degree.
Exam trap (i) κ(Kₙ) = n − 1, not n. You need to remove all but one vertex to disconnect Kₙ. (ii) A graph with a cut-vertex has κ = 1 — it is not 2-connected. (iii) κ ≤ λ ≤ δ is always true; equality on both sides holds for Kₙ and Cₙ but not generally.
Memory trick "κ is the weakest link, δ is the strongest ceiling." Vertex connectivity (κ) ≤ edge connectivity (λ) ≤ minimum degree (δ). The minimum degree is an upper bound — you can always disconnect by removing all neighbours of a min-degree vertex, but sometimes fewer suffice.
Worked example ✍ connectivity values (a) Tree with n ≥ 2: κ = 1 (has cut-vertices), λ = 1 (has bridges). (b) Cycle Cₙ, n ≥ 3: κ = 2, λ = 2 — removing any 1 vertex or edge leaves a path (connected). (c) K₆: κ = 5, λ = 5 — you must remove 5 vertices/edges to isolate one vertex. (d) K₃,₃: κ = 3, λ = 3 (3-regular, each vertex has degree 3).

Written question Prove that every tree with n vertices has exactly n − 1 edges. 10
  1. Base case (n = 1). A tree with one vertex has 0 edges. Formula: 1 − 1 = 0. ✓ 2
  2. Inductive hypothesis. Assume every tree with k vertices has k − 1 edges.
  3. Inductive step. Let T be a tree with k + 1 vertices. T has at least two leaves (vertices of degree 1). Remove a leaf v and its incident edge e. The remaining graph T' has k vertices and is still a tree (removing a leaf preserves connectivity and acyclicity). By the hypothesis, T' has k − 1 edges. Therefore T has (k − 1) + 1 = k = (k + 1) − 1 edges. ✓ 5
  4. Conclusion. By mathematical induction, every tree with n vertices has exactly n − 1 edges for all n ≥ 1. 2
