2Design Procedure

written favourite
  1. Fix the inputs and outputs; name them
  2. Write the truth table (2ⁿ rows; unused codes = X)
  3. Simplify each output (K-map, Boolean Algebra sheets 7–8)
  4. Draw the circuit (AND-OR → NAND-NAND)
  5. Verify a few rows
Worked example ✍ 3-bit prime detector: F = 1 when ABC (A = MSB) is 2, 3, 5 or 7.
F = Σm(2, 3, 5, 7): pairs m2, m3 = A′B; m5, m7 = AC
F = A′B + AC · check 001: 0 ✓
Families Arithmetic: adders, subtractors, comparators, ALU · Data routing: MUX, DEMUX, decoders, encoders · Code conversion: BCD↔XS-3, binary↔Gray, 7-segment · Error detection: parity · Programmable: ROM, PLA, PAL

6Ripple-Carry (Parallel) Adder

Definition An n-bit parallel adder chains n full adders: each Cout feeds the next Cin (C₀ = 0). All bits are applied at once, but the carry ripples from LSB to MSB.
Delay Carry path per stage = 2 gate levels (AND → OR); worst case it passes all n stages: t ≈ n × tcarry ≈ 2n gate delays. 16 bits × 10 ns = 160 ns.

IC 7483 (newer pinout 74283): 4-bit binary adder with fast carry; cascade two for 8 bits (C₄ → next C₀).

Cheap (n FAs) but slow: delay grows linearly with n.

7Carry Look-Ahead Adder (CLA)

high-yield
Idea Compute every carry directly from the inputs, no ripple. Per bit: Gi = AiBi (generate: makes a carry itself), Pi = Ai ⊕ Bi (propagate: passes Ci on).

C₁ = G₀ + P₀C₀
C₂ = G₁ + P₁G₀ + P₁P₀C₀
C₃ = G₂ + P₂G₁ + P₂P₁G₀ + P₂P₁P₀C₀
C₄ = G₃ + P₃G₂ + P₃P₂G₁ + P₃P₂P₁G₀ + P₃P₂P₁P₀C₀

Worked example ✍ A = 1011, B = 0101, C₀ = 0 → G = 0001, P = 1110 · C₁ = G₀ = 1, C₂ = P₁C₁ = 1, C₃ = 1, C₄ = 1 (one carry propagated three places, yet all four appear together) · S = P ⊕ C₃C₂C₁C₀ = 1110 ⊕ 1110 = 0000 → 1 0000 (11 + 5 = 16 ✓)
Memory trick G = "both 1, I Give a carry" · P = "one 1, I Pass it on". 3 levels: P/G → AND → OR.
Exam trap CLA delay is fixed only in theory: fan-in grows with n, so real adders use 4-bit CLA blocks + the 74182.

DLD · Combinational CircuitsArithmetic circuits

84-bit Adder-Subtractor (XOR trick)

Each Bi goes through an XOR with mode line M; C₀ = M:

M = 0 → B ⊕ 0 = B, C₀ = 0 → A + B

M = 1 → B ⊕ 1 = B′, C₀ = 1 → A + B′ + 1 = A − B (2's complement)

Signed overflow: V = C₄ ⊕ C₃

Unsigned: C₄ = 1 → A ≥ B; C₄ = 0 → negative result.

Worked example ✍ 7 − 5: 0111 + 1010 + 1 = 1 0010 → 2 (drop C₄) · 5 − 7: 0101 + 1000 + 1 = 0 1110 = −2 · 6 + 5 = 1011: C₃ = 1, C₄ = 0 → V = 1, overflow

9BCD Adder

Adds two BCD digits + carry. A 4-bit binary adder gives K Z₈Z₄Z₂Z₁ (max 9 + 9 + 1 = 19).

If the sum > 9 (or K = 1), add 0110 (6) to skip the 6 unused codes:

C = K + Z₈Z₄ + Z₈Z₂

Two 4-bit adders + correction logic (2 AND + 1 OR); C is the decimal carry out.

Worked example ✍ 8 + 7 = 1111 → + 0110 = 1 0101 → 0001 0101 = 15 ✓ · 9 + 9 = 1 0010 (K = 1) → 0010 + 0110 = 1000 → 0001 1000 = 18 ✓ · 4 + 5 = 1001: no correction

12Encoder & Priority Encoder (2ⁿ → n)

Reverse of a decoder. 8-to-3 (octal-to-binary), one input active at a time; just 3 OR gates:

A₂ = D₄ + D₅ + D₆ + D₇
A₁ = D₂ + D₃ + D₆ + D₇
A₀ = D₁ + D₃ + D₅ + D₇

Two faults: D₃ and D₆ together → 111 (wrong); "D₀ active" and "nothing active" both give 000.

Priority encoder: the highest active input wins; V (valid) = 1 if any input is active. D₃ highest:

13Multiplexer (MUX): Data Selector

high-yield
Definition A MUX routes one of 2ⁿ data inputs to a single output; n select lines choose which. Many-to-one, "data selector", parallel-to-serial converter.

2:1: Y = S′I₀ + SI₁

4:1: Y = S₁′S₀′I₀ + S₁′S₀I₁ + S₁S₀′I₂ + S₁S₀I₃

4:1 gates: 2 NOT + 4 AND + 1 OR.

Inputs2481632
Select lines12345

ICs: 74151 8:1 (outputs Y and Y′) · 74153 dual 4:1 · 74157 quad 2:1 · 74150 16:1

Implementing a function with a MUX

An n-variable function needs only a 2ⁿ⁻¹ : 1 MUX: n − 1 variables drive the selects; each data input is 0, 1, x or x′ (x = last variable).

(A 2ⁿ:1 MUX works directly: Ii = the truth-table output, 0 or 1.)

14Demultiplexer (DEMUX): Data Distributor

One input D → one of 2ⁿ outputs, chosen by n selects. One-to-many, serial-to-parallel.

1:4 → Y₀ = S₁′S₀′D, Y₁ = S₁′S₀D, Y₂ = S₁S₀′D, Y₃ = S₁S₀D

A decoder with enable = DEMUX: feed the data into E, the selects into the code inputs. So the 74138 also works as 1:8 DEMUX, and the 74155 is a dual 2-to-4 decoder/DEMUX.

Exam trap A MUX has 1 output, a DEMUX 1 input. 16:1 from 4:1 needs 5, not 4. A MUX is a universal logic module (any function).
IT link A MUX picks the ALU operand in a CPU; TDM links = MUX + DEMUX.

15Code Converters

BCD → Excess-3 (XS-3 = BCD + 0011; codes 10–15 are don't-cares). Inputs ABCD (A = MSB), outputs wxyz:

z = D′ · y = CD + C′D′ = (C ⊕ D)′
x = B′C + B′D + BC′D′ · w = A + BC + BD

Check 5 = 0101 → w = BD = 1, x = 0, y = 0, z = 0 → 1000 = 8 ✓

Binary → Gray: G₃ = B₃, Gi = Bi+1 ⊕ Bi (n − 1 XORs)
Gray → binary: B₃ = G₃, Bi = Bi+1 ⊕ Gi (uses the new B)

1011 → 1110 (Gray) and back: 1, 1⊕1 = 0, 0⊕1 = 1, 1⊕0 = 1 → 1011 ✓

16Parity Generator & Checker

Even-parity generator (3-bit message ABC): P = A ⊕ B ⊕ C, so the total number of 1s (with P) is even. Odd parity: P = (A ⊕ B ⊕ C)′.

Checker (receiver): PEC = A ⊕ B ⊕ C ⊕ P; 0 = OK, 1 = error.

n bits → n − 1 two-input XOR gates (a "parity tree"). ICs: 74180, 74280 (9-bit generator/checker).

Example: 101 → P = 0, send 1010; receive 1110 → PEC = 1 → error ✓

Exam trap Parity detects any odd number of bit errors, but not 2 (or any even number) and it cannot correct (Hamming code can).

17BCD-to-7-Segment Decoder

Digit0123456789
Segments lit6255456376

4 BCD inputs → 7 outputs (a–g), one function per segment; codes 10–15 = don't-cares. Segment a is off only for 1 and 4: a = A + C + BD + B′D′

7447: active-LOW (open-collector) outputs → common-anode display · 7448: active-HIGH → common-cathode · CMOS: 4511.

Memory trick "47 is LOW, Anode": 7447 pulls a segment LOW to light it, so the common pin goes to +V (anode). 7448 is the opposite.

18ROM, PLA, PAL

high-yield
Idea Any SOP = an AND array (product terms) feeding an OR array. PLDs differ only in which array is programmable.
DeviceAND arrayOR arrayKey point
ROM / PROMfixed (decoder)programmableall 2ⁿ minterms; stores the truth table as is
PLAprogrammableprogrammablemost flexible; product terms shared
PALprogrammablefixedcheaper, faster; no sharing (GAL: erasable)

F₁ = AB′ + AC, F₂ = AC + BC: a PLA needs 3 product terms (AC shared); a PAL needs 4.

ROM size 2ⁿ × m: 32 × 8 → 5 address lines, 8 outputs, 256 bits. Full adder = 8 × 2 ROM.

PLA size n × k × m (inputs × products × outputs): minimise distinct product terms, not literals.

Modern: CPLD, FPGA (look-up tables).

Memory trick ROM: AND fixed · PAL: OR fixed (P-A-L: "AND is programmable, the Last stage is locked") · PLA: nothing fixed.

19Hazards (glitches)

A hazard is a momentary wrong output caused by unequal path delays.

  • Static-1: should stay 1, dips to 0 (SOP)
  • Static-0: should stay 0, jumps to 1 (POS)
  • Dynamic: changes 3+ times instead of once

F = AB + A′C, B = C = 1: when A falls, AB turns off before A′C turns on. Fix: add the consensus term BC (Boolean Algebra notes, sheet 3), i.e. cover every pair of adjacent 1s by one K-map group.

Exam trap The redundant term a minimal K-map drops is exactly what removes the hazard. Clocked systems sample after outputs settle, so hazards matter most in asynchronous circuits.
