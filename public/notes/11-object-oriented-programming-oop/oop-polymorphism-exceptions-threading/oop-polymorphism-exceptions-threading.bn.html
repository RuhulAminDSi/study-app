সবচেয়ে বেশি আসে ★
সংজ্ঞা পলিমরফিজম (Polymorphism) ("এক ইন্টারফেস, অনেক রূপ") একই নামকে জড়িত টাইপ অনুযায়ী ভিন্ন কাজ করতে দেয়। বাইন্ডিং (Binding) = একটি কলকে ফাংশন বডির সঙ্গে যুক্ত করা। আর্লি (স্ট্যাটিক) বাইন্ডিং হয় কম্পাইল টাইমে — ওভারলোডিং ও টেমপ্লেট। লেট (ডাইনামিক) বাইন্ডিং হয় রান টাইমে — বেস পয়েন্টার বা রেফারেন্সের মাধ্যমে ওভাররাইডিং।
ফাংশন ওভারলোডিংয়ের নিয়ম একই নাম, একই স্কোপ; প্যারামিটার তালিকা ভিন্ন হবে সংখ্যা, টাইপ বা ক্রমে। শুধু রিটার্ন টাইপ যথেষ্ট নয়: int f(int) + double f(int) = কম্পাইল এরর। কম্পাইলারের ক্রম: হুবহু মিল → প্রমোশন (char→int, float→double) → স্ট্যান্ডার্ড কনভার্শন → ইউজার কনভার্শন; দুটি সমান ভালো মিল = অস্পষ্টতা (ambiguity) এরর। Java-তে সাবক্লাসও উত্তরাধিকারসূত্রে পাওয়া মেথড ওভারলোড করতে পারে।

২ভার্চুয়াল ফাংশন, vtable ও ওভাররাইডিং

আউটপুট প্রশ্ন ★
সংজ্ঞা ওভাররাইডিং (Overriding) = ডিরাইভড ক্লাস উত্তরাধিকারসূত্রে পাওয়া মেথডকে একই সিগনেচারে নতুন করে লেখে। C++-এর ভার্চুয়াল ফাংশন (Virtual function) পয়েন্টারের নয়, অবজেক্টের টাইপ দেখে ঠিক হয়, তাই Base* p = new Derived; p->f(); চালায় Derived::f। virtual না থাকলে পয়েন্টারের টাইপই ঠিক করে (স্ট্যাটিক বাইন্ডিং)। কম্পাইলার এটি করে প্রতি ক্লাসে একটি vtable ও প্রতি অবজেক্টে একটি লুকানো vptr দিয়ে।
class Base { public: void show() { cout << "Base "; } virtual void print() { cout << "BasePrint"; } }; class Derived : public Base { public: void show() { cout << "Derived "; } void print() override { cout << "DerivedPrint"; } }; Base* p = new Derived; p->show(); // Base (static) p->print(); // DerivedPrint (dynamic) // output: Base DerivedPrint

পরীক্ষার ফাঁদ কনস্ট্রাক্টর ভার্চুয়াল হতে পারে না; কনস্ট্রাক্টরের ভেতরে ভার্চুয়াল কল বেস ভার্সন চালায়। Java-তে ওভাররাইড করে অ্যাক্সেস কমানো বা বড় checked এক্সসেপশন ছোড়া যায় না।
সমাধানকৃত উদাহরণ ✍ sizeof ৬৪-বিট: class A { int x; }; → 4। একটি ভার্চুয়াল ফাংশন যোগ করলে → 16 (8-বাইট vptr + 4 + প্যাডিং)। আরও ভার্চুয়াল ফাংশনেও vptr একটিই।

৩অ্যাবস্ট্রাক্ট ক্লাস ও ভার্চুয়াল ডেস্ট্রাক্টর

হাই-ইল্ড ★
সংজ্ঞা পিওর ভার্চুয়াল ফাংশন (Pure virtual function) ঘোষণা করা হয় = 0 দিয়ে — virtual double area() = 0; — অর্থাৎ "প্রতিটি সাবক্লাসকে এটি দিতেই হবে"। অন্তত একটি পিওর ভার্চুয়াল ফাংশনযুক্ত ক্লাস হলো অ্যাবস্ট্রাক্ট ক্লাস (Abstract class): এর অবজেক্ট তৈরি করা যায় না, তবে পয়েন্টার ও রেফারেন্স রাখা যায়। যে ডিরাইভড ক্লাস সব পিওর ভার্চুয়াল ফাংশন ওভাররাইড করে না, সেটিও অ্যাবস্ট্রাক্ট। Java ও C# ব্যবহার করে abstract কিওয়ার্ড।
class Shape { public: virtual double area() = 0; // pure virtual ~Shape() {} // virtual dtor }; class Circle : public Shape { double r; public: Circle(double r) : r(r) {} double area() override { return 3.14159*r*r; } }; Shape* s[2] = { new Circle(1), new Rect(2, 3) }; double total = 0; for (auto x : s) total += x->area(); // Shape t; → error: abstract class

শূন্য অ্যাবস্ট্রাক্ট মেথড থাকতে পারে?না — ≥ ১টি পিওর ভার্চুয়াল হলেই অ্যাবস্ট্রাক্টহ্যাঁ, abstract লিখলে
অ্যাবস্ট্রাক্ট মেথডের বডি দেওয়া যায়?হ্যাঁ, বাইরে: Shape::area()না
Java-তে একই abstract class Shape { abstract double area(); } · class Circle extends Shape {…} · Shape s = new Circle(1); বৈধ — রেফারেন্সের টাইপ অ্যাবস্ট্রাক্ট হতে পারে।
ভার্চুয়াল ডেস্ট্রাক্টর Base* p = new Derived; delete p; — ~Base() ভার্চুয়াল না হলে কেবল বেস ডেস্ট্রাক্টর চলে (আনুষ্ঠানিকভাবে undefined behaviour), ডিরাইভড অংশ লিক হয়। নিয়ম: যে ক্লাসে কোনো ভার্চুয়াল ফাংশন আছে, তার ডেস্ট্রাক্টর ভার্চুয়াল হবে। তখন ক্রম: ~Derived() তারপর ~Base()।
অবজেক্ট স্লাইসিং (Object slicing) Derived d; Base b = d; কেবল Base অংশ কপি করে; ডিরাইভড ফিল্ড "কেটে বাদ" যায় এবং b.print() ডাকে Base::print। পলিমরফিজম কাজ করে কেবল পয়েন্টার বা রেফারেন্সে, ভ্যালুতে কখনো নয়। Java-তে স্লাইসিং নেই: ভেরিয়েবল রেফারেন্স রাখে।
মনে রাখার কৌশল "= 0 মানে শূন্য অবজেক্ট।" ক্লাসে কোথাও = 0 বসালে আর অবজেক্ট বানানো যায় না।
পরীক্ষার ফাঁদ "অ্যাবস্ট্রাক্ট ক্লাসে কেবল অ্যাবস্ট্রাক্ট মেথড থাকে" — ভুল। C++-এ abstract কিওয়ার্ড নেই। অ্যাবস্ট্রাক্ট ক্লাস বনাম ইন্টারফেস: প্রথম লেসন।
সমাধানকৃত উদাহরণ ✍ মোট ক্ষেত্রফল Circle(1) + Rect(2,3) = 3.14159 + 6 = 9.14; প্রতিটি area() রান টাইমে বাছাই।

সংজ্ঞা এক্সসেপশন (Exception) হলো রান টাইমের অস্বাভাবিক ঘটনা (শূন্য দিয়ে ভাগ, ভুল ইনডেক্স, ফাইল নেই) যা স্বাভাবিক প্রবাহ ভাঙে। try ব্লক পাহারা দেয়, throw এক্সসেপশন অবজেক্ট ছোড়ে, catch মিলে যাওয়া টাইপ সামলায়। throw হলে শুরু হয় স্ট্যাক আনওয়াইন্ডিং (Stack unwinding): হ্যান্ডলার না মেলা পর্যন্ত ফ্রেম সরানো হয় ও লোকাল অবজেক্ট ধ্বংস হয়; কোনো হ্যান্ডলার না পেলে → std::terminate() (C++) বা স্ট্যাক ট্রেসসহ থ্রেড বন্ধ (Java)।

হাই-ইল্ড ★
সংজ্ঞা থ্রেড (Thread) হলো CPU শিডিউলিংয়ের ক্ষুদ্রতম একক — একটি "লাইটওয়েট প্রসেস"। মাল্টি-থ্রেডিং (Multi-threading) এক প্রসেসের ভেতরে দুই বা ততোধিক থ্রেড চালায়; তারা কোড, ডেটা ও হিপ ভাগ করে, কিন্তু প্রত্যেকের নিজস্ব স্ট্যাক, রেজিস্টার ও প্রোগ্রাম কাউন্টার। এক কোরে থ্রেড চলে সমকালীনভাবে (concurrent), পালা করে; বহু কোরে সমান্তরালে (parallel)। ব্যবহার: সাড়া-দেওয়া GUI, সার্ভার, ব্যাকগ্রাউন্ড ডাউনলোড।

start() বনাম run() start() JVM-এর কাছে নতুন থ্রেড চায়, সেই থ্রেড পরে run() ডাকে। সরাসরি run() ডাকা বর্তমান থ্রেডে সাধারণ মেথড কল। দুবার start() → IllegalThreadStateException। Runnable ভালো: ক্লাসটি তখনও অন্য ক্লাস extend করতে পারে (একক ইনহেরিট্যান্স), আর একটি টাস্ক বহু থ্রেড ভাগ করতে পারে। থ্রেডগুলোর প্রিন্টের ক্রম নিশ্চিত নয়।
