২ ফাইল পারমিশন: chmod ও chown ★ সর্বোচ্চ yield

পারমিশন মডেল প্রতিটি ফাইলের ৩টি user class: owner, group, others। প্রতিটি পায় r=4, w=2, x=1 bit। chmod NNN file — প্রতিটি digit = r×4+w×2+x×1।
কমান্ডউদ্দেশ্যউদাহরণ
chmod 755 fileowner=rwx, group=r-x, others=r-xexecutable-এর জন্য standard
chmod 644 fileowner=rw-, group=r--, others=r--data file-এর জন্য standard
chmod 701 fileowner=rwx, group=---, others=--xgroup gets কোনো bit নেই (0=---)
chown user:group fileowner ও group পরিবর্তন করুনchown www:www index.html
chgrp group fileশুধু group পরিবর্তন করুনchgrp dev project/
স্মৃতি-কৌশল r=৪, w=২, x=১ → যোগ করুন: rwx=৭, rw-=৬, r-x=৫, r--=৪, --x=১, ---=০। তিন-সংখ্যার octal বাম থেকে ডানে লিখুন: owner · group · others।
পরীক্ষার ফাঁদ chmod 701: মাঝের digit হলো 0 = --- (group-এর কোনো access নেই), --x নয়। অনেকে 701 = rwx--x--x লেখেন — ভুল। 0 = ---, 1 = --x।
কাজের উদাহরণ chmod 755 script.sh: 7=rwx(owner), 5=r-x(group), 5=r-x(others) → -rwxr-xr-x।
পরীক্ষার ফাঁদ chown ownership পরিবর্তন করে। chmod permission পরিবর্তন করে। এগুলো আলাদা operation — MCQ-তে সাধারণ বিভ্রান্তি।
স্মৃতি-কৌশল ls -l: -rwxr-xr-x user group size Oct 30 file — প্রথম character file type, তারপর ৯ bit (owner·group·others)।

OS ▸ RAIDRedundant Array of Independent Disks

৪ RAID: ধারণা ও লেভেল ★ Bank/PSU favourite

RAID = Redundant Array of Independent Disks। একাধিক physical disk-কে একটি logical unit-এ একত্রিত করে। লক্ষ্য: performance (striping) বা reliability (mirroring/parity) বা উভয়।
LevelTechniqueMin diskFault toleranceUsable capacityসেরা ব্যবহার
RAID 0Striping২০N × diskগতি (video editing)
RAID 1Mirroring২১ drivedisk_sizeOS drive, critical data
RAID 5Dist. parity৩১ drive(N−১) × diskFile server, NAS
RAID 6Double parity৪২ drive(N−২) × diskবড় array
RAID 10Mirror+stripe৪ (জোড়)১ per pairN/২ × diskBanking database ★
স্মৃতি-কৌশল RAID ৫ usable = (N−১)×disk। একটি disk "সমতুল্য" স্থান parity-তে যায় — distributed, কিন্তু গণিতে একটি disk consumed। পরীক্ষায় এই formula বারবার আসে।
পরীক্ষার ফাঁদ RAID ≠ backup। RAID শুধু hardware disk failure থেকে রক্ষা করে — ransomware, accidental deletion, বা data corruption থেকে নয়।
স্মৃতি-কৌশল ২ কোন RAID কোথায়? — RAID 0: শুধু speed (temp storage) · RAID 1: OS drive, small critical data · RAID 5: file server, NAS · RAID 10: banking database, high-I/O systems।

৫ RAID Capacity ফর্মুলা ★ সংখ্যাসূচক favourite

ফর্মুলা শিট এই ৫টি ফর্মুলা মুখস্থ করুন — বাংলাদেশের পরীক্ষায় প্রতিটি RAID সংখ্যাসূচক কভার করে।
RAIDUsable capacity ফর্মুলা৪ × ২ TB উদাহরণ
RAID 0N × disk_size৪ × ২ = ৮ TB
RAID 1disk_size (এক copy)২ TB (N নির্বিশেষে)
RAID 5(N − ১) × disk_size(৪−১) × ২ = ৬ TB
RAID 6(N − ২) × disk_size(৪−২) × ২ = ৪ TB
RAID 10(N / ২) × disk_size(৪/২) × ২ = ৪ TB
কাজের উদাহরণ ১ BSCS AP 2026: ৪টি ২ TB drive সহ RAID 0, RAID 5 ও RAID 10-এর usable storage গণনা করুন।
  • RAID 0: ৪ × ২ = ৮ TB (redundancy নেই — যেকোনো failure সব data হারায়)
  • RAID 5: (৪−১) × ২ = ৬ TB (১ drive parity-র জন্য; ১টি failure সহ্য করে)
  • RAID 10: (৪/২) × ২ = ৪ TB (২টি mirrored pair stripe করে)
কাজের উদাহরণ ২ Combined Bank AME 2026: ৫টি ৪ TB drive RAID 5-এ। কেন ২০ TB নয়?
  • Usable = (৫−১) × ৪ = ১৬ TB
  • ৪ TB distributed parity-তে consumed — একটি drive-এর সমতুল্য
স্মৃতি-কৌশল banking প্রশ্নে কোন RAID? → RAID 10 (mirror pairs + stripe = সেরা I/O performance + redundancy, কোনো parity calculation delay নেই)।
পরীক্ষার ফাঁদ RAID 10-এ জোড় সংখ্যক disk প্রয়োজন (minimum ৪)। RAID 5-এ minimum ৩। RAID 1 (min ২) ও RAID 10 (min ৪) গুলিয়ে ফেলা সাধারণ ভুল।

৬ RAID Failure Recovery ও Drive Types

RAID failure recovery পদ্ধতি

  1. Controller failure শনাক্ত করে → array degraded mode-এ চলতে থাকে (বাকি disk + parity ব্যবহার করে)
  2. নষ্ট drive প্রতিস্থাপন করুন সমান বা বড় capacity-র নতুন drive দিয়ে
  3. Controller স্বয়ংক্রিয়ভাবে rebuild করে parity/mirror থেকে নতুন drive-এ হারানো data reconstruct করে
  4. Rebuild চলাকালে: array vulnerable — RAID 5-এ দ্বিতীয় failure সব data হারাবে
