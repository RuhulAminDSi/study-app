OS · File SystemsFiles & attributes

1The File System and the File

most asked ★
Definition A file system is how the OS names, stores, shares and protects data on secondary storage, giving programs one device-independent view — a tree of named files, not raw blocks. Two halves: physical (which blocks belong to a file) and logical (what a program may do with it). The disk is already cut into blocks of 512 B – 4 KiB.
AttributeWhat it recordsExam hooks
1 namethe symbolic namedirectory entry, not the inode
2 identifierthe number the OS usesinode no · first cluster
3 typetext, binary, exec, specialcharacters vs packed records
4 locationpointer(s) to data blocksstart block, chain or index
5 sizelength in bytes and blocksfixed field ⇒ alloc size
6 protectionwho may read / write / execmode bits · ACL · ACE
7 timestampscreation, modification, accessUNIX: atime, mtime, ctime
8 owneruser id and group idonly root may change it

Logical file = the bytes the program sees, from offset 0. Physical file = the blocks on the medium + the directory entry / inode pointing at them. The logical → physical mapping is the file organisation.

Types. text (.txt .md .csv) · binary (.jpg .mp4 .exe) · executable (machine code; ELF on UNIX) · special (UNIX devices, FIFOs, sockets: /dev/sda, /dev/null).

Nothing inside a file marks where a "record" ends — the format does, so one file can be read byte-wise, record-wise or block-wise.

Memory trick "The inode holds everything except the name." Attribute 1 sits in the directory, 2–8 in the inode. That split explains hard links, ln -s and every path lookup.
Exam trap A file's identifier is not its name, and the superblock is not a file's metadata — it describes the volume. A file system manages secondary storage; RAM holds buffers.
Worked example ✍ decode one directory line -rwxr-xr-- 1 rahim exam 8200 Sep 9 10:14 report.txt → - regular file (d = directory) · rwxr-xr-- = 7 5 4: owner rahim rwx, group exam r-x, others r-- · link count 1 · size 8 200 B = 17 blocks of 512 B.

2The Seven Standard File Operations

written favourite ★
Definition A file is an abstract data type: a named, protected sequence of bytes. Every operating system gives it exactly seven operations, and every system call is one of them.
OperationWhat it doesTypical call
createmake a new empty file, add an entrycreat(), open(O_CREAT)
deleteremove the entry, free the blocksunlink(), remove()
openresolve name, read metadata, check rightsopen()
closeflush, release the descriptorclose()
readcopy bytes from the offset to a bufferread(), fread()
writecopy bytes to the file at the offsetwrite(), fwrite()
seekmove the offset: SET / CUR / ENDlseek(), fseek()
The byte-stream model ✍ Everything follows from one number: the offset, initially 0.
fd = open("/home/rahim/report.txt", O_RDONLY); n = read(fd, buf, 512); /* 0 → 512 */ p = lseek(fd, 0, SEEK_END); /* p = size */ close(fd);

Sequential access reads from the start, record by record. Direct access turns block n into a physical block in O(1).

AllocationBlock n found by
contiguousstart + n
linked / FATFAT[n]
indexed / inodeindex entry n
Memory trick "Create before you open, open before you read, close when done." Only read and write touch bytes.
Exam trap append is not an eighth operation: it is write with the offset at the end. rename is a directory operation.
Worked example ✍ turn an offset into a disk address A contiguous file starts at block 12, block size 512 B. lseek(fd, 2048, SEEK_SET) → logical block 2048 ÷ 512 = 4, offset in block 2048 mod 512 = 0; the transfer starts at block 16, so reading 1 KB touches blocks 16 and 17.

3File Organisation I — Contiguous & Linked

high-yield ★
Definition File organisation decides which disk blocks belong to a file, and so how a logical block number becomes a physical one.

Contiguous keeps the blocks neighbouring, so one seek serves the file. Linked scatters them and keeps the next address in each block, so the file grows anywhere.

PointContiguousLinked
Directory holdsstart block + lengthfirst block only
Random accessO(1): base + nO(n): walk the chain
Grows latermust be movedfree, anywhere
Fragmentationexternalnone outside
Cost, damageno pointer; loses 1 block1 pointer; truncates file

4The FAT — Linked Allocation with a Table

MCQ staple
Definition The File Allocation Table (FAT) is linked allocation in which the "next block" pointer of every block on the volume is kept in one table at the start of the volume instead of inside the data blocks. Entry i holds the block after block i of the same file; 0 = free, 0xFFF = end of chain.
Memory trick "A FAT is linked allocation whose links were moved into a table."
Exam trap A FAT is not contiguous and not indexed. It is per volume, not per file.
Worked example ✍ what does the FAT cost? A 1.44 MB floppy has 2 880 sectors of 512 B: 1 boot sector + 2 × 9 FAT12 sectors + 14 root-directory sectors, leaving 2 880 − 1 − 18 − 14 = 2 847 data clusters. Check: 2 847 × 12 bits = 4 271 B → 9 sectors ✓.
Worked example ✍ the allocation-size problem A 4 096 B file with 512-B blocks needs 8 blocks, so contiguous allocation must declare a length at create time. With a 16-bit length field a file holds at most 65 535 blocks = 32 MiB; appending past it forces the file to be relocated. The fix is extents — a list of (start, length) runs.

OS · File SystemsIndexed & the inode

5Indexed Allocation & the UNIX Inode

written favourite ★
Definition Indexed allocation gives each file an index block — one block whose entries are the addresses of the file's data blocks. To reach logical block n the OS reads the index block and takes entry n: no external fragmentation, direct access, and the file may grow anywhere. Its one weakness is internal fragmentation — a 3-block file still burns a whole index block. Multi-level indexing lets index blocks point to index blocks, so the reach grows as nk instead of n.
LevelReachReads
direct (10)blocks 0–91
single indirect+ 128 blocks2
double indirect+ 16 3843
triple indirect+ 2 097 1524
total2 113 674≈ 1.01 GiB

Where 128 = block size ÷ pointer size = 512 B ÷ 4 B. Modern ext2/ext4 keeps the shape with 12 direct + 1 + 1 + 1 = 15 pointers; with 4 KiB blocks and 1 KiB indirect blocks (1 024 addresses) it reaches 4 MiB + 4 GiB + 4 TiB.

An i-node ("index node") holds the metadata and the pointers. A hard link is a second directory entry on the same inode, so the file dies only when nlink falls to 0 — and because the name is not in the inode, one file can have many names.

Worked example 1 ✍ locate logical block 20 Direct covers 0–9, so block 20 is single indirect: 20 − 10 = 10 → the 11th address in that block. Cost: 2 disk reads (index, then data).
Worked example 2 ✍ locate logical block 300 Direct + single reach only 138 blocks, so 300 is double indirect: 300 − 138 = 162 → sub-block 162 ÷ 128 = 1 (the 2nd) and address 162 mod 128 = 34 in it. Cost: 3 disk reads.
Memory trick "Subtract as you climb." Direct takes the first 10; subtract 10 and read a single indirect; if the answer is still ≥ 128, subtract 128 and read a double indirect. An indirect block is an address book, never data.
Exam trap The inode stores the name? No — the directory does. The superblock holds the block bit map and the inode-table pointers, so it is volume-wide, not a file's metadata. A file descriptor is an integer index, not the inode.

6Directory Structures

high-yield ★
Definition A directory is a special file whose entries map a name to an identifier (an inode number or the first cluster) of a file or sub-directory. It does four jobs: grouping, naming, searching, sharing. A directory's own "write" bit is what allows entries to be added or removed inside it.
StructureShapeBuysWeakness
single-levelone flat listsimplestname clashes, no grouping
two-levelmaster + one per userper-user isolationno per-project grouping
treeacyclic, any depthnatural hierarchysharing needs copies or links
acyclic graphtree + shared dirone copy, many parentscan dangle; ownership unclear
general graphcycles allowedmaximum flexibilitytraversal may loop
hashh(name) → bucketO(1) lookupno order; poor when it grows
Path names absolute /usr/bin/gcc, relative ../docs/r.txt.
Memory trick single → two → tree → acyclic → general → hash.
Exam trap A symlink stores a path, a hard link an inode number.
Worked example ✍ what does a path cost? Opening /a/b/c/file: read the root's block → find a; read a's block → b; read b's block → c; read c's block → file; then the inode. With 512-B blocks and 16-byte UNIX directory entries (2-byte inode number + 14-character name) a block holds 32 entries, so it is 4 directory reads + 1 inode read before a single data byte moves.

7Worked Trace: Opening a File

10-mark written ★
Definition open() does not read the file — it resolves a path name to an inode, checks the caller's rights and returns a file descriptor. Data blocks are touched by the first read or write.
  1. Parse the path. It starts with /, so the walk begins at the root (inode 2).
  2. Walk the components. Match home in the root's blocks, take its inode (30); repeat for rahim (41) and report.txt → inode 4711.
  3. Fetch the inode. Using the inode-table pointers in the superblock: mode, ids, nlink, size, pointers.
  4. Check protection. Compare the mode's owner / group / other bits with the caller's ids; a missing right fails with EACCES.
  5. Build the open-file entry. Store the inode pointer, O_RDONLY, offset 0, a refcount; return the descriptor (fd = 3).
  6. read(fd, buf, 512). Offset 0 → block 0 → the first direct pointer → block 1042 → DMA.
  7. close(fd). Flush, free the descriptor, decrement the refcount; at zero the inode goes.
CallReads from diskChangesReturns
open("/home/rahim/report.txt", O_RDONLY)3 directory blocks + inodeone open-file entry, offset 0fd = 3
read(3, buf, 512)data block 1042offset 0 → 512512
lseek(3, 0, SEEK_END)nothingoffset ← size8200
close(3)nothingdescriptor freed, refcount −10
Exam trap open() touches no data block — only directories and the inode. Every component must resolve: a missing name anywhere aborts the whole call.
Memory trick "Resolve, record, return — then read": path → inode → open-file table → descriptor → data block.
IT link This is exactly what a shell does for ./app --config conf.ini: every component becomes a directory walk, every open an inode lookup, and the descriptor an entry in the process table that /proc/<pid>/fd exposes. A slow NFS mount makes step 2 one network round trip per component.

8Free-Space Management

high-yield ★
Definition The file system must always answer "where is the next run of free blocks?". Free-space management is that bookkeeping; protection decides which subjects (users, processes) may touch which objects (files, devices).
MethodNote
bit vectorcached, very fast
linked listno extra space
groupingmany per block
extentsone entry per run
Worked example ✍ how big is the bit vector? A 1 GiB volume with 512-B blocks has 2³⁰ ÷ 2⁹ = 2 097 152 blocks, so the map needs 2 097 152 ÷ 8 = 256 KiB — it fits in cache. A pointer list would need 4 B each = 8 MiB.

9Protection: Matrix, ACLs, Capabilities

frequently tested
Definition The access control matrix has subjects as rows and objects as columns; a cell holds the rights allowed on that pair. The classical rights are read, write, execute, append, delete, change ownership. It can never be stored densely, so two sparse forms are used.
FormStored whereCatch
Access list (ACL)per file: (user or group, rights)every user on every file
Capability listper process: unforgeable tokensrevoked by hand
UNIX modethe inode: 9 bits, owner / group / othersrwx = 4 + 2 + 1
NTFS ACEthe MFT record: allow / deny per SIDdeny is evaluated first
Worked example ✍ modes chmod 640 notes.txt → owner rw- (6), group r-- (4), others --- (0). Special bits: setuid 4000, setgid 2000, sticky 1000 — so /tmp is 1777.
Exam trap The matrix is the model; the ACL is per object and the capability per subject. Protection is about rights; authentication and encryption are security.

Journaling = what exactly? A write-ahead log of intended metadata changes, flushed to stable storage before the change itself; on the next mount it is replayed and discarded. A crash therefore leaves the file system consistent, not the data intact: it protects the metadata, not the user's bytes.
Recovery without a journal fsck (Linux: e2fsck) and chkdsk run at boot: verify the superblock, the bit maps, the inode table and the free-block count, rebuild the free-space map, then report or remove unreferenced inodes. It is O(volume size) — the cost a journal removes.
Memory trick "ext3 = ext2 + a log (2001); ext4 = extents + 64-bit + checksums (2006)." NTFS 1993; XFS = allocation groups.
Exam trap FAT12's limit is 4 096 clusters (≈ 2 MB); 65 524 belongs to FAT16. A journal protects metadata, not data.

11Case Study of Operating Systems

final syllabus line
MS-DOS (1981) Single-user, single-tasking, real mode on the 8086, 640 KB conventional memory, no memory protection. FAT12 / FAT16, 8.3 names.
UNIX (Bell Labs, 1969–70) Ken Thompson and Dennis Ritchie; Version 1 in 1970, renamed "Unix" in 1972, rewritten in C in 1973. Multi-user, multi-tasking; everything is a file; pipes join commands.
Windows NT (1993) A hybrid kernel — microkernel core, large executive, user-mode subsystems — plus a HAL hiding the hardware. Its signature is the registry, a settings database that replaced the DOS text files.
Linux (announced 14 August 1991) Linus Torvalds, inspired by MINIX and UNIX. A monolithic kernel, modular at run time through loadable kernel modules. Everything is a file; the VFS makes ext4 and XFS look identical.
