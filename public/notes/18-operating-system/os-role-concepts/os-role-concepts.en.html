OS · Role & StructureGoals and roles

1What Is an Operating System?

foundation ★
Definition An operating system is system software sitting between the user and the hardware, doing three jobs at once: an interface (a program asks for a service instead of driving the device), a resource manager (CPU, memory, files and I/O shared fairly) and a control program (hardware access is privileged, so only the OS may do it). Two textbook names for one object: the extended machine and the resource-manager system.
no OS ⇒ only a circuit
Two classic views of the same program Resource manager / control program — answers who gets what, and when: CPU time by scheduling, memory by allocation, files by the file system, devices by controllers and drivers. It optimises efficiency.
Extended machine — answers what the program sees: an abstract machine of files, processes and devices, with interrupts, DMA and cache protocols hidden underneath. It optimises convenience and portability.
GoalWhat it demandsWhere you meet it
Conveniencea usable interface, not machine codesystem calls, CLI shell, GUI, drivers
Efficiencyresources used at full capacityscheduling, paging, buffering, caching
Ability to evolvenew hardware absorbed without a rewritemodularity, layers, loadable modules
Portabilitythe same OS on different hardwarestandard language (C), hardware abstraction layer
Memory trick Four Gs: Convenience = easy, Efficiency = full, Evolution = changeable, Portability = moves house. "Which goal does paging serve?" → efficiency: it raises utilisation, not comfort. "Which does a hardware abstraction layer serve?" → portability.
Exam trap A driver manages one device; the OS manages all devices and decides who gets them. And "the interface" is ambiguous: the shell is the interface to the user, the kernel is the OS proper. "Which part runs privileged?" → kernel, never the shell.
Worked example ✍ goals applied to one machine One CPU, 8 GB RAM, one disk, four users. Convenience — each user gets a shell and named files instead of programming the disk controller. Efficiency — the scheduler time-slices so the CPU never idles; the file system caches hot blocks. Evolution — a new printer needs one driver, not a new OS. "Which goal did virtual memory serve?" → efficiency.

OS · Role & StructureSystem calls

2System Calls, Traps and the Mode Switch

MCQ staple ★
Definition A system call is the interface through which a user program requests a service from the kernel — open a file, map memory, create a process, read a device. The kernel is the only code that runs privileged, so the request must change the CPU's privilege level. The mechanism is a trap (software interrupt): the CPU saves the context, switches to kernel mode, runs the handler, and returns. A mode switch that only changes the privilege bit is cheap; a context switch that also loads another process's state is not.
Group of system callsExamples
Process controlfork, execve, wait, exit, kill
File operationsopen, close, read, write, lseek
Device managementioctl, read, write on a device
Informationgetpid, uname, sysconf, time
Memory managementbrk, mmap, munmap
PointUser modeKernel mode
Who runs thereevery ordinary process: shell, editor, compilerscheduler, memory manager, drivers, file system
Memory accessits own address space onlyany address space, MMIO registers, page tables
Instructionsa restricted subset; privileged ones trapthe complete set (x86 rings 3 → 0)
Entered bya trap from a call, fault or interrupt— (it leaves by return-from-interrupt)
Memory trick Three doors into the kernel: the trap (the program asks), the fault (the CPU complains — page fault), the interrupt (the world asks — timer, keyboard, disk). All three land in kernel mode, the handler chosen by a vector number.
Worked example ✍ what does the overhead cost? A function call ≈ 20 ns; a system call with trap and return ≈ 1 μs. A program issuing 10⁶ system calls per second of its own work therefore spends 100 % of one core inside the kernel.
IT link `man 2 read` = manual page of the read syscall; `strace -c ls` counts the traps; `time ls` reports user and system time separately.
Exam trap A system call is not a call between two functions of your own program: the library wrapper (glibc) runs in user mode and only the trap enters the kernel.

OS · Role & StructureKernel structure

3Kernel Structure: Monolithic, Layered, Micro, Modular, Hybrid

highest-yield ★
Definition The kernel is the privileged core: it runs in kernel mode, stays resident in memory, owns the hardware and implements the system calls. Its internal structure is a design choice — monolithic, layered, microkernel, modular — plus the hybrid compromise. All answer one question: how much code is trusted enough to run privileged?
StructureWhere things liveStrengthWeaknessExample
Monolithiceverything in the kernelspeed, simple call pathone bug stops allUNIX, Linux, MS-DOS
Layeredall in the kernel, in layerseasy to verifycost of crossing layersTHE, MULTICS, OS/2
Modularcore + loadable modulesflexible, small imagesmodule bugs not isolatedLinux, Solaris, VxWorks
MicrokernelIPC, scheduling, address space onlyreliable, provablemessage overheadMach, MINIX 3, QNX, seL4
Hybridmost of it, microkernel-stylespeed and modularityneither simplest nor safestWindows NT, macOS XNU
Exam trap Hybrid is not "half of each" — it borrows microkernel modularity but keeps drivers in kernel space for speed. Modular ≠ microkernel: a module is kernel code, a microkernel server is user code. A layer may use only the layer directly below it.
Memory trick "Big kernel, fast calls. Small kernel, chatty calls." Whatever the drawing style, the only thing that decides performance is whether a request crosses the user/kernel boundary or stays inside one address space.
Worked example ✍ price of the small kernel A microkernel serves a file read as client → IPC message → file-system server → IPC message → back: at 2 μs per round trip that is 4 μs of messaging where a monolithic kernel calls directly in under 0.1 μs. At 100 000 reads/s, 40 % of the CPU goes on messaging; at 1000 reads/s, 0.4 %.
Where the textbook examples really sit Windows NT and macOS (XNU) are hybrid — macOS is the Mach microkernel with BSD services and the IOKit driver framework around it. Linux is monolithic but modularly built. seL4 is a microkernel of a few thousand lines that has been formally verified.

OS · Role & StructureKernel, shell, utilities

4The Three Parts: Kernel, Shell, Utilities

definition trap ★
Definition "Operating system" is used loosely for two different sets of software. Narrowly it is the kernel alone: privileged, resident, in charge of the hardware. Broadly it is kernel + shell + utilities — the whole distribution a user touches. The three sit at three different privilege levels, and every question about "is the shell part of the OS?" turns on that difference.
kernel ≠ shell ≠ utilities
KernelShellUtilities
Runs inkernel mode, x86 ring 0user mode, ring 3user mode, ring 3
Memoryresident in main memoryan ordinary process, swappableordinary processes
Jobprocesses, memory, files, devices, protectionreads the command line, starts the programone task each: cp, ls, sort, editors
Replaced bynever, while runningfreely — bash, sh, cmd.exe, PowerShellfreely — any program at all
Touches hardwareyesnono
Exam trap The shell is not the kernel and is not privileged; it issues system calls for you. Removing it would not crash the machine, corrupting the kernel would. The compiler is a utility, not part of the OS.
Memory trick "The kernel is the one that cannot be replaced." Kernel — removing it stops the OS. Shell — you are stranded at a bare login prompt. Utility — you lose one command.
Worked example ✍ trace one keystroke to a file cp a.txt b.txt: the shell splits the line and execve()s cp; cp issues open(), read(), write(), close(), each trapping into the kernel. Privileged code entered: five times.
Real-world names Shell: bash, zsh, fish on UNIX-like systems, cmd.exe and PowerShell on Windows. Utilities: the coreutils family (ls, cp, mv, grep) plus editors and compilers. On Linux the shell is a program in /bin, replaceable per user.

5Types of Operating Systems

frequently tested
Definition An OS is "typed" by how it shares the processor and whom it serves, not by its vendor. Three questions fix the type: how many jobs sit in memory, is anybody at a keyboard, must a deadline be met?
Hard real-timeSoft real-time
Missed deadlinefailuredegraded quality
Examplepacemaker, ABS, flight controlstreaming video, live TV
Typical buildsmall dedicated RTOSgeneral OS + RT extension
Not the same axis Multiprogramming, time-sharing, multiprocessor and distributed differ in how many machines and users; real-time and embedded differ in what promise is made. Your phone is all of them at once.
TypeHow the CPU is sharedChief goalTypical use
Batchone job at a time, queued off-lineCPU utilisationmainframe runs
Multiprogrammingmany jobs resident; switch on I/O waitutilisationbase of the next two
Time-sharingmany users online, short slicesresponse + fairnessUNIX, Linux
Multiprocessortwo or more CPUs share memoryparallelismservers
Distributedindependent computers, one machinesharing + reliabilityclusters
Real-timepriority, bounded responsepredictabilitycontrol, avionics
Embeddedone dedicated chip, tiny kerneldeterminism, low powercar ECUs
Mobileapp sandboxes, flash storageuser experienceAndroid, iOS
Memory trick Time-sharing shares among people; real-time shares among deadlines. A time-shared UNIX can still miss a 1 ms deadline: fairness and predictability pull opposite ways.
Exam trap Real-time does not mean fast — it means predictable. Batch is not "single-user": multiprogramming is what lets several jobs share a CPU.
Worked example ✍ the time-sharing trade-off 100 users, quantum q: worst-case wait = 100 × q. q = 100 ms → 10 s; q = 20 ms → 2 s, but switches now happen every 0.2 ms, so at 2 μs each the CPU loses 1 % of its time.

OS · Role & StructureGenerations

6Generations of Operating Systems

history ★
Definition Operating systems are dated by the hardware generation they were built for. Five generations are standard: the first had no OS at all, and each later one bought a single new capability.
GenYearsTechnologyWhat the OS gainedLandmark
1st1945–1955vacuum tubes, paper tapenothing: one job, machine languageIBM 701, EDSAC (1948)
2nd1956–1965transistorsbatch: off-line input, spooling, fixed jobsIBM 7090; FORTRAN 1957, COBOL 1959
3rd1966–1975integrated circuitsmultiprogramming + time-sharingUNIX (1969), MULTICS, System/360 (1964)
4th1975–VLSI, microprocessorsPC era: GUI, networking, client–serverMS-DOS (1981), Windows, Linux (1991)
5thpresentvery large-scale integration, ubiquitous devicesmobile, embedded, virtualised, cloudAndroid (2008), hypervisors
Memory trick None → batch → sharing → GUI/network → mobile/cloud. Say the technologies aloud — tube, transistor, IC, microprocessor, everywhere — and the generation and its dates fall out.
Exam trap Generations are not types: batch is a 2nd-generation type, time-sharing a 3rd-generation type. A paper offering both as rival answers is testing this confusion.
Worked example ✍ reading a clue chain "Several jobs in memory, interactive users, integrated circuits, famous system of 1969." → multiprogramming → time-sharing → 3rd generation → UNIX. The clue chain beats the dates.
One historical detail worth knowing UNIX was written in 1969 for a DEC PDP-7 by Ken Thompson and Dennis Ritchie, rewritten in C in 1970. Generation labels describe the era, not one machine.

7Structural Models: Extensible, VM & the Hypervisor

conceptual ★
Definition The extensible / VM-based model keeps the OS tiny: the kernel only traps, schedules and switches, while every user runs a complete little OS on top as a virtual machine. That gives fault isolation — a crash kills one VM, not the system — and it is the ancestor of the hypervisor (also VMM).
ModelIdeaUsed by
Simple (MS-DOS-like)one program, no protectionMS-DOS, early CP/M
Monolithicevery service in one kernel blockUNIX, Linux
Layeredlayers, each using only the one belowTHE, MULTICS, OS/2
Microkernelminimal kernel, user-level serversMach, MINIX 3, QNX, seL4
Modularcore plus loadable modulesLinux, Solaris, VxWorks
Hybridmicrokernel ideas, monolithic speedWindows NT, macOS XNU
Extensible / VMtiny OS; each user runs a whole OSIBM VM/CMS, ES/VM; Xen, KVM
PointType 1 — native / bare-metalType 2 — hosted
Runs ondirectly on the hardwareon top of a host OS, as an app
Needs a host OS?noyes — Windows, macOS, Linux
Speednear-native, thin layerslower: host kernel in the path
Who uses itdata centres, clouds, serversdesktops, labs, training
ExamplesXen, KVM, ESXi, Hyper-V, ProxmoxVirtualBox, Workstation, Parallels
Memory trick "Type 1 owns the floor, Type 2 asks the landlord." Installed into an existing OS → Type 2.
Exam trap Do not confuse hypervisor with container: a container shares the host kernel, a VM ships a whole guest OS.
Worked example ✍ consolidation arithmetic 20 old servers at 20 % load, each application in its own VM: 20 × 20 % = 400 % of one core, i.e. 4 cores. One 32-core host at 15 % leaves 19 servers free. KVM makes the Linux kernel itself a Type 1 hypervisor; Xen is paravirtualised.

OS · Role & StructureBoot process

8The Boot Process: Firmware → Bootloader → Kernel → init

written favourite
Definition A stored-program machine does nothing until an address holds an instruction and the program counter points at it. The boot sequence is the ladder that puts the first instruction in the CPU and hands the machine to the OS, one owner at a time.
StageWhat it doesWhere it livesExamples
1. Firmwarepower-on self-test, initialise the hardware, find a boot devicea chip on the motherboard; settings in CMOSlegacy BIOS; modern UEFI
2. Bootloaderload the kernel image into RAM and jump to itfirst sector of the disk — MBR or the ESP partitionGRUB, Windows Boot Manager, U-Boot
3. Kernelinitialise subsystems, set up memory, probe devices, start initloaded into RAM, now residentLinux, Windows NT, BSD
4. init / systemdstart services in order, mount filesystems, run the login managerthe first user-space process, PID 1systemd (modern Linux), SysV init, launchd
Memory trick "Firmware sells the machine, the bootloader loads the OS, the kernel owns the machine, init starts the services." Four verbs, four owners — only stage 3 is a kernel.
Exam trap The bootloader is not the OS, and BIOS is not the firmware's only name — UEFI is the successor and uses the ESP, not the MBR. A kernel panic is a stage-3 failure.
Worked example ✍ why an examiner cares "Logo and nothing else." No POST beep → failure before the bootloader (RAM, CPU, power). "No bootable device" → the firmware ran and found none. No GRUB menu → the bootloader is damaged.
IT link Dual boot is the bootloader earning its keep: GRUB shows a menu and loads a different kernel — so it is not part of any OS, and one bootloader can boot Windows and Linux from the same disk.

OS · Role & StructureTraps & interrupts

9Traps, Interrupts and the Cost of a Context Switch

most tested ★
Definition Control reaches the kernel three ways. A trap is synchronous — the program caused it (system call, page fault, divide by zero). An interrupt is asynchronous — a device caused it (timer, keypress, disk). A fault is the CPU reporting a bad instruction. All save the context, take a vector from the vector table and run a handler in kernel mode.
KindCaused byWhenExample
Trapthe running programsynchronousread(), exit(), breakpoint
Faultthe instruction itselfsynchronouspage fault, divide by zero
Interruptan external deviceasynchronoustimer tick, keyboard, disk
OperationCostWhere the time goes
Function call≈ 1–10 nspush registers, jump, return; caches stay warm
System call (trap)≈ 1 μssave context, enter kernel mode, dispatch, return
Context switch≈ 1–10 μssave + restore a PCB; TLB and caches cold after
Major page fault≈ 100 μs – 1 msdisk read for the missing page
What a context switch really costs Saving one process's CPU state and restoring another's is only the direct cost, typically 1–10 μs. The indirect cost is larger: the new process meets an empty instruction cache, a cold TLB and cold data caches. More syscalls or a shorter quantum mean more switches.
Memory trick "Trap is the program's fault; interrupt is the world's."
Exam trap A page fault is not a crash — the OS pages the frame in and restarts the instruction. A trap is not a context switch: that means a different process ran.
Worked example ✍ throughput lost to switching 50 users, quantum 20 ms, switch 2 μs. Average wait ≈ (50 − 1)/2 × 20 ms ≈ 490 ms. Overhead per slice = 2/20 000 = 0.01 % — the design point.
IT link `time` splits a program's life into user and system time; system time is time in the kernel. High system time with low CPU use is the signature of thrashing.

Written question Define an OS, explain it as a resource manager and as a control program, describe with a labelled diagram how a user program reaches a kernel service through a system call, and compare the monolithic and microkernel structures. 10 marks
  1. Definition (2) — system software between the user and the hardware, managing CPU, memory, files and devices. 2
  2. Resource manager (2) — who gets what and when: CPU by scheduling, memory by allocation and paging, files by the file system, devices by drivers. 2
  3. Control program (1) — the only program that touches the hardware; programs are isolated, so a bug in one cannot damage the system. 1
  4. Call path (3) — program → library routine → trap → CPU saves context and switches to kernel mode → dispatch from the system-call table → service → return-from-trap. Label: user mode, kernel mode, trap, hardware. 3
  5. Comparison (2) — monolithic: all services in one kernel, fast but one bug can stop the machine (UNIX, Linux). microkernel: only IPC, scheduling and address space, files and drivers as user servers — reliable, but it pays message overhead (Mach, QNX). 2
